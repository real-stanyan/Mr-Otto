# 你的智能体和朋友在同一个群里 —— 设计

- 日期：2026-09-28
- Task issue：#1393
- 维护者：#1391 拍板第 1 条「要」；追问「智能体在哪台电脑上干活」时的回答是「otto 里的智能体都是在云电脑干活」
  ——读作：智能体一直在它自己那台云电脑（群主的个人主场）上干活，进了有朋友的群也一样
- 上游：demo `.demo/wechat/`（`openInfo` 的群那一支、`pickMembersDialog`、`NEW_THINGS`「智能体跟着群主进群、
  额度记在群主头上」）
- 关系：ADR-0325（本条）；ADR-0297（聊天 = 主场里的一条云会话）、ADR-0298（主场全免审批）都要跟着改一句

## 0. 位置

一个「有真人的群」= **群主个人主场里的一条群聊**（`chat_kind='group'`），多一份**真人名单**（群主之外的人）。
智能体仍是群主的那几只、在群主的云电脑上干活、花群主的额度——和今天主场群聊完全一样，只是群里多了会说话的人。

否决了「群 = 一个团队、把你的智能体带进去」：智能体会在另一台电脑上干活（群的共用文件夹），记忆也分成两份——
与维护者说的「都是在云电脑干活」不是一个画面；而且要让 runtime 跨工作区借智能体，改动面更大。

## 1. 已验前提（2026-09-28，只读核过）

- 在籍今天**只有工作区一级**：SQL 的 `is_ws_member`、runtime 的 `membershipCache` 都按 workspace_id 查；
  主场的 `workspace_members` 只收群主本人（0037 的 `wsm_insert_owner`）。
- 主场的会话**一张审批卡都不出**（`approveAll`，ADR-0298），而 ADR-0298 自己写着「主场哪天收了别人要重判」。
- 朋友今天读不到别人主场的任何一行：`workspace_sessions` / `workspace_agents` / `workspace_mentions` 的 select 都要在籍。
- 钱：主场会话一律以群主身份调网关（on-behalf-of = owner）。
- `profiles` 人人可读；好友关系是 `friendships` 里 status='accepted' 的一对。

## 2. 决定

1. **名单是日志事实**：`chat_roster_changed` 多一格可选的 `humans: {uid,name}[]`（群主之外的真人）。缺席 = 没有别人
   （存量日志里本来就没有）。之后每一条名单事件都带齐两份名单（智能体 + 真人），最新一条胜出。
2. **投影一张表** `workspace_session_members(session_id, uid, added_by)`：写方只有 runtime（service key），
   先落日志再写表，和 `agent_ids` 那一列同一个规矩。它存在的理由是 RLS 与「我被拉进了哪几个群」这条查询。
3. **读的权限按会话给**（0043）：`is_session_guest(sid, uid)`；朋友能读自己在的那几条 `workspace_sessions`、
   那几条会话的真人名单、自己那几行 `workspace_mentions`；智能体只经一个 RPC `guest_chat_agents(session)` 读
   **这条群里那几只**的名字 / 职责 / 头像——不给提示词，不给群主别的智能体。
4. **runtime 的在籍 = 工作区成员 ∪ 这条会话日志里的真人名单**。进房、发言、批、停、打电话、补跑的复查都走它；
   建会话 / 改文件 / 改 wiki 这些「关于整个工作区」的动作仍然只认工作区成员。
5. **谁能改名单**：群主（或建群的人）什么都能改；群里的朋友**只能拉自己的朋友进来、只能把自己移出去**（demo 同款：
  「你能拉朋友进来；智能体归群主管」）。拉进来的人必须是**动手那个人**的好友（服务端现查 `friendships`）。
   真人上限 20。
6. **朋友发起的那一轮不免审批**：`approveAll` 只对群主自己发起的那一轮生效；朋友 @ 智能体让它跑命令、写文件、
   用应用、推代码、建智能体，都要**群主**批（朋友不能批自己的请求——动的是群主的东西）。只聊天不用批。
   这是比维护者的「要」更严的一步，理由写在 ADR：一句话能让群主的 Gmail 发信、Shopify 改价，中间没有人看一眼
   不是「让朋友碰得到」该有的样子。维护者说放开就放开（改一个判据）。
7. **钱**：照旧记群主（on-behalf-of = owner），界面上群信息里写一句「群里的智能体归群主管，干活走群主的额度」。
8. **协议 20 → 21**：`create` 帧的 `chat` 多 `humans`、`chat_update` 多 `humans`、welcome 的 `chat` 多 `humans`。

## 3. 客户端

- **手机**：发起群聊那张单子多一段「朋友」；聊天信息的成员格里有人；群主能移人，朋友能拉自己的朋友、能退出；
  列表里多出别人拉我进的群（它们在别人的主场里：`workspace_session_members` → 那几条会话 → RPC 取智能体）；
  群里「@ 谁」列出人；朋友那一侧的审批卡写「等群主批」。
- **桌面**：随 #1386 桌面那一半一起做（新布局里直接带上），这一条不改旧界面。

## 4. 不做的

- 朋友在别人的群里建智能体、改智能体（智能体归群主管）。
- 朋友拉进群的人不是群主的好友时，群主那边不另外确认（demo 同款；代价写在 ADR）。
- 删好友不自动踢出群（微信同款；群主可以手动移出）。

## 5. 上线

migration 0043 先 → runtime 后 → 客户端随发版（旧客户端连新 runtime：协议号不等，提示升级）。
