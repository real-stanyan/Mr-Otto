# Otto 应用 第 1 期（骨架）Implementation Plan

**Goal:** 主人对管理员说「我要一个记账本」→ 管理员派给「应用」专员 → 专员在沙箱里写出一个多页小网页、调 `build_app` → 文件进 Storage、聊天里一张应用卡 → 手机「应用」页出现它、点开在沙箱 WebView 里跑、桥给它 `storage / nav / share / ask`。

**Spec:** `docs/superpowers/specs/2026-10-05-otto-apps-design.md`（§0 六条拍板、§3 形状、§8 三条拍板）。

## 对 spec 的三处小修（实现以本计划为准，收尾写回 spec）

1. **不打 zip**：`build_app` 把目录里的文件**逐个**上传到 `otto-apps/<uid>/<appId>/<version>/<path>`，清单里带文件表（路径 / 大小 / sha256）。手机按文件表逐个下载到 `Paths.document/otto-apps/<appId>/<version>/`，WebView 以 `file://` 载入入口。理由：手机没有 zip 库、加 JS 库也能 OTA 但多一份依赖与一次解包；文件数封 40、单文件 512 KB、总量 3 MB，逐个传不慢。
2. **`build_app` 只给 `apps` 域的专员和管理员**（spec §3.3 两句互相矛盾，取这一句）：管理员 L0 全能是制度，专员按域。
3. **`ask` 第 1 期只做「聊天里那一半」**：桥的 `ask(text)` 把手机带到管理员的私聊并发出「[应用「X」]: text」——消息正文里带应用名，不加 greeting、不动协议版本。回答回到应用里显示（spec §8 第 1 条「两边都有」）要一条结果通道，第 2 期做。
4. **专员写文件的位置固定**：`/work/apps/<slug>/`（专员用 write_file 写，`build_app({ dir: "apps/<slug>" })` 读）。

## Global Constraints

- 硬规则：日志是唯一事实来源——应用卡是事件（`app_card`），`apps / app_versions` 表是投影 + 文件索引；工具只依赖注入的接口（`buildAppTool` 不知道 supabase、不知道 fs）。
- `SessionEvent` 只加 `ignorable: true` 的新事件；七张登记表（KNOWN / agentView / persistencePolicy / PRIVACY / PEN / contextEstimate / cloudTimeline / deriveMessages）同 task 事件那一轮。
- 协议版本 28 **不升**：手机侧第 1 期不加新帧。
- 手机不加原生依赖（ADR-0340）。
- 最新 migration 0062 → 本期 **0063**；ADR 另开（spec 已记决策，ADR 在 1a 合并时按 ADR-0074 核号）。
