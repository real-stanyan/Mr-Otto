# ADR-0238：接力刹车换成额度预算，且**钱只能往下压、不能往上抬**

- 状态：已接受
- 日期：2026-09-07
- 关联：#1017、PR #1018（撤输入框）；推翻 ADR-0223「两层刹车」的表述与 ADR-0231 关于 `relay_max_depth` 的第三条决定的**地位**（那道 24 的总量闸原样保留、升成唯一天花板）；纪律沿用 ADR-0237、ADR-0233、ADR-0176

## 起因

维护者看着工作区智能体 tab 顶上那行「接力上限 6 棒 / 保存」说了两句话：不用显示出来；**「定上限这个办法有点傻」**。

傻在**单位**。`workspaces.relay_max_depth` 量的是棒数，而棒数跟任何人真正在意的东西都不成比例：

- **钱**：一棒 200k 上下文的 turn 和一棒一句话的 turn 都算「1 棒」，成本差两个数量级；型号之间最贵与最便宜差 21 倍（seed 0017：qwen3.8-max 输出 6000000 vs deepseek-v4-flash 277778 micro/M）。
- **进展**：A 查 → B 改 → C 审 → B 修 → C 过，这是一条在干活的链，第 6 棒被砍纯属倒霉；而 6 棒纯乒乓早就该停了，周期护栏那时只会注话不停。

**对真活太紧、对空转太松**，于是 owner 没有任何依据去填它——填 6 还是 20 全靠猜。一个没人填得出正确值的输入框不该摆在设置页上（PR #1018 已撤）。

## 决策 1：主意换成钱，但**钱只能往下压，不能往上抬**

这一条是整次改动的要害，也是初稿被自己的对抗式复审推翻的地方。

初稿的提议是「预算取代棒数上限」。复审用仓库里的真数算了一遍，两个方向同时失守：

- **太紧**：lite 档 5h 窗口 665000 micro（seed 0017:11），取 limit 的 10% = 66500。ADR-0237 的 Auto 对判成 hard 的请求取 `models.at(-1)` = qwen3.8-max（输入 2000000 micro/M）。按本仓自己的缓存命中假设算，一个 3 圈工具调用 / 60k prompt 的普通 turn ≈ 62400 micro = 整份预算的 94%——**真活的第一棒就被拒**，而窗口还剩 90%。
- **太松**：同一个常数配最便宜那款（deepseek-v4-flash，一棒约 214–1200 micro），max 档能跑几百棒，而今天的硬上限是 24。而 Auto 恰恰把「简单」的请求路由到最便宜那款，**退化的乒乓接力正是分类器会判成 simple 的形状**——这道闸在它唯一存在理由的那个场景上比现状松一个数量级。

同一个百分比，「等价棒数」随（档位 × 型号）跨约 250 倍。**没有任何一个 `RELAY_BUDGET_FRACTION` 在两个方向上同时是对的**——所以这不是参数没调好，是机制选错了。

修正后的三道闸：

| # | 闸 | 何时生效 | 与档位/型号的关系 |
|---|---|---|---|
| ① | `RELAY_MAX_HOPS_PER_IGNITION = 24` | **无条件** | 完全无关 |
| ② | 已花 >= 所有者 5h 窗口**剩余**的一半 | 问得出剩余额度时 | 强相关，但只可能比 ① **更早**命中 |
| ③ | 周期护栏：`minRepeats` 注话不停 / `RELAY_SPIN_STOP_REPEATS` 硬停 | 无条件 | 无关 |

① 是三者里唯一与档位、型号、价目全都无关的量——owner 换个订阅档不该改变群聊里的行为，而正是这个数用来兜住那种漂移。② 永远不可能让链跑得比 ① 更长。

**被删掉的只有 `relay_max_depth` 这一个**——那个可配的、按分支计数的、owner 填不出正确值的旋钮，也正是维护者点名的那一个。

## 决策 2：预算的分母是**剩余**，不是 limit

`WindowState` 同时带 `usedMicro` 与 `limitMicro`，同一次探针返回的同一个对象里。取 limit 的话，窗口用掉 95% 时拿到的预算与全空时逐字节相同——刹车对「快没额度了」完全无感，而窗口触底之后 `hold()` 会退到用户真金白银买的**加购桶**（`services/edge/src/quota.ts`），于是这条没被刹住的链接着吃加购额度，一声不响。那正是 ADR-0237 点名不许的「安静地走更贵那条路」。

取剩余还顺带收敛了另一件事：人在 5 小时里说十句带 @ 的话就授权了十份预算。份额随窗口变小而变小，这个和是收敛的。

取「一半」而不是某个小百分比：正常干活永远碰不到它——要触发就得让**一件委托**吃掉剩下的一半，那时候停下来告诉人恰恰是对的。而「一半」在每个档位上是同一句话，「上限的 10%」不是。

## 决策 3：护栏长出硬停，阈值是算出来的

`detectToolLoop` 要 `n >= period × repeats`，所以周期 p 的链停在**第 3p 棒**：p=2（两只乒乓）→ 6 棒、p=3 → 9、p=6（3 只全互 @，`agentRelay.ts` 开头记的真实形态）→ 18，全部落在 24 之内，护栏因此真的比天花板早。

取 4 的话 p=6 恰好是 24（与天花板同时命中 = 白加），p≥7 更是永远轮不到。**一道永远不响的闸比没有更糟**：它会让人以为打转有人管。

加硬停的理由与 engine 的 `loopGuardMaxNudges`（ADR-0225）逐字相同：ADR-0212 的「只注话不停」成立**是因为人就坐在屏幕前**，云会话没有那个人。

## 决策 4：降级 = 改动前逐字相同

`hostedProbe` 把网络失败也缓存 60 秒，所以「问不出剩余额度」不是罕见态——一次 edge 抖动就是 60 秒的降级。降级路上补回 `DEFAULT_RELAY_MAX_DEPTH`（6）那道分支闸。

不补的话，读不到钱的那条路**反而比今天松**（停点从第 7 棒推到第 8～25 棒之间，最坏 4 倍），而那是唯一一条我们是瞎的路。把「拿不准」翻译成「更宽松」是这套东西最不该有的方向。

`relayRemainingMicro()` 因此**三种「没有数」一律回 `null` 不回 `0`**：探针不可达、没有活跃订阅、旧 edge 不发 `windows` 这一格——它们的共同点是「这一刻问不出来」，而 `0` 会被读成「预算为零，下一棒立刻停」。这个 dep 是**必需字段**（同 `isMember` / `contextWindowOf` / `rateLimit` 的纪律）：写成可选就是「忘接线那天接力安静地退回按棒数走」。

## 决策 5：`context_compacted` 补上 `creditCostMicro`

自动压缩发的是阈值处的**全量上下文**，是会话里与相邻那次采样并列最贵的一次调用。engine 明明从 `reply` 上拿到了 `creditCostMicro`，落盘时主动丢掉——于是它成了唯一「钱花了、日志里查不到」的模型调用。

补这一格不是为了对账好看：预算按日志求和，漏掉它就是**系统性少算**，且链越长压缩越多、少算越狠，而「链很长」正是这道闸存在的理由。可选字段，向后兼容，取值路径与 `assistant_message` 那一格同源。

## 决策 6：`spentMicro` 是**下界**，而这不影响安全

已知的两处少算：

- **Auto 的分类调用**（`autoModel.ts`）走裸 fetch，扣所有者的窗口但一条事件都不落。量级约 200 输入 / 8 输出 token，与一棒真 turn 差三四个数量级，认了。
- 任何一次 `creditCostMicro` 没落到事件上的调用（流式被中断时 edge 的尾注贴在 `flush` 那条路上，中断走不到）。**缺席按 0 计，不当作「读不到钱要降级」**——把一次抖动升级成「整条链切到另一套规则」比少算一笔更糟。

下界安全的理由只有一条，但足够：**少算只会让预算闸晚命中，而 ① 是无条件的**。任何少算都不可能让一条链跑得比改动前更长。这也是为什么初稿里那个 `spend.complete` 标志被删掉了——它声称的完整性它本来就不可能有（压缩与分类调用都不是 `assistant_message`），而有了无条件的 ①，它不再承重。

给人看的那句话因此写「**至少**已经花掉 X credit」。写成确数就是一句会被账单打脸的话。

## 决策 7：单位是 credit，不是美元

ADR-0176 决定五：托管模式的花费和 BYOK 的「$X」不能长得一样。一位小数——micro 级的精度对读的人没有意义。

## 明确的已知代价

1. **同一轮 @ 了 N 只时 `spend` 是进循环前的一张快照**，循环里不推进，所以这 N 只要么一起过要么一起被拒。不是漏做：钱的判据天生是**事后**的（这一棒还没跑，花多少不知道），推进它需要的数此刻并不存在。兜住这次扇出的是 `chain.push(hop)` 让无条件的 `cap_hops` 在同一轮里逐个收紧。
2. **`workspaces.relay_max_depth` 这一列留在库里**，没有读者也没有写者（写链 IPC / `updateRelayMaxDepth` / store action / RLS 允许的那次 update 全撤了）。删列要 migration 且不可逆，留着不花钱。
3. **`CostPanel` 仍然不计压缩那一笔**：`deriveUsage` 只对 `assistant_message` 取 credit，而 `context_compacted` 的 `route` 被硬编成 `direct`。数据现在终于在日志里了，改法是另一件事，不夹带在这次里。
4. `relayAfterTurn` 里两次 await 期间人再说一句，`bounds.lastHumanOpening` 会跳、链与花费双双清零——**改动前就是这样**（`relayChain` 本来就在 await 之后 load），不是这次引入的。

## 否决过的路

- **「让订阅额度自己当唯一刹车」**：窗口是所有者一个人的、整个工作区所有云会话加他自己的桌面共用；等它触底时钱已经花完了，而且 `hold()` 还会退到加购桶。刹车要在窗口触底**之前**响。
- **「弹一张审批卡问要不要继续」**：#959 已经量过——接力棒上的审批人常常早就不在场，一张挂起的卡把整个群冻住。硬停 + 人回来说一句（人话点火 = 新授权 = depth 与预算一起归零），比一张没人批的卡好。
- **按 token 而不是按钱计**：`usage` 的覆盖面确实更大，但 token 跨型号不可比（21 倍价差），而把 token 换算成钱需要 `model_route` 的价目表——那张表在 edge，不在 runtime。补 `context_compacted.creditCostMicro` 用一格可选字段换到了同样的覆盖面。
- **给预算配一个设置页旋钮**：这次改动的起点就是「一个没人填得出正确值的旋钮」。「剩余的一半」有一个说得出理由的默认值，棒数从来没有过。真需要调是以后拿实测说话。
