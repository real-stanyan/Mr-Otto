# ADR-0113：握手取对端最新的那一条 hello，而不是只认第一条

> 原为 ADR-0107：与 main 上先合入的「反引号是指令的转义写法」 ADR 撞号，按 ADR-0074 在合并前改号。

日期：2026-08-26
状态：已接受

## 背景

手机端详情屏停在「没等到时间线」，诊断日志里是一串：

```
手机桥:电脑到场,开一轮握手
手机桥:已建立会话,忽略这一轮之外的握手包
手机桥:电脑到场,开一轮握手
手机桥:已建立会话,忽略这一轮之外的握手包
手机桥:帧解密或计数器校验失败,丢弃
```

两端都自认为 ready，而每一帧都解不开，并且**没有出口** —— 重新握手只由中继的
`:peer` 触发，不再有 `:peer` 就不再有新的一轮。重启 app 才能恢复。

成因是两侧轮次错配：

- `services/gateway/src/relay.ts` 的 `attach` 在**任何一端接上时都给两边各写一条
  `:peer`**（含同角色重连）。
- 手机重连一次，桌面这侧就实打实收到一条 `:peer` 并 `startRound()`；
  手机自己那条 `:peer` 却写给了正在被拆掉的旧连接，收不到。
- 于是桌面开了两轮（D1、D2）、手机只开了一轮（M1）。老实现里两侧都「只认
  ready 之前的第一条 hello」：手机锁死在先到的 D1 上，桌面停在 (D2, M1)。
- 密钥 = HKDF(x25519(selfEph, peerEph), …)，两对不同 ⇒ 两把不同的钥匙 ⇒ 互相解不开。

ADR-0112 那一轮给手机传输加的「回前台立刻换连接」和「读满 4MB 回收连接」把重连
次数提高了一个数量级，这条一直存在的竞态从偶发变成了常见。

## 决策

**规则改成「永远用对端最新的那一条 hello」，两侧对称。**

1. 记住对端最近一条验过的 hello（`lastPeerHello`），它**活过自己的一轮**：
   `startRound()` 换掉自己的 eph 之后，当场拿它重新派生 —— 对端可能早就 ready，
   不会为我这一轮再送一次。
2. 收到对端新的 hello（任何 phase）都重新派生，装上新的 sealer/opener。
3. 桌面每次重新派生都清去重基线并补推 fleet 快照，并回调 `onRekey`
   让上层补推时间线；手机每次重新派生都报一次 `onReady(true)`，上层据此重发 `watch`。

收敛性：两端各自永远用 (我最新的 self, 对端最新的 hello)，而这两样都会经由有序的
中继流告诉对方，最终一定落到同一对上。

**原来那道 phase 门挡的东西必须原样挡住**，所以门只是换了位置，没有被拆掉：

> 同一对 `(self.eph, peerEph)` 只许派生一次。

实现是每套 self 一份 `usedPeerEphs`，`startRound()` 换 self 时才清空。理由：
密钥完全由这一对决定，「这一对没用过」⇒「这把密钥没用过」⇒ `createSealer`
从 `counter=0n` 起算是安全的。

被挡住的仍然是那个灾难：握手包是明文过中继的，网关运营者手里始终有逐字节的副本；
重放一条会让 `deriveSession` 用没换过的 `self.eph/nonceHalf` 算出**同一把密钥和
同一条 nonce 前缀**，而 sealer 又从 0 起算 —— 同 key 同 nonce 加密两段不同明文，
`c1^c2 = p1^p2` 直接还原桌面→手机的明文（会话标题、pendingApproval 的动词/目标/
全路径、workspace 路径），Poly1305 的一次性密钥也取自同一个 keystream 块，
连该计数器上的帧伪造一并送出去。

`onReset`（上层丢掉「手机在看哪个会话」）从此**只在连接真的断开时发**，不再跟着
重新握手发：手机重连不等于换了观众，那份订阅正是重新派生之后要补推的东西。

## 代价与残余风险

- **DoS**：中继可以塞旧 hello 逼两端反复重新派生。它本来就能直接丢包，拿不到比这
  更多的东西；`MAX_DERIVES = 64` 给每条连接封了顶。
- **收敛过程中的丢帧**：两端派生的先后不同步时，中间那几帧解不开。补推（fleet +
  时间线 + 手机重发 watch）覆盖掉这一段，代价是重连时多传一份快照。
- 严格递增计数器守的是**当前这把密钥**下的重放，换密钥之后旧帧根本解不开，
  那扇窗没有被重新打开。

## 测试

- `tests/shared/remote/mobileBridge.test.ts`：两条新用例直接复刻这个场景
  （`relay.announce("desktop")` = 只有一侧听见在场信号），两个方向各一条。
  在老实现上两条都红。
- `tests/main/remoteBridge.test.ts`：「ready 之后来一条**新**的合法 hello →
  重新派生并补推快照」替换掉原来「一律忽略」那条 —— 那条钉的正是这个 bug 的行为。
  重放侧的三条（同一条 hello 再来一次 / 逐字节重放 / 计数器不回零）全部保留。
