# ADR-0304：记忆分档的那句劝告，要指得出是哪一条

- 日期：2026-09-21
- 状态：已接受
- 关联：#1290（承接 #1281 / PR #1288 的终审）、ADR-0299 第 8 条 seam、ADR-0269

## 背景

`src/tools/memory.ts` 的分档核对是**卫生劝告不是安全闸**（ADR-0299）：决策模型判这条内容更像另一档时，
工具抛一条指路的错，模型原样再交一次就放行。

单条时那句话是可执行的 —— 只有一条内容，说「这条更像 project 档」指得明白。

批量时不是。一次 `operations` 带三条、只有第二条对不上时，抛出的话只报 `hits[0]`，**不带下标也不带内容**：
「这条内容更像 project 档的事」—— 三个候选，哪一条？模型最便宜的回应是原样再交一次，于是它过了，
**但它什么都没学到，而这个劝告存在的全部理由就是让它学到**。

## 决策

文案抽成 `tierMismatchMessage`（`src/shared/memoryTierJudge.ts`，纯函数，有单测）。三条判据：

### 1. 下标报 operations 里的那个，不报 pending 里的

`TierMismatch.index` 指的是 `pending` 里的下标，而 `pending` 滤掉了 `remove` 与已经被劝过一次的那几条
（`insisted`）—— 两者在有滤掉项时不相等。所以原始下标一路带着走（`PendingEntry { at, content }`）。

**一个指错行的下标比不给下标更坏**：模型会照着它去改一条根本没被判过的内容，而外部表现与「它改对了」一样。

单条调用不报下标（只有一条，下标是噪音；何况那时 `operations` 可能压根没出现在调用里 —— 单对象形态也合法）。

### 2. 命中几条列几条，各带一段折成一行的内容前缀

记忆条目是多行 markdown，原样贴进去会把这句话撑散，所以 `preview` 先折空白再截到 48 字。
有了内容前缀，即使下标那一半将来被谁改坏了，模型仍然认得出是哪一条 —— 两个指认手段互为兜底。

### 3. 只有整次调用每一条都命中、且都指向同一档时，才说「改 target」

`target` 是整次调用一个值。批量里只有一部分命中时说「改写 target」，等于让模型把**没命中的那几条一起搬走**。
其余情形改说「把这几条挑出来、用那一档的 target 单独发一次，其余的留在原档」。

拆开重发那条路是通的：搬走的那几条键变了（键是 `${tier}\n${content}`）会被重新核一次，而这次目标档与决策模型
的答案一致，不会再被劝；留下的那几条已经在 `insisted` 里，直接放行。

## 不许动的那条不变量

**一个错判永远不能把一条真事实永久挡在外面。** 今天它靠三样成立，本次改动一样都没碰：

1. 键是 `${tier}\n${content}`，所以原样再交时 `pending` 为空、整段跳过
2. `insisted` 到 64 条是整份 `clear()` —— 最多让还在手上的那几条多被劝一轮
3. `MAX_CONSECUTIVE_FAILURES` 到了工具进终态，会自清零

逃生门仍然是**整批**的：命中一条就把整批 pending 都记上 `insisted`。半开的逃生门（只放行命中的那几条）
会让「原样再交一次」这条最简单的出路失效，而那是不变量的落点。

## 顺带记下的两笔小账（都不改，方向是对的）

- **键不含 `old_text`**：一次 `replace` 如果新内容与之前被劝过的某条逐字相同，会继承那个「已经劝过」的记号。
  失败方向是**漏劝** —— 对一个卫生劝告来说方向是对的（错劝才会挡住真事实）。
- **64 条上限是整份 `clear()` 不是按序淘汰**：代价是清空那一刻还在手上的条目最多多被劝一轮，
  换来的是这段簿记没有任何顺序结构要维护。

## 代价

- 批量时那句话从一行变成多行（一条一行）。工具错误是给模型读的，清楚比短重要。
- 48 字的前缀是拍的，没有断言钉住 —— 保鲜期在紧挨常量的那行注释里。
- 影子期还没开始（ADR-0299：五处全关），所以**这条改动在真机上一次都没触发过**；它要等 `memory` 这一处
  从 `shadow` 翻到 `on` 才会有人真的读到。
