# ADR-0353：共享车道——一人对一位朋友只有一条车道、朝向可切；朋友以客人身份进同一条；朋友那一侧用第二条连接读

日期：2026-10-04 · issue #1523（#1461 的 P2）· 维护者原话：「人对人的聊天窗口里，目前链接智能体只能仅我可见，可以选择是否公开或者是仅我可见。」
**修订 ADR-0346 决定 1**（「最多两条：只面向自己 / 面向两人」）。协议 24 → 25。

## 背景

#1461 设计稿 v1（维护者拍板方案 B、9 条决策按推荐）把「朋友私聊里带自己的智能体」分成 P1 私密车道（ADR-0346，#1476 已合）
与 P2 共享车道。P1 的车道只有主人看得到、只听主人的。维护者要的 P2 是一个**开关**：带进来的智能体可以公开给朋友，也可以收回只给自己看。

开工前只读核过的前提：手机同一时刻只连得上一条云会话（chatStore / cloudSessionClient 都是单 ActiveSession，spec §5.3），
私聊页已经用它连着自己的车道。ADR-0325 的客人机制（0043：`chat_roster_changed.humans` 事实 + `workspace_session_members` 投影 +
`wss_select_guest` / `guest_chat_agents`）现成，群里的客人进房、发言、被审批都走它。

## 决定

1. **一人对一位朋友只有一条车道，朝向（`facing`）可切。** 否决掉 ADR-0346 的「私密 + 共享各一条」：两人各带、各两条 = 一页私聊
   要同时连 3～4 条会话，手机做不了；维护者的措辞也是一个开关。0056 把唯一索引从（主场，朋友，朝向）收成（主场，朋友）；
   runtime 的 `findPairSession` 不再按朝向找。
2. **公开 = 朋友以客人身份进同一条车道。** 事实在日志里：`chat_roster_changed.humans` 有那位朋友 = 公开（`pairFacingOf`），
   没有 = 仅我可见。`facing` 那一列是投影，runtime 切时跟着写。不另加事件字段、不加策略、不加 RPC：朋友读那一行走 `wss_select_guest`，
   读名字走 `guest_chat_agents`。车道里的客人名单只可能是 [朋友] 或 []（`updateChatRoster` 的闸）。
3. **协议 25**：`create` 的 pair `facing` 收 self / both；`chat_update` 多 `facing`，只有主人能发（frameHandler：facing 不算进客人能动的
   「只动客人名单」）。daemon 把 facing 折成 humans [朋友] / []，走现成的 `updateChatRoster` + `syncGuestRows`；公开之前复查一次仍是好友。
4. **车道里的 `say` 放客人进来**（原来「只听主人的」）；朋友点起的轮走现成的 `guestTurn`——每一刀问主人、不看 `sandbox_approval`
   （ADR-0325 第 7 条、#1461 决策 5）。
5. **提示词按朝向在两版之间换**（`pairLaneSegments`）：公开时「对面是谁」说朋友看得到你、能 @ 你、你仍是主人的智能体；「审批」
   换成主场群里有客人那一版（朋友点起的轮等群主批）；信封头「朋友看不到你」那半句一起换。朝向从日志里最后一条名单事件推导，
   `modelContextScan` 把 `chat_roster_changed` 捞进有界集——有界与全量投影逐字节一致的契约不破。
6. **手机·主人侧**：第一次带上先挑智能体、再选给谁看（建车道那一帧带 facing）；横幅右侧一颗朝向标签、聊天信息页一行，都能切。
   车道气泡底下那行按朝向写（仅你可见 / 你和 TA 都看得到）；朋友在公开车道里说的话也画出来（`LaneItem.who = "friend"`）。
7. **手机·朋友侧用第二条连接**（`peerLane.ts`）：再建一份 `cloudSessionClient`（自己的传输与 sinks），只做进房 / 收事件 / 说一句 /
   离开；不碰 chatStore 的单连接模型，不接审批 / 语音 / 岛 / 缓存。朋友那条的行画成另一种底色的虚线气泡、底下写「TA 的智能体 · 两人都看得到」；
   @ 名单合并两边的智能体（`guest_chat_agents` 那份只有名字 / 职责 / 头像）。`listGuestChats` 把 `chat_kind = 'pair'` 摘掉——
   公开给我的车道让我成了那条会话的客人，但它画在私聊页里，不是一条群。

## 否决的

- **两条车道并存**（ADR-0346 原案）：见决定 1。
- **把 chatStore 改成多连接**：改动面横跨 cloudSessionClient（桌面共用）、审批路由、语音、岛；一条只读 + 偶尔说一句的车道不值这个代价。
- **朋友那条画成聊天列表里的一条「群」**（ADR-0325 对客人群的做法）：维护者的画面是「人对人的聊天窗口里」看到对方的智能体，不是另一个入口。
- **在 `pair_context_loaded` 上加 facing 字段**：朝向已经在名单事件里，多一份就是两份要对齐的事实。

## 代价与已知未做

- **朋友点起的轮的审批卡没画在私聊页里**（P1 的私聊页本来没有审批卡）：朋友 @ 主人的公开智能体让它动手，那一轮会等主人批、10 分钟
  没人批按拒绝收口；纯聊天（不用工具）不受影响。另开 issue。
- **不推回复、不发 @ 提醒**照旧（ADR-0346 决定 5）：朋友不在私聊页时智能体答完了不会推给他。
- **朋友那一侧没有本机缓存**：离开私聊页就忘，下次进来重拉。
- **协议 25 硬切**：runtime、手机要一起出；部署顺序 0056 → runtime → 手机。0056 没跑时旧索引仍在，同一行切朝向不撞自己，
  但老 runtime（按朝向找）会建出第二条——所以 runtime 要在 0056 之后部署。
- **`pair_presence` 仍只数私密车道**：公开的那条朋友自己看得到。
- 真机一次没跑过（Windows 上没有模拟器）。
