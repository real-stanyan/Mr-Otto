# ADR-0247：回车=排队；「顶替」= 提到队首 + 中止当前 turn，取代插话（steer）

> 原为 ADR-0245、ADR-0246（两次撞号，ADR-0074：编号在合并时认领——0245/0246 分别被云会话删除、云会话头部模型两条先占了）。

- 状态：已采纳
- 日期：2026-09-07
- 关联：#1048；推翻 #344 的 steer（插话）；投影层顺序修复的引入见 deriveMessages 头注（issue #344），它**不随本 ADR 拆除**

## 背景

#344 给「turn 跑着时敲回车」定的语义是**插话（steer）**：不中断当前 turn，把这句话
当场 append 成一条 `user_message`，loop 每圈从日志重新投影，模型下一次采样自然看到
并转向。后来 ⌥回车 排队作为第二语义加上来，于是输入框在 running 时有两种回车，
要用户记哪个是哪个。

steer 这条链路真跑起来有三个老毛病：

1. **「这句话说没说到」要靠乐观锁才能回答**。提交瞬间 turn 可能刚好结束/换代，
   于是有了 turnId 一整套 plumbing：engine 的 `runningTurnId`、turnStatus 推送
   分两拍（第二拍带 turnId）、`SessionRuntime.turnId`、store 的 `turnIdBySession`、
   渲染层重载后的 turnId patch——五个组件各持一份，只为了回答「我这话注进了哪一
   轮」这一个问题。
2. **注入的话可能晚于 engine 的最后一次采样**。话落了盘、模型却没看到就收口的
   窗口真实存在（unseenUserTail 那圈补采样就是为兜它加的）。
3. **语义解释成本高**。placeholder 要写「回车插话（注入当前任务），⌥回车排队」，
   一句话里两个动词三个概念。

排队的语义一句就说得清：回车 = 排进队尾，这条跑完自动发出。

## 决策

### 一、回车一律排队，插话链路整条拆除

`dispatch` 的 `status === "running"` 分支不再分岔：一律 `enqueue`。`submit` 去掉
`opts.queue`，textarea 的 `onSubmit({ queue: e.altKey })` 回到无参。placeholder 换成
「回车排队，这条跑完自动发出」。

拆除不留死代码：`engine.steer` / `CHANNELS.steerTurn` / preload / ipcMain handler /
store.steer 全删；turnId 乐观锁 plumbing（上面那五处）的唯一消费者就是 steer，一并
拆掉，turnStatus 推送回到一拍。

**两处刻意保留**：

- `engine.currentTurnId` 内部字段与 `runningTurnId` getter——后者是 turnDiff 聚合的
  本轮键（agent.ts 的 `createTurnDiffMiddleware` 现读），前者还是 `appendBackground`
  判「此刻有没有 turn 可接后台结果」的落点。它们与乐观锁无关，只是恰好同名。
- **投影层的顺序修复**（deriveMessages 的延后队列）：组开着时落的 user_message 推迟到
  组的结果之后再进上下文。它是 #344 为 steer 引入的，但 steer 拆了之后它服务的对象
  还在——后台回注（appendBackground，#871）、云会话群聊的 chat_message 都是中途落盘
  的 user_message，配对约束的破坏与是谁落盘的无关。`tests/session/deriveMessages.steer.test.ts`
  因此保留（文件名不动），只更新措辞。

### 二、「顶替」= promote + abort，纯渲染层编排，不新增主进程接口

「立即改跑这条」不再是独一份的 steer 通道，而是对两条**现成**机制的编排
（store.runQueuedNow）：

1. `promoteTask` 把这条提到队首（只改先后顺序，认不出的 id / 已在队首都原样返回）；
2. `stopTurn` 让当前 turn 以 aborted 收口；
3. 收口那一刻 onTurnStatus 的 idle 分支本来就 `drainQueue`——队首正是这条，第一个发。

两步之间不需要新原语：abort 与 drain 都是既有机制，渲染层把它们的顺序拼起来就是全部
语义。竞态是良性的：turn 恰好自己收口时 `stopTurn` 是 no-op（幂等是 stopTurn 本来就
有的性质），这条仍在队首，下一轮 drain 第一个发——两种时序落到同一个结果。

UI 上每条排队项在 × 左边加一颗「顶替」（对照上游 QueueItemPrimitive.Steer 的
"Run now" 位置）。

## 理由

- **一个词能说完的语义胜过两个**。排队不需要回答「注进了哪一轮」——它压根不注进
  任何一轮，turnId plumbing 那五个组件存在的前提就此消失。
- **编排现有机制比新增通道便宜**。顶替没有碰主进程、没有碰协议、没有碰日志 schema；
  它的正确性完全押在 stopTurn 幂等 + drainQueue 挂在 idle 这两条已被钉住的性质上。
- **拒绝 steer 的那些状态（压缩进行中）也跟着消失**——排队没有「此刻不能排」这一说。

## 代价

- **abort 不是即时的**。点「顶替」到这条真的开跑之间，隔着当前 turn 的收口（正在执行
  的 bash 要收 SIGTERM、挂起的审批要 resolve 成 denied）。steer 是「不等收口就生效」，
  顶替是「中止后第一个发」——想要「说一句话但别停下手里的活」的那个动作没有了，
  它正是 steer 被拆掉的那半。
- 排队的活只排文字（队列项挂不住附件）——这一限制与改动前相同，不是新代价。

## 推翻关系

推翻 #344 的 steer 决定本身（插话作为回车语义），不推翻它留下的投影层顺序修复——
那一层的服务对象换成了后台回注，行为一个字不变。
