# ADR-0364：智能体分级调度制——L0 管理员 / L1 专员 / L2 子工；派活只能往下、报结果只能往上；工具按域圈；任务 event-sourced；旧智能体清除重来

日期：2026-10-05 · issue #1571 · spec `docs/superpowers/specs/2026-10-05-agent-tiers-design.md` · 维护者原话：「OTTO 中的 AGENT 需要有等级之分……
我希望 OTTO 中 AGENT 制度是严格的，完成任务是高效的，而不是每个 AGENT 都可以跨界完成各种任务。」六条拍板见 spec §0；
追加一条（同日）：「智能体除了管理员，其他的都是可以删除的。」

## 背景

今天的智能体是扁平的：`workspace_agents` 没有等级、域、上下级；任何一只都能被 @、都能用自己白名单里的工具；`decideRelay`
只看棒数 / 预算 / 空转，不看谁派给谁。唯一的特殊角色 `admin` 只是删不掉，没有特权。ADR-0363 把「管理员是唯一入口」做进了
好友车道，但主人自己的主场仍是扁平的。

## 决定

1. **三级**（`workspace_agents.tier`，0060）：L0 管理员（每主场有且只有一只，`admin ⇔ tier 0` 用 check 钉死、部分唯一索引钉一只；
   缺了自愈）、L1 领域专员（必填域）、L2 子工（`parent_agent_id` 指同主场的一只 L1）。
2. **派活只能往下一级、报结果只能往上一级**（`agentTier.canDispatch`）：L0→L1、L1→自己的 L2、L1→L0、L2→自己的 L1 四种放行，
   其余（横向、越级、别人的子工）一律拒。**闸在 runtime**（落 `agent_relay` 之前），不靠提示词；主人点名不经过它。
3. **工具按等级 + 域圈**（`agentTier.scopedTools` / `agentDomain.domainFace`）：L0 全部；L1 = 域的面；L2 = 自己 ∩ 上级。
   不在面里的工具**模型看不见**。域是固定清单 + `custom:<名字>`；自定义域默认只读、不碰连接器。
4. **管理员可以自己动手**——它判断「一句话能答完、不用动手、不用查」时；其余拆任务派专员。没有对应域的专员时**提议建一只**
   （`task_needs_owner` 一张卡），不自动建、不退回。
5. **任务是事件**（`task_created / assigned / progress / done / failed / needs_owner`，落在管理员那条私聊的日志里），`tasks`
   表（0061）是 runtime 折出来的投影，客户端只读。状态行从它来。
6. **L2 不进列表**（`visibleAgents`）：通讯录 / 聊天页「智能体」格 / AgentChats 只画 L0 与 L1；L2 在它上级的资料页里。
7. **除管理员外都能删**（沿 0021 的策略）；删 L1 连带删它的 L2（fk cascade），删之前说清「连同 N 只子工」。
8. **旧智能体清除重来**（0060 里 `delete … where agent_id <> 'admin'`，不可逆）——维护者选的；生产跑前在 #1571 再确认一次。
9. **部署顺序**：0060 + 0061 → runtime → 手机热更新。分级本身没有能先 OTA 的部分（手机要写不存在的列会 42703）。

## 否决的备选

- 等级只写在提示词里：「觉得不该跨界」≠「不能跨界」，维护者要的是严格——同 ADR-0363 否决「只在手机上收口」。
- 任务独立建表不走事件：违反 Hard rule；而且来龙去脉本来就在管理员那条日志里，重放即审计。
- 自由文本域靠模型匹配：匹配错了就是跨界。
- 旧智能体迁成「未分配」：维护者选了清除。

## 代价

- 简单事也可能多一棒（管理员判错「简单」）；靠提示词那句判据，不是硬规则。
- `parent_agent_id` 指向的那只是不是 L1，库里只有 fk 没有跨行 check，由 `tierRowError` + runtime 复核——绕过客户端直打 REST 能插出一只上级是 L2 的子工，runtime 对它按「认不出上级」处置（只按自己域的面）。
- 一主场一只管理员：分部门要多只那天，`admin` 字面量（0021 触发器、RLS、常量）与唯一索引都要重想。

## 落地

第 1 步（本 PR）：shared 判据 + 提示词 + 0060 / 0061 + 快照三列容错读写。第 2 步 runtime 四道闸 + 三个任务工具 + 投影；
第 3 步 SessionEvent 五种 task 事件 + 时间线任务卡；第 4 步手机 UI。
