# ADR-0328：群聊派活翻到决策模型（on）——说给群里某个人的话，智能体不接

- 日期：2026-09-28
- 状态：已采纳
- 关联：#1405。维护者 2026-09-28 原话：「把 jev 应用到群聊决策分配任务，但是要考虑到群聊里也存在人类会互相聊天」
- 关系：派活（ADR-0270）的决策模型那一格从 `shadow` 翻到 `on`（ADR-0299 的上线第 5 步）；ADR-0301 的前提（「两条路的延迟回到同一个数量级」）解开了；ADR-0275「通话里必须有人应」多一个例外；ADR-0325 的客人第一次进了派活的判据
- 维护者拍板两条：通话里只有「另一个人这场通话里也用语音开过口、且 Jev 很确定这句是说给他的」才不接；合并后直接部署

## 背景

开工时量到的三件事：

1. **影子数据等不来。** 线上 runtime 自 2026-09-21 部署 shadow 起，`sudo -n journalctl -u otto-runtime` 4478 行里零条 `[decision]`、零条派活日志——没人在群里不 @ 地说过话。ADR-0299 设想的「影子跑几天、看一致率」在今天的流量下永远等不到第一行。
2. **延迟回到同一个数量级了。** 从 runtime 那台 VPS 打 `/llm/v1/decision`（这天从 Cloudflare 的 AMS 进，`hold` 一趟 ~330ms，#1398 之后），九发 0.73–1.79s，闲 70 秒后的第一发 1.23–1.77s。9 月 21 日同一条路是 3.5–13.9s（ADR-0301）。
3. **派活看不见群里还有谁。** 一句没 @ 谁的话可能是说给群里另一个人的，而两条路（Jev 与便宜 LLM）都不知道：
   - 给它们的最近几句只是一串「[名字]: 正文」，分不出哪句是人说的；
   - 「要做事、谁的职责都对不上 → 归管理员」那一格恰好是一句布置给人的活的样子（「小王，把合同发给客户」），两条路是同一条规则；
   - 聊天里只剩一只智能体时不问分类器（#1280），有客人的群（#1393）里人和人说的每一句它都接。

   一句「小王，你下午几点能到公司？」今天 Jev 给 `act=0.33`、三只都低于 0.2——拿不准，交给 LLM。

对拍的时候还撞见第四件：**LLM 那条路一半时间交白卷。** 最便宜那款（`glm-5.3-flash`）回一个编号之前先推理 36–77 个 token，而 `DISPATCH_MAX_TOKENS` 是 64——四发里三发 `finish_reason=length`、正文是空串。ADR-0270 当年写过「这个数要靠真机校」，这是第一次校。今天线上每一句没 @ 谁的话都有一半机会在群里落一句「这句话没派出去（分类器没给出可识别的答案）」，包括人和人之间的闲聊。只放宽上限还不够：**拿不准的那几句**（正是决策模型会交给它的）它会推理 300–500 多个 token、一发 14–16 秒，撞上这条路 5 秒的超时。这款「始终思考，不支持关闭思考」（`thinking: {type:"disabled"}` 被上游拒掉），但收 `reasoning_effort: "low"`：推理降到 0–24 个 token，一发 1–3 秒。

## 决定

1. **`DispatchInput` 多一格必填的 `people`**：群里除了说这句话的人，还有几个真人（`count`）、叫得出名字的是谁（`names`）。必填是为了漏接线的那天编译不过，而不是安静地当成「群里只有他」。三种名单：
   - **通话里**：只算这场通话里也用语音开过口的人（维护者拍板）。人类「谁在听」不落盘（ADR-0271 的已知代价），「用语音说过话」（`voice: true`，ADR-0288）是日志里唯一证明他在通话里的东西；
   - **不在通话里**：成员（`hostUids`，与在籍判断同一份 60 秒缓存）+ 这条群的客人——与点名提醒认「这条会话里有谁」的口径相同。主场的成员只有群主，所以**主场没客人时直接短路为空**（私聊每一句都走到这里，不为一份注定只有自己的名单打网络）；成员名单读不出来时退回「这条会话里说过话的别人」，不当成只有自己；
   - 名字取这条会话里真说过话的（`speakerLabels`）与名单上客人的名字；没说过话的成员只计数。
2. **最近几句结构化**（`DispatchLine`：`by` / `kind` / `text`），LLM 那条路照旧渲染成 `[名字]: 正文`（逐字相同）。拆前缀的正则抽成 `speakerPrefix.ts`：那条正则的注释写着「只此一份」，名字表与派活现在都要认它。拉进通话的招呼（`greeting`）不算群里的话（同 `humanSpeakerOf` 与 `hiddenFromCloudTimeline` 的口径）。
3. **Jev 多问一题 `people`**（群里有别人才问；没有别人时题目与 `state` 都不多一个字）。判决表新增：

   | 条件 | 判决 |
   |---|---|
   | `P(people) ≥ 0.7`，没有哪只 `P ≥ 0.6` | `none`，记下 `to: "people"` |
   | `P(people) ≥ 0.7`，却有一只 `P ≥ 0.6`（「小王你跟开发一起看下」） | 交给 LLM |
   | 归 fallback 那一格（要做事、没人对得上） | 另要 `P(people) < 0.3`，否则交给 LLM |
   | 其余 | 与改动前相同 |

   `people` **单独问、不并进 `act`**：「小王，把合同发给客户」是在要求做事（`act` 高），只是不是要智能体做。并进去的话这类话会成普通的 `none`，而通话里普通的 `none` 要由最近开口的那只应——那正是维护者要它闭嘴的那一种。阈值取高（0.7）是因为判错的代价不对称：该接没接，人 @ 一下就好；不该接却接了，是插进别人的对话、花群主的额度，通话里还会打断人说话。
4. **LLM 那条路的提示词加同一条规则和「群里的其他人」一行**：交给它的正是 Jev 拿不准的那些。它的 `max_tokens` 64 → 512（上限只决定网关那一笔预扣，结算按实际用量），并且**按平台白名单**带 `reasoning_effort: "low"`（`LOW_REASONING_PLATFORMS`，此刻只有 `zhipu`）。白名单而不是一律带：别家没真机验过，而有的厂商对陌生字段回 400——那样派活会每一句都失败（同 ADR-0274 `REASONING_PASSBACK` 的规矩：逐家验过才准进）。平台取 `/me` 的 `modelPlatforms`，缺席就不带；daemon 那一格接线有读源码的断言（漏传的样子是安静地又慢回 14 秒）。
5. **两条「只剩一只」的捷径，有别人时都改成照问分类器**：聊天里（#1280）与通话里（ADR-0275 决策 2）。私聊、没客人的群、只有自己在打的电话一字不变。
6. **通话里「必须有人应」只让一种 `none` 闭嘴**：`to: "people"` 且真有别人开过口。只有决策模型会给 `to`（LLM 那条路只回 `none`），所以 LLM 的 `none` 仍按 ADR-0275 由最近开口的那只应——让一场电话沉默的判据只有「Jev 很确定」这一个。`people.count > 0` 在 sessionService 里再判一次不是多余的：任何别的来路的 `to` 都不许让一场只有他一个人的通话沉默。
7. **翻成 on**（`DECISION_USES = { dispatch: "on" }`），派活的决策超时 20s（影子期的测量窗口）→ 2s（「谁在等」预算表里派活那一格）。`tests/edge/decisionUses.test.ts` 里「一格都不许是 on」照 ADR-0301 自己写的拆法处理，但**没有整条删**：收窄成「除了 dispatch」，另外四处的超时还没按各自那条路的真实分布定（#1300）。「超时要落回预算」那条从这一刻起真的在拦东西。
8. **`withDecision` 在 on 档下落到 legacy 时记下 `legacy` 与 `legacyMs`**：翻成 on 之后 shadow 那行对照就没了，这是唯一还看得到「拿不准时 LLM 判成了什么、人多等了多久」的地方。
9. **部署顺序 runtime 先、edge 后。** 反过来的话，旧 runtime 会带着影子期那 20 秒的超时进 on 档：每一句不 @ 的话先干等 20 秒。

## 离线对拍（代替等不来的影子数据）

36 句带标注的群聊场景：人对人 12、给智能体的活 7、在回答某只智能体刚提的问题 3、对智能体的闲聊 2、拿不准的 3（两种结局都算对）、群里只有他自己 4、主场群带客人 5（含一个只剩一只智能体的群）。请求体用生产那份 `dispatchQuestions` / `dispatchPrompt` / `DISPATCH_SYSTEM` 拼，回包用生产那份 `parseDecisionReply` / `verdictFromScores` / `parseDispatchReply` 判，打线上 edge（dev 账号）。

| | 对 | 交白卷 | LLM 一发（Mac 上量） |
|---|---|---|---|
| 改动前：只走 LLM，`max_tokens` 64 | 19 / 36 | 17 | — |
| 只走 LLM，放宽到 512 | 34 / 36 | 2（拿不准的两句，推理到 512 仍没想完、一发 14–16 秒） | — |
| 只走 LLM，512 + `reasoning_effort: "low"` | 36 / 36 | 0 | 中位 1.15s，最慢 2.81s |
| **这次：on**（Jev 先判，拿不准交给上一行那条路） | **36 / 36** | 0 | 只有交过去的那 4 句要付 |

Jev 三轮里每一轮都自己判了 32 句、32 句全对，拿不准交出去的始终是同样 4 句（「小王你看下群里那个 bug 报告」「我来吧」「小王你跟开发一起看下这个 bug」「大家周五下午开个会，讨论下 Q4 计划」——前两句是人对人、后两句本来就两可）。人对人那 12 句里 10 句 Jev 直接判「说给人的」，主场群的 5 句（含只剩一只智能体的那个群）全对。改动前 LLM 那 17 句错全是交白卷，没有一句是判错。从这台 Mac（SYD）打 Jev 中位 284ms、最慢 553ms；从 runtime 那台 VPS 打是 0.73–1.79s（背景第 2 条）。

LLM 那条路修好之后自己也对了 36 句——Jev 仍然值得开：它从 VPS 上更快（LLM 那一发还要另付 hold 那一趟）、给的是**校准过的概率**（`[decision]` 日志里有 `scores`，往后调阈值有得看），而且只有它说得出「这句是说给人的」（`to: "people"`），通话里那条例外靠的就是这一格。

## 否掉的

- **把「是不是说给人的」并进 `act`**：见决定 3。
- **按名字做规则**（正文里出现某个成员的名字就不接）：「帮我给小红的咖啡店写一段开业文案」里有小红，却是给智能体的活——字符串判据分不出来，这正是要一个模型来判的地方。
- **通话里照旧一律有人应**：维护者没选。
- **继续 shadow 攒真数据**：没有流量，等不来；而 LLM 那条路此刻一半时间交白卷，多等一天就是多一天的「没派出去」。
- **通话里的「别人」用全体成员**：人类「谁在听」不落盘，一个没进通话的成员被算进来，就会让一句对着智能体说的「你能听到吗」被判成说给他的——#1183 那个坑换个入口回来。

## 代价与已知未做

1. 派活的回执要等 Jev（≤ 2s）；拿不准再等 LLM（≤ 5s）。最坏 7 秒，改动前是 5 秒——只落在拿不准的那一成里；而 LLM 那一发带上 `reasoning_effort: "low"` 之后一般 1–3 秒。
2. 超时中断的那一发照样全价计费（#1303），这条路上 2 秒对应的尾巴大约是一成（九发里最慢 1.79s）。
3. 阈值是 36 句**自己写的**场景调的，不是真实流量。往后看线上 `[decision]` 日志（on 档下每一行都带 `scores`，交给 LLM 的那几行带 `legacy` / `legacyMs`）。
4. 团队里没在这条会话说过话的成员只计数、不报名字：叫一个没说过话的人时，模型只能从「这个名字不在智能体名单里」推。
5. 通话里只认用语音开过口的人；只打字的人不算在通话里。
6. 会话自动起名读的上下文少了拉进通话的招呼那几行（那几行本来就不是对话）。
7. Auto 判难度（`max_tokens: 8`）与云会话起名（`TITLE_MAX_TOKENS = 64`）用的是同一款便宜模型，多半也在交白卷——不在这次射程里，单独提了任务（`LOW_REASONING_PLATFORMS` 可以直接复用）。
8. `reasoning_effort` 只对白名单里的平台生效：哪天最便宜那款换成别家，拿不准的那几句又会回到 14 秒——那时候要先真机验那一家、再把它加进名单。
9. **要部署 runtime（#791）再部署 edge 才生效**；桌面一字未改。

## 推翻前提

- 线上 `[decision]` 日志里 `none:people` 误伤了该接的话（人 @ 了一遍才有人接）：先把 `DISPATCH_PEOPLE_AT` 往上调，别急着拆这一题。
- VPS 那条路的决策延迟回到秒级以上（换了 colo、上游变慢）：`dispatch` 翻回 `shadow` 是一行，LLM 那条路已经修好，退回去不会更差。
