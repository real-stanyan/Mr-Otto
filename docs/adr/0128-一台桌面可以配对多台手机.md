# ADR-0128：一台桌面可以配对多台手机（pin 从单值变成一组）

- 状态：已接受
- 日期：2026-08-26
- 推翻：ADR-0095 里「一台桌面只 pin 得住一把公钥」这条隐含前提（TOFU 的验证方式不变，
  变的只是能存几把）
- 相关：ADR-0094（远程投影）、ADR-0123（被挡下的握手要有主动信号）、
  ADR-0127（删设备行必须连着解除配对）

## 背景

`PinnedPeerStore` 存的是单个 `peer: string | null`，握手时 `remoteBridge` 拿这一把去
`deriveSession`。配第二台手机 = `pinPeer()` 覆盖，**第一台当场失效**。

三个后果，一个比一个不该有：

1. 换手机（或换一份安装，见 ADR-0127）要重新核对一次安全码
2. `pin()` 的注释写着「覆盖旧的 pin = 换了手机，**由调用方先问清楚**」，而调用方
   （`RemoteDevicesSettings` 的 `pair()`）**没问** —— 契约写在注释里，没人兑现
3. 被顶掉的那台没有任何提示。它下次来握手会被记进拒绝台账（ADR-0123），但用户
   在按下「配对」的那一刻看不到任何东西

## 决定

### 1. `peerIdentity(): Uint8Array | null` → `peerIdentities(): Uint8Array[]`

`pinPeer(pub)` 变成**加一把**（已在组里就是空操作），`unpinPeer()` 变成
`unpinPeer(pub)` 删一把。

### 2. 握手时**逐把试**，哪一把对由签名说了算

```ts
for (const pub of pinned) {
  keys = deriveSession(p, { self, peerHello: hello, peerIdentityPub: pub });
  if (keys) break;
}
```

**不能拿 `hello.deviceId` 查表挑公钥。** 握手包是明文过中继的，`deviceId` 由对端自称 ——
按它查表等于让对端自己指定"用哪把公钥来验我"，冒名者只要报一个存在的 deviceId 就能
让桌面用一把它挑的公钥去验它自己的签名。签名验不过就是验不过，所以只能挨个试。
组的大小是用户配了几台，个位数，性能不是问题。

拒绝的两种 reason 一个不少：空组 = `unpaired`，一把都对不上 = `identity-mismatch`。

### 3. 身份文件 `v: 1` → `v: 2`，**v1 必须永远读得回来**

`peer: string | null` 换成 `peers: string[]`。读到 v1 就地升级（有值 = 只有一个元素的
组），已配好的那台不用重配；写出去一律 v2。桌面（`remoteIdentity.ts`）和手机
（`mobile/src/identity.ts`）两侧同样处理。

降级读不了 —— 装回旧版本 = 重新配对一次。这个代价是明说的，而且只涉及配对关系，
身份密钥本身不受影响（devices 目录里的行不用动）。

### 4. `unpin(deviceId)` 和 `forget(deviceId)` 是两件事

- `unpin` = 只解除配对，**目录行留着**
- `forget` = 删目录行，那把 pin 一起清掉（ADR-0127）

分开是因为**停用要停得住**：删了行，装着 app 的手机下次打开又会重新登记回来 ——
那是"把列表擦一遍"，不是"不让它连"。

## 明确不做：同时在线多台

中继的槽位就是 `{ desktop, mobile }` 两个（`services/gateway/src/relay.ts`），
同角色重连**顶掉**旧的；桥的状态机（`self` / `sealer` / `opener` / 去重基线）也是
单会话的。所以现在是「**信任多台，同时连一台**」：后连上的把先连上的顶下线。

做到多台同时在线要的是另一件事 —— 中继按连接分发、桌面侧 N 份会话状态、以及一个
这份 ADR 没有答案的问题：两台手机同时对同一个 agent 下命令怎么办。那是独立的一步，
不该混在"换手机不用重配"里搭车。UI 上把这条限制直说了（"同时只连得上一台，
后连上的会把先连上的顶下线"），而不是让用户自己撞出来。

## 什么前提失效会推翻它

- 中继改成按连接分发 + 桥支持 N 份会话 —— 那时「同时只连一台」这条限制消失，
  UI 文案和这份 ADR 的最后一节要一起改
- 组无限增长成为问题（用户攒了几十把 pin 而没人清理）—— 那时要么加上限，
  要么给 pin 加「最后一次用上是什么时候」并按它清理
