# ADR-0138 取消「GUI 改动必贴 e2e 结果」的验收义务

状态:已接受(2026-08-26)
关联:Issue #579;修订 ADR-0058 决定 2 的后半段;不影响 ADR-0058 决定 1/3
层级:L1(删除既有协议义务)——维护者 stanyan 在会话中明确同意,本仓单人,
     符合 gearbox ADR-0034/0042 的会话内同意路径

## 背景

ADR-0058 决定 2 在把 `npm run e2e` 挡在门禁之外的同时,加了一条替代约束:

> 代替的约束是 PR 模板里「验收证据」一栏:GUI 改动的 PR 必须贴 `npm run e2e` 的输出
> 或真机截图,「没跑」也要写明,不准留空。

当时的判断是对的:GUI 改动只有 `electron-vite build` 把关,而 build 通过说明不了
窗口能不能出来——这一层确实第一次跑就抓到两个真 bug(见 ADR-0058)。

## 问题

这条义务的**成本随并行 agent 数量放大**,而它拦下的风险没有跟着放大。

实测数据(2026-08-26 夜):

- `tests/e2e/` 30 个 spec / ~70 条用例 / **90 次 `launchOtto`**,零 `beforeAll` 复用。
  每条用例冷启一只真 Electron:换 `HOME`、换 `OTTO_PROFILE`、跑完删目录
  (隔离是必须的,见 `tests/e2e/harness.ts` 开头 #480 的教训)
- `playwright.config.ts`:`workers: 1` 全串行,`timeout: 60_000`,`retries: 2`
- 一轮全量 30+ 分钟。同机有别的 worktree 在动时触发 #274 那类偶发挂,重试再翻倍
- 一条 lane 一晚上连跑四轮,每轮占满机器,其余 lane 全部变慢

更关键的是这条规定**从来没有真的要求跑**——它约束的是「不准留空」,「没跑」是合规
写法。但写在 PR 模板里的「GUI 改动必贴」在实践中被读成硬要求,agent 倾向于加码跑
全量以求合规。也就是说:成本是实打实的,而规定本身并不为这份成本背书。

## 决定

取消这条义务,**保留能力**:

1. 删 `AGENTS.md` 索引行里的「GUI 改动的 PR 贴它的结果」
2. PR 模板保留「验收证据」栏与 `npm run e2e` 那一行,去掉「GUI 改动必贴」的强制措辞
3. `tests/e2e/` 一个文件不动,`npm run e2e` 不动。想验随时跑,推荐只跑相关 spec:
   `npx playwright test tests/e2e/xxx.e2e.ts`

## 不做的

- **不动门禁**:`npm test`(`tsc --noEmit` + `vitest run`)原样。e2e 本来就不在门禁里
  (ADR-0053),这次也不往里加、不往外拿
- **不动 ADR-0058 决定 1**:`tests/architecture.test.ts` 那三条 Hard rules 断言照旧
- **不动 ADR-0058 决定 3**:Issue/PR 模板的「验收证据」栏保留——「代码写了 ≠ 做完了」
  这个提醒本身没成本,有成本的是把 e2e 钉成唯一合规证据
- **不删 e2e 用例**:这次改的是义务,不是覆盖。按 gearbox ADR-0020,「删测试换绿」
  才是 L1 违规行为;本 PR 的 diff 里 `tests/` 零改动

## 什么前提翻掉会推翻这个决定

- e2e 跑一轮的成本降下来(并行化、复用 app 实例、或拆出一个几分钟的快速子集):
  那时把「GUI 改动必贴」加回来是划算的,加回来按 L1 走
- 出现一次「GUI 改动进了 main,窗口打不开/静默失败」的事故,且事后确认全量 e2e
  能拦住:说明这条义务的保障被低估了
