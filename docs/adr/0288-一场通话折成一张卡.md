# ADR-0288：云会话时间线里，一场语音通话折成一张居中的卡

- 状态：已采纳
- 日期：2026-09-10
- Issue：#1233
- 相关：ADR-0271（团队语音通话）/ ADR-0273（人说话走本机识别）/ ADR-0286（通话那一行居中 + 名字左边画脸，本条换掉它的载体）/ ADR-0250（折叠头那句摘要为什么也撤了）/ ADR-0285（时间线窗口化）

## 背景

维护者原话：

> 现在团队的会话里会把通话记录的文本全部转写到会话记录里。不需要，把通话的所有文本内容集成为一个卡片居中显示在会话框里，如果用户想看的话，自己点进去再看。

真机形态：通话里人说的话走 `cloudSay(text, [], [])`（ADR-0273 的 `final` 那条路），落成一条**普通** `user_message`；通话里那几只 agent 的回复照旧 `assistant_message`。两者在云会话时间线上都是普通气泡，于是**一场 12 句的通话把时间线撑开约 1400 像素**，通话前后真正的工作对话被挤到看不见。

ADR-0286 刚做完的那一行（居中 + 每个名字左边一张脸）说的是「通话开始 / 拉人 / 结束」，管不到正文——它把名单那一行做对了，而正文那一大片是另一件事。

设计过程是**先出 HTML demo 再动代码**（维护者要求的顺序）：一份独立 HTML，含「现状 / 卡片」对照 + 三种展开方式 + 明暗两套 + 进行中/已结束两态，维护者对着它拍板。那份 demo 是一次性的手写原型，**没有进仓**——它的每一条结论都写进了下面的决策，留一份会过时的 HTML 在仓里只会多一个第二事实源。

写完代码之后另起了一个 vite harness 把**真组件 + 真 `app.css`** 渲一遍截图（也没进仓）。这一步不是走过场，它当场抓出两件 demo 那份手写 CSS 钉不住的事：一是任意值类名（`max-w-[402px]` / `size-[18px]`）在那个 harness 里没被 Tailwind 扫到，卡画成通栏、头像两百像素高（harness 自己的毛病，加一行 `@source` 解决）；二是 `callDurationText` 遇到一个跨度很大的 `sinceTs` 会写出「1483577 分 34 秒」—— 那不是假数据的锅：日志里「通话结束」是一条真事件，daemon 崩在通话中的话那条永远不来，卡会一直是「通话中」，于是补了小时那一档（决策 2 末）。

## 决策

### 1. 卡片吞哪些消息：`user_message` / `chat_message` 加一格 `voice`，不按 seq 区间吞

新增可选字段 `voice?: true`（两个事件都加），协议 18→19 在 `say` 帧上多一格，runtime 原样落盘。判据：

- **人说的话**认 `voice` 记号 —— 转写出来的正文与手打的正文一个字节都不差，麦克风那一侧是这条链上唯一知道这件事的地方（`store.speechOnEvent`）。
- **agent 的回复**认「它此刻在通话名单里」，**不用第二个字段**：通话里那几只的回复会被读出来（ADR-0271），这本身就是日志（`voice_call_changed` + `assistant_message.agentId`）推得出的事实。

否决的两条路：

- **按 seq 区间吞**（通话开始到结束之间全算）：零 schema 改动、纯渲染层投影、不用重新部署。但云会话是**群聊** —— 通话期间没在通话里的人打的字会被吞进一张他没参与的通话卡，而这条 issue 修的正是「不该进时间线的东西进了时间线」，**方向修反就是同一类 bug 的新一版**。
- **按「谁在通话里」过滤人类发言**：判不出来。人类「谁在听」不落盘，那是 ADR-0271 写明的已知代价。

也否决了**给 `assistant_message` 加一格「这条被读出来了」**：读没读出来是**每个听众各自的事实**（谁在听、有没有静音都在本机），不是日志事实。runtime 压根不知道 —— TTS 发生在桌面侧（ADR-0271）。

**已知代价**：通话期间有人打字提问、而通话里的 agent 答了，那条答案进卡片、问题留在时间线上（卡里出现一句没有问题的答案）。混着说与打字的用法很少见，且两半都还读得到；反过来（把打字的也吞进去）会连旁人的话一起吞，那个方向更糟。

**为什么加字段也要进协议位**：握手是精确相等（`frameHandler` 的 `version_mismatch`）。老 runtime 拿到这一格会 `JSON.parse` 掉再丢弃，于是新桌面以为通话内容会折成卡、而落盘的每一条都没有记号，时间线上又是一句一条气泡 —— **那正是这一版要修的形态，且完全无声**。

`voice` 只认 `true` 这一个值，别的值当缺席**不拒帧**（与 `mentions` / `memberMentions` 那两格的「形状不对整帧拒掉」不同）：那两格丢掉会静默改变「这句话点了谁」，而这一格只影响折不折卡，脏值退化成「不折」= 改动前的行为，为它拒掉一句真话更糟。

### 2. 收起时报「多久 · 多少句」+ 参与者的脸，**不带最新一句**

`语音通话 · 6 分 12 秒 · 12 句`，下面一行是参与者的脸 + 名字，右边「看记录 ›」。约 56px。

- **只报多久 / 多少句**：人能据此决定点不点开。不报「几步 / 几次工具调用」那类量 —— ADR-0250 已经为折叠头判过一次，那句摘要说的是干活的量，读者既不能据此判断进度也不能据此做任何事。
- **不带最新一句**（维护者拍板）：带了等于把转写文本又请回时间线一点，而通话进行中人一般正看着通话栏或全屏通话视图（ADR-0278），那两处有字幕。demo 里做了带的那一版供对照。
- 句数**不含名单变更那几行**：一场谁都没说话、只拉了两次人的通话不该报「2 句」。
- 参与者是**整场的并集**不是此刻的名单：中途被移出的那只照旧算参与过这场通话。

### 3. 展开走**弹窗**，不走内联展开、不走右侧栏

三种都做了 HTML 原型，维护者选弹窗：

| | 优点 | 代价 |
|---|---|---|
| 内联展开 | 一次点击、不离开上下文 | **展开时仍然把时间线撑开一次** —— 只解决了默认态 |
| **弹窗（选中）** | 时间线上永远只剩那张 56px 的卡；全文一整屏；`DialogContent` 的溢出兜底已有（ADR-0279） | 遮住会话、一进一出 |
| 右侧栏 | 边读边聊；与 Files / 后台任务同一族（`sidePanel.ts` 的单一开关现成） | 与别的面板互斥 —— 读通话记录把 Files 挤掉 |

维护者那句「自己点进去再看」本身就是弹窗的语气；而一场几十句的通话要一整屏才读得舒服。

卡里的全文是**剧本式悬挂缩进**（脸 + 「名字 第几分几秒」在上，正文缩进在下），**刻意不套气泡**：弹窗本身已经是一层容器，里头再套一层就是多一层边界，而这一屏要读的是一段连续的对话，不是要分辨谁靠左谁靠右。每行的时刻是 **mm:ss**（相对通话开始）不是墙上时间 —— 通话里「第几分几秒说的」才有意义，整场通常只跨几分钟。

### 4. 一场通话一张卡：中途的名单变更折进卡里

`voice_call_changed` 只有**开场那一条**留在时间线上（卡就画在它的位置），中途的拉人 / 移出 / 结束全部折进卡里，画成一道居中的细线分隔。文案仍然走 `voiceCallLineParts` —— **ADR-0286 的两条结论原样成立，只是换了载体**：卡本身居中（这一条说的是整个群此刻的状态，不是机器的内务，所以与 `AgentBriefedRow` / `AgentRelayRow` / `SystemNoteRow` 那几行靠左的旁白照旧不同款），名字左边那张脸搬到了卡里那道分隔线上。

`VoiceCallRow`（#1228 那个组件）因此**零调用**，删掉 —— 留着跑不到的代码，下一个人会以为它还在被谁读（同 ADR-0250 / ADR-0214 的纪律）。它的测试文件换成了 `tests/renderer/voiceCallCard.test.tsx`：**不是删测试换绿**，产品代码在同一个 PR 里换掉了那个组件，ADR-0286 的那几条断言跟着搬进新文件。

### 5. 判据不塞进 `hiddenFromCloudTimeline`

那个函数是**逐事件的纯谓词**，而「这一条属不属于某场通话」要跨事件才答得出。折卡走一个单独的纯函数 `voiceCallCards(events, ws, selfUid)`，在组件里 `useMemo` 一次，回两样：`cards`（按开场那条事件的 seq 索引）与 `folded`（被吞掉的每一条 seq）。渲染循环先问 `hiddenFromCloudTimeline`，再问 `folded.has(e.seq)` —— 同一个循环里 `prevVoiceCall` 那张表本来就是这个手法。

### 6. 通话中那只表的作用域圈在卡里

已结束的卡一个定时器都不挂；还开着的那场每秒一跳，但 `setInterval` 在卡这个组件里 —— 挂在时间线那一层会把窗口化那套（ADR-0285）的开销放大一倍，而这一格只有这张卡在读（同 ADR-0255 那枚点「表 60 秒一跳且作用域圈在这一枚钮里」的取舍）。`motion-reduce` 下那枚呼吸的点不动。

## 代价与已知未做

1. **要重新部署 runtime 才生效**（#791）：`services/runtime/` 与协议号都动了。部署之前，新桌面连不上旧 runtime（握手精确相等，会明确报 `version_mismatch` 而不是静默少一格）。
2. **存量日志里那些通话内容永远折不起来**：append-only 补不回 `voice` 记号，旧会话的时间线上仍然是一句一条气泡。这是 schema 向后兼容那条硬规则的必然代价，不是漏做。
3. **混着说与打字时，卡里可能出现一句没有问题的答案**（决策 1 的已知代价）。
4. **手机端不受影响也不受益**：手机还没有云会话客户端，它发的 say 帧永远不带这一格。
5. **卡上没有「跳到时间线」这条路**：弹窗里读到一句话，想看它前后的上下文只能关掉弹窗自己找。通话内容本来就是一整段，跳出去意义不大，但一场穿插着打字的通话里这条会想要。
6. 「下载 .txt」没做（demo 里画了）：要走保存对话框 + 一条 IPC，是独立的一件事。「复制全文」做了 —— 一次 `navigator.clipboard.writeText`，抄给别人时名单变更那几行也带上。
7. **真机一次都没跑过**（同 ADR-0264 / ADR-0265）：验收要一台部署过新 runtime 的 VPS + 一场真通话。
