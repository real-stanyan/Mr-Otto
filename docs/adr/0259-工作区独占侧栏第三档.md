# ADR-0259：侧栏切换器加第三档「工作区」——工作区独占一栏

- 状态：已接受
- 日期：2026-09-08
- 关联：#1087 / ADR-0217（工作区搬进侧栏项目区 + 订阅闸）/ #923（「新工作区」只在项目栏）/ #921（并排那一对要长一样）/ ADR-0218（工作区里开会话和本地一个开法）/ ADR-0256（被 @ 的人收到提醒）/ ADR-0236 第 1 条（几何不写断言）

## 背景

维护者对着侧栏头部那张图说：

> 把工作区移到上面的 Switch 里，所以说应该是上面的 Switch 显示三个：任务、项目、工作区，工作区和任务、项目一样，独占一个栏

改动前那一栏的样子由 ADR-0217（#917 规则三）定形：工作区列表**置顶挂在项目栏里**，段尾一道内缩的细线把它和本地工程分开；头部是并排等宽的一对「＋ 新会话」/「新工作区」（#921 要求两颗长一样），而这一对只在项目栏出现（#923）。

## 诊断

ADR-0217 当时的判断是「工作区是项目那一侧的概念」。这次维护者把它抬平了：**工作区和任务、项目一样，是「我在哪儿干活」的一个完整答案**，不是项目的一个子类。三个答案是并列的——不用先懂文件夹（任务）/ 我自己机器上的文件夹（项目）/ 和别人共用的云上文件夹（工作区）。

所以这不是「把一节挪个位置」：它把一个二分法改成三分法，而原来那一节里有三样东西的存在理由是「我和项目挤在同一栏」——那三样必须跟着重判，否则会留下三处说不通的残留（分组线、空态、按钮位置）。

## 决策

### 1. 切换器三档，工作区是其中一档

`sidebarTab` 从 `"tasks" | "projects"` 扩成三态，抽成 `store.ts` 导出的 `SidebarTab`：这三个字面量原本要在 state、setter、`onValueChange` 的断言三处各写一遍，**加一档时漏改一处 tsc 不会红**，只会让那一档在某一处静默不认识。

图标沿用各自既有的语汇（`ListChecks` / `FolderOpen` / `Boxes`）——`Boxes` 已经是「新工作区」那颗钮、弹窗标题、侧栏组头的那张脸。

推翻的只是 ADR-0217 的**位置**结论。它的闸与语义一个字不动：订阅闸仍卡在创建这一侧（`workspaceAccess` 四态 + RLS 两道），额度仍记在创建者头上。

### 2. 「新工作区」跟着它生出来的东西走

工作区栏的头部按钮是「新工作区」，任务/项目栏是「新会话」，每栏一颗、通栏左对齐（`SOLO_BUTTON`）。

**#923 那条判据原样成立，只是换了一栏**：「按钮留在任务栏的话，点完人在原地看不见任何结果」——它生出来的东西（`WorkspacesSidebarSection`）如今只在工作区栏画得出来，所以钮跟着搬过来。

**工作区栏没有「新会话」**：云会话必须落在某一个工作区里，而这一栏顶上没有「哪一个」可言；开一条的入口在每个工作区组头那颗 ＋ 上（ADR-0218）。

`TWIN_BUTTON` 随之删掉——#921 要的是「并排那一对不分主次」，而现在任何一栏都只有一颗，不再有「并排」。留着一个跑不到的类名串，下一个人会以为它还在被谁读（同 ADR-0214 的纪律）。

### 3. 未读点名的记号必须跟着上切换器，且画点不画数

ADR-0256 的角标画在两处：工作区组头 + 会话行。工作区独占一栏之后，**人站在任务/项目栏时那两处一处都不在屏幕上**——「有人在等你」这件事整个消失，而它恰恰是那条能力存在的全部理由。

所以「工作区」那一格右上角亮一枚点，判据是 `unreadMentionCounts(...).total`。

- **`total` 加在那个纯函数里**，不在渲染层写 `rows.filter(r => !r.read).length`：「哪一条算未读」只能有一份判据。
- **画点不画数**：这一格量出来只有 78px 宽，塞不下数字；量级本来就在下一层（组头 + 会话行各一枚带数的角标），这颗只回答「工作区那边有事」——同 ADR-0255 那颗额度点的取舍。
- 绝对定位，不占版面宽度（占了的话「工作区」三个字先被顶出去）。
- 色取 `--brand` 不取 `--warn`：被 @ 不是「出事了」（同 `MentionBadge`）。
- 话进 `aria-label` 不进 `title`，点自己 `aria-hidden`。

### 4. 空态从「故意不画」翻成「必须画」

`WorkspacesSidebarSection` 原来一条工作区都没有时 `return null`，**理由写在组件注释里**：「项目栏底下已经有一段『还没有项目』的空态，顶上再压一句，第一次进来的人要读两段才走到列表」。

独占一栏之后那个前提没了：这一栏里没有别的东西会说话，不画就是切过来一片空白，人分不出「还没建过」和「读不到 / 坏了」。拉取失败那一档不变（空列表 + 有错 = 「读不到」，不是「没有」），并且**出了错就不再劝人去建一个**——两句话不同时出现。

### 5. 段尾那道内缩的分组线删掉

它是 #917 规则三「和本地工程分开显示」的落点（内缩而不是通栏，因为通栏的横线读作「界面构件之间的分隔」）。分开显示这件事现在由切换器本身承担，这一栏底下没有第二组要分开——留着就是一条指向空气的分组线。

### 6. 工作区栏不画「已归档会话」

归档的云会话在每个工作区 ⚙ 那一页的底部（ADR-0218），不在这一屏。摆一颗在这儿等于给一颗永远报 0、点开永远是空屏的钮，而那句空态文案（「会话行的 ⋮ 菜单里有归档」）在这一栏还是假的。`archivedCount` 因此在这一档显式回 0，不复用项目栏那个数。

### 7. 切档顺手退出归档屏，收在入口

侧栏那棵树的分支顺序上 `archivedView` 排在 `tab` 之前，所以「人正开着项目的归档屏 → 切到工作区栏」会画着项目的归档、切换器却写着「工作区」。修在 `switchTab` 这个**入口**上，而不是给那棵树再加一个 `tab !== "workspaces"` 的条件——同一个判据写两处迟早分家。

### 8. 三档在 16rem 侧栏里怎么排是量出来的，不是算出来的

真机（Playwright 起真 Electron，量 `getBoundingClientRect`）：侧栏 16rem 减去 header 的 `p-2` 与 `TabsList` 的 `p-[3px]` = 234px，三等分每颗 78px；「工作区」三个全角字 42px、图标 16px。

配 shadcn 默认的 `px-2 gap-1.5` 需要 80px > 78。**失败形态和事先猜的不一样**：flex 项的 `min-width` 是 `auto`，所以它既不截断也不撑破侧栏，而是**自己长到 82px、把两个邻居各挤成 76px**——一排分段控件从此不等宽，切档时那颗白药丸的宽度还会跳。收窄到 `px-1.5 gap-1` 之后需要 74px，三颗都稳在 78。

两档时代富余 12px，所以这笔账是第三档带来的。**故意没写成断言**（同 ADR-0236 第 1 条）：两个 Tailwind 字面量之间的算术，扫源码的正则会在任何无害重构上翻红，保鲜期是紧挨类名那段写着「为什么是 1.5 不是 2」的注释。

### 9. 初值判定不动

`tabDecided` 那条仍然只在任务/项目之间选（库里有项目会话的老用户落项目，全新用户落任务）。没有把「有工作区就落工作区」加进去：`sidebarTab` 本来就不持久化，每次冷启动都从任务开始，而工作区栏值不值得被自动选中，取决于那一刻有没有事——那个信号已经由决策 3 那颗点回答了，再加一条判断只会让同一个问题有两份判据。

## 代价与已知未做

1. **冷启动仍落在任务/项目栏**，去工作区栏要点一下（决策 9）。补偿是那颗点，但它只在有未读点名时亮——没人 @ 你的时候，工作区那边有没有新会话仍然要自己去看。
2. **那颗点不报量级**（决策 3），且它是 `workspaceMentions` 的投影，所以 ADR-0256 那三条拉取路径（realtime / 开机 / 窗口重新聚焦）的天花板原样继承：0030 还没在真库跑过的话它永远不亮。
3. 三档的几何没写成断言（决策 8）。
4. 工作区栏没有「已归档会话」入口（决策 6），归档的云会话仍然只能从工作区设置页底部翻到——这不是本条引入的，是 ADR-0218 的现状。
5. 项目栏的空态文案没跟着改：它现在说的是「还没有项目」，而工作区已经不在这一栏了——两段空态各说各的，不再互相依赖，这正是决策 4 要的。
