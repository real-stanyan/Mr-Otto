# ADR-0333：不是活、但在等人回一句的话，由一只智能体应

- 状态：已采纳（2026-09-29）
- Issue：#1422
- 修订：ADR-0270（#1153「闲聊/问候不是活，没人接」）的一半；ADR-0275、ADR-0328 不变

## 背景

维护者真机：群聊里发「有人在吗」，群里两只智能体都没回。VPS 日志：

```
[decision] {"use":"dispatch","mode":"on","verdict":"none","scores":{"act":0.08,"people":0.26,...}}
```

这不是故障，是 #1153 定下的口径：问候不是活，判 none，没人接，而且不出声。可「有人在吗」
「在吗」「大家好」是在等回话的——没人应，界面上就像群坏了。「好的」「谢谢」「哈哈」则
确实不需要谁回，每句都回会很吵。维护者拍板：等着回话的由一只应，其余照旧。

## 决定

1. **none 分两种**：`DispatchVerdict` 的 `none` 多一格 `reply?: true`，意思是不是活、但在等人回
   一句。它与 `to: "people"` 互斥：说给群里某个人的话，智能体不该应。
2. **谁应**：用通话里「必须有人应」（ADR-0275）的同一个人选，函数改名为 `answererAmong`。
   - 最近开口的那只；
   - 一只都没开过口（**刚建的群**、招呼被限速掐掉、超出尾段窗口）时，退回 `dispatchFallbackOf`：
     管理员在群里就是它，否则名单第一只。

   开场白照旧带 `dispatch: "auto"`，走与人亲手 @ 同一条路。
3. **决策模型多问一题 `reply`**：同一请求里的题目并行，多一题只多 token 不多时间。它只在
   `act < DISPATCH_NONE_BELOW`、且没有哪只对得上时起作用：

   | 条件 | 判决 |
   |---|---|
   | `reply ≥ 0.6`，且 people 低于 `DISPATCH_PEOPLE_CLEAR`（或群里没有别人） | `none{reply}` |
   | `reply < 0.3` | 普通 none |
   | 其余 | escalate，交给 LLM |

   有同事的团队群里，「大家好」可能是说给人的，拿不准就不替智能体抢答。回包里缺 `reply`
   时整份不认（同其余各题）。
4. **LLM 那条路**：提示词把原来那条「不是在要求做事 → none」拆成两条。在等回话的回 `reply`；
   不用谁回的回 none。解析认 `reply` → `none{reply}`。
5. **通话里不变**：通话里的普通 none 本来就由一只应（ADR-0275）。

## 代价

- **阈值是拍的**：`DISPATCH_REPLY_AT = 0.6`、`DISPATCH_REPLY_QUIET = 0.3` 没对拍过。上线后看
  `[decision]` 日志里的 `reply` 分数再调；判词里多了 `none:reply`。
- **中间地带多走一趟 LLM**：拿不准的问候要多等 LLM 那条路（≤5 秒），那一发照样计费。
- **应的那一轮要花钱**：每一句「有人在吗」都会起一轮模型调用，花所有者的额度。
- **要重新部署 runtime 才生效**（#791）；桌面、手机不用改。
