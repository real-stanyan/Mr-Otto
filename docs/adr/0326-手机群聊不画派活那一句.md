# ADR-0326：手机群聊不画派活那一句

- 日期：2026-09-28
- 状态：已采纳
- 关联：#1396。维护者 2026-09-28 在模拟器上用真账号看微信式手机端（#1386），指着群聊里那行居中小字「没 @ 谁 —— 开发接了」原话：「这句话文案不需要显示」
- 关系：撤掉 `docs/superpowers/specs/2026-09-23-mobile-agents-app-design.md` §5.6（#1356 A3）里的「派活那一句」。ADR-0270 的派活本身一个字不动

## 背景

人在群里说话没 @ 谁时，runtime 按职责挑一只接（ADR-0270），落盘的那条 `user_message` 带 `dispatch: "auto"`。#1356 A3 在手机端把它投影成那句话底下的一行旁白「没 @ 谁 —— 运维接了」（`dispatchLineText`），注释写着「手机先画，桌面那侧还没接」。桌面从来没画过它。

## 决定

1. **手机端不再画这一行。** 判据是本仓已有的两条：它说的事紧接着就有人说——被派到的那只一开口，气泡旁就是它的头像和名字（同 ADR-0235 ①「同一件事说两遍」）；而「是 runtime 挑的还是人亲手点的」这一层，读者据此做不了任何事（ADR-0260：用户能不能据此行动）。
2. **`dispatchLineText` 删掉，不是留着不调用。** 它只有手机时间线这一个消费方。留一个没人调的函数、带着一句「桌面那侧还没接」，下一个做桌面微信式那一半的人会照着把它接到桌面上。
3. **`user_message.dispatch` 这一格照写。** 它是日志事实；删字段要动 schema（旧日志必须永远可重放），为一行不画的字不值。

## 后果

- 回话之前谁在忙，时间线末尾「此刻」那一行（作答 > 执行 > 排队）照旧说。
- 被派到的那只一个字没说就出错收口时，出错那一行是「「X」这一轮出错」，接的是谁仍然看得见。
- 派不出去时照旧有话：那句「没派出去（原因），需要谁接的话 @ 一下」是 runtime 落的系统发言（`chat_message{fromUid:"system"}`），走旁白那条路，不受影响。
- 两端从此一致：桌面本来就不画。
