# ADR-0014：分支选择器——给 git 服务开一个受限的写口

日期：2026-08-18
状态：已接受
关联：#23（Task）、ADR-0013（Git Graph 只读可视化）

## 背景

ADR-0013 给 GitGraphService 定的边界是**严格只读**（log / rev-parse / show），理由是可视化不需要改仓库，只读的东西不会有后悔药问题。

维护者提出的新需求打破了这个前提：新会话选好工程文件夹后要能**选分支再开工**，会话中要**常显当前分支**。列分支仍是只读，但"选分支"落地就是 `git checkout` —— 一个会改工作区的写操作。

## 决策

**给 GitGraphService 开一个写口 `checkout(repoDir, branch)`，且只开这一个。** 边界写死成三条：

1. **只服务用户显式操作。** 触发点只有 UI 里的分支下拉框。agent 的工具集不含它，`ExecutionWorld` 也不暴露它——agent 想切分支照旧走 bash 工具，走审批流。
2. **参数验形先于 exec。** `isValidBranchName` 挡掉 `-` 开头（会被 git 当选项读）、空白、`..`、`@{`、`~^:?*[\` 等 git 自己就禁的字符；exec 时再补一个 `--` 终止选项解析。参数是数组传的不过 shell，所以这里防的是**选项注入**，不是命令注入。
3. **失败要能行动。** checkout 最常见的失败是工作区脏，用户自己能解（提交 / stash）。这种情况单独归一个 `dirty` kind，UI 给"先提交或 git stash 再切"，而不是把 stderr 甩到脸上。

## 为什么不另建一个服务

想过把写操作拆到 `gitWriteService` 里，用文件边界物理隔离读写。放弃了：依赖（execGit / dirExists）完全相同，拆开只是把同一个 DI 复制一份，读者还得在两个文件间跳。**边界靠"只有一个写方法 + 这份 ADR"来守，比靠文件名守更诚实**——文件名拦不住任何人往里加第二个写方法，代码评审能。

如果哪天写方法涨到第二个、第三个（commit？push？），那时再拆文件，并且要先回答"为什么 app 要替用户做这些，而不是让 agent 走审批流做"。

## 分支状态不进事件日志

当前分支**不是**事件日志的投影，它是 git 的实时状态，只能重新问 git。所以：

- store 里按目录缓存（`branchesByDir`），不是按会话
- agent 在对话里 checkout / merge 之后，靠 `tool_result` 事件触发**重新问 git**（600ms 尾随防抖，连环工具调用只刷尾部一次），不是从日志推导

这不违反"任何投影必须可从日志推导"——分支显示压根不是投影，是外部世界的读数，跟文件系统内容同一性质。

## 后果

- 好处：开工前站对分支这件事，从"进会话后自己去终端切"变成一次下拉选择；会话中站在哪根枝上一眼可见，agent 切了也跟着变
- 代价：GitGraphService 不再是纯只读，读这份代码的人得先读这份 ADR 才知道边界在哪（所以服务文件头注释直接指向本文件）
- 风险：用户在 turn 进行中切分支会让 agent 脚下换地板。缓解 = turn 跑着时下拉框禁用；彻底的解法要等 v2 的 per-bot 容器隔离
