# ADR-0209：套餐额度并进上下文那张浮层卡，主数字取吃紧的那扇窗

日期：2026-09-03
状态：已接受
相关：#892、ADR-0174（双固定窗）、ADR-0176（托管优先）、ADR-0203（订阅制落地）

## 背景

订阅制走通之后，5 小时窗 / 本周两扇窗的用量只在**设置 → Keys** 的订阅卡片里露面。
聊天时看不到还剩多少，只有真用完那一下，时间线上会插一条 `route_changed`
（「订阅额度已用完，本次起用的是你自己的 key」）。

数据本来就是活的：`main/hostedQuota.ts` 的 `noteHeaders` 每次网关响应都把响应头里的
剩余额度换算成 `usedMicro` 推给渲染层（`onBillingChanged` → store 的 `billing`），
只是没人画。

## 决定

### 1. 挤进上下文浮层卡，不给它第二枚常驻控件

额度是**全账号**的，上下文是**这个会话**的，两件事；但用户问它们的时机是同一个——
「我还能接着干吗」。所以它长在输入框右上角那枚上下文环的浮层里
（`components/PlanQuotaSection.tsx`，挂在 `App.tsx` 的 `CtxDetails` 底部，
排在 `CostPanel` 之后）。读起来是一路往外拉：窗口里装了什么 → 这个会话花了多少 →
我的账号还剩多少。

**代价明写在组件头注里，免得下次有人当疏漏来修**：不悬停就看不见。给它第二枚常驻
控件要在那条已经很挤的工具条上再占一格（模型选择 + thinking + 上下文环，520px 以下
前两个已经收起来了），而它多数时候是个不需要盯着的数；真用完那一下有时间线上那条
`route_changed` 说话。

**会被推翻的前提**：额度用完变成常态（用户反复撞墙），那时该给它一个被动信号——
但那个信号也应该是「快满了」的预警，不是再画一份同样的数。

### 2. 主数字取**吃紧**的那扇窗，不固定取 5h

两扇窗独立，任一打满都停。`bindingWindow` 取占比高的那扇当主（并列取 5h——预算小、
烧得快，同样百分比下先满的一定是它）。周窗打满而 5h 窗空着的时候只报 5h，
等于报喜不报忧，而用户看这个数就是想知道还能干多久。

两扇窗照旧都列出来，主次只影响**强调**：当主那扇的条走语义色，另一扇走中性灰。
一张卡里两条彩条会互相抢，而真正拦住人的只有一扇。色档（>90 危 / >75 警）
**与上下文环共用同一组阈值**——同一张卡里同一个百分比不该上半张是绿的、下半张是黄的。

### 3. 倒计时只在当主那扇底下，单独一行

三样东西挤一行时最长的形态（`4.1 / 6.7 credit · 2 小时 12 分后恢复`）会顶出这张
300px 的卡、标签跟着折行。另一扇窗的恢复时刻本来也不是此刻要做决定的依据——
真轮到它拦人时它就是当主的那扇。

顺带把 `countdown` 补了「天」这一档：周窗按小时写出来是「96 小时 0 分后恢复」，
没人这样读时间。天数向上取整（还剩 3 天半说「4 天」）——这行字的用处是
「别指望它马上回来」，说晚一点比让人白等强。

### 4. 过了 `resetAt` 的窗按清零画（`liveWindow`）

客户端这份快照是**上一次网关响应**留下的，而窗口到点会自己清零。睡一觉回来照着旧数
画，就是对着一个额度早已回满的人说「你用了 62%」。设置页那两条因为进页会 `refresh`
一次而躲开了，常驻在浮层里的这份躲不开——所以换算下沉成纯函数，**两处共用一份**：
同一扇窗在两个界面上不能给出两个数。

清零之后没有倒计时可言（5h 窗要等下一次调用才重新开窗），`countdown` 那句「已恢复」
正好是要说的话。

### 5. 判据是 `me.windows`，不是 `me.plan`

服务端只在订阅 `active` 时下发 `windows`（`services/edge/src/billingQueries.ts` 的
`meFromParts`），非 active 时报一份满额度的窗口是谎话。没有它整段不画——
这段常驻在一张每个人都会悬停的卡里，画错的成本是「以为自己有额度」。

## 后果

- 纯逻辑（`liveWindow` / `bindingWindow` / `quotaTone` / `usageLine` / `planName`）
  落在 `renderer/src/lib/billingView.ts`，与订阅页共用；组件只负责画。
- `countdown` 多了「天」档，设置页与时间线那条 `route_changed` 一并受益。
- 浮层里多一段 ≈ 60px 高；没订阅的人（含 BYOK）一个像素都不多。
