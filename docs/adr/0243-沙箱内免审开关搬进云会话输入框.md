# ADR-0243：「沙箱内免审」开关从工作区设置搬进云会话输入框那一行

> 原为 ADR-0240（撞号，ADR-0074：编号在合并时认领）。提交信息里写的 0240 指的就是这一份。

- 状态：已接受
- 日期：2026-09-07
- 关联：issue #1029；上游 ADR-0231（这颗开关的由来与它管什么）/ 0234（「这个东西属于谁」的判据，本 ADR 对它的例外）/ 0232（同工作区多条会话共用一容器一卷）/ 0228（三个 store 动作不碰 `workspaceGroupsError`）/ 0238（「只能往一个方向变」这条纪律的另一处）
- 来源：维护者原话——「把这个地方"沙盒内免审批"删掉，把审批开关放到会话区的用户输入框那里，就跟其他本地会话一样」（配图 = 工作区设置「智能体」tab 里那一行）

## 背景

ADR-0231 把「沙箱内 `bash`/`write_file` 要不要人批」做成了工作区一格（`workspaces.sandbox_approval`），控件落在工作区设置的「智能体」tab 顶部。

它解决的问题是**一张审批卡挂着的时候整个群的回复都在排队**——而人撞上这个问题的时刻，一定是在一条云会话里、盯着一张卡。控件却在两层抽屉之外的设置页里。本地会话那颗（`BypassToggle`）从来都在 composer 的工具条上，就在手边。

## 决策

### 1. 只搬位置，不搬语义——作用域仍然是**整个工作区**

- 落库那一列、RLS（0024 `ws_update_owner`）、runtime 的 `policyApprover`、覆盖面（只有容器里那两把刀，连接器与 `create_agent` 照旧要批）**一个字不动**，cs 协议不进位。
- **不做成按会话**：隔离面是容器，而同一个工作区的所有云会话共用一个容器一个卷（ADR-0232）。会话 A 免审、会话 B 逐条批，B 那边的审批挡不住任何东西——这与 ADR-0231 否掉「按 agent 配免审」是**同一条理由**。做成按会话还会顺带把授权人从 owner 放宽到「任何能建会话的成员」（`create` 帧只要求在籍），而钱是 owner 的、卷是共用的：那是权限扩大，不是收窄。
- 于是「跟本地一样」这句话兑现到**位置**与**手感**，不兑现到作用域。差别由文案与常驻警示行说出口（决策 3、4）。

### 2. 与 ADR-0234 的关系：这是它的例外，判据说得出来

ADR-0234 的判据是「工作区级设置挂在会话上，等于强加『先开一条云会话』这个前置条件」，据此把仓库配置从会话头部搬进了工作区设置。这次方向相反。

分野在**这个设置什么时候被人想起**：

- 仓库地址是**开工之前**配一次的东西，与任何一条会话无关，所以它属于设置页。
- 免审是**干活当中**踩的刹车，它被想起的那一刻，人必然正开着一条会话、正看着一张卡。给它加「先开一条会话」这个前置条件不构成负担——那个前置条件本来就成立。

已知代价写在下面。

### 3. 标签不叫「免审批」，判断收进纯函数

两颗开关四点不同：作用域（这一条会话 / 整个工作区）、覆盖面（每一把 `requiresApproval` 的刀含全部 MCP 工具 / 只有容器里那两把）、谁能改（自己 / 只有 owner）、持久化（内存态、新会话默认 ask / 落库、翻了就一直是那样）。同名同形就是「位置搬对了、话说错了」。

- 标签固定为「沙箱内免审」，`tests/renderer/sandboxApprovalControl.test.ts` 里有一条断言专门钉住它**不等于**「免审批」——日后有人来「统一文案」时会在那里红。
- 三态由 `sandboxApprovalControl(ws, selfUid)` 一处算出：owner 一枚真开关 / 成员一行只读事实 / 读不到时不画开关。**非 owner 不画开关**：一枚点了必然拿到「无权修改」的钮是 #722 那个撒谎的勾。
- 危险状态**不按人分可见性**：成员照样看得见此刻是不是免审。它花的是 owner 的额度、动的是大家共用的那个卷，藏起来只会让「刚才为什么没弹卡」永远问不出答案。
- owner 判据取 `ws.ownerUid` 不取 `cs.ownerUid`：后者在开会话的占位期间是空串，照它判 owner 自己会先看到一拍「所有者可改」再跳变。

### 4. 开着时输入框上方常驻一行警示

ADR-0231 的「已知代价」原话是「这是 owner 翻开关时接受的账，**开关旁边那句提示说的就是这个**」——那句常驻可见的 hint 是被记过账的缓解措施。把它塞进一枚 100px 药丸的 `title` 就是把它悄悄降级。

所以免审开着时，输入框上方常驻一行：说清「整个工作区」「不再问你」「连接器与新建智能体照旧要批」。关着不占这一行——那是今天的行为，不值得一条常驻警示。

**「读不到」那一格也要出声**：它恰恰可能正开着免审，闷着就等于把一个「可能正危险」的状态藏进一枚灰药丸的 `title` 里——正是这一节否掉的那条路。那一行说的是「此刻说不准会不会先问你」，不假装知道。

### 5. `WorkspaceSnapshot.sandboxApproval` 收窄成三态：`null` = 读不到

`sandbox_approval` 走的是**单独一条容错查询**（ADR-0231 决策 1，为了 0026 落地前整份快照还打得开）。原来查失败兜底成 `"ask"`，于是：

> 界面画一枚**关着**的开关 → 人以为每条命令都会问他；而 runtime 用 service key 走的是另一条查询，照旧按真值免批 → 一条都不问。界面与实际反着说，且一个字的提示都没有。

改成 `null` 之后这一格画「读不到」。**脏值仍然回 `"ask"`**（读到了但值不认识，往严的一边倒）——「读不到」与「值不认识」是两件事，`normalizeSandboxApproval` 因此从 `assembleSnapshot` 搬进了 `fetchSandboxApproval`。

读不到时 owner 仍然按得下**「改成逐条批」**，按不动放行：不知道现状也照样能踩刹车，而不知道现状就打开免审等于蒙着眼睛放行。与决策 6 是同一条纪律的第二处落点。

### 6. 一轮之内策略**只能收紧**（`jobSandboxPolicy` 单向复用）

原来是「每个 job 第一次撞门时查、这一轮复用」。开关坐在输入框那一行上之后，它的形状说的是「随时踩得到的刹车」（本地那颗的 `setApprovalMode` handler 就故意不查 `runningSessions`，注释原话「必须随时可踩」），而一轮之内踩下去毫无反应是这次搬家最不该带来的静默失败。

- 解析成 `auto` → 丢掉缓存，下次撞门重查。**关掉免审立刻生效。**
- 解析成**确认的** `ask` → 钉住这一轮（缓存留着）。与 ADR-0231 的「下一轮生效」逐字相同：一轮里问过一次的人，不会因为别人半路翻了开关而突然不再被问。
- **查询失败（问不出来）→ 也不钉。** 这一次按 `ask` 问人（往严的一边倒不变），但不能拿它当「确认是 ask」钉住整轮：改成每次撞门现查之后，一次网络抖动会把一个 `auto` 工作区剩下的每一把刀全部翻成要人批，而群里没有任何人看得出为什么突然开始弹卡。所以缓存的判据是「**确认**是 ask」，不是「这次的结果是 ask」。

  这条要成立，`daemon.ts` 那层的 `.catch(() => "ask")` 必须**拿掉**：吞掉之后「问不出来」与「库里确认是 ask」在 `sessionService` 那一层形状完全相同，上面那段区分两者的代码在真机接线下一次都跑不到（单测直接递函数进去所以照样绿——最难发现的那种漏接线）。`querySandboxApproval` 的头注本来就写着「查询失败原样抛，不在这里回落：回落成 ask 还是 auto 是调用方的决定」，只是装配那一行自己把它抵消了。

  问不出来时还要**在群里说一句**（每个 job 一次，同 `relayWaitAnnounced` 的去重）：免审开着的工作区里，输入框上方那行常驻警示写着「不会再问你」，而这一刻突然弹出一张卡——不出声的话，这个观测与「这开关坏了」一模一样，而真实原因只在 VPS 日志里。

同 ADR-0238「钱只能往下压不能往上抬」是同一条纪律的另一处落点：**没有任何输入能让这一轮比它开始时更松。**

### 7. store 那半：这颗开关一个字都不往共享错误格里写

`setWorkspaceSandboxApproval` 回 `FriendsResult<null>`，成功就地 patch 那一格。

- **失败原因不进 `workspaceGroupsError`，成功后的那次重拉也不碰它**：那一格是页脚共享的错误带，随便哪件不相干的成功都会把它清掉（ADR-0228 C2-I4 已经为 say/approve/stop 拆过这条线）。这颗开关现在坐在输入框上，翻一次就擦掉那格里躺着的东西是不能接受的——被擦掉的不只是「名单读不出来」（那条本来就该随重拉成功消失），还有 runtime 推来的 `status.notice`（限速 / 审批失效 / 事件过大，#819）、进房失败、归档失败，它们都不会被一次成功的 `workspaceList` 推翻。
- 成功后**先就地 patch 再补一次权威重拉**。只 patch 不重拉挡不住一种情形：写之前就在飞的那次 `workspaceList` 后到，拿一份不含这次改动的旧快照把整格盖回去——屏幕上那颗开关自己弹回旧位置而库里是新值。这颗开关说的是「会不会有人替你看每一条命令」，让它显示一个旧值不能只靠「下次刷新会自己好」。重拉失败**不把这次写报成失败**（写已经成功了）。这次重拉**不走 `refreshWorkspaceGroups()`**，自己拉一次只写 `workspaceGroups` 一格——那个 action 成功清空、失败写入 `workspaceGroupsError`，走它就等于翻一次开关擦一次页脚那格共享错误，与本节第一条自相矛盾。代价是翻一次开关一次 `workspaceList`（主进程侧 = 一次列表查询 + 每个工作区各自的 `fetchWorkspace`）——翻开关是一个刻意的、不常发生的动作，不是按键。

## 否决的备选

| 备选 | 为什么否 |
|---|---|
| 做成**会话级**（真的跟本地一样） | 容器与卷是工作区级的（ADR-0232），会话级的审批挡不住任何东西——同 ADR-0231 否掉「按 agent 配免审」的理由。且授权人会从 owner 放宽到任何成员（`create` 帧只要求在籍），钱却仍是 owner 的：那是权限扩大 |
| 「工作区级默认 + 会话级覆盖」 | 同上，加一层不解决隔离面的问题，只多一格要解释的设置 |
| 塞进 cs `config` 帧 / 进协议 | ADR-0231 已经否过一次：桌面写库、runtime 读库这条路走得通，不值得让桌面与 VPS 一起发版 |
| 逐字复用 `BypassToggle`（同名同形） | 四点差别（作用域/覆盖面/谁能改/持久化）全被同一个名字盖住。共用药丸外形、不共用组件，两者并排住在 `BypassSwitch.tsx` 里，想合并的人先读到那四点 |
| 非 owner 干脆不画 | 那就没有人答得出「刚才为什么没弹卡」。危险状态对全群可见是故意的 |
| 设置页留一行**只读镜像** | 维护者说的是「删掉」。留着是另一个可以再谈的东西，不是这次的一部分——它的代价见「已知代价」第 1 条 |
| 把警示行做成 `title` | ADR-0231 明写那句常驻提示是这笔账的缓解措施，降级要有人明说 |
| 一轮之内 `auto` 也钉住（不改 runtime） | 那就是把开关画成刹车、踩下去没反应。判据见决策 6 |
| 查询失败也钉住（省一次重试） | 一次抖动把 `auto` 工作区剩下的每一把刀翻成要人批，群里看不出原因。判据是「确认是 ask」不是「这次的结果是 ask」 |
| 失败继续在 `daemon` 那层吞成 `"ask"` | 吞掉之后上面那条区分「问不出来 / 确认是 ask」的代码在真机接线下一次都跑不到，而单测照样绿 |
| 问不出来时只写 VPS 日志、群里不说 | 那条常驻警示此刻正写着「不会再问你」，而卡弹了出来。不出声 = 与「这开关坏了」不可区分 |
| 读不到时干脆什么都不画 / 只留一枚灰药丸 | 那一格恰恰可能正开着免审。危险状态不出声就是藏起来 |
| 读不到时也让 owner 打开免审 | 不知道现状就放行 = 蒙着眼睛。只留收紧那一个方向 |

## 已知代价

1. **没有活云会话的工作区，这一格摸不到也看不到**（ADR-0234 的判据在这个方向上的账）。不是死锁：组头那颗 ＋ 会开出开局卡（ADR-0218：它不建任何东西，得发出第一句话才真的建会话），而归档的云会话在设置页底部点进去也有这一行。真正够不着的只有「一条云会话都没建过的新工作区」，而那种工作区里也还没有任何东西在等审批。
2. **免审的工作区里每次真跑命令 / 写文件多一次单行主键查询**（决策 6 的代价）。只在撞门时发生，不撞门的 turn 一次都不查。
3. `workspaceGroups` 没有推送通道（只在进会话与本地写之后刷新）。别人在另一台机器上翻了开关，你这边这一格是陈旧的，直到你重进这条会话。作为设置页一行时这没什么，作为输入框旁边那个「我此刻是不是免批」的答案就是个短窗口的假话。同一族的残留：决策 7 那次重拉在写之后才起跑，**收窄**了「旧快照后到把开关盖回去」的窗口，没有消灭它——`workspaceGroups` 这一格没有序号，一次更早起跑、更晚回来的 `workspaceList` 仍然盖得掉。真修法是给那一格加个单调序号，属于另一条 issue。
7. 策略这一刻问不出来时，那一轮里会多弹一张本不该弹的卡（往严的一边，且群里有一句解释）。免审工作区里查询次数从「一轮一次」变成「一刀一次」，所以撞上抖动的机会也乘了刀数。
4. **自动放行那条 `approval_decision` 在云会话时间线上是藏起来的**（ADR-0235 ③：批准了的决定不画）。所以「这条命令是策略放的」这个事实只活在原始日志里。决策 4 那条常驻警示行是这次给它的补偿——它说的是「此刻整个工作区都不问」，不是逐条。逐条要画得再单列一类事件，留给后面。
5. 三态里的「读不到」在真机上一次都没出现过（决策 5 是照代码路径推的）。
6. 真机验收一条都没跑（见下）。

## 真机验收清单（UNVERIFIED）

1. owner 进一条云会话 → 输入框工具条上出现「沙箱内免审」药丸；翻开 → 药丸整枚染警示色、输入框上方多一行警示；@ 一只 agent 让它 `ls`：不弹卡、日志里 `approval_decision.reason` 是「工作区设置：沙箱内工具免审」。
2. 同一条 turn 里让 agent 连跑两条命令，第一条跑完之后**当场关掉**开关 → 第二条弹卡（决策 6 的正面）。反过来（`ask` 中途打开）→ 这一轮照旧弹卡，下一轮才免。
3. 非 owner 进同一条会话：看得见「沙箱内免审 开（所有者可改）」与那条警示行，没有开关。
4. 工作区设置的「智能体」tab 里没有那一行了。
5. 断网 / 把 `sandbox_approval` 列改名，重进会话 → 药丸写「读不到」，不是一枚关着的开关。

## 推翻它的前提

- 如果云会话改成**每条会话一个容器**（今天是每工作区一个，ADR-0232），决策 1 的地基就没了，会话级免审立刻变成一个说得通的设计。
- 如果维护者认为「没有活会话就摸不到」是真痛点，正解是在设置页补一行**只读镜像**（可写的地方仍然只有一处），而不是把开关搬回去——两处可写就是两个事实来源。
