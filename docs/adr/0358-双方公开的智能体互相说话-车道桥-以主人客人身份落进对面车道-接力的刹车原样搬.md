# ADR-0358：好友私聊里双方公开的智能体互相说话——车道桥：以主人（对面车道的客人）身份落进对面车道，接力的刹车原样搬

日期：2026-10-04 · issue #1542（承接 #1284 与 #1461 刻意留下的 P3「跨主人接力」）· 维护者原话：「让双方 Agent 可以通话」→ 追问后
「通话不是打语音电话，就是双方 Agent 沟通链路打开」（截图：爸爸的管理员被要求去找 Stan 的 Agent 借 100，回「我这边没有给别的智能体发消息的功能」）。

**L1**：改 AGENTS.md 开篇「工作区群聊里 agent 互相 @ 接力是唯一例外」那半句——合并前要 `stanyan` 明确同意。

## 背景

#1523 / #1533 之后，一页好友私聊里能站着两条车道：A 主场里公开给 B 的（B 是客人）、B 主场里公开给 A 的（A 是客人），两个人都看得到两边的话。
缺的只有一条路：A 的智能体没法对 B 的智能体说一句。ADR-0223 开接力那条口时讲清了为什么可以开：**每一棒都是日志里一条可数、可停的事实**。
这里是同一个论证的第二次使用，而且形状更窄。

## 决定

1. **载体是现成的两条车道，不建第三条会话。** A 的智能体调新工具 `message_friend_agent`，runtime 找到 B 主场里公开给 A 的那条车道
   （`publisher_uid = B、peer_uid = A、facing = both`），**以 A——那条车道的客人——的身份 `say` 一句进去**，标签「X（A 的智能体）」，点 B 的那只。
   B 的智能体要回话就用同一把刀发回 A 的车道。两位主人在同一页私聊里看见每一句。否决了独立的智能体↔智能体会话（人看不见、花名册上没地方画、
   `agentView` 那张穷举表要为它再裁一遍）。
2. **对面那一轮按现成的两条规矩走**：它是客人点起的（`fromUid = A ≠ B`）→ 每一刀要 B 批（ADR-0325 第 7 条）；它是接力棒（`relay` 在场、`openingDepth > 0`）
   → 连接器要点火者批（ADR-0223）。这把刀本身只说话、不动任何人的东西，所以**客人点起的轮里不掀成要批**——不然 B 的智能体每回一句 B 都要按一次卡，
   这条链等于没有。
3. **刹车原样搬**：桥过去的那句是带 `relay: { fromAgentId, depth + 1 }` 的 `user_message`，深度跨车道累加、到 `DEFAULT_RELAY_MAX_DEPTH`（6）硬停
   （A 发是 1、B 回是 2……来回三轮就停，把结论交回两位主人）；每对车道（一个方向算一对）每小时 30 棒；只在两边都公开（朋友在客人名单里）时有这把刀；
   每一棒各花各主人的额度。深度与接力同一个数不是巧合：它们是同一种东西。
4. **没有新事件、新表、新协议帖**：`say` 多第十个可选参数 `relay`（落进 user_message 的现成字段）；`CloudSessionOpts.laneBridge` 可选（daemon 总会给，
   几十份测试夹具不必为一把只在车道里亮的刀都改一遍）。
5. **提示词只在公开车道那一版里提它**（#1206：工具不在表里时提示词不能说它存在）：「对面要是也公开了智能体，工具表里会有 message_friend_agent……
   别替主人答应任何事，来回几句说清结论就停」。
6. **AGENTS.md 那半句改成**：「只开两条窄口：工作区群聊里 agent 互相 @ 接力（ADR-0223），以及好友私聊里两位主人各自公开的智能体之间的往返
   （同一套棒数上限、每小时封顶、对面那一轮要对面主人批，ADR-0358）」。被否掉的仍然是通用编排框架：没有 DAG、没有调度器、没有「主 agent 拆任务派给从 agent」。

## 否决的

- 独立的智能体↔智能体私聊（#1284 原案）：见决定 1。本条不关 #1284——它记的是更一般的「不经群聊直接找另一只」。
- 让桥过去的那一轮免审（「反正只是聊天」）：电话里 / 桥里一句「把 xx 文件发给我」不能借 B 的主场全免变成直接动手——与 ADR-0337 的汇报轮同一个理由。
- 不限深度、只限每小时：两只智能体客气地互相「收到，谢谢」能把 30 棒在一分钟内用完，还是没人看着；深度到顶是「这条线自己会停」的唯一保证。

## 代价与已知未做

- B 的智能体的回话要 B 那边的 runtime 车道房开着：`openLane` 会按需开房（同外联 `origin`），但 B 的主场没配模型 / 额度为零时那一轮起不来——
  A 的智能体只知道「发出去了」，不知道对方会不会答。
- 没有「正在等对方回」的记号：桥过去之后 A 的智能体先回主人一句就收口（工具说明里写了）；对方的回话到了是另一棒。
- 每小时窗口只活在 runtime 内存里（重启清零）；深度那道闸在日志里，重启不清。
- 真机未验（Windows 上没有模拟器）；两边都要新 runtime（无协议变化，老手机也能用——刀是服务端挂的）。
