# 0135 打包为项目走事件标记 + 越界能力，不改旧会话

日期：2026-08-26 ｜ 状态：已定 ｜ 关联：#559、PR（任务/项目切换器）、ADR-0035（能力注入方向）

## 背景

任务/项目分栏（#559 后续）想让第一次用 AI 智能体的人从「任务」（内置 Default
工作区）被慢慢引向「项目」概念：当 Default 里的产出成形为一个项目时，agent
主动问用户要不要打包。这需要三件事：模型知道自己在 Default 工作区、有一把能
把文件搬出围栏的工具、旧对话的归属不被改写。

## 决定

1. **`session_created` 加可选字段 `workspaceKind?: "default"`**，建会话那一刻由
   主进程判定（workspace === 内置 Default 路径，且非子会话/SideChat）并落日志。
   引导段（`PACKAGE_NUDGE`）由投影按这个标记注入——**不现场读设置**：投影必须
   可从日志推导（硬规则），设置是可变的，重放会漂。旧日志没有此字段，投影
   逐字节不变（tests/session/deriveMessages.packageNudge.test.ts 钉住）。

2. **`package_project` 走新的可选 world 能力 `projects`**（`withProjects`，
   ADR-0035 的注入方向）：落点在文档区 `Mr Otto/<项目名>`，不在 workspace 内，
   `world.fs` 表达不了；工具层只认接口，文档区路径是组装根（index.ts）的事。
   只焊给内置 Default 工作区的主会话——项目会话用不上，子会话拿不到（同
   simulator 的收权立场）。这是**唯一一把故意越出围栏的工具**，两道闸：
   requiresApproval（审批卡列全参数）+ 实现侧路径校验（name 纯文件夹名、
   files 必须解析在 workspace 内、目标已存在即拒、整单校验完才动第一个文件，
   tests/main/projectPackager.test.ts 钉住）。

3. **打包不改旧会话**：日志 append-only，旧对话的 workspace 改不了也不该改——
   打包 = 文件搬进新项目文件夹 + 时间线上一张带「在新项目开会话」CTA 的卡。
   旧对话留在任务栏，新会话在项目栏开张。

## 被否掉的路

- **提示词现场读设置判断「在不在 Default」**：重放不确定，违反「投影可从日志
  推导」。
- **模型用 bash 自己 mkdir + mv 打包**：能走通（bash 出得了围栏、有审批），但
  UI 无从得知项目诞生，给不了「在新项目开会话」的出路；且每次打包的安全性
  取决于模型当次拼的命令，而不是一段被测试钉死的实现。
- **改旧会话的 workspace 让它「搬进项目」**：改写历史，直接违反硬规则。

## 什么前提垮了要重看

- 若将来出现「多工作区会话」或 Default 语义不再钉死在文档区固定路径，
  `workspaceKind` 的判定和 packager 的落点要一起重审。
- v2 SandboxWorld 下「文档区」不在容器里，`projects` 能力要换实现（接口不变）。
