# ADR-0287：订阅用户的灵动岛——三档切换器 + 额度页脚，删掉用量表

- 日期：2026-09-10
- Issue：#1229
- 设计稿：`docs/superpowers/specs/2026-09-10-island-subscription-redesign-design.md`（含三个方向的可交互 demo 所定的取舍）
- 状态：已落地（真机未跑）

## 病在哪

岛的展开态上半区此前是 `IslandDisplay` 的**二选一**：会话 fleet，或者「用量模式」那张表（`islandUsage`：每个模型 今天/7天/14天 的 token 数）。

那张表是 BYOK 时代的产物。ADR-0248 之后**订阅用户不许自带 key**，于是他看到的每一个 token 数都是一个他无法据此行动的数字：既不能换一款便宜的省钱（钱在月费里），也不能去关掉哪一台。而订阅用户真正会问的那句话——「我还剩多少、什么时候刷新」——岛上一个字都没有，尽管 ADR-0209 / 0239 / 0254 已经为这句话定过三遍口径。

第二处病：岛只有一份平铺的会话列表，而侧栏早在 ADR-0259 就分成了**任务 / 项目 / 团队**三档。同一批会话在两块屏幕上是两种组织方式，且岛上那份还看不见「有人在团队里 @ 了我」。

## 决策 1：额度是**页脚**，不是一个模式

展开态从上到下：**顶栏（logo + 三档切换器）→ 列表 → 详情 → 额度页脚**。页脚一行说完：`[档位徽章] 当主那扇窗 · 剩余% · 条 · 倒计时`。

维护者对着三个可交互方向点过之后选的这一个。另外两个方向与它们各自的死因：

- **页眉双表**（额度当第一眼，两扇窗并排，与账号页 `PlanQuotaSection` 同一套语言）：两扇窗都在场是它唯一比 A 强的地方，但它把「我有哪几只水獭在跑」挤到了下半屏——而人拉开岛八成正是为了看那个。**额度是每天问一两次的事，会话是每分钟。**
- **环境**（不给额度任何区块，只有一根 3px 的剩余细线 + 每行底下「这只吃掉多少」的细柱）：零纵向像素成本，还多回答了「是谁在吃」这个今天没人回答的问题；死在**不报数**——真到 90% 它也只是变红一根线，说不出「还剩 6.1%」。行底那根细柱另有 ADR-0239 点过的名：满格的底色会被读成「这一行选中了」。

**已知代价**：页脚只报**当主**那一扇（`bindingWindow`），另一扇要悬停 `title` 才知道——一行放不下两扇。

## 决策 2：同一条页脚，两个主语；`spend` 那一支报 token 不报钱

没有订阅的人不是「额度为 0」，他是**没有额度可言**（ADR-0255 已经把这两件事记成两条，`quotaAlert` 对 `windows === null` 一个像素都不画）。但把页脚整条抽掉，等于 BYOK 用户从此比改动前少一块东西——今天那张用量表就是他唯一能在岛上看到的账，而这次改动把它删了。

所以 `IslandRail` 是一个二选一的联合体：`quota`（有订阅）/ `spend`（没订阅但跑过计费调用）/ `null`（两者都不成立，整条不画，回到改动前的样子）。

**`spend` 报 token 不报钱**，与 demo 里给维护者看的措辞（`本周 $2.14`）不同，理由是数据：`store.billedUsage()` 回的 `BilledRow` 只有 `{ts, model, promptTokens, completionTokens, cachedTokens}`——**没有 route、没有 credit**。一个 `$` 要现查 `modelPricing` 拼出来，而那张表里 `UNPRICED` 是常态（ADR-0241：订阅制第三方压根没有按量价）。「混着算不出来就退回 token 总数」是 `CostPanel` 与 ADR-0239 已经定过两遍的规矩；在一条 420pt 的页脚上重新实现一遍「清一色才报得出合计」的分支判断，换来的是一个多数时候画不出来的 `$`。

判据从既有代码原样搬，不重新发明：`billing`/`me` 为 `null` 一个像素都不画（同 `quotaAlert` 判据①——这里连 `spend` 都不能退，那会对一个订阅用户报一条他根本不该看到的 BYOK 账）；`exhausted` 排在百分比前面且**现算**（过期的记号不算数）。`quotaTone` 的 `brand` 一档映射成 `neutral`：ADR-0239 决定 1。

## 决策 3：三档切换器住在 helper 里，不走线

`IslandDisplay` 那个二选一是**设置项**（落盘 `island.json`、设置页有一格、每次 `pushFleet` 带在线上）。三档切换器不是设置项，是**此刻在看哪一档**——与 `selectedSessionId`、`collapsedWorkspaces` 同一族的 helper 进程内存态（ADR-0063 已经为后两者定过这个位置）。

线上加的因此不是「当前哪一档」，而是**每一行属于哪一档**：`IslandAgent.kind` + `groupLabel`。缺席 = `"project"`，也就是改动前的行为。

三条随之而来的判断，每条都对着一个具体的坏结局：

- **`classifyIslandRow` 先判云会话**。它的 `workspace` 是一串合成路径，`workspaceLens` 顺着它找不到 `.git`、会回落成「就地当根」，于是 `projectRoot` 等于那串字符串本身——放到后面判就成了一个组名是 UUID 的「项目」。
- **团队名查不到时写「团队」，不回落成那串 UUID**：一个人读不懂的十六进制当组头，比一个笼统但读得懂的词更糟（同 ADR-0254「认不出的型号不画厂商标」的方向）。
- **Swift 侧「这一档要不要画组头」看 `tab` 不看 `groupLabel`**：JSON 的 `null` 与「字段缺席」在 Swift 里都是 `nil`，拿它当判据的话旧主进程推来的行会被当成「不分组」，而那时的行为是分组的。

另有两条落在视图上：**兜底链路收进当前这一档**（跨档兜底会让详情区画一条此刻列表上根本看不见的会话），**空态按档说话**（三档空掉的原因不一样，一句「主窗里先开会话」对团队档是错的指引）。

`CLOUD_WORKSPACE_PREFIX` 提成两处共用的常量：合成它的是 `cloudSessionFleetRow`，识别它的是分档。各写一份字面量的话，改了一半而没改另一半**不会报错**——只会让所有云会话安静地掉回「项目」档。

## 决策 4：未读 @ 由渲染层推给主进程

`workspace_mentions` 是**渲染层直连 Supabase** 拉的（#1064），团队名单同理住在渲染层的 store 里；主进程手里两样都没有。

选「渲染层推一笔」而不是「主进程自己再拉一份」。**代价明写：主窗没开时那两样是陈旧的，而岛可能还开着。** 可接受的理由是失败方向——陈旧只会让角标少亮或多亮一会儿，而主窗关着的时候人本来也不在看岛做决定；反过来要为一枚 5px 的点复制 #1064 的整条链路（一处查询 + 一份缓存 + 一条 realtime 通道）。

线上是 `IslandFleet.unreadMentions`，**缺席 = 不画，但 `0` 要上线**——「查到了，是零」和「还没查到」不是同一件事（同 ADR-0240 不许把 `null` 退成 Free）。角标**画点不画数**（那一格只有 40pt，量级留给下一层的组头/行角标），色取 `--brand` 不取 `--warn`：被 @ 不是「出事了」（ADR-0256）。

## 决策 5：两处改名，且**知道它是三处一起改**

`WINDOW_LABELS.h5`：`"5 小时窗"` → `"5h"`；`countdown()`：`"…后恢复"` → `"…后刷新"`，时长写成 `1h 38m`（天那一档跟着写 `4d`，不到一分钟写 `<1m`）。

两个都是**共用函数**，消费方是岛 / 账号页 / 上下文浮层。改了就是三处一起改，**这正是要的**：同一扇窗在两块屏幕上不能有两种叫法（ADR-0209 已经为「同一扇窗两个界面不能给出两个数」立过这条）。天那一档跟着改是因为不跟的话同一行会出现「4 天」与「1h 38m」两把尺子。

顺带修一处存量不一致：`BillingSettings.tsx` 把 `"5 小时窗"` 写死在 JSX 里、没走 `WINDOW_LABELS`——不改的话账号页会成为唯一一处还叫老名字的地方，而它恰恰是那个常量的主消费方。

**不在射程内**：`modelRoute.ts` 那三处 `「X 恢复」` 是 blocked 文案里的另一句话（说的是「这条路什么时候通」，不是「这扇窗什么时候刷新」）。

## 决策 6：额度那套窗口数学抬进 `src/shared/`

页脚由**主进程**算好推给 helper，而 `bindingWindow` / `remainingPercent` / `quotaTone` / `countdown` / `planBadge` / `fmtCtx` 此前住在 `renderer/src/lib/`。主进程 import 渲染层是反向依赖，仓库里一处都没有过。

搬进 `src/shared/quotaView.ts` 与 `src/shared/fmtTokens.ts`，纪律同 `shared/billing.ts`、`shared/remote/wire.ts`：改这里 = 所有消费方一起改。留在 `billingView.ts` 的是要读 `BillingSnapshotView` / `PlanInfo` 的那些判断（价目卡、`hostedModels`、`quotaAlert`）——它们回答的是「这个账号在哪一档」，不是「这扇窗的数字怎么写」。两边原样再导出，既有 import 点一个都没改。

## 决策 7：删掉 `IslandDisplay` / `islandUsage` 整条链

决策 1 之后那张表没有位置，决策 2 之后 BYOK 用户也不再需要它当唯一的账。留着它意味着「不分屏」这条口径只兑现了一半。

删除面：`shared/islandUsage.ts`、`IslandDisplay`、`IslandSettings`、`main/islandSettingsStore.ts`（连同 `userData/island.json` 这个落点）、`IslandFleet.display` / `.usage`、`getIslandSettings` / `setIslandSettings` 两条通道、设置页「外观 → 灵动岛」那一格、Swift 的 `Display` / `UsageRow` / 用量表视图 / 厂商 logo 查找、`Resources/providers/` 那 140K 图片。

**删测试的动机（ADR-0020 要求写出来）**：`tests/shared/islandUsage.test.ts` 与 `tests/main/islandSettingsStore.test.ts` 覆盖的产品代码在**同一个 PR 里一起删了**，不是为了让门禁变绿而删。

`trimForMobile` 对四个新字段**显式表态：一个都不出机器**——`rail` 是账单投影、`unreadMentions` 是团队未读计数，手机端的职责是「看 + 审批」（ADR-0094 的范围）；`kind`/`groupLabel` 是桌面岛顶栏三档的分组用料，同 `projectRoot`/`branch` 的理由。

## 已知代价 / 未做

1. **真机一次没跑过**。`native/MrOttoIsland/Tests` 只有 Codable 往返，顶栏与页脚的版式没有自动化测试——同 ADR-0236 第 1 条，几何不写成断言。
2. 主窗没开时岛上的未读数与团队名是陈旧的（决策 4）。
3. `spend` 那一支不报钱（决策 2）。
4. 岛上的三档**不与侧栏那一档联动**（各看各的）——两处回答的问题不同：侧栏答「我现在要进哪条」，岛答「我这会儿盯哪一批」。
5. 存量用户的 `userData/island.json` 不迁移也不清理——它就此成为一个没人读的文件。
6. 「团队」那一档只画得出**此刻 join 着的那一条**云会话（`cloudSessionFleetRow` 的既有天花板：云会话从不 `store.append`，fleet 里只有活着的那条）。这一档因此多数时候只有一行或空着，与侧栏那一栏列出全部云会话不同。
