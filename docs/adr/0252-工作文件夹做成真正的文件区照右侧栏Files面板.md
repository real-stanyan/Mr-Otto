# ADR-0252：工作区「文件」tab 做成真正的文件区——照右侧栏那个 Files 面板

- 状态：已接受
- 日期：2026-09-07
- 关联：#1066 / 协议 11→12 / ADR-0251（这一页的重定义）/ ADR-0092（本机 Files 面板）/ ADR-0134（先验前提）

## 背景

维护者：

> 可以参考右侧栏的"文件"功能，把这里作为工作区的文件区。

ADR-0251 把这一页从「仓库」重定义成「文件」，但浏览能力只做到最低限度：面包屑 + 一层清单 + 一个裸 `<pre>`。而右侧栏的 `FilesView`（ADR-0092）才是这件事在本仓已经做完的样子——树、过滤、内容搜索、高亮预览、图标。

## 先验前提（ADR-0134）

「云端沙箱里能不能搜」这件事，本来很容易被写成「做不了：容器里没有 ripgrep」。ssh 上 VPS 跑了一次：

```
$ docker run --rm --entrypoint /bin/bash otto-sandbox -lc "command -v rg"
/usr/bin/rg                    # ripgrep 13.0.0
```

而且 `-w /work` 下的输出与本机面板逐字同形：

```
$ rg --files --no-ignore --hidden     →  a.txt / sub/b.md
$ rg --json -n -- hello               →  {"type":"match","data":{"path":{"text":"a.txt"},…
```

**所以这不是「长得像 Files 面板」，是判据可以共用同一份。**

## 决策

### 1. 搜索共用 `src/shared/files.ts` 的三个纯函数

`parseRgJson` / `matchesFilter` / `classifyRgError` 由 runtime 直接 import。两处各写一遍的话，「rg 退出码 1 是没匹配不是出错」「文件名过滤是子序列匹配」这两条规矩迟早分家——而分家的样子是「搜不出来」这种没人会报的 bug。

`CsWorkHit` 与 `FileHit` 结构相同但**各是各的类型**：后者住在 Files 面板那一层，收窄或扩宽它会把本机那条路一起打红。共用的是**判断**，不是类型。

### 2. 退出码必须单独带回来

脚本里 `rg` 的输出要过一次 `head -c` 截断，而管道之后 `$?` 是 `head` 的。不带退出码的话，**「rg 没装」（127）与「搜过了没有匹配」（1）产生的观测一模一样**——于是「rg 挂了」会被说成「仓里没有」。所以先落一个 `mktemp` 再 `head`，退出码写进表头。

`rc === 0` 在分类之前先择出去：`classifyRgError` 收的是一个**抛出来的错误**，成功那一路它从来没见过（本机是 try 里没抛就直接用 stdout），喂 0 进去会被判成 `search-error`。

### 3. 恒含被忽略与隐藏文件

`--no-ignore --hidden`，与本机 `filesService.search` 逐字相同的理由：树是全显的，搜索另设一套规矩会让「树里看得见、搜不出来」变成一个要解释的怪现象。一条规矩管两处。

### 4. 树一次只列一层

展开哪个目录才发一次 `files` 帧，不是开页面扫全树。折叠不清缓存，再展开不重发。同 FilesView。

「刷新」重拉的是**整棵树**（根 + 所有展开着的层），不是只刷根——不然「刷新过了」和「没刷」在屏幕上分不出来。

### 5. 三样搬不过来，且说清楚为什么

| 本机有 | 这一侧 | 原因 |
|---|---|---|
| 打开方式 / 在访达中显示 | 不做 | 文件在 VPS 的容器里，不在这台 Mac 上 |
| @引用到输入框 | 不做 | 这一页是抽屉里的设置页，没有 composer |
| 正文里「文件:行号」跳过来 | 不做 | 云会话时间线没接这条线 |

复制路径做了（跟这三条不同：它在这一侧完全成立）。

### 6. 「搜不成」不许说成「没有匹配」

`hits: []` 与 `ok: false` 是两回事，三处落地：runtime 抛错走 `ok:false`、桌面客户端拿到 `ok:true` 却没有 `hits` 当失败（不兜底成空数组）、渲染层把降级原因单独画一行红字。同 ADR-0243 的三态纪律，也同 ADR-0251 决策 8。

## 顺手修掉的一个真 bug（#1056 带进来的）

**`\0` 在普通模板串里是一个真的 NUL 字节，而 execve 的参数在 NUL 处截断。**

ADR-0251 那两段脚本是拼在普通模板串里的，于是：

- `find … -printf '%y\t%s\t%T@\t%f\0'` 的格式被截到 `%f` → 记录之间没有分隔符 → 解析器只看到一坨 → **每个目录都显示成空的**；
- `tr -d '\0'` 变成 `tr -d ''` → **二进制永远判不出来**，一张图会被当文本发回来。

两处都不报错。单测压根不看脚本字节，所以全绿；而协议 11 还没部署，所以真机上也还没人踩到。

修法是脚本一律走 `String.raw`。**保鲜期是一条断言**（`tests/runtime/workFilesScript.test.ts`）：built 出来的脚本里除了分隔命令的换行，不许有任何裸控制字符，反过来还钉住 `\0` / `\t` / `\n` 这三个转义序列必须在。判据是**脚本的字节**，不是「有没有调那个函数」——这正是上一版全绿的原因。

修完在真机上跑了五段脚本（真镜像、真容器）：`od -c` 看得到 `\0` 是真分隔符，`binary 64` 说明 `tr` 活了，两条 rg 路径的相对路径与 `parseRgJson` 逐字对上。

## 否决的路

| 路 | 为什么不 |
|---|---|
| 客户端在已加载的树上做过滤 | 只搜得到你展开过的那几层，长得却和本机那个全仓搜索一模一样——撒谎的搜索框 |
| 把 `query` 挂在 `files` 帧上当可选字段 | 搜索永远从根开始，`path` 与 `query` 必有一个是被忽略的；一个字段永远没用是下一个人要花时间才能确认的事 |
| 共用 `FileHit` 类型本身 | 那个类型住在 Files 面板那一层，改它会把本机那条路一起打红 |
| 容器里改用 `grep -rn` | 已验：镜像里就有 rg。用 grep 等于把 `parseRgJson` 那条共用路径主动放弃掉 |
| 把脚本字节的断言写成「调了 String.raw」 | 那是钉手法不是钉结果，换个写法（拼接、模板串加转义）照样正确却会翻红 |

## 已知代价

1. **预览上限 64 KB**（本机面板是 512 KB）：中继单帧 256 KiB 顶着。大文件只看得到开头。
2. **搜索没有分页**：名字模式 500 条、内容模式 200 条封顶，超了只截断不给「看剩下的」。
3. **`rg --files` 在大仓上是一次全量列举**（2 MiB 输出上限），每敲一次过滤都跑一遍——去抖 150 ms 之外没有别的节流。
4. **树没有虚拟滚动**：一个上万条目的目录会一次画完。
5. **没有实时刷新**：水獭新建的文件要手动点刷新才看得见。
6. 上面表里那三样（打开方式 / @引用 / 行号跳转）。
7. **搜索命中点开的是整份文件，不滚到那一行**：本机那条跳转依赖 `rehypeCodeLines` 的 `data-line` + 一次 `scrollIntoView`，这一侧没接。

## 验收（真机）

1. 「文件」tab 打开 → 树列得出根目录；点一个目录展开，再点收起，收起再展开不重新发请求（网络面板里看）。
2. 点一个 `.md` → 预览区渲染成 markdown；点一个 `.ts` → 高亮的代码块。
3. 过滤框输入 `menu` → 只剩名字里子序列命中的那几条；输入 `?hello` → 出现带行号和正文的命中，点一条能打开那个文件。
4. 一个没装 rg 的假想情形不用测，但**停掉 runtime 再搜** → 一行红字说明原因，**不是**「没有匹配」。
5. 一张图（`.png`）点开 → 「这是一个二进制文件（… KB）」，不是一屏乱码。**这一条是上面那个 NUL bug 的回归验收。**
6. 点「刷新」→ 展开着的那几层都重新拉了（在容器里 `touch` 一个新文件，刷新后它出现在那一层里）。
