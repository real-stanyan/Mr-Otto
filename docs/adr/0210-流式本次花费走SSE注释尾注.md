# ADR-0210：流式响应的「本次花费」走一行 SSE 注释尾注，托管段按 credit 记账

日期：2026-09-03
状态：已接受
相关：#895、#857、ADR-0176（托管优先）、ADR-0203（订阅制落地，本 ADR 消掉它「两处偏差」里的第二条）

## 背景

#857 给网关 2xx 加了 `x-otto-cost-micro`：这次调用实际结算了多少 credit。
客户端一路接到 `assistant_message.creditCostMicro`，`deriveUsage` 也按型号归并好了。

但**没有任何渲染层读它**，而且它在主路径上基本永远缺席：响应头在第一个字节之前
就发出去了，而流式的 settle 发生在流收尾那一刻——那时头早没了。主对话全走流式
（`onDelta` 在场就 `stream: true`），所以「本次花费」实际上算了不用。

## 决定

### 1. 流式那半：一行 SSE 注释，追在最后一帧之后

`SSE_COST_COMMENT = ": otto-cost-micro "`（`src/shared/billing.ts`，三端共用一份，
纪律同 `wire.ts`）。网关在 `tapSseUsage` 的 `flush` 里、上游全部帧（含 `data: [DONE]`）
之后 enqueue 一行 `: otto-cost-micro <micro>`。

**为什么是注释行而不是一个自造的 `data:` 帧**：SSE 注释行以 `:` 开头，合规的解析器
一律跳过——对任何 OpenAI 兼容客户端都是隐形的。换成 `data:` 帧就得赌对方的解析器
对不认识的 chunk 形状足够宽容，而那是它们没有义务做到的事（网关同时服务桌面、
云 runtime，将来还可能是别的东西）。

**只在 `flush` 那条路贴**：中断的两条路（上游出错 / 下游 cancel / signal abort）走的是
`cancel()`，那时 controller 已经不收新块了，客户端也不在读。

**尾注的字节不计进 `info.bytes`**：那个计数回答的是「上游的内容有没有出门」，是
「结算还是 release」的判据（ADR-0203 决定 17）。把自己贴的一行算进去，会让一次
零字节中断看起来像发生过内容传输。

数字与 `settle` 那一笔**同源**：流里挑得出 usage 就按 usage 算，挑不出就按预扣估算
（#855 定的规矩），两处都调 `costMicro`，不会出现「账上扣的和显示的不是一个数」。

### 2. 客户端只在托管路上认这行

`endpoint.route === "hosted"` 才把它记成 `creditCostMicro`（与非流式那支同一判据）。
direct 打的是用户自己的上游，那边冒出来的同名注释与我们的账本无关。

### 3. 花费面板：托管行按 credit 写，没记到才写「托管」

`CostPanel` 的托管行以前一律写「托管」两个字。现在：记到了写 credit，没记到仍写
「托管」——**不是破折号**。破折号说的是「查不到价」，「托管」说的是「这笔不按 $ 计，
只是它花了多少没落到日志里」。两种「不显示 $ 的理由」混成一件事，读者会把
「订阅覆盖」当成「价目缺失」。

什么时候会没记到：中断的流、旧日志、以及网关那侧还没升级的版本。缺席 ≠ 0。

### 4. 合计那个数：清一色且齐全才报得出来

两种计费口径不能相加，所以 `sessionTotal` 分三种：全 direct 且都有价 → `$`；
全 hosted 且**每一笔**都记到了 credit → credit；其余退回 token 总数。

这不是新规矩，是原来那条「只要有一款没价就整个退回 token」的同一条，只是分两个
币种各判一次——把已知的几笔加起来当「本会话花费」，是在报一个偏小的数，比不报更坏。

## 后果

- 网关吐的流多一行（约 30 字节），排在 `[DONE]` 之后；旧客户端看不见它。
- `tapSseUsage` 多一个可选的 `trailer` 形参，默认不贴——纯函数那一层没有变成
  「知道价格表」的东西，算钱仍在调用方。
- 云 runtime 走同一个 adapter，跟着一起拿到本次花费。
- ADR-0203「两处偏差」的第二条（本次花费不回显）与「已知未做」那一条同时消掉。

## 会被推翻的前提

- 有一天需要在流里回传更多结构化的账目信息（不止一个数）：那时注释行不够用，
  该改成一个带自有 `event:` 名的 SSE 事件——同样对合规解析器无害，但要三端一起改。
