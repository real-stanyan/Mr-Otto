# ADR-0328：桌面换成微信式布局——写代码那一半先藏起来

- 日期：2026-09-28
- 状态：已采纳
- 关联：#1386（桌面那一半；手机那一半是 PR #1389 / ADR-0323）；#1391（维护者拍板）；spec `docs/superpowers/specs/2026-09-28-wechat-desktop-design.md`；demo `.demo/wechat/desktop.src.html`
- 关系：ADR-0323 的桌面那一半，判据全部共用 `src/shared/wechatInbox.ts`；ADR-0325（朋友同群）在桌面落地。不推翻既有 ADR：旧界面一行不删，`OTTO_CODING=1` 时原样

## 背景

维护者（#1386）：「干脆就做成和 WeChat 一样的布局。取消掉像 Claude 这样的 coding part，只保留把 Agent 作为联系人聊天使用的功能。」手机那一半先合了。桌面那一半开工前问了三件事（#1391），回答是：写代码那一半**先藏起来**（不删代码，删另开一条）；朋友同群要（「otto 里的智能体都是在云电脑干活」——已由 ADR-0325 落地）；额度只按周（ADR-0324 已落地）。

桌面比手机多两件麻烦：一是写代码那一半（本机会话、Files、终端、灵动岛……）是这个 app 的来历，代码量是聊天那一半的好几倍，维护者自己和 e2e 都还在用；二是聊天那一半在桌面上已经有一套成熟的云会话主区（`CloudSessionPage`），审批、@、语音、窗口化、错误行的判据是一条条 issue 攒出来的。

## 决定

1. **开关是环境变量 `OTTO_CODING=1`**：主进程读（`src/main/uiMode.ts`），随 `boot()` 下发 `codingUi`；渲染层过了登录那道闸之后二选一——开着画原来的界面，关着（默认）只画 `WxApp`。藏的是**入口**不是能力：主进程照旧装配本机会话那一套。e2e 的 harness 默认带上它，维护者自己用 `OTTO_CODING=1 npm run dev`。
2. **聊天主区就是 `CloudSessionPage` 本体，加一档 `wx` 外观**：头部换成 render prop、输入框换成一块平的面板（表情 / @ / 免审批 / 发送）、时刻不再逐条写而是隔 5 分钟插一行（`needsTimeRow`，手机同一份）、群里别人的话上面写名字、头像 36px 圆角方块。朋友私聊走现有那条私信路，换同一张皮。
3. **列表、角标、已读游标、时间文案全用手机那一份 `wechatInbox`**；游标落 `localStorage`、按 uid 分键。渲染层自己那点编排（列表一行对应哪条聊天、实时推来的最后一句与列表那一份谁新、最近私信怎么并）放在 `src/renderer/src/lib/wxInbox.ts`，进 vitest。
4. **缺的数据补四条 IPC**：`workspaceCloudLasts`（0040 那三列）、`workspaceGuestChats`（0043，别人拉我进的群）、`friendsRecentMessages`（我收发过的最近 300 条私信）、`workspaceAgentClearOnboarding`（桌面「建一只」也照 ADR-0319 让它先开口；行落了、私聊没建成而人不建了时把「先开口」那一格清掉——手机 A2 那条 `createNewAgentFlow.abandon` 同一份）；`workspaceCloudList` 的类型收成 `CloudSessionRow[]`（`humans` 本来就带上来了）。**服务端一行不改、不进协议位、不跑库。**
5. **列表刷新：开机、聚焦、回到「聊天」、自己改了东西之后，外加窗口看得见时每分钟一次。** 与手机不同的这一条：桌面窗口一开一整天、一直聚焦着，「重新聚焦」一天可能一次都不来。一次是每个 workspace 两条小查询，窗口看不见时不打。
6. **朋友同群（ADR-0325）在桌面落地**：发起群聊 / 拉人可以勾朋友（`createGroupChat` / `updateGroupChat` 带 `humans`），别人拉我进的群列进来、客人那一侧拼快照（`assembleGuestChat`）。**主场群的审批卡只有群主批得了**（客人点起的那一轮每一刀都问群主），等谁批那一行写群主；团队群照旧「发起人或所有者」。
7. **「读不到免审批」那句警示只对团队会话说。** 主场一次都不查 `sandbox_approval`（ADR-0298 / 0325），客人那一侧拼出来的快照这一格恒为 null——照判就是对每个客人说一句假话。旧界面有同一个洞，一起修了（`tests/renderer/cloudSessionShell.test.tsx` 钉着）。
8. **「我」那一栏每一格是一个铺满主区的 `NavStack`。** 应用 / 记忆那两格是为团队设置的推入式导航写的，里面「添加主机」「编辑页」要 `useNav().push`，离了 `NavStack` 直接抛错——冒烟时点「应用」整页白屏就是这么发现的。`NavStack` 为此多两个可选开关：`dragBar`（导航条贴着窗口上沿，要能拖窗口）、`contentClassName`（正文收成居中一列，不然二级页的输入框被拉到一千像素宽）；抽屉里的用法一个字不变。二级页的返回写「应用」不写「连接器」（`WorkspaceConnectorsTab` 的 `backLabel`）。
9. **头像照微信是圆角方块**：像素脸画在一枚纸白圆盘上（ottoFace 不改），底下垫一块同色方块（`DISC_COLOR`），看上去就是一张方形的脸。群头像是九宫格（`gridLayout` 与手机共用）。

否决的：

- **现在就删掉写代码那一半**：维护者定的是先藏。删之前要先想清楚 e2e（大半用例跑的是本机会话）与维护者自己的用法怎么办，另开一条。
- **设置页里放一颗「开发者模式」开关**：这一版要的是界面上看不见那条路；开关摆进设置，入口只是换了个地方又回来了。要用的人只有维护者和 e2e，环境变量对他们零成本。
- **桌面另写一条微信时间线**：审批卡、@ 选人、语音、窗口化、错误行、名单变更那一行……每一格都有自己的一串 issue，第二份一定会分家。代价是 `CloudSessionPage` 里两套外观并存。
- **只靠聚焦刷新（照手机）**：见决定 5。

## 后果

- 默认启动的人看不到本机会话、Files、终端、灵动岛入口；主进程那一套照常装配（岛、托盘、后台任务都还在，只是没人从界面上起本机会话）。
- `CloudSessionPage` 里两套外观并存，改输入框、头部要两边都看。
- 智能体资料页的「说话的声音」只读（ADR-0322 决定 6）；型号与应用在「更多设置」里（原来那扇抽屉）。
- 团队的成员管理仍在原来的团队设置页（聊天信息抽屉里一颗「团队设置」进去）。
- 未读只有朋友私聊是条数，其余一枚点（同 ADR-0323 决定 4）；已读游标不跨设备。
- 真机一次没跑过：登录后的流程要人输密码。冒烟是临时根组件 + 假桥 + 假数据（浅色、深色，1280 / 740 / 540 宽），不进仓库。
- 要发一次桌面版才到用户手上；服务端不用部署。
