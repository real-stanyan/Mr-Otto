# ADR-0202：模型 key 跟着工作区走，runtime 不持有任何 key

状态：已接受
日期：2026-09-01
关联：#844；**推翻 ADR-0199 决策⑥**（「过渡期模型 key：维护者一份 key 配进 VPS env」）；
三期计费的前置形态见 #826

## 被推翻的那条

ADR-0199 决策⑥ 写的是：过渡期由维护者把一份模型 key 配进 VPS 的 `MODEL_API_KEY`，
额度强制执行留到三期。二期落地那天这条还没有实际后果——runtime 从未部署过，那把 key
从未存在过。真要按它部署的那一刻，问题才显形：

`MODEL_API_KEY` 是**进程级**的，一台 VPS 一份，所有工作区的所有 turn 都烧它。ADR-0201
第二节那三个令牌桶拦的是脚本，不是账单——它们挡得住「一分钟刷一百次」，挡不住「二十个人
各自正常用一整天」。在计费（#826）落地之前，这把 key 是一个**没有上限**的口子，而且
它的持有者不是使用者。

维护者的裁定：现阶段让创建者自己提供 API key，后面走用户的订阅用量。

## 这一版的形状

模型配置**跟着工作区走**，由 owner 配，和仓库配置走同一条既有的路——同一个 `config` 帧、
同一道 owner-only 校验、同一份 0600 的 `workspace-config.json`（那里本来就躺着仓库 PAT，
同样是别人的凭据，同样不进 Supabase）。

四个判断：

1. **runtime 不再持有任何模型 key，也不做 env 兜底。** `config.ts` 的 `REQUIRED_KEYS`
   从 9 个减到 6 个，`RuntimeConfig` 里连 `modelApiKey` 这个字段都没有了。
   **兜底是这条 ADR 最重要的那个"不做"**：留一个 env 默认值，语义就变成「忘了配的工作区
   默默烧维护者的钱」——正是要消灭的东西，而且它的失败模式是静默的（没人会收到通知，
   只有账单会）。`tests/runtime/config.test.ts` 里那条「配置对象里没有任何 model 字段」
   的断言就是为这件事留的一份会红的证据。

2. **每次 `chat()` 现读一次配置**，不在开会话房那一刻把 adapter 定死。会话房是长命的
   （daemon 重启才重开），定死意味着 owner 改完 key 要等重启才生效。构造 adapter 只是
   拼一个闭包，现读的代价可以忽略。

3. **没配 = 抛一条给人看的错**，不是回落、也不是静默卡住。这条错走 engine 的 turn 失败
   路径落进日志，群里每个人都看得见，并且直接写了怎么修（「所有者打开工作区 → 云会话 →
   右上角」）。同 ADR-0201 第二节那条纪律：拒绝要看得见。

4. **config 帧的两组字段各自可选**（`repoUrl` 从必填变成可选）。模型和仓库是两件独立的
   事——只改模型时把仓库地址也发过去，等于替 owner 声明「那一格我也确认是这个值」，而
   他可能根本没看那一格。服务端按 patch 语义合并：这一帧没提到的那一组原样保留。
   `apiKey` 的三态与 `pat` 完全同款（省略 = 不动 / `""` = 清除 / 非空 = 换新），理由也
   同款：密码框永远预填不了，"留空 = 清掉"会让"顺手改个型号"静默毁掉一把 key。

## 协议进位与发版

`CS_PROTOCOL_VERSION` 3 → 4（welcome/config_result 多一格 model，config 帧多一组字段）。
握手是精确相等，所以 **v1.1.5 的桌面连不上新 runtime**——这正是想要的：v1.1.5 没有配模型
的界面，让它连上去只会得到一条「turn 起不来」的死路。runtime 与桌面必须一起发版。

## 与三期的关系（为什么这不是白做）

三期（#826）是**平台统一 key + 用量计费**：用户买订阅，平台出 key。这一条是它之前的过渡
形态，把「谁付钱」从维护者挪到建工作区的人。挪的方式（每工作区一份配置 + 每次调用现读）
恰好是三期唯一要动的那一格——把 `adapterFor()` 里"读工作区配置"换成"读订阅额度 + 平台
key"，其余（读路径、UI、三态、owner-only）原样留着。

## 什么前提失效会推翻它

- 三期落地，平台开始出 key + 记账：那时这一格退化成「高级用户可以填自己的 key」的可选项，
  而不是唯一的路；
- 出现「一个工作区多个人分摊 key」的需求：现在的形状是一把 key 归 owner，改成分摊要
  重新想「谁的额度被扣」这个问题，不是加个字段能了事。
