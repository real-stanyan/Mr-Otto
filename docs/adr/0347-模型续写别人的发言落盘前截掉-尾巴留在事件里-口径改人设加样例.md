# ADR-0347 模型续写别人的发言落盘前截掉，尾巴留在事件里；云会话口径改成人设 + 口吻样例

- 原为 ADR-0345：合并前 re-fetch 发现 #1476 / #1473 已经把 0345、0346 用掉，按 ADR-0074 改到 max + 1
- 状态：已采纳（2026-10-04）
- Issue：#1483（维护者原话「改完智能体说话拟人化，反而说出来的话更加机械式了，说话要有活人感」）
- 前情：ADR-0266（#1132 第一轮）、#1448 第二轮、#1454 第三轮，三轮都是改 `PLAIN_TALK`

## 背景

2026-10-04 群 64997e68 的 seq 1132（deepseek-flash，思考开着，runtime 已经吃到 #1454 第三版口径）长这样：

```
@Stan Yan lane 里那 4 个提交现在工作树是干净的——之前 ADR-0337 那半截改动已经收进最后一个提交了，测试和类型检查都绿。推还是只卡一件事：……

我这边继续往下走 #1443 的实装（……），不等令牌。

[Otto产品经理]: 刚扫了一眼 #1444 那条复盘...

Hmm wait, the message ends with "[Otto产品经理]: …" — it's truncated? …（三百字英文思考）…

I'll finalize.@Stan Yan lane 里 4 个提交齐了，……
```

全在 `assistant_message.content` 里；`reasoning` 字段里另有它真正的思考。提示词和上下文里都没有「刚扫了一眼」——那一行是**模型编的**：它答完没停，接着把群聊转录「写了下去」，先替产品经理说了半句，再对着自己编的这半句思考，最后把答案重写一遍。同一个工作区近 300 条回复里只此一条，但一出就是整屏机器味，而且会被存成「最后一句」、被同伴那只读进上下文。

前半截（答案本身）每条都合规：一百来字、没有标签分段、有 @。合起来却是一张填好的表。三轮都在往 `PLAIN_TALK` 里加「别这样」，模型照单填表，填得越全越像表。

## 决定

### 一、续写别人的说话人行，落盘前机械地截（`src/shared/speakerLeak.ts`）

- **判据只有一条**：content 里某一行行首是「[群里真有的某个名字]: 」。方括号本身不是罪证（模型自己列的「[参考]:」留着），代码围栏里的不算（那是交付物里的字）。名字比对 NFKC + 去空白 + 小写（同 `safeSpeakerLabel` 判保留名那把尺子）。
- **开头是自己的名字只剥前缀**：那是把投影格式学了回来，不是在替别人说话。
- **名单从日志现算**（`speakerNamesOf`）：`agent_briefed` 的自己 + 名单、`chat_message.label`、`user_message` 正文的「[名字]: 」前缀，加系统旁白的保留名「系统」。只在配了 `agentId` 的 engine 上做——本机会话没有说话人行这回事，日志形状一个字节不变。
- **截掉的尾巴不丢**：`AssistantMessageEvent` 多一个可选字段 `trimmed`，原样放那一截。日志仍然说得清模型那一刻到底吐了什么；所有投影（模型上下文 / 气泡 / 最后一句 / 语音）只读 `content`。字段只加不改，旧日志照常重放。
- **预览过同一把尺子**：runtime 的累计快照（`deltaStream` 的 sink）也截，名单取此刻认得的人（`speakerLabels` + `specNames` + 「系统」）。不截的话客户端会先画出一行伪造的发言、答案落下来时又消失。

### 二、`PLAIN_TALK` 从禁令清单改成人设 + 口吻样例

四样替掉原来的七句规则（长度持平）：

1. 人设一句：在群里是个同事，不是客服也不是助手；像在微信群里跟同事聊天那样说话。
2. 用词跟着对方走——取代「群里的人来自各行各业」那个假前提（那个群全是开发和产品，对开发说「别提编号」只会让它绕着说）。
3. @ 只用来叫人：回刚跟你说话的人不用 @ 他（每条以「@Stan Yan」开头是机器味的头一条）。
4. 一组口吻样例代替对照例——内容是日常事（「那块我弄好了，你看一眼」「卡在小王那了，等他回」），不撞真实任务的词，照抄进别的群也不穿帮。

机制事实照留：空行 = 下一条气泡（`chatBubbles` 那一半不动）、纯文字、允许不回（#1454）。私聊版仍是对群版的替换：身份换成「对面这个人的同事」，@ 那一行整个不要，「只对一个人」不说。

## 为什么截在落盘前、而不是投影时

投影有七处（模型上下文、同伴视角、手机气泡终态与流式、桌面时间线、最后一句、语音），每处各截一遍是七份判据；engine 一处截 + 预览一处截，两处共用一个纯函数。代价是日志里的 `content` 不再逐字等于模型吐的字——所以才有 `trimmed`：事实没少，只是分了两格。

## 为什么不用 `stop` 序列

把「\n[Stan Yan]: 」这类前缀当 stop 序列发给模型，能在源头掐住。但 DeepSeek 思考模式下 stop 是否也作用于 reasoning 没验过——它的思考里本来就会复述「[Stan Yan]: 来人说话」，掐在那里就是把思考掐断；而且 OpenAI 方言最多 4 条，群里不止 4 个人。先用后处理，真机上再出就回头验 stop。

## 为什么不再加规则

三轮的真机证据：规则每加一条，模型就多合规一条，整体却越像表。第四轮改路的判据是维护者的观感，不是字数——所以这一版的验收也只能是真机再看一轮（部署后拿同一个群录）。推翻条件：换成人设之后回复**变长**或开始编不存在的「同事日常」，就把样例收掉、只留人设与机制事实。

## 代价与边界

- 一句合法的引用「[Stan Yan]: 这句我没看懂」若恰好顶格写在行首会被截掉。口径本身就说别复述别人，接受。
- 预览的名单取自 `speakerLabels`（只认说过话的人）——一个还没发过言的成员被模型编了一句，预览可能漏截，终态照截。
- 文字层的病（内容机械）与机制层的病（该停没停）是两件事，这条 ADR 各修一处；哪一处以后要回退，另一处不受影响。
