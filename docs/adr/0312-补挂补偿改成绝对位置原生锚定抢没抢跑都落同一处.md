# ADR-0312：补挂补偿改成绝对位置——原生锚定抢没抢跑，都落同一处

- 状态：已采纳
- 日期：2026-09-21
- 关联：#1262（#1259 真机排查时撞见，单开）、ADR-0285 决定 2（时间线窗口）、ADR-0292（会话地图 / reveal 桥）

## 背景

`WindowedMessages` 的补挂补偿（ADR-0285 决定 2）原来是这么写的：

```ts
const delta = el.offsetTop - firstTopRef.current;
viewport.scrollTo({ top: viewport.scrollTop + delta, behavior: "instant" });
```

一个**相对量**：读此刻的 `scrollTop`，加上 prepend 的净增高。它成立的前提是「读到这一行时，
还没有别人动过 `scrollTop`」。那条前提当时写在代码注释里，措辞是「只用一层 —— 原生的
scroll anchoring 管的是 content-visibility 的延迟尺寸修正，这里管的是 prepend 这个结构性
变化，量的对象不同，不叠两层」。

**那句话是错的。**

## 量出来的

不改产品代码，在真 app 里把 `Element.prototype.scrollTo` 包一层，记下每次调用的目标、
调用那一刻的 `scrollTop`、以及补挂之前视口停在哪儿（用 scroll 事件跟）。
Electron 43 / Chromium，2026-09-21，一条 60 轮的会话：

**reveal 桥那条路**（会话地图点窗口外的一轮），先用真滚轮离开底部：

| 量 | 值 |
|---|---|
| 补挂前 `scrollTop` | 4435.5 |
| 补挂前 `scrollHeight` / `clientHeight` | 6289 / 816 |
| 净增高 | 13888 |
| **补偿跑的那一刻 `scrollTop`** | **18323.5** |
| 补偿算出的目标 | 32211.5（被夹到底部 19361.5） |

`18323.5 = 4435.5 + 13888` —— **原生锚定确实先挪了整整一个 delta**，补偿再加一次就是双倍。

**同一组数还排除了另一个嫌疑人。** #1262 的上一班列了三个候选，头一个是 assistant-ui 视口
自己的 `autoScroll`（`turnAnchor="bottom"`）。这一次故意先离开底部再点，就是为了把两者分开：
autoScroll 若是凶手，该把视口拽到 `scrollHeight − clientHeight = 19361`，而不是 18323.5。
（**贴着底时两者预测同一个数**，所以第一次测量分不开 —— 那一版的数据在 #1262 的评论里。）

**哨兵那条路**：锚点是哨兵自己，在插入点上方，原生一格都不挪，`at` 就等于补挂前那个值。

> 上一班在**最小页面**上四种变体都没复现出这一步，因此结论是「谁挪的还没确定，别照着修」。
> 那个判断在当时是对的：条件不足以重现 ≠ 观测是假的。搬进真 app 就出来了。
> 一般教训与 ADR-0134 同族：**把「我复现不出来」写成「它不会发生」，下一班会拿它当既定前提。**

## 决定

补偿的目标从相对量换成**绝对位置**：

```ts
viewport.scrollTo({ top: lastTopRef.current + delta, behavior: "instant" });
```

`lastTopRef` = 补挂之前视口停在哪儿，由视口上一个 passive 的 `scroll` 监听维护。

**为什么这个值拿得到、且不会被污染**：`scroll` 事件在「更新渲染」那一步派发，晚于本次提交的
layout effect，所以原生锚定自己挪出来的那一下不会在补偿之前写进这一格。

**为什么这是正解而不是补丁**：它是**幂等**的 —— 原生挪过（reveal 桥）还是没挪过（哨兵），
落点都是同一个绝对位置。所以不需要在运行时判断「它挪了没有」，也就不会在判断错的那条路上
自己制造一次偏移（那正是 #1262 上一班担心的失败形态）。

## 被否决的

- **在补偿里现读 `scrollTop` 再判断「它是不是已经挪过 delta」**：那是把一个环境行为编进产品
  逻辑，Chromium 换个版本就静默失效；而且「挪了半个 delta」这种中间态无从判起。
- **给视口加 `overflow-anchor: none`**：能让原生彻底不插手，但它同时关掉了流式增长、图片
  加载这些地方本来受益的锚定。代价远大于收益。
- **不补偿，全交给原生**：哨兵那条路原生不动手（锚点在插入点上方），交出去就是不补偿。

## 代价

1. **多一个 passive 的 `scroll` 监听**（只在 `hiddenCount > 0` 时挂）。
2. **这条的保鲜期在 e2e 里，而 e2e 不在门禁里**（ADR-0138）。`tests/e2e/windowReveal.e2e.ts`
   两条用例各守一条路，且**各自把自己的前提也写成断言**：reveal 那条断言原生确实抢跑、
   哨兵那条断言原生确实没抢。哪天 Chromium 变了，红的是前提那一条 —— 修法会被叫回来重判，
   而不是默默变成一次没人再理解的冗余。
3. **真机（人手）一次没跑过**：上面每一个数都是 Playwright 驱动真 Electron 量的，不是人看的。
