# ADR-0108: 「跟随主会话」的型号继承要真的继承，内置那三份改为显式钉档

日期：2026-08-25
状态：已接受
相关：issue #447、ADR-0047（子 agent 是一次独立会话）、ADR-0051（内置子智能体住代码里）

## 背景

设置页里子智能体的型号选择器，不 pin 时显示「跟随主会话」。它不跟随。

`subagentRunner.ts` 只写了单向那一半：

```ts
if (def.model) child.switchModel(def.model);
```

`else` 不存在。子 agent 是 `createAgent` 新建、无 `resumeLog`，模型落到日志投影的兜底分支
`process.env["OTTER_MODEL"] ?? DEFAULT_MODEL`。于是父会话开着贵档、派出去的子会话静默用
`deepseek-v4-flash` 干活，界面全程写着「跟随主会话」。

三处文档把「继承」当既成事实：`SubagentDef.model` 的注释（"缺席 = 跟主会话当前模型"）、
设置页文案、以及 `parent()` 里那个从接线到 issue #447 为止**没有任何一处读过**的
`model: string` 字段。死字段是这个洞的化石：写它的人以为自己接通了。

没有测试钉过未 pin 的行为——所以它能活这么久。

## 决定

### 1. 继承变真

```ts
child.switchModel(def.model ?? parent.model);
```

选它而不是「改文案承认现状」（issue #447 的 B 方案）的理由：现状是**静默降级**，用户从没
选过 flash；而「跟随主会话」这个选项如果不兑现，用户就没有任何办法表达"用我此刻这一档"，
而那正是他们以为自己一直在用的东西。三处文档说继承、一处代码不继承，改代码那一处比改
三处文档更接近本意。

### 2. 内置那三份显式钉到 `DEFAULT_MODEL`

`general-purpose` / `Explore` / `memory-reviewer` 原本都不写 `model`，靠兜底默认落到便宜档。
决定 1 之后「不写 model」的含义变了——变成"跟着父会话走"。不钉的话，用户在贵档会话里
随手派个 Explore 横扫目录，账单量级就变了，而他从没为这件事做过决定。

钉上之后，数值和改动前逐字节一样，但性质不同：**"便宜"从没人做过的选择，变成写出来的选择**。
想让某一份跟着会话走，materialize 成自己那份、清掉型号即可——那条路是显式的
（同 ADR-0051 的规则）。

### 3. 继承会在子日志落一条 `model_changed`，这是要的

父不在默认档时，`switchModel` 落一条 `model_changed`（seq 通常是 1，在 `subagent_briefed`
之前）。不能为了日志好看而跳过它：子会话的型号必须能从**它自己的日志**推导出来
（硬规则：投影必须可从日志推导），否则重放出来的型号会和 `subagent_briefed.model`
自相矛盾。`resumeChild.ts` 早就为这条让过路——它按 `.find()` 取 briefed 而不是按位置取，
注释里写着"`model_changed` 可能占掉 seq 1"。两条顺序测试相应改成滤掉这条事件再断言。

## 代价与边界

- **lane 不跟着继承**：`switchModel(model, lane = "auto")`，而 `parent()` 拿不到父的 lane
  （agent 没有暴露它的 getter）。子会话一律 `auto`（老规矩：自带 key 优先，ADR-0020/0045）。
  与改动前对 pin 了型号那条路的行为一致，不新增不一致。真要继承 lane，得先给 agent 加
  getter——等有人真被这条咬到再说。
- **贵档会话派活变贵**：这是决定 1 的正面效果，不是副作用。用户自己选的档，派出去的活
  用同一档；不想要就 pin 那份 subagent 的型号，或者把会话切回便宜档。
- 已经 materialize 过内置定义的用户不受决定 2 影响——他们那份是磁盘文件，盖住内置的。

## 被否决的方案

- **改文案承认现状**（选项改成「默认型号（deepseek-v4-flash）」）：最便宜、零行为变更，
  但等于删掉"用我此刻这一档"这个能力，而这个能力用户以为自己一直有。
- **给 `createAgent` 加 `model` 入参**，在构造时定死、不落 `model_changed`：省一条事件，
  代价是型号从此有两条来源（入参 vs 日志投影），而"当前模型 = 最后一条 model_changed"
  是现在唯一的口径。为省一条事件牺牲单一口径不划算。
