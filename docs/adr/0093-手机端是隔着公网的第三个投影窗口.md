# ADR-0093: 手机端是隔着公网的第三个投影窗口

日期：2026-08-25
状态：已接受
关联：spec `docs/superpowers/specs/2026-08-25-mobile-remote-control-design.md`；plan `docs/superpowers/plans/2026-08-25-remote-relay-core.md`；ADR-0059（否决"投影的投影"）、ADR-0061 / ADR-0063（灵动岛原生 helper 与多会话 fleet）、AGENTS.md 硬规则（append-only 日志是唯一事实来源）

## 背景

需求是「人不在电脑前时，能看见 Otto 在干什么，并且能远程点同意/拒绝」。
最自然的读法是「做一个手机 app」，而那个读法会立刻把整条 `ShellBridge`（998 行、
建会话/改设置/文件树/切模型/管 MCP）推上公网。

但仓库里已经有一个**隔着进程边界的状态消费者**：灵动岛（`src/main/islandBridge.ts`）。
它定义过一套完整的契约——主进程把 `IslandFleet` 投影推出去，对面回四个命令。
手机与它的唯一差别是那条管子有多长。

## 决定

1. **手机是第三个投影窗口，不是新子系统。** `src/main/remoteBridge.ts` 与
   `islandBridge.ts` **平级**：同一个投影源（`islandProjection.ts` 的 `reduceIsland` /
   `IslandFleet`）、同一套"状态下行、命令上行"的形状，只把传输从 stdio 管道换成
   隔着公网的加密 SSE + POST。桌面持**出站**长连接，用户机器不开任何入站端口。
2. **不做"投影的投影"**（沿用 ADR-0059）。桌面推的是 `IslandFleet` / `deriveMessages`
   这两层已定义的投影，不是渲染层的 React 状态。手机自己渲染。
3. **两种帧，timeline 走订阅。** `fleet` 帧是 `IslandFleet` 原样（几百字节，每次投影变化就推）；
   `timeline` 帧是单会话的 `deriveMessages` 投影经 `trimForMobile` 裁剪，
   **仅在手机发过 `watch(sessionId)` 之后才推**，切走发 `unwatch`。
   分两种是因为 `IslandAgent` 里根本没有对话内容，而用户要判断该不该同意
   `rm -rf build/`，必须看见 Otto 前面说了什么；订阅式是因为蜂窝网上"不订阅就零流量"
   是硬要求，而 stdio 管道那边零成本全推、根本不需要这个词。
4. **命令面五个词**：`approve` / `deny` / `send` / `watch` / `unwatch`，
   用 `decodeCommand` 同款的逐字段校验器，认不出来的**整条丢弃**而不是剥掉多余字段
   （剥字段等于替攻击者做归一化）。刻意不含岛的 `focusSession`——
   "看哪个会话"在手机上是本地视图状态，不该变成一条能远程操纵桌面窗口的命令。
5. **手机永不产生事实。** 手机上的一切操作都是**命令**，回到桌面变成
   `approval_decision` 事件落盘，再投影回两端。这是 AGENTS.md 硬规则
   「先落盘再喂模型」在公网这一侧的直接后果。
6. **不拆 monorepo。** `src/shared/*` 实测零 node builtin、零 electron，
   `src/session/` 的投影函数同样纯，v1 直接跨目录 import（metro `watchFolders` 指到仓库根）。
   这一条被 `tests/architecture.test.ts` 的第 5、6 条断言钉住：把"碰巧是纯的"变成会红的规则。

## 后果

- 手机端的能力上限由 `IslandFleet` 的形状决定，不由 UI 想做什么决定。要多显示一个字段，
  得先问"岛要不要"。这是约束，也是这条路线的全部价值。
- 整条 `ShellBridge` 不上公网：建会话、改设置、切模型、管 MCP 一个都不在手机上。
- 岛与手机共享投影源，意味着 `IslandFleet` 的任何改动同时影响两端 ——
  这是**要的**耦合（分仓 = 保证漂移），也是把 `mobile/` 放在本仓、
  与 `native/MrOttoIsland/` 平级的理由。
- 首发 iOS。Android 的推送机制（FCM data message + headless JS）与 NSE 完全不同，另设计。

## 会推翻它的前提

- **若 `IslandFleet` 将来要装对话内容**：两种帧的分工失效，`fleet` 帧也得进裁剪路径，
  订阅式就不再只管 timeline 那一路。
- **若手机端范围扩到"开新会话 / 改设置"**：窄命令面不再成立。那时要重议的不只是接口边界——
  远程唤起一个 agent loop 的风险面完全是另一回事，不能靠"再加两个命令词"滑过去。
- **若岛与手机的投影需求分叉**（例如岛要更省、手机要更全）：共用 `reduceIsland` 变成负担，
  届时该拆的是投影函数，不是重新引入"投影的投影"。
