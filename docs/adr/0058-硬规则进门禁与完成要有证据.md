# ADR-0058 硬规则进门禁,完成要有证据

状态:已接受(2026-08-22)
关联:Issue #172、#170;Harness Engineering 课程 https://walkinglabs.github.io/learn-harness-engineering/en/

## 背景

对照 Harness Engineering 十四讲审计本仓。协议层(Gearbox:仓库即记忆 / ADR / handoff /
清场 / 门禁 == CI)已覆盖大半,三处缺口:

1. AGENTS.md 的 Hard rules 只是文字。「工具不直接 import fs」「渲染层不碰 Node」
   「MCP SDK 只在 mcpClient.ts」三条,至今守住了,但没有任何东西在盯——守住靠的是
   每班自觉,不是机制。
2. 「做完」没有证据。Issue 只写做什么,不写怎么证明做完了;四条「真机验收」欠账
   (#123 #142 #147 #169)同一个根因:仓库没有端到端这一层,GUI 改动只有
   `electron-vite build` 把关,而 build 通过说明不了窗口能不能出来。
3. 指令漂移:AGENTS.md 提到不存在的 `scripts/gearbox-prune`(#170),索引里还留着
   模板占位符。

## 决定

1. **Hard rules 的可执行版进门禁**:`tests/architecture.test.ts`,grep 级 import 检查,
   三条各一个断言,失败信息带修法(搬去哪、加什么接口),不只报违规。
   新增更严断言 = L2(ADR-0010)。
2. **端到端冒烟 `npm run e2e`**(Playwright `_electron`):build 后起真 app,断言窗口
   有内容、`window.otter` 桥接在、渲染层零 `pageerror` / `console.error`。用独立
   profile(`OTTO_PROFILE=e2e`),不碰模型不碰网络。
   **不进 gate**:要 build,十几秒起步,而 gate 是每次提交前跑的内循环。代替的约束是
   PR 模板里「验收证据」一栏:GUI 改动的 PR 必须贴 `npm run e2e` 的输出或真机截图,
   「没跑」也要写明,不准留空。
3. **Issue / PR 模板**:Task 模板带「验收(做完的证据)」栏,PR 模板带「验收证据」栏,
   把「代码写了 ≠ 做完了」从口头变成表单上空着就显眼的一格。
4. `.nvmrc` 记 24,和 ci.yml 对齐。
5. AGENTS.md:删掉不存在的脚本引用,索引占位换成真路径(L2)。

## 第一次跑就抓到的两个真 bug

证明这一层不是摆设:

- `app.dock.setIcon` 路径按 `app.getAppPath()` 拼,用 `electron out/main/index.js`
  起 app 时 getAppPath 是 `out/main`,图标加载抛异常,而它在 `whenReady().then` 里、
  建窗口之前——**窗口永远不出来**,连白屏都没有。已包 try/catch;e2e 改传仓库根。
- 打包版 CSP `default-src 'self'` 没放行 `font-src data:`,Vite 把 KaTeX 4KB 以下的小字体
  内联成 data URI,被静默拦掉,公式缺字。dev 模式不复现(字体走 URL)。已加 `font-src 'self' data:`。

## 不做的

- **lint 进 gate**:改 Gate 命令 = L1,等维护者拍板。本 ADR 不碰 `npm test`。
- **PROGRESS.md / DECISIONS.md**:课程推荐,本仓用 issue + ADR 代替(gearbox-adr 0003/0005),
  不回头加文件——两处真相比一处差。
- **拆 App.tsx / main/index.ts**(各 2800 / 1250 行,「知识在代码旁边」那讲的反例):
  另开 Task,不混进这条 PR。

## 什么情况下推翻

- e2e 在 CI 上跑得起来且稳定(macOS runner 成本可接受)→ 可以考虑进 gate,届时是 L1。
- 架构测试误报多(合法的例外越来越多)→ 换 AST 级检查或改成 eslint 规则。
