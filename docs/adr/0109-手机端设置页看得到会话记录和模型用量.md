# ADR-0109：手机端设置页看得到会话记录和各模型用量

日期：2026-08-26
状态：已采纳
相关：#462、ADR-0094（手机端范围）、ADR-0108（好友页可以写）、`src/shared/remote/trim.ts`、issue #141

## 背景

`src/shared/remote/trim.ts` 是「什么东西离开这台机器」的唯一收口。它今天剪掉两样：灵动岛的 `display` 设置，和 `usage`（近 14 天每天烧了多少 token）。剪掉 usage 的理由写在那个文件里，两条：

1. 手机端的职责是「看 + 审批」（ADR-0094 的范围），用量不在里面；
2. usage 跟着**每一次** fleet 推送走，等于把账单流水**持续**送过公网 —— 中继解不开，但这是「本来就不该发」而不是「发了也没事」。

现在要在手机的设置页放两块：会话热力图（桌面新会话屏那张），和各模型用量（token 进/出 + 花费）。

## 决策

**加一对 `stats` 帧：手机开口问一次，桌面答一次。`trim.ts` 一个字不动。**

- 上行 `{ type: "stats" }` —— 不带任何字段，多一个键整条丢弃。
- 下行 `{ type: "stats", stats: RemoteStats }` —— 逐字段校验，一条畸形的模型行让整帧被丢掉。

这样处理上面两条理由：

- **理由 2 直接消失。** 发送次数由「人翻到设置页」决定，不由会话状态变化决定。fleet 那条路上仍然什么用量都不带 —— 一条工具事件推一次 fleet，那条路上的每一帧都还是干净的。
- **理由 1 是范围问题，本 ADR 显式放宽**：手机端的范围从「看 + 审批」扩到「看 + 审批 + 看自己的账」。这是同一个账号、同一个人、自己那台电脑的数；配对时逐位核过安全码（ADR-0095），帧走密封流，中继解不开。ADR-0108 已经在好友那条线上退过一步，这是第二步，理由同源：**手机不是第二个完整客户端，说的是它不参与「操作」，不是它看不到自己的东西。**

### 拉取而不是订阅，还有一条更硬的理由

`store.sessions()` 和 `store.billedUsage()` 都是全表扫描级的查询（`session/store.ts` 里就标着这件事，`pushFleet` 为此专门做过记忆化）。挂在推送上等于每条工具事件都拖一次全表扫描。所以就算不考虑「什么该出机器」，这两块也只能是拉的。

### 口径与桌面对齐，靠共用同一份投影

- 热力图：`sessionActivity` 从 `renderer/src/lib/` 搬到 `src/shared/`，两端 import 同一份。跨度同样是 181 天，同样只数主会话（子会话不算 —— 派一次活热力图就多一格的话，它说的不再是「你开过多少会话」，issue #141）。
- 用量：`projectStats` 沿用 `usageStats` / `CostPanel` 的两条规矩 —— 认不出厂商的型号整行丢掉（少算一点，好过算到别人头上）；**查不到价的型号 `costUsd` 是 `null` 不是 `0`**，而且只要有一款没价，合计就退回 `null`（把查得到的几款加起来当总数，报的是一个偏小的数，比不报更坏）。

## 代价 / 余量

- **统计不实时**：翻进设置页问一次，之后要靠那一行「重新读一次」。这是拉取模型的直接后果，也是它想要的样子。
- **窗口写死**：热力图 181 天、用量 14 天，手机上不给切。切窗口要一套选择器，而这一屏的用处是「扫一眼」。
- **不画厂商 logo**：`IslandUsageRow` 那边 Swift 按 provider 取 bundle 里的图，手机端没有那套资源；这里只把 provider 当一行小字。
- 桌面的 `ProviderUsage` 那张按天分层柱状图没有搬过来：它需要一个图表库，而手机上这一屏要回答的是「哪款烧得多、花了多少」，一张表就够。

## 什么前提不成立会推翻这条

如果以后手机端要**持续**显示用量（比如放进品牌栏当常驻数字），拉取就不够了，那时得重新论证「持续送过公网」这件事 —— 而 `trim.ts` 里那条理由 2 会原样回来。
