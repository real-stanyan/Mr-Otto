# ADR-0313：悬空的团队授权在对账时自动清掉

- 状态：已采纳
- 日期：2026-09-21
- 关联：#815（M7）、ADR-0197（好友代理云端执行面 / 托管箱）、ADR-0198 切片 2（团队连接器）、#843（列表一格挂了不等于整份没有）

## 背景

我给团队贡献一台连接器，本机台账 `proxyStore.workspaceGrants` 上就多一条。清它的地方只有三处，
全是**我自己动手**的那几条路：`remove`（我解散群）、`leave`（我退群）、`withdrawConnector`（我撤回）。

别人动手的那两种——**团队被 owner 解散**、**我被踢出去**——本机什么都不知道，那条授权就永远留着。
全仓没有第二处碰它，`list()` 也不对账。

#815 把这一条记成「台账上标缺失：无 UI 可见、无撤回入口（闸上已拒，安全无虞）」。
**「安全无虞」只说对了一半。** 闸确实拒（云端每次调用现判在籍），但还有一条后果它没记：

`buildEscrowDoc` 的 `wanted` 集合**含 `workspaceGrants`**，所以那台 server ——连同它的
OAuth 凭证——会**一直留在 edge 的托管箱里**，而 ADR-0197「零授权 = DELETE 整箱」那条撤销级联
的后半**永远不触发**。群早就没了，凭证还托管在云上。

## 决定

`workspaceManager.list()` 拿到在籍名单之后顺手对账：不在名单里的 `workspaceGrants` 当场删掉，
然后 `resyncEscrow()`。判据抽成纯函数 `danglingWorkspaceGrants(store, memberOf)`。

**推翻了 #815 自己写的处置**（「标出来 + 给一个撤回入口」）。理由是维护者定的口径，附带两条：
标出来要新开一个账号级的面（全仓没有「我授出去的一览」，`ProxyDialog` 是按好友开的），
而这条授权在用户心里早就随着群一起没了——让他再手动撤一次，是把一次本该自动完成的级联
变成一件家务。

## 判据只有一条，而它整个重量在「名单是不是权威的」

对账的输入是 `deps.listWorkspaces(client)` 的返回（`rows`），**不是** snapshots：

- 那条查询**整体失败**时 `withSession` 直接回 `{ok:false}`，压根走不到对账 —— 一次网络抖动
  不等于我退了所有群。
- 某个团队的**明细**拉不下来（#843 的 `loadError` 占位快照）**不影响它**：那一行仍然在 `rows` 里，
  说明我还在籍。拿 snapshots 当判据的话，一次明细查询失败就会把一条活着的授权删掉，
  **而且完全无声**。

这是这条改动唯一容易写错的地方，所以两边都有断言钉着（`tests/main/workspaceManager.test.ts`），
其中「明细拉不下来」那条真的会在「判据换成 snapshots」的实现上翻红 —— 验过。

「拿不到」不许当「被清空」，与 ADR-0197 里 grants 缓存那条纪律是同一条。

## 被否决的

- **标出来 + 手动撤**（#815 原文）：见上。
- **在 `kickMember` 那一侧清**：踢人的是别人的机器，我的机器不在场。
- **每次 `list()` 无脑 `saveStore` + `resyncEscrow`**：`list()` 挂在每一次刷新上，那等于让
  「打开侧栏」变成一次托管上传。只在真有悬空项时才写，有断言钉着。

## 代价

1. **用户看不见这次删除**。台账上少了一条，没有任何提示。可接受：在他心里这条授权随着群
   一起没了；真要提示，就得回到被否决的那个账号级面。
2. **只有 `list()` 成功跑过才会清**。一台长期离线、或从不打开团队那一栏的机器上，悬空授权
   会一直留着（箱子也一直在）。这不是漏做：对账的前提就是拿得到权威名单。
3. **真机一次没跑过。**
