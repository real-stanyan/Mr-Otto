# ADR-0124：摘掉 OTTO_REMOTE 灰度开关，远程投影默认开

- 状态：已采纳
- 日期：2026-08-26
- 相关：issue #484；ADR-0094（手机端远程投影）、ADR-0095（TOFU 按人核对安全码）、ADR-0123（被挡下的握手要有主动信号）

## 背景

远程投影自落地起就挂在 `OTTO_REMOTE=1` 后面。当时写在代码里的理由是：

> 配对（TOFU 首次确认那一步）还没有 UI，没 pin 过对端的话每次握手都会被拒 —— 默认开着只是白连中继。

这条理由已经逐条失效：

- 配对 UI 在 `bea0195` 落地（设置页「手机」栏目 + 6 位安全码核对），手机端那一屏也在
- 中继网关已重新部署，服务器侧自检 11/11 通过（见 #424）
- 之后的时间线订阅、附件分片上传、stats 帧，全是压着这个开关做完的
- 被挡下的握手现在有主动信号（ADR-0123）—— 「白连中继」这件事本身也不再是无声的了

留着的代价是：用户在设置页看到的那张卡，唯一作用是告诉自己开关没开。

## 决定

### 1. 摘掉开关，`RemoteStatus` 的 `reason: "disabled"` 一并作废

远程现在只有一种开不起来的情况：`no-secure-storage`（身份私钥进不了系统安全存储 →
不开远程，而不是明文落盘）。

`reason` 的第二支改成 `unavailable`，语义变了：它**不来自主进程**，是渲染层在
`remoteStatus()` 这一问失败时自己兜的底。原来那句「用 OTTO_REMOTE=1 启动才会开」
没有对应的现实了。

### 2. 顺带修掉被开关掩着的缺陷：登录之后传输不会自己醒

`createSseTransport` 构造时就 `void connect()`，而 `connect()` 拿不到令牌就直接返回、
**不排重连**（重连一个必然失败的东西没有意义）。原注释说「登录之后由调用方重新建这条
传输」—— 但调用方从来没建第二次：`accountManager.onChange` 里只有 `friends.start()`。

表现：**冷启动时未登录的用户，登录之后远程一直不连，要重开 app。**

开关摘掉之前这条路很少走到（会去设环境变量的人基本已经登录了）；摘掉之后它是默认路径。

修法是给真实现加 `retryNow()`，在 `onChange` 的登录分支叫一次。不把它加进
`RemoteTransport` 接口：那个接口手机端也在实现，而这件事只有桌面有。

登出不用管：流一断，下一次 `connect()` 拿不到令牌就自己停住了。

## 代价 / 风险

- **每台桌面默认都会连中继**（登录之后）。没配对的话连上也进不了 ready，
  是一条空着的 SSE 长连接 —— 网关侧多一条连接的成本，换掉的是「用户永远发现不了这个功能」
- 远程这条链路的 bug 从此对所有用户可见，不再有环境变量当缓冲。这是摘开关的目的，
  也是它的风险：ADR-0123 的信号、以及 `console.warn` 那几条诊断，是唯一的护栏

## 前提若变

若中继的连接成本成为问题（大量登录但从未配对的桌面挂着长连），出路不是把开关加回来，
而是让传输在「从未 pin 过任何对端」时不主动连、由设置页打开那一栏时才起 ——
用户表达意图的时刻是明确的（同 `remoteStatus` 里 `registerSelf` 的位置选择）。
