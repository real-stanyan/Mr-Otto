# ADR-0311：任务会话的「回到这一步」改成复制式还原

- 状态：已采纳
- 日期：2026-09-21
- 关联：#1252、#1223 / ADR-0291（任务会话云端日志，终审 C2 那条裁决）、ADR-0084 / issue #352（引用式零拷贝分叉）、ADR-0090 / issue #395（回到检查点）、ADR-0206（内置 Default 按会话分格）

## 背景

「回到这一步」（`rewindToCheckpoint`）做两件成对的事：对话侧从某条 `turn_ended` 分出一条新会话，
文件侧把影子 git reset 回那个检查点。对话侧这一半自 #352 起是**引用式零拷贝**——新会话在库里
只有一行 `session_created{forkedFrom: {sessionId, seq}}`，历史前缀仍住在父会话的事件行里，
`load()` 沿链读出来。

#1223 给任务会话接上云端日志之后，这个形状与 0036 的 RPC 撞了：引用式分叉 `load()` 扁平化
之后有**两条** `session_created`（seq 0 是父会话的，`endSeq+1` 是它自己的），而 RPC 只许
seq 0 有 `session_created`，推上去就是 P0012 → 整条会话**永久冻结**。

ADR-0291 终审 C2 当时的处置是在同步层把这种分叉整个挡在云外（`isTask` 里判 `forkOrigin`）。
那是对的急救：冻结是终态，比不同步坏得多。但它留下的代价一直挂着，而且是**静默的**——
用户在任务会话里回到某一步、接着聊的那条分支只在本机，手机和另一台电脑上它不存在，
界面上一个字都不说。

## 决定

**按「这条会话上不上云」分两条路**，判据就是同步层用来决定推不推的那一条：

| 会话 | 落法 |
|---|---|
| 任务会话（`isCloudTaskSession` 为真） | **复制式**：`retargetForImport(load(parent, {untilSeq: boundary}))` 整份抄成一条独立会话，不写 `forkedFrom` |
| 其余（项目会话、以及本 ADR 之前留在本机的存量分叉） | 引用式零拷贝，一个字不改 |

落点是新模块 `src/main/checkpointRewind.ts` 的 `rewindBranch()`，`index.ts` 那个 handler 只剩一行调用。
抽出来不是洁癖：`index.ts` 一 import 就要连 electron、进不了 vitest，留在那儿等于这个判断
**零执行覆盖**（同 `usageAttribution` 与 `sandbox.freeKib` 接线的教训）。

### 判据只有一份

`isCloudTaskSession(first, forkOrigin)` 住在 `src/shared/taskSync.ts`，两处消费方——同步层的
`isTask`（决定推不推）与 `rewindBranch`（决定落成哪一种）——读同一份。各写一遍迟早分家，
而分家的形状正是这个洞本身：落成一种、判成另一种。

`forkOrigin` 那一半**不是冗余**。`load(id, {untilSeq: 0})` 会沿 fork 链扁平化，所以对一条
任务会话的存量分叉，它给出的是**父会话**那条 `session_created`——单看它会把分叉判成任务会话，
于是复制一段含两条 `session_created` 的流上云，P0012 原样重演。这条有用例钉着。

### 两条路的前置校验逐字相同

分叉点必须是 `turn_ended`、目标会话不许已存在——复制式那条不许比 `store.fork` 松，否则同一个
非法输入在两种会话上给出两种结局（一条抛错、一条落下半截会话）。

## 被否决的

**同步层在推送时把第二条 `session_created` 改写掉**（#1252 正文里就否了，记在这里）：那会让
本机与云端的前缀不再逐字节相等，而 `reconcile` 的 `divergence` 判据正是逐字节比对——这条分支
从此每次对账都被判成分歧，含 executor 痕迹的那一批走 `forkCopy` 流放，比不同步更坏且完全无声。

**放行 `seq > 0` 的 `session_created{forkedFrom}`**：拉到另一台机器之后 `forkOrigin` 会认出
`forkedFrom`、`load()` 再前缀一遍父会话，事件重复、seq 撞车。

**给项目会话也改成复制式**：它们本来就不上云，改了只是白白放弃零拷贝。

## 代价（都是明知的）

1. **前缀不再零拷贝**：父会话那一段在本机库里存了第二份，推上云也是第二份。长会话回退一次
   = 整份历史再传一遍。这是 #1252 选这条候选时就接受的。
2. **`purge` 的 fork 保护（#352）不再挡删父会话**。不是漏做：复制式分支的历史住在它自己的
   行里，删父**不会**把它的记忆连根抽走，那道保护此刻没有要保护的东西。反过来说，用户删父
   会话时不再被拦一次 —— 这是行为变化，写在这里。
3. **侧栏标题从「新会话」变成「<父标题>（分支）」**。这不是顺手改的，是**必须**改：复制式
   分支继承了父会话的全部 `user_message`，而 `sessions()` 的标题投影取第一条 `user_message`
   首行，于是它会给出与父会话**逐字相同**的一行，两条会话在侧栏上分不出来。落法是复制完
   追一条 `session_renamed`（`session_renamed` 是人的动作、免笔，建行那一批照常上云）。
   顺带记一笔：`store.fork` 的 payload 里本来就写着「（分支）」，只是 `sessions()` 从不读
   `session_created.title`，那一格一直是死数据。
4. **存量分叉补不回去**：本 ADR 之前在任务会话里回退落下的引用式分叉仍然只在本机。日志
   append-only，改不了。同步层那道闸因此继续守着它们，注释里点名说清了它此后只剩两种来客。
5. **复制那一步没有事务**：`EventStore` 没有跨会话的批量原语，复制是一条一条 `append`
   （同 `taskSessionSync` 的 `forkCopy`）。半路抛错会在侧栏上留一条残会话。缓解是顺序——
   这一步仍排在动文件**之前**，抛错时磁盘一个字节没动，与改动前同级。
6. **真机一次没跑过**。

## 保鲜期

`tests/main/checkpointRewind.test.ts`（两条路各自的形状、共用的前置校验、以及「少了 `forkOrigin`
那一半会判错」那条）与 `tests/main/taskSessionSync.test.ts` 里新增的那条端到端（复制出来的分支
过假 RPC 的 0036 约束真的推上去了）。两处方向相反的红绿都验过：强制走引用式时 4 条红，强制
走复制式时 2 条红。
