# ADR-0315：残留清单的四个查询搬出装配根

- 状态：已采纳
- 日期：2026-09-21
- 关联：#780（I3 / I5，issue 自己标的「独立小任务」）、#759 / ADR-0193（残留物生命周期）、ADR-0058（Hard rules 的可执行版）

## 背景

`pendingResidueNow` / `currentResidueDiff` / `residueListNow` / `residueCleanPool` 四个函数
原来是 `src/main/index.ts` 里的装配根闭包。那个文件一 import 就要拉起 Electron，
所以它们**进不了 vitest**——全部执行覆盖只有 `tests/main/residueWiring.test.ts` 里
两条读源码的断言，而那种断言钉得住「源码里有没有这一行」，钉不住返回值。

问题在于这一族**坏掉的样子全是无声的**，#780 自己数过三种：

- 遍历口写成 `store.sessions()` = 系统归档会话上的残留一条都重放不出来，清单里只是少几行（M4，真发生过）；
- 没有 baseline 时兜底成空快照 = 整机的端口和模拟器全被算成本会话的残留，进了一个默认勾选、一按就清的清单（I5，真发生过）；
- `residueClean` 的匹配池按会话级算 = 跨会话的 id 一条都对不上，`targets` 是空数组、循环一圈不做事，而渲染层对空数组的 `every(...)` 恒真，于是报「清理成功」（I3，真发生过）。

三条都不会让任何东西报错。

## 决定

搬进 `src/main/residueQueries.ts`，导出 `createResidueQueries(deps)`。依赖一律注入，
所以那个文件自己不碰 Electron、不碰 `node:child_process`，装配根只剩一句接线。

**注入的是 `store` 本身，不是三个回调函数。** 那三个方法（`sessionIdsWithEvent` /
`eventsOfType` / `lastOfType`）的形状就是 `EventStore` 的形状，拆成三个回调只会让装配根
多写三行转发——而那三行转发同样进不了 vitest，等于把同一个问题往上挪了一格。

**`residueCapOf` 递的是这个会话自己那份能力**（`agents.get(sessionId)?.world.residue`），
不是清理侧那条 app 级退路 `residueCapFor`。两者差一个字而后果是静默的：基线是会话级的，
拿 A 的基线去减 B 的现场，算出来的既不是 A 的残留也不是 B 的。所以 `residueCapFor`
留在装配根没跟着搬——它是 `residueClean` 那个 IPC handler 的事，不属于这一族查询。

## 保鲜期分两层，缺一不可

- **`tests/main/residueQueries.test.ts` 真跑**：遍历口、`detected`/`cleaned` 按 seq 归并
  （「先清后检出」那条必须留着）、进程组身份核对而端口/模拟器不探活、没有基线就不做、
  现查覆盖重放、匹配池是 app 级的。每一条都对着上面那三种无声失败里的一种。
- **`tests/main/residueWiring.test.ts` 继续读源码**，但判的东西换了：不再判查询逻辑
  （那已经真跑得起来），只判**接线本身**——模块接上了没有、`residueCapOf` 递的是哪一格、
  `escapedGroups` 接的是不是真的那张出走登记表、`index.ts` 有没有把本体抄一份回来。
  那一句接线住在装配根里，仍然只有读源码这一条路（同 `tests/main/accountScope.test.ts`
  与 `tests/runtime/sandbox.test.ts` 的处置）。

「有没有把本体抄回来」的判据是 `index.ts` 里不许再出现 `pendingResidue(` / `mergeResidue(` /
`store.sessionIdsWithEvent("residue_detected")` —— 抄回来的那一份不会报错，只是又一次没有覆盖。

## 已知代价

1. **行为一个字没改**，所以这次改动本身**不修任何 bug**——它买的是「下一次改这几个函数时
   会当场翻红」。
2. `diffResidue` 仍有第二个调用方在装配根里（`archiveSession` 的全量 diff，它另有自己的
   守卫与异步收口），那一处**没有**搬进来，于是「没有 baseline 就不做」这条判据在仓库里
   有两份实现。合并它要把归档那段的 append/推送一起搬，是另一件事。
3. 接线断言读的是字面量，一次无害的重命名（比如 `agents` 改名）会让它红。这是刻意的
   ——那种红要求人回来重判一次接的是哪一格，而不是默默变成冗余。
