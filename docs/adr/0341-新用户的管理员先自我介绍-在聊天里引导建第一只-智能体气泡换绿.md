# ADR-0341：新用户的管理员先自我介绍、在聊天里引导建第一只；智能体气泡换淡绿

日期：2026-10-04 · issue #1465 · 维护者：「所有新用户登录后原本创建一个 agent 改为创建一个你自己的 agent 主管，就是现在的管理员，但是要让用户知道他是干什么的。他需要自我介绍，然后引导用户去创建第一个他的专属 agent，管理员可以让用户去命名。并且所有 agent 的对话框背景色不要和用户背景色一个颜色」

## 决定

1. **复用「新建的智能体先开口」那条路**（ADR-0319），不另造一套：
   - 0051 让新**主场**里的管理员带 `onboarding = 'greet'`。存量主场与团队一个字不变：老用户早有自己的智能体。
   - 手机建主场时，`ensureHomeWorkspace` 回 `created: true`，手机就替他开好和管理员的私聊。
   - runtime 建这条新私聊时抢到那一格，才落开场白。开不成（断网）也不拦进门：之后他点进管理员照样会建这条私聊，
     那一格还是 `'greet'`，管理员照样先开口。
2. **招呼类型 `admin_intro`，不是 `new_agent`**。管理员的职责是固定的；用 `new_agent` 的话，`advanceRoleWait`
   会把人的第一句回话写成管理员的职责，手机还会在它底下画六个「职责」快捷选项。所以开过口就把那一格清回 null。
3. **在聊天里建**（维护者选的）：开场白让管理员先用两三句话说清自己是干什么的，再问用户想要一只帮他干什么的、
   请他起个名字（没主意就提一个让他点头），两样清楚了用 `create_agent` 建好（主场里不弹审批卡，ADR-0298），
   最后告诉他回聊天列表去找它。名字叫「管理员」不改（维护者：「就是现在的管理员」）。
4. **智能体的气泡换成淡绿**（维护者从三个 demo 方向里挑的 B）：新 token `bubbleAgent`，浅色 `#d9e6dc`、
   深色 `#16301f`（ok 绿调进纸面）。我说的仍是蓝调、别的人仍是暖灰，三方三个色相。智能体那一侧的通话记录、
   来电记录、「正在回复」三个点一起换。

## 代价

- 引导靠提示词，模型可能跳步（没问名字就建了）；靠的是「一次只问一件事」那一句软约束。
- 只在手机上建主场时开这条私聊；桌面新建主场不开（桌面在退役，#1404）。
- 部署顺序：0051 → runtime → 手机 JS 热更新（这一份没碰原生，可以走 ADR-0340 的热更新）。真机一次没跑过。
