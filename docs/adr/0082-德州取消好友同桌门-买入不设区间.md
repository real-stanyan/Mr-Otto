# ADR-0082: 德州取消好友同桌门，买入不设区间（全部筹码可上桌）

日期：2026-08-24
状态：已接受（推翻 ADR-0022 决定四）
关联：issue #318、migration 0010

## 背景

ADR-0022 决定四把德州定位成「私人圈子」：仅 accepted 好友可同桌，落在三处——
migration 0005 的 poker_join 好友门（P0005）、poker_tables 的 RLS select 政策、
gateway listTables 的可见性过滤。同时建桌时的 min_buyin/max_buyin 区间在
poker_join 里强制（P0007）。

用户裁定两条都取消：谁都能同桌；游戏里可用手上全部筹码，不受建桌时的买入区间限制。

## 决策

1. **好友门三处全删**（migration 0010 + gateway）：
   - RLS select 政策放开为所有登录用户可见
   - poker_join 重建，无好友检查
   - gateway listTables 直接列出所有开着的桌
   - 好友邀请（migration 0006 的 game_invites）保留——它是便利功能，不再是准入条件
2. **买入区间不再强制**：poker_join 只查 `p_amount > 0`；上限由钱包余额天然限制
   （poker_buyin 的余额检查不动，**不能透支**）。`min_buyin`/`max_buyin` 列保留
   （schema 兼容、老桌数据不动），仅不再参与判定。
3. **客户端买入语义 = 全部**：大厅/等桌页的买入按钮把对应档位桶的全部余额带上桌；
   在座等待（手与手之间）可「补充筹码」再次全额买入（服务端本就支持 rebuy 路径）。
   手牌进行中不能加筹码——这是扑克规则（边池结算依赖起手栈），不是本决定的例外。

## 为什么引擎零改动

betting.ts 本就支持任意正数栈：盲注不足自动 all-in（postBlind 取
min(amount, stack)）、不足额 all-in 不重开叫牌权、边池按 startStack 分层。
买入额从「区间内」变成「任意正数」不触碰任何引擎不变量（零和校验三道墙不动）。

## 后果

- 陌生人可同桌观战/对局——「私人圈子」前提废弃；若未来要防骚扰，重新加门时
  这份 ADR 就是回滚说明书（0005 的 poker_join 原文在 git 里）。
- 「全部买入」意味着桶余额清零挪到桌上；推理扣费与德州筹码同源（ADR-0021），
  用户在桌上时桶里没钱推理——离桌（cashout）即回。客户端文案已说明。
- 部署面：Supabase 跑 migration 0010 + VPS 重启 gateway，两者都改完才生效；
  客户端老版本仍显示买入区间文案，但服务端已不再强制，行为兼容。

## 推翻条件

出现真实骚扰/陌生人恶意行为，或代币经济需要重新引入桌位准入与买入上限。
