# ADR-0241：「订阅」是第三种不显示 $ 的理由 —— 它不是「查不到价」

- 状态：已接受
- 日期：2026-09-07
- Issue：#1025
- 相关：ADR-0211（CostPanel 的钱的规矩、「托管」vs「—」）、ADR-0117（ProviderId 是
  「一个端点 + 一把 key」不是「一家公司」）、ADR-0239（账号页的用量卡刻意不报钱）

## 背景

issue #1025 报的现象属实：本机用量最大的那一家在花费面板上永远画破折号。
但它给的病因不对 —— 原话是「两张表的键对不上，`k3` 是 `kimi-k3` 的笔误，对齐即可」。

查了一遍：

| | provider | id | 计费 |
|---|---|---|---|
| 月之暗面 | `moonshot` | `kimi-k3` / `kimi-k2.6` | 按量，价目表里**有** |
| Kimi Code | `kimicode` | `k3` / `k3-256k` / `kimi-for-coding*` | **订阅制，按月限频不限量** |

`providerCatalog.ts` 原话：「编程订阅制，按月限频不限量；与上面那家同公司，但端点和 key
都不通用」——两套账号体系，订阅 token 拿去按量端点必 401。按 ADR-0117，它们是两个
ProviderId，**不是同一款型号的两个写法**。

所以把 `kimi-k3` 的 $3/$15 抄到 `k3` 上，不是修 bug，是给一个按月付费、边际成本为零的
调用**编一个用户从没花过的数**。价目表头注那句「宁可少一行，不能给一个错的钱数」
挡的正是这个。

**真正缺的不是价，是一个标签。**

## 决定

### 1. 目录里每一款没价的，都得说明为什么；理由分两种

`modelPricing.ts` 新增 `UNPRICED: Record<string, "flat_rate" | "unknown">`：

- **`flat_rate`** —— 这一款**根本没有按次单价**，钱在月费里。这不是「查不到」，是「不存在」。
- **`unknown`** —— 这一款**有**按量单价，只是查不到公开数（或上游没单列）。

原来那段名单是注释里的四条 bullet，读得到但程序读不到。换成一张表之后它同时是
两件事的载体：解释，和下面那条断言的判据。

### 2. CostPanel 给 `flat_rate` 画「订阅」，不画破折号

破折号说的是**「我不知道」**，而这一格我们知道得很清楚 —— 不存在这样一个数。
这条分辨在 hosted 那侧已经做过一次（ADR-0211 的「托管」vs「—」：「不按 $ 计」
与「价目缺失」必须分得开），这次是同一条规矩落到 direct 那侧。

「订阅」与「托管」也不是一回事，两句话都写进了常量的头注：**「托管」是走我们自己的
key、按 credit 计，只是这一笔没记到；「订阅」是用户自己在别人那儿包了月，钱压根不经过我们。**

### 3. 合计照旧退回 token，不把包月那几笔当 0 加进去

它们的**边际**成本确实是 0，所以「加进去」在算术上说得通。不做的理由是那句话会变成
「这个会话花了 $0.03」——对一个每月付着订阅费的人说这句，比不报更坏（同 ADR-0211
那条「把已知的几笔加起来是在报一个偏小的数」的推论）。

这一格没有 $ 答案不是缺陷：「这一次花了多少钱」对包月的部分本来就问不出数来。

### 4. 保鲜期：一条把目录和价目对起来的断言

`tests/shared/modelPricing.test.ts` 断言**目录里每一款都必居其一**：有价 / 本机那一族 /
在 `UNPRICED` 里说明了理由。加一款新型号不表态就会红。

这类「两张表对不上」是静默失败 —— 界面上只多一个破折号，而破折号本身是合法状态
（上游下架了、查不到公开价），肉眼分不出「抄错一个字符」和「真的没有价」。
这正是 #1025 被当成笔误报上来的原因。

配套两条反向断言：`UNPRICED` 里不许躺着目录里已经没有的 id（那是过期的解释）；
`UNPRICED` 与 `PRICES` 不许同时命中同一款（两处必有一处是错的）。

## 后果

- 花费面板上 Kimi Code 那几行从「—」变成「订阅」。**没有任何一款型号的价格被改动**
  —— 这次改的全是标签与断言。
- 加型号的检查清单多一处：`PRICES` 或 `UNPRICED` 二选一，漏了 tsc 不红但门禁会红。
- 哪天要让合计把 `flat_rate` 当 0 算，改一行 `sessionTotal` 即可，但先想清楚决定 3。
