# ADR-0048: 子智能体的作用域与三层前置词

- 状态: 已接受
- 日期: 2026-08-21
- 相关: ADR-0047（子 agent 是一次独立会话）、ADR-0007（skill 根目录的覆盖规则）、issue #140

## 背景

ADR-0047 落地的第一版 subagent 有两处硬边界：

1. **定义只有一个作用域**。根目录写死两条 —— `~/.otter/agents/`（可写）和
   `~/.claude/agents/`（只读兼容）。于是一个「本项目专用的审查员」要么污染全局清单
   （在别的工程里也被模型看见、也可能被派活），要么根本没法存在。
2. **前置词是硬编码的**。`subagentRunner.ts` 里一段 `PREAMBLE` 常量拼在
   `def.instructions` 前面，用户碰不到，也没有任何办法让某一个子智能体不要它、
   或者让子智能体知道本工程的规矩（AGENTS.md 那种）。

用户拿另一款工具的配置页做参照，要的两件事就是：**可选作用域**、**可配置前置提示词**。

## 决策

### 1. 作用域 = 根目录的一层，工作区盖用户

扫描顺序（同名先到先得，与 ADR-0007 的 skill 规则同构）：

| 顺序 | 目录 | 可写 | scope |
|---|---|---|---|
| 1 | `<工作区>/.otter/agents/` | 是 | `workspace` |
| 2 | `<工作区>/.claude/agents/` | 否 | `workspace` |
| 3 | `~/.otter/agents/` | 是 | `user` |
| 4 | `~/.claude/agents/` | 否 | `user` |

`SubagentDef` 加一个 `scope: "user" | "workspace"` 字段。`listSubagents()` 变成
`listSubagents(workspace?)` —— 不给工作区就只有后两条根目录。

**运行时按会话工作区过滤**：`task` 工具的清单来自「该会话的 workspace 那次扫描」，
工作区级的定义自然只在本工作区可见。这是「作用域」这个词本来的意思；只做设置页分类
而运行时全给，等于这个词名不副实。

### 2. 前置词三层，派活时按序拼

```
前置词(③ 自定义 ?? ① 全局)  +  ② 工作区文档注入  +  instructions
```

**① 全局前置词** 存 `~/.otter/subagent-preamble.md`，纯文本，无 frontmatter。
文件不存在 = 用内置默认（就是原来那段常量）。不新开设置存储机制：`~/.otter/` 下一个
文件，与 skills/agents 同一套路数，用户可以直接手改。

**② 工作区文档注入** frontmatter 加 `context: AGENTS.md, CLAUDE.md`（逗号列表，
缺席 = 不注入）。派活时按会话 workspace 读根目录下这些文件，读到就拼一段，读不到跳过。
**只收 basename**：带 `/` 或 `..` 的一律拒绝 —— 否则一份子智能体定义就是一个任意
文件读取原语，而定义文件可能是用户从别处抄来的。

**③ 每个子智能体自己的前置块，覆盖 ①**：

- frontmatter 无 `preamble` → 用全局（老文件行为不变）
- `preamble: off` → 一段前置词都不加
- `preamble: |` + 缩进块 → 用这段，替换全局

拼好的整段进 `subagent_briefed` 事件的 `instructions` 字段 —— 快照记的是模型看到的
全部，不是用户敲进去的部分（ADR-0047 已定的规矩，这里不变）。

### 3. 重建历史子会话一律信快照（了结 #140）

`resumeChild.ts` 重建一个历史子会话时，只读 `subagent_briefed` 快照，不再读磁盘定义。
磁盘定义只在**新派活**那一刻读。

## 理由

**为什么 ③ 是「覆盖」而不是「追加」。** 如果每个子智能体的前置块只是「更多文本」，
它和 `instructions` 拼起来对模型完全一样，那它就只是 UI 分栏，没有任何工程语义。
定成覆盖全局，它才有一个 `instructions` 表达不了的能力：*关掉/换掉那段所有子智能体
共享的边界说明*。

**为什么块标量放 frontmatter，不放正文。** 正文是自由文本。在正文里约定一条分隔符
（比如一行 `---`）等于给用户的 Markdown 加了一条隐形语法 —— 他写一条横线，正文就被
切成两半，而且这个坑只有在派活时才暴露。代价是解析器要认 YAML 块标量 `|`：现在那个
正则只认单行，要加一个分支。这个代价是有界的、可测的；前一个代价不是。

**为什么全局前置词是文件不是设置项。** 主进程里根本没有通用设置存储。为一个字段
新建一套持久化机制，比在已有的 `~/.otter/` 目录里多放一个文件贵得多，而且文件这条
路顺带白送了「用户可以用自己的编辑器改、可以纳入版本管理」。

**为什么重建信快照。** 快照是 append-only 日志的一部分 —— 事实来源。磁盘定义是可变的
外部状态。用磁盘重建，等于让一个历史会话的内容随文件改动而改写，这与「任何投影必须
可从日志推导」直接冲突。这次让磁盘定义变肥（多了三层前置词），赌注比 #140 开出来的
时候更大，所以一并拍掉。

## 被拒绝的替代方案

- **作用域只做设置页分类，运行时全给。** 改动最小，但「作用域」就成了一个骗人的标签：
  用户以为本项目的审查员不会在别的工程里被派出去，事实相反。
- **正文用一行 `---` 分隔前置块与主体。** 免掉块标量解析，但给用户正文加隐形语法（见上）。
- **全局前置词做成设置页的一个持久化字段。** 需要新建设置存储；且用户失去手改与版本管理。
- **`context` 收全路径。** 更灵活，但把定义文件变成任意文件读取原语。
- **③ 追加而不是覆盖。** 见上，没有 `instructions` 之外的语义。
- **工作区根目录从选择器里现挑。** 设置页没有文件选择的既有入口；用「有过会话的工程
  文件夹」当候选，与用户参照的那个界面同一个来源。

## 接受的代价

- **从没开过会话的文件夹建不了工作区级子智能体** —— 候选列表来自会话历史。得先在那儿
  开一次会话。
- **同名可以两边各一份，但清单里只看得见赢的那一份。** `scanSubagents` 的去重是先到
  先得，所以被盖住的那份根本不进返回值 —— 设置页切到工作区作用域时，看到的是覆盖后的
  结果，不是「这一层有什么」。用户想确认自己那份用户级定义还在，只能切回用户作用域看。
  行上的作用域徽章告诉他当前这一行属于哪一层，但「我这个名字在别处还有没有一份」
  这个问题，界面回答不了。
- **一个工程 `.claude/agents/` 里的定义会盖过用户自己写的同名定义**，因为覆盖顺序里
  作用域优先于「谁的配置」。也就是说克隆一个仓库可能会静默改变一个名字在该工程里的
  含义。这是「工作区盖用户」这条规则的直接后果，接受它是为了让「本项目专用」真的专用。
- **`context` 注入是运行时读盘**，文件改了下次派活就是新的 —— 快照里能看见当时读到的
  是什么，但派活前无法预览。
- **块标量解析是我们自己写的**，不是 YAML 库。只支持 `key: |` 一种形态；别的 YAML
  高级写法照旧不认。自定义前置词里统一的前导缩进会在往返中被拉平（公共缩进按 YAML
  语义不是内容）。
- **注入的工作区文档进的是 `subagent_briefed`，而它投影成 user message，压缩永不触碰。**
  所以这里的体积上限（单份 64 KB、总量 128 KB）不是普通的性能限制：超了不是变慢，
  是那个子会话从第一轮起就超上下文，而日志 append-only，事后改 `.md` 也救不回已经
  发生的那个会话。
