# ADR-0104：「今天是几号」从日志的 ts 推，不读时钟

- 状态：已接受
- 日期：2026-08-25
- 相关：issue #430、硬规则「投影必须可从日志推导」

## 背景

系统提示词里没有当前日期，模型只能按训练截止猜年份 —— 而它要往 commit message、
ADR、文件正文里写日期。补一行「今天是 X」是最便宜的高价值修补。

但 `deriveMessages` 是纯函数：同一份日志必须永远投出同一串字节。在里面读
`Date.now()` 会让投影随时间漂移 —— 昨天重放和今天重放得到不同的模型上下文，
而"模型看到了什么可从日志推导"是硬规则。

## 决定

日期从**日志里最后一条事件的 `ts`** 推（`dayOfLastEvent`），不读时钟：

- **纯**：ts 本来就在日志里。重放一份三个月前的日志，投出来的还是当时那一天，
  和三个月前逐字节一致。
- **取最后一条，不取 `session_created`**：跨夜的会话不该一直以为还是开会话那天。
- **只取到「天」**：系统提示词是缓存前缀。按天变 = 一天失效一次；按 turn 变 =
  每轮都重付一次前缀。天级粒度是这两者之间唯一合理的点。
- 投影和用量估算（`shared/contextEstimate`）共用 `dayOfLastEvent` 与
  `systemPromptText` 同一处出口 —— 两边各算一遍就会出现「估算里没有日期那一行、
  真实请求里有」的偏差。

## 代价

`dayOf` 用本机时区格式化。同一份日志在另一个时区的机器上重放，日期串可能差一天。
接受：Otto 是单机桌面应用，重放发生在同一台机器上；而换成 UTC 会让 UTC+10 的用户
在本地上午看到"昨天"，那是每天都在错，比跨机器重放的边角情况严重得多。

若将来日志要跨时区流转（比如手机端远程接管，ADR-0094 那条线），正确的修法是把
当时的时区偏移随事件落盘，而不是把格式化改成 UTC。
