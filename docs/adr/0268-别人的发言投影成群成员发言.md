# ADR-0268：群聊里别人的发言投影成群成员发言，不是我自己的 assistant 消息

- 状态：已接受
- 日期：2026-09-09
- 关联：#1146（真机 400）/ #1151（自己的 reasoning 传回给 API，从这次探针里分出去的）/ ADR-0219（agentView 是变换不是过滤——本篇改的是「变换成什么」）/ ADR-0226 与 #965（发言人标签与正文的防伪闸，这条投影从此直接吃到）/ `docs/superpowers/specs/2026-09-04-workspace-multi-agent-design.md` §1「群里我听得见你说话」

## 背景

真机（2026-09-09，deepseek-v4-flash，导出日志 `otto-cloud-fd6f6f31-20260909-135256.jsonl` seq 210）：接力到「管理员」那一轮，第一次调用模型就 400——

```
The `reasoning_content` in the thinking mode must be passed back to the API.
```

同一条日志里紧挨着的上一轮（「开发」，带一次 bash 工具调用）是成功的。同一次导出里还有一处不对劲：「开发」答的是「收到接力，管理员这棒我来收个尾」——那一棒 @ 的是管理员，不是它。

## 诊断

全部用真接口（经 edge 网关打 deepseek-v4-flash）对着**从日志重建的请求**逐字验过，探针记录在 #1146：

1. DeepSeek thinking 模式的规矩：请求带 `tools` 时，**最后一条 user 之后的每一条 assistant 消息都要带 `reasoning_content`**（键在即可，空串也行）；之前几轮的不要求；不带 `tools` 的请求不查。
2. 自己的工具回合能过，**不是**因为本仓传了 `reasoning_content`（从没传过，`toWireMessage` 里没有这一格），而是 DeepSeek 按它自己发出的 tool_call id 在服务端缓存了思考内容：把日志里真实的 `call_00_…` 换成一个现编的，同一个请求立刻 400；带上日志里自己那段 `reasoning` 又能过。所以每一轮工具调用都在赌它的缓存还在——这是另一件事，见 #1151。
3. 别人的发言在 ADR-0219 的变换里是「剥掉 toolCalls / reasoning / usage 的 assistant_message」，到 deriveMessages 仍是 **assistant 角色**。接力开场白（user）之后跟着「开发」的两句话，就是两条没有、也不可能有它的 `reasoning_content` 的 assistant 消息——这一轮还没开口就 400。
4. 同一个投影也解释了「我是管理员」：每只 agent 把别人说过的话读成自己说过的。系统提示词明写着「他们的消息以「[名字]: 内容」的形式到你这里」，但只有人类成员真的长这样。

## 决定

1. **agentView 把别人的 assistant_message 投影成 chat_message**：`fromUid = agentId`、`label` = 那只 agent 的名字、`content` 原样、`mention: false`。deriveMessages 不用改——chat_message 本来就投影成 `[名字]: 内容` 的 user 消息，label 过 `safeSpeakerLabel`、正文过 `promptSafeBody`：一只 agent 从此也伪造不出别人的说话人行。
2. **名字从日志里现取**：那只 agent 自己的 `agent_briefed` 是日志里唯一写着「`a_8e93…` 叫开发」的地方（它对别人的视图是 drop，但读名字发生在判决之前）。按日志顺序推进 = 发言那一刻的名字，与 `chat_message.label`「发言那一刻的显示名快照」同一条规矩；日志里没有（旧日志）退回 agentId，不编一个。
3. **日志一个字不动**。这是读路径的投影；spec §4.2「不给 agent 发伪 uid」管的是写路径，`fromUid` 在投影里只用来做保留名判定，不落盘、不进审计。
4. 那条 API 规矩写成一条投影不变量钉在 `tests/session/agentView.test.ts`：接力开场白之后跟着别人的发言时，模型看到的消息里**最后一条 user 之后没有 assistant**。

## 否决的

- **给别人的 assistant 消息补 `reasoning_content: ""`**：探针证明能过。但那是拿一个假字段哄 API，而「别人的话是我说的」那个病原样留着。
- **在 deriveMessages 里判「这条 assistant_message 是不是我的」**：deriveMessages 不知道「我」是谁（本机会话压根没有 agentId），而 agentView 正是为「谁在看」而存在的那一层。
- **runtime 落盘时就写成 chat_message**：日志是事实，agent 说的话就是 assistant_message（spec §4.2）；改写路径也救不了已经躺着的日志。
- **顺手把自己的 reasoning 也传回**：方向对，但要按 provider 门控并逐家验过（OpenAI 那种严格校验会拒陌生字段；Kimi K2 thinking 文档反过来要求必传），是独立的一件事（#1151）。

## 代价 / 已知

- 别人的发言从 assistant 角色变成 user 角色：模型不再把别人的结论当成自己的承诺——这是要的；代价是上下文里 user 消息变多，对「这一轮谁在问我」的判断全靠 `[名字]` 前缀与开场白措辞。
- `[名字]` 与人类成员的标签同形，同名的人与 agent 在标签上分不开（@ 那一侧 ADR-0252 已处理，标签这侧接受）。
- `agentView.ofType(sessionId, "assistant_message")` 对别人的发言现在回 chat_message；仓内没有消费方按这个组合查。
- 验收：修完对着日志重建「管理员」那一轮，非流式 / 流式都 200；线上要**重新部署 runtime** 才生效（#791）。
