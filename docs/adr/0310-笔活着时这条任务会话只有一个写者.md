# ADR-0310：笔活着时，这条任务会话只有一个写者

- 状态：已采纳
- 日期：2026-09-21
- 关联：#1258、#1223 / ADR-0291（任务会话云端日志）、ADR-0247（turn 跑着时回车 = 排队）、#1253（云端兜底执行器，同一个形状的第二个持笔方）

## 背景

0036 的 `_task_append` 有一张**免笔白名单**：人的动作（人话 / 改名 / 归档 / 换型号…）任何设备
随时可落。理由是对的——手机从不握笔，不给它这条路它就一个字都发不出去。

但它完全不看笔，于是有这么一个窗口（#1258 读代码推出来的，这一轮**跑出来了**）：

设备 Y 握着笔在跑 turn，设备 X 这时落一条人话，且恰好落在 Y「本地刚 append 了一条、还没推
上去」的那 200ms 防抖 + 一次 RPC 往返里：

1. X 的人话免笔，直接落在云端 seq N；
2. Y 推它本地同号的 executor 事件 → `seq_conflict`；
3. `reconcile` 看到 `isRunning` → 先不动本地、留在脏集合；
4. 收口后再对账：分歧处本地尾巴含 turn 痕迹 → `has_executor` → `forkCopy` + `replaceWithCloud`。

**Y 刚跑完的一整轮被流放**进「（本机未同步的分支）」，主会话换成云端那份（X 的话、没人答），
随后再被答一遍。用例里跑出来的原样：

```
分支: ['第一句（本机未同步的分支）']   replaced: ["s1"]
主会话: [session_created, user_message, user_message]     ← A 的回答没了
```

窗口外（Y 在等模型 / 跑工具、没有未推事件）X 的话会被 Y 的拉取正常收进去 —— 那是 spec §3.3
「正在跑的那一 turn 会在增量采样里读到它」成立的那一半，也是这个洞一直没被发现的原因。

## 决定

**笔活着且在别人手上时，人的动作也落不进去**：`_task_append` 对人的动作新增一条
`pen_busy`（SQLSTATE `P0014`），客户端**留着待会儿再推**。

### 为什么是「挡住」而不是「到货之后把两边缝起来」

另一条路是修对账：分辨「云端那一段全是人的动作」这种**交错**，把本地的 executor 尾巴重放到
云端那段之后（`human_only` 那条路的镜像）。否决它的理由有两条，第二条是决定性的：

1. 重放之后 X 那条人话会排在 Y 那一轮的**前面**，而 `lastUnanswered` 是倒着扫到第一条
   `turn_ended` 就收手的 —— 于是「X 说过一句没人答的话」这个事实会被 Y 那一轮的收口**盖掉**，
   没人会去答它。要修好就得给 `lastUnanswered` 引入「这条 turn_ended 答的是哪条消息」这个
   今天日志里不存在的概念。
2. 挡住之后，X 那条话落在**那一轮之后** —— 而那正是它该在的位置：那一轮确实没看见它，
   `lastUnanswered` 于是找得到它，下一轮来答。**不是把话丢掉，是把它排到队尾**，
   等于 ADR-0247「turn 跑着时回车 = 排队」的跨设备版。

### 三条边界

- **`session_created` 例外**：建行那一刻行和笔都还不存在（RPC 建行时才把笔发给创建者），
  拦它等于任务会话根本建不出来。这一条在 `src/shared/taskSync.ts` 的 `PEN_BUSY_EXEMPT` 里，
  SQL 与 fakeCloud 两份实现对着它对表。
- **只挡「别人的」活笔**：自己握着笔时照落 —— 同一台机器上 turn 跑着，用户刚说的话当然要记下来。
- **笔有 30 秒 TTL 且要续期**：持笔方崩了，最多 30 秒后 X 那条就落得进去。这条能力本来就有
  （`PEN_TTL_S` / `PEN_RENEW_MS`），这条决定只是开始依赖它。

### `pen_busy` 与 `pen_required` 分成两个码

前者说「笔是别人的、他正在跑一轮」，出路是**等**；后者说「你要落 executor 事件但没有笔」，
出路是**去拿笔**。合成一个码的客户端会在别人跑 turn 的时候去抢笔。客户端对 `pen_busy` 的处置
因此是「留着 + 排一次重试」——不 acquirePen、不 reconcile（云端没有我们看不见的分歧）、
不 freeze（这是个会自己过去的状态）。

## 后果

- **上线顺序：先发客户端，再跑 0039**（与 0038 那条相反）。老客户端不认识 `P0014`，它落进
  `codeOf` 的 default → `other` → 30 秒重试循环，笔放了照样推上去；但那期间账号页会写一句
  莫名其妙的失败。反过来先跑 migration 没有任何好处。
- **手机客户端（#1254，还没建）从此要认得 `pen_busy`**：它没有本地日志，所以「留着待会儿推」
  在它那儿是一个真的发送队列 + 一句「对方正在回复」。契约已经在 `src/shared/taskSync.ts` 里。
- **云端兜底执行器（#1253）不用另立规矩**：它是同一个形状的第二个持笔方，这条决定对它成立。
- 代价：X 在别人跑 turn 期间发的话**要等到那一轮结束**才在云端出现（最长 = 一轮的时长）。
  这正是 ADR-0247 在单机上已经接受过的代价。
- 一条既有用例的契约翻面了（「人话免笔：别人握着笔也照推」），因为那句话正是这个洞本身。
