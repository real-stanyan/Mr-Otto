# ADR-0235：云会话界面对齐本地会话（头部钉顶 / 占满 / 去审计噪音 / 发言人同形 / 归档进侧栏，协议 9）

- 状态：已接受
- 日期：2026-09-06
- 关联：#993；推进 ADR-0218（工作区里开会话和本地一个开法）/ ADR-0234（仓库配置搬进控制房）/ #987（输入框钉底）/ #985（输入框外壳对齐）

## 背景

维护者对着真机截图一口气点了五处：

> 1. 上面的 header 应该和其他本地会话一样 fixed 在顶部，用户下滑依然也能看到
> 2. 会话区域两边不应该有 padding，应该占满，和其他本地会话一样
> 3. 把「会话已创建，管理员就位，请求信封由用户批准」那些废话全去掉
> 4. 人类发送的信息和智能体一样，只用显示人类用户的名字和发送的时间，不需要显示发送给谁
> 5. 归档按钮不应该显示在 Header，应该显示在左侧栏里会话的点点点 icon 按钮里面，跟其他本地会话一样

五条都是同一句话的分身：**云会话是一条会话，它该长得像一条会话**。ADR-0218 立的「工作区里开会话和本地一个开法」此前只兑现到了「怎么开」，没兑现到「开完之后长什么样」。

## 决策

### 1. 头部钉顶，与已经钉底的输入框对称

#987 把输入框钉在了底部，头部却还跟着内容滚——翻旧消息时「这是哪个工作区、路由走哪条、设置在哪」全看不见。现在 `CloudSessionPage` 是三段：`header(shrink-0)` + 滚动区(`flex-1 min-h-0`) + `footer(shrink-0)`，头部带 `border-b`，与本地会话的 `HEADER`（`settingsShell` 的 `h-11` + `border-b`）同形。

### 2. 占满，不居中

原来是 `w-[min(760px,92%)]` 居中量尺，宽屏上左右各留一大条空白。本地会话的 aui viewport 写的是 `max-w-(--thread-max-width) px-4`，而 **`--thread-max-width` 这个变量本仓从没定义过**——也就是说本地看到的一直是「占满 + 左右 16px」。云会话照抄这一条：外层不再夹量尺，内边距下沉到 `CloudSessionPage` 的三段各自 `px-4`（头部那条 `border-b` 才画得满整幅）。

### 3. 审计噪音不进群聊时间线

`hiddenFromCloudTimeline` 从一条（带 relay 的开场白）扩到五类，新增四类：`session_created`（点开一条会话本来就意味着它存在）、`agent_briefed`（「「管理员」就位」——brief 是提示词/花名册变了就补一条的内务事件，群里会看到一串「就位」而没有任何人做了任何事）、`request_envelope`（「请求信封已更新：型号 · 工具 3 把」是给维护者调参用的）、**批准了的** `approval_decision`。

判据是**这条事件说的是群里发生的事，还是机器的内务**。本地会话那套 AUDIT 小灰字有它的道理——单人调试时「请求信封长什么样」是有用的；群聊的读者是工作区里各行各业的人，同一行字在这里是噪音。这与 ADR-0230 让云会话「说人话」是同一条线上的两步。

**拒绝仍然画**：它中断了流程，群里得看得见「这件事没做成、以及为什么」。这不是噪音，是对话事实。

### 4. 发言人一律左对齐，标签只有名字 + 时间

原来人发的消息靠右、tinted 气泡、标签行写「时间 · → 管理员」，agent 的靠左、muted、写「名字 · 时间」。维护者要的是「人类发送的信息和智能体一样」。

于是 `SpeakerRow` 去掉 `mine` 这个参数——**由构造保证只有一种排布**，而不是把两处条件对齐（同 ADR-0214 那次流式光标的修法）。「→ 发给谁」整条去掉：@ 谁在正文里写着，标签行再说一遍是同一件事说两遍，而它在多人群聊里占的正是最贵的那一行横向空间。

代价明说：群聊里「哪条是我说的」从「靠右」这个视觉线索退化成读名字。取舍理由是这是**群聊**不是双人 DM——三个人以上时靠边站本来就分不出谁是谁，而名字永远分得出。

### 5. 归档搬进侧栏 ⋮，协议 8 → 9

归档从会话头部搬到侧栏那条会话行的 ⋮ 菜单里，同本地会话。为此 `archive` 帧跟着 `config`（ADR-0234）走同一条路搬进**控制房**：带 `workspaceId` + `sessionId`，新增 `archive_result` 回执（控制房没有会话房那条 `session_archived` 广播可当回执；房里的人照旧收得到那条事件，那是**他们**的回执）。会话房里出现 `archive` 视为越权，同 `create` / `config` / `workspace`。

判据与 ADR-0234 逐字相同：**归档一条会话不该以「你此刻正开着它」为前提**。那个前提在界面上的样子，就是那颗只能待在会话头部的钮。

**「删除」不给**：0016 迁移把 `wss_delete_publisher` 钉死在 `kind = 'package'`，云会话故意删不掉（注释写着理由——删了 VPS 上那份权威事件日志就成了够不着的孤儿，且不产生任何归档事件）。给一颗点了必然失败的「删除」是撒谎，比没有更糟。菜单里因此只有「归档」一项。

显隐判据抄服务端那条（#822：owner 或建这条会话的人），为此 `CloudSessionRowView` 多带一格 `creatorUid`——带 uid 不带名字，名字会变而这是个权限判断。渲染层不是安全边界，服务端仍然自己判一次。

## 后果

- 协议 9：runtime 必须 `npm run runtime:deploy`，dev 与它一起换。
- `cloudArchive(workspaceId, sessionId)` 归档成功后自己重拉那个工作区的云会话清单（归档的不进侧栏，不重拉那一行会一直挂着），并且**归档的正是此刻开着的那条时退回主区**——留着一条已收尾的会话在主区没有意义。
- 控制房 RPC 现在是四条（create / workspace / config / archive），共用 `ctlRequest` 一副骨架。
- 已知代价：群聊里分辨「哪条是我说的」要读名字（见决策 4）；`userRowIdentity` 的 `mine` / `targets` 两格还在（`cloudTimeline` 的纯逻辑与它的测试都留着），只是渲染层不再消费——留着是因为它们回答的问题（「这条是不是我发的」「这句话点了谁」）本身没有消失，将来若要给自己发的消息加一个别的记号，判据现成。
