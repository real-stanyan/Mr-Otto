# ADR-0200：云沙箱克隆——判据是一张表、凭据不进水獭的容器、配置要有读路径

- 状态：已接受
- 日期：2026-09-01
- 相关：#832 #833 #834 #835 #836（#821 的后续复审）；推翻 ADR-0199 落地时的两处做法

## 背景

#821 把云沙箱的 `git clone` 接上线之后，一次通读复审在同一条链路上找出五组缺陷。
它们看起来分散，其实是三个同源的判断失误。

## 一、要不要 clone：一个布尔答不了这个问题（#832）

原实现只问一件事：`git -C /work rev-parse HEAD` 成不成功。

两个答案各自都能造成损失：

- 答「能」⇒ 跳过。于是 owner 换了仓库地址**永远不生效**——`invalidateClone`
  （#821 复审专门加的那道口子）被这条判据吃掉，而且跳过分支从不通报，
  人完全看不出自己的修正被吞了。
- 答「不能」⇒ `find /work -mindepth 1 -delete` 后重新 clone。于是一个
  「先用了一阵、后来才配仓库」的工作区，水獭之前的产出被**无声清空**，
  而本期不允许 push ⇒ 没有任何远程备份。

**决定**：把这个问题拆成「现状是什么」和「据此该做什么」两步。
`probeWorkState` 探成五态（empty / repo / partial / foreign / unknown），
`decideCloneAction` 是纯函数决策表：

| /work 现状 | 动作 |
|---|---|
| 空 | clone |
| 有 .git 但没有可用 HEAD（我们自己上次的半成品） | 清空 + clone |
| 完整克隆，origin == 配置 | skip |
| 完整克隆，origin != 配置，干净且没有本地领先提交 | switch（清空 + clone） |
| 完整克隆，origin != 配置，脏 / 有本地领先提交 | **refuse** |
| 非空且不是 git 仓库（水獭的产出） | **refuse** |
| 探不出来 | **refuse** |

三条支撑判断：

1. **清空只发生在"能证明可丢弃"的两种情形**，其余一律拒绝并说明。默认值
   从「删」翻成「不删」——删错不可逆，拒错只是让人多点一下。
2. **`ahead` 拿不准时按最坏情况**（没有 upstream / 命令失败都算「有本地
   领先提交」）。云沙箱不允许 push，所以本地领先的提交在这台机器之外
   没有任何副本。
3. **每条分支都有回执**，包括 skip。`CloneOutcome` 从 `ok + reason` 换成
   `kind` 五态——判据是**事实**不是线索，同 ADR-0193 那条教训。上一版的
   类型里「幂等跳过」根本没有位置（它被实现成"压根不回调"），这正是它能
   瞒住所有人的原因：没有回调 = 没有任何一处消费方有机会说话。

**什么前提失效会推翻它**：如果将来允许 push，「有本地领先提交就拒绝」
这条会从保护变成阻碍（提交已经有远程副本了），那时该改成「已推送的
提交不算数」。

## 二、凭据落在哪：用完即焚防不住同居（#835⑤，推翻 #821 的做法）

原实现把 PAT 写进**水獭自己那台容器**的 `~/.git-credentials`，clone 收尾
用 `git credential reject` + 删文件 + unset helper 擦掉，`try/finally`
保证至少跑一次。#821 的复审为这套机制补过两个洞（C1 异常路径、C2 残留
探测）。

问题是这套机制存在的前提本身就是缺陷：

- clone 那几分钟里凭据就在水獭的容器里，它**之前起的后台进程**读得到
  （前台工具调用被 `ensure()` 串住，后台 bash 不受这条约束）；
- 清理终究是尽力而为——cleanup 自己那条 exec 也会失败（容器正在重启），
  失败之后 PAT 要留到「下一次这个 workspaceId 被 ensure 到并命中幂等
  分支」才有机会补救。

**决定**：clone 跑在一台**一次性旁路容器**里（挂同一个卷，跑完整台删掉）。
凭据只存在于那台容器的可写层，容器一死凭据跟着死。原来那套
`cleanupCredentials` / `cleanupResidualCredentialsIfAny` / try-finally
整个删掉——不是"简化"，是它们要解决的问题不存在了。旁路容器打
`mrotto.clone` 标签，`reconcile` 收走 daemon 崩溃时漏下的那台（里面有
PAT，不能等孤儿宽限那 7 天）。

代价：每次真 clone 多一次 create+start+remove（幂等跳过不付这个钱）。

**什么前提失效会推翻它**：如果将来 clone 需要在水獭容器内的上下文里跑
（比如要复用它的网络命名空间/挂载），就得重新找一条隔离路径，而不是
退回同居 + 擦干净。

## 三、云会话的模型没有 system 提示词（#833）

`deriveMessages` 只从 `session_created.workspace` 产出那条 system 消息，
engine 不会补默认值；而 daemon 建云会话时从不 append 这条事件。于是云端
水獭跑在一条**完全没有 system 提示词**的上下文里。顺带日志从第一条起就
不满足 `invariants.ts` 的「session_created 唯一 / 在头部」。

**决定**：建会话时 append `session_created`（`workspace = /work`），并给
这条事件加可选的 `cloud` 字段，投影据此多注入一段云会话独有的事实。
身份走**日志字段**而不是 runtime 现场拼提示词——投影必须可从日志推导
（硬规则）。

云那一段只收四条，判据是「模型不知道就会做错事」：在容器里 / 群聊消息
长什么样（否则它会把别人的发言当成对它说的） / 审批归发起人或工作区
所有者（桌面那句「弹给用户审批」在多人场景字面上不成立） / 不允许 push
（否则它会以为提交已经安全了）。

## 四、配置只有写路径（#834）

原协议里 config 是单向的：发上去，静默保存，没有回执，也没有任何查询
窗口。三个后果：按钮上的「已保存」只证明本地 encode 没抛异常（叠加 #829
的静默丢帧）；没人查得到「现在配的是哪个仓库、拉下来没有」；校验只在
渲染层，而那份的定位已经写明是 UX 提示。

**决定**（协议进位到 v2）：

- `validateRepoUrl` 两端共用一份，**结构化白名单**：解析得开 / 是 https /
  userinfo 为空 / 有 host。刻意不是「检测有没有藏凭据」那种黑名单——那条
  路在 #821 被复审连破三轮。凭据在 git URL 里只能住在 userinfo，所以这条
  判据是结构性的，不依赖认出任何花样。服务端**自己**校验一次。
- `welcome` 带 `repo`（当前配置 + 最近一次 clone 结局），任何成员一 join
  就看得见。**token 本身永远不下行**，只回 `hasPat` 布尔。
- 新下行帧 `config_result`，不复用 `error`（那条帧还承载 backlog 跳过、
  审批失效之类消息，await 它会被不相干的 error 提前唤醒）。客户端等不到
  回执时说「不确定有没有生效」而不是「失败了」——服务端完全可能已经存好了。
- **加字段照样进位**：握手是精确相等，宁可让老客户端在 hello 那一步被
  明确拒绝，也不要它收到一条读不懂的 welcome 之后静默少一格状态。
- PAT 三态（省略 = 不动 / `""` = 清除 / 非空 = 换新的）：地址栏一旦预填，
  「留空 = 清掉 token」就成了静默陷阱。

## 五、磁盘（#836）：只做能做的那一半

每工作区一个卷，CPU/内存/PID 都有上限，**磁盘没有**。真正的每卷配额要看
存储驱动（overlay2 + xfs prjquota 才支持 `--storage-opt size=`，ext4 上传
这个参数 docker 直接报错）。

**验过的前提**（ADR-0134 要求记下验法）：这台 runtime VPS 现在没法验——
`scripts/runtime-deploy.mjs` 的 `RUNTIME_SSH` 是运行时 env，仓库和
`~/.ssh/config` 里都没有记录主机；二期从未部署过。

**决定**：先做 clone 前的可用空间下限闸（挡不住「一个 50G 的仓库占 50G」，
能挡住「磁盘已经快满了还起一次 clone 把整台机器写死」）。`df` 读不出数字
就放行——为一个猜不出来拒绝 clone，代价比它挡住的风险大。真配额等机器
落地后按存储驱动定，#836 留着。

## 其余三处（#835①②③④）

- `ensure()` 加并发去重：两条会话同时起 turn 会各建一次容器，后者拿 409。
- 容器/卷真被回收后 `forget` 掉 `cloneAttempts` / `lastActive`，否则那个
  工作区在本进程内再也不会 clone。
- `destroy()` 没有调用方这件事写进注释——**reconcile 才是唯一真删路径**，
  留一个看起来接了其实没接的方法比没有更糟。
- 工作区被回收时连带删掉 `workspace-config.json` 里那条（含明文 PAT）记录，
  上一版只写不删。
