# 0063 灵动岛多智能体列表

日期：2026-08-22 · 设计：docs/superpowers/specs/2026-08-22-notch-island-multiagent-design.md · 演进 ADR-0061，兑现 ADR-0059 失效前提

## 背景

ADR-0061 落地的原生 Swift 灵动岛只跟主窗当前选中的单一会话（单 `activeSessionId` → 单 `IslandSnapshot`）。这个单会话版从未合并上线，一直在 `claude/notch-island-swift` 分支上。

用户对单会话版验收后要求：岛展开态不能只显示一个会话，要像主窗侧栏那样列出所有 otto 会话、各自显示运行状态。

ADR-0059（灵动岛是第二个日志投影窗口）早就写了这条失效前提：

> 若将来岛要聚合多会话，`activeSessionId` 单值模型要改成集合。

本 ADR 记录兑现这条前提所做的模型变更：单会话投影 → 会话集合投影。**这是 ADR-0061 的演进，不是它的推翻**——原生 Swift helper、stdio NDJSON 桥、主进程算权威投影/Swift 无权威状态这几条 ADR-0061 立下的架构决定原样保留，只是被投影、被推送的载荷从"一个会话的状态"变成"一组会话的状态"。

## 决定

- **主进程状态从单 `IslandState` 换成 `Map<sessionId, IslandState>`**：每会话一份现有结构的 `IslandState`（`phase`/`currentTool`/`turnStartedAt`/`pendingApproval`/`callsById` 不变）。`feedIsland` 的四类输入（event / turnStatus / approvalRequest / activeSession）都带 `sessionId`，路由到 `Map` 里对应那份继续复用 `reduceIsland`（`reduceIsland` 本就按 `sessionId` 过滤事件，不用改）——**不为多会话另写 reducer**。会话删除/purge 时从 `Map` 里删对应条目。
- **推送载荷从单 `IslandSnapshot` 换成整包 `IslandFleet`**：
  ```ts
  interface IslandAgent {
    sessionId: string;
    title: string;
    phase: "idle" | "active" | "approval";
    currentTool: { verb: string; target: string } | null;
    turnStartedAt: number | null;
    pendingApproval: { callId: string; verb: string; target: string; fullPath: string | null } | null;
  }
  interface IslandFleet {
    agents: IslandAgent[];
    focusedSessionId: string | null;
  }
  ```
  `flattenFleet(states, sessions, focusedSessionId)` 遍历会话、拍平成 `IslandAgent[]`，任一状态变化就整包（非增量）重推——沿用 ADR-0059 已经论证过的"推送多一份拷贝，丢弃成本可忽略"。
- **镜像侧栏可见集合**：列表口径 = `groupSessionsByWorkspace` 的可见集合——`spawnedFrom === null`（非子会话）且 `workspace !== null`（非史前），按 workspace 分组、组内 `lastTs` 倒序展平。不自造一套新的可见性规则；子会话不独立成行（子会话只活在父时间线里）。
- **审批行置顶**：`phase === "approval"` 的 `IslandAgent` 排到列表顶、加高亮——这些是需要人当场动手的行。
- **就地操作按选中行的 sessionId 分发**：出向命令（`send`/`approve`/`deny`）本就带 `sessionId`，未变；主进程收到命令后按这个 `sessionId` 路由到对应 agent（`handleSendMessage`/`handleDecideApproval` 已经是按 sessionId 工作的，不用改）。选哪一行操作哪一行，跟主窗当前聚焦的会话（`focusedSessionId`，即原来的 `activeSessionId`）解耦——`focusedSessionId` 现在只是"默认高亮哪一行"的提示，不再是"唯一被投影的会话"。
- **Swift 侧**：`IslandModel` 从持单 `snapshot` 改成持 `@Published var fleet: IslandFleet` + `@Published var selectedSessionId: String?`（默认取 `fleet.focusedSessionId`，回落到列表首行，选中会话消失时同样回落）。展开视图渲染 `List(fleet.agents)`（每行状态点 + 标题 + active 时的当前工具），选中行下方就地展开该会话的详情（active 详情 / 审批三按钮 / compose 输入框，复用 ADR-0061 已有的详情视图，只是入参从 `snapshot` 换成选中的 `IslandAgent`）。
- **展开面板限宽**：真机验收发现展开态因为行内 `Spacer(minLength: 0)` 贪婪吃满宽度、叠加 DynamicNotchKit 面板本身 `maxWidth: .infinity`，渲染成横贯全屏的黑条。修法是给展开根节点加 `.frame(width: 380)`——落在设计预期的 360–420pt 区间，够放状态点+标题+简短工具 caption 单行不换行，也给审批三按钮和输入框留够地方，同时保持"贴刘海的紧凑卡片"而不是全宽条。

## 否决项

- **Swift 侧聚合多会话**（Swift 自己拿事件流投影出会话列表）：会导致 TS 和 Swift 各写一份"多会话怎么分组/怎么排序"的逻辑、手动保持同步，重复 ADR-0061 已经否决过的"跨语言重复 reducer 是维护地雷"。主进程本就是事件日志的所有者，继续由它算好整包 `IslandFleet` 推出去，链路仍是权威投影的一环，不是二次投影。
- **增量推送**（只推变化的那几个 agent，而不是整包 `agents[]`）：先用整包重推，理由是 YAGNI——每个 `IslandAgent` 就几个字段，会话数量在个位数到十几的量级，载荷仍小；ADR-0059 已经论证过"丢弃成本可忽略"同样适用于这里。真要因为会话很多导致抖动明显，再单独立项做增量。

## 后果

- **推送载荷随会话数线性增长，但单个字段量很小**：每次任一会话状态变化都整包重推 `IslandFleet`，载荷大小 = 会话数 × 每 agent 几个字段（sessionId/title/phase/tool/timestamp/approval），个位数到十几个会话的量级下可忽略。
- **选中态是 Swift 本地状态，不进事实源**：`selectedSessionId` 只活在 `IslandModel` 里，不回传主进程、不影响任何投影——纯 UI 局部状态，符合"投影可从日志推导"的 Hard rule（选中哪一行不是事实，是查看视角）。
- **`Map` miss 必须带 sessionId 播种，否则非聚焦会话永远卡 idle**——这是 review 中抓到的一个 Critical bug：`feedIsland` 遇到 `Map` 里还没有对应条目的会话时，如果用一个 `sessionId` 为 `null`/未播种的默认 `IslandState` 去跑 `reduceIsland`，`reduceIsland` 自带的按-sessionId 过滤 guard 会把这个会话的 event/turnStatus/approval 事件全部挡在外面——效果是这个会话在列表里永远显示 idle，功能实质失效（违背"列出所有会话各自状态"的设计目标）。修法是 `Map` miss 时用**该会话自己的 sessionId** 播种初始 `IslandState`，让后续事件能通过 `reduceIsland` 的 guard 正常路由进去。这是本次改动里最容易复发的一类 bug，写入 ADR 供后续改动这段代码时对照。
- **打包/签名/构建链不变**：沿用 ADR-0061 的 Swift toolchain、`scripts/build-island.mjs`、`afterPack` 签名流程，本次改动只是协议载荷和 UI 层的变化，不涉及打包管线。

## Hard rules 自检

- **投影可从日志推导**：`IslandFleet` 里每个 `IslandAgent` 仍由主进程从既有事件流（`store.sessions()`、每会话的 `reduceIsland`、`approver.pendingRequest()`）算出，Swift 无权威状态，只做渲染。✓
- **不新增 SessionEvent**：多会话状态是既有事实的另一种投影方式（从"单值"变"集合"），没有引入新的事实来源。✓
- **ShellBridge 边界**：Swift helper 仍是主进程独占的外部 seam（子进程 + stdio NDJSON），不是 Electron 渲染进程，ADR-0061 里的说明继续适用。✓
- **SessionEvent 向后兼容**：不改事件 schema，本次只改主进程内部状态结构（`IslandState` → `Map<sessionId, IslandState>`）和桥协议载荷（`IslandSnapshot` → `IslandFleet`）。✓
