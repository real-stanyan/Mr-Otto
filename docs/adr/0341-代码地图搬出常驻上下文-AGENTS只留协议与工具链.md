# ADR-0341：代码地图搬出常驻上下文，AGENTS.md 只留协议与工具链

日期：2026-10-04 · issue #1466 · 维护者在会话里说「按你推荐处理」

## 背景

`AGENTS.md` 是每个会话、每个子 agent 都常驻加载的文件。一次提示词审计（按 Claude Opus 5.5 的口径）量出来：

- 全文约 18.4 万字符，其中「Where to find things」索引占约 15.7 万（91%），176 条。
- 每条在复述对应 ADR 的论证，夹着 issue 号、「真机一次没跑过」（19 处）、部署状态。这些状态写下来就开始过期。
- 复述已经和代码分家了。三条路径（`src/renderer/src/lib/billingError.ts`、`src/renderer/src/lib/workspaceUsageView.ts` 两处）指向早已搬进 `src/shared/` 的文件，而同一份索引后面那条自己就写着「挪进 shared」。
- 协议里「交接只引用、不复述——副本会腐烂，引用不会」（ADR-0045）说的正是这件事，只是写给 Memory 的。

这份内容本身有用：动一块代码之前，那一条往往写着最容易踩的坑。问题不在内容，在于它常驻。一个只改手机端的会话，也要先读完计费、中继、灵动岛的全部论证。

## 决定

1. **索引原样搬到 `docs/where-to-find-things.md`**，一个字不删、不改写。路径打头的格式不变，按路径 grep 就能找到那条。
2. **`AGENTS.md` 只留 8 条**：协议与工具链的入口（`CONTEXT.md`、两套 ADR 目录、Hard rules 与 ADR 编号的两条断言、`wip`、`lane`、`pre-commit`），再加一行指针，写明「动一块代码之前先按它的路径在新文件里 grep；新条目加在那里」。
3. **Division of labor 那段 Gearbox 模板菜单**（三选一，从 2026-08-16 接入起没填过）改成一句话，即菜单里第 2 项写着的默认规则：claim-based ownership。这一条改的是 Working agreement 的正文，属于 L1，维护者在会话里同意了。

## 代价

- 模块上下文从「一定读到」变成「要去 grep 才读到」。指针那句话是唯一的保证，没有机制强制。如果之后发现 agent 改代码前不再翻代码地图、重新踩已记录的坑，就把高频那几条挪回来，或者在 lane 脚本里提示。
- 三条过时路径**没有随这次一起改**：审计方法规定，「路径与代码对不上」这类改动要逐条确认后才动，补丁另放。
- 新文件约 30 万字节。`tests/architecture.noControlChars.test.ts` 扫 `.md`；内容是原文照搬，不会引入控制字符。

## 推翻的前提

如果 Claude Code 之后支持按路径条件加载（只在碰到某目录时注入对应段落），代码地图就该按目录拆回去，跟着代码走。
