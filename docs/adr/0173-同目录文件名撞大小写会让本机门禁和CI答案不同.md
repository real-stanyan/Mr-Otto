# ADR-0173：同目录 TS 文件名不许只差大小写——它会让本机门禁与 CI 给出不同答案

- 状态：已接受
- 日期：2026-08-29
- 关联：issue #687；起因是 PR #685（连接器目录页）；被它证伪的是同一个 issue 里最初那份「平台二进制差异」的判断

## 背景

PR #685 本机 `npm test` 全绿，推上去 CI 立刻红：

```
tests/renderer/McpDirectory.test.tsx(281,41): error TS2493: Tuple type '[]' of length '0' has no element at index '0'.
```

CI 是对的——那行 `saveMcpServer.mock.calls[0]![0]` 确实有问题（`vi.fn(() => …)` 的实现不收参数，`mock.calls` 是 `[][]`）。问题是本机放过了。

第一版判断写成「TypeScript 7 是 Go 重写的，二进制按平台走 optionalDependencies，本机 darwin-arm64 与 CI linux-x64 同版本结论不同」，并在 issue 里列了四条收口方向，其中一条是改 AGENTS.md 门禁一节（L1）。**这个判断是错的**，下面的排除过程把它证伪了。留下这段是因为它本身是个教训：一个能解释现象的假说，和现象的真实成因，是两回事。

## 排除过程

1. **node_modules 漂移**：另 clone 一份、`npm ci --ignore-scripts` 全新装（同一份 lockfile），本机对那份文件仍然 exit 0 → 排除
2. **本机是不是压根不查这条规则**：单独写一个最小文件（`vi.fn(() => Promise.resolve(...))` + `calls[0]![0]`），本机立刻报 TS2493 → 排除
3. **决定性的一步**：往 `tests/renderer/McpDirectory.test.tsx` 里塞一行 `const x: number = "nope"`，本机 tsc 一声不吭

第 3 步之后没有悬念：本机压根没在检查这个文件。

## 成因

`tests/renderer/` 下同时有：

```
tests/renderer/McpDirectory.test.tsx     ← 组件测试
tests/renderer/mcpDirectory.test.ts      ← 纯逻辑测试
```

去掉扩展名后是 `McpDirectory.test` 与 `mcpDirectory.test`，**只差首字母大小写**。macOS 的 APFS 默认大小写不敏感，tsc 按规范化（小写）路径给 program 里的文件去重，两者撞成同一个键，而 `.ts` 的扩展名优先级高于 `.tsx`——`.tsx` 那份被静默丢出 program。Linux 上文件名大小写敏感，两者是不同的键，都在，所以 CI 查得到。

把 `mcpDirectory.test.ts` 改个名，本机立刻报出那条 TS2493。

全仓当时有两对，逐个塞错误验过（`1` = 本机会检查它）：

```
McpDirectory.test.tsx     0        SideChatWindow.test.tsx   0
mcpDirectory.test.ts      1        sideChatWindow.test.ts    1
```

解开遮蔽后全仓只多出上面那一条错，`SideChatWindow.test.tsx` 本身是干净的——但它同样从没被本机检查过，是一个还没兑现的洞。

**vitest 照跑不误**：它按文件系统 glob，两个文件在盘上是真的两份。所以现象不是「测试少跑了」，是「测试都在跑，其中一份从没过过本机的类型检查」——没有任何症状，直到它里面有一个错，而那个错只在别人的机器上出现。

## 决定

**同一个目录下，两个 TS 文件去掉扩展名之后不许只差大小写。** 由 `tests/architecture.caseCollision.test.ts` 断言，跑在门禁里。

两对碰撞按「只改名、不动目录结构」消掉：`mcpDirectory.test.ts` → `mcpDirectoryLogic.test.ts`，`sideChatWindow.test.ts` → `sideChatWindowLogic.test.ts`。三个文件（两个改名的 + 那份 `.tsx`）的头部各留一行，写明名字里那个 `Logic` 不是修饰语而是碰撞的解药——否则下一个做整理的人会觉得它冗余而改回去。

**为什么光改名不够**：改名只处理了当下这两对。下一个人再起一对同名文件，静默复发，而复发的表现是「某个测试文件从此不过类型检查」——没有任何人会注意到。断言才是改名的保鲜期。

## 被否掉的

- **按 `src/` 结构把 `tests/renderer/` 拆成 `components/` 与 `lib/`**：这是根因层面的修法（碰撞是 `tests/renderer/` 把 `src/renderer/src/lib/` 和 `src/renderer/src/components/` 拍平进同一个目录的直接后果），也更贴 AGENTS.md「测试镜像 `src/` 结构」那句。否掉的理由是代价与收益不成比例：一次搬动 `tests/renderer/` 下 40+ 个文件，diff 大到 review 只能看个总数，而防复发的效果和一条断言相同——拆完之后照样可以在 `components/` 里起一对撞名文件。**推翻它的前提**：如果 `tests/renderer/` 因为别的原因要重排，那时顺手拆掉，这条断言仍然有效、不冲突。
- **打开 `forceConsistentCasingInFileNames`**：管的是 import 路径的大小写与磁盘不符，不是同目录两个不同文件互相遮蔽，对本问题无效。
- **改 AGENTS.md 门禁一节，承认本机门禁只是预筛**（issue #687 原文列的第 4 条，L1）：建立在「平台差异不可消除」这个已被证伪的前提上。命令没问题，平台也没问题，是仓里两个文件名起重了——不该为一个可修的 bug 去放松协议。

## 后果

- 本机门禁与 CI 在这一类上重新对齐：「本机绿 ⇒ CI 绿」这个前提恢复成立（AGENTS.md 门禁一节的 CI == Gate contract 靠的就是它）
- 断言扫的是全仓 `.ts` / `.tsx`（跳过 `node_modules` / `out` / `dist` / `mobile` / `.git` / worktree 目录），不限于 `tests/`——`src/` 里起一对撞名文件同样会让其中一份逃出类型检查
- 报错信息直接给出撞的是哪两个文件、以及为什么必须改名，不需要读这篇 ADR 才知道怎么办
- 代价：两个测试文件的名字比原来长了一截，且这个长度是防御性的，不是描述性的——所以三处头部注释必须留着，它们是这个名字唯一的解释
