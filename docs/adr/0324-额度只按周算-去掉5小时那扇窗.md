# ADR-0324：额度只按周算——去掉 5 小时那扇窗

- 日期：2026-09-28
- 状态：已采纳
- 关联：#1392；维护者在 #1391 拍板第 2 条（「要」）。之前维护者原话（#1386）：「改一下额度的规矩，不要分 5 小时和本周了，只分本周就行，这样子简单一点」
- 关系：**推翻 ADR-0174 决定 2/3 里 5 小时那一扇窗**（双固定窗只剩周窗；ADR-0203 决定 2/5 的累计数 + 惰性清零照旧，用在周窗上）。ADR-0238 的预算闸分母从「5h 与周窗里更吃紧的那扇」换成周窗、份额 0.5 → 0.1（决定 6）。ADR-0323 决定 7（手机那句「5 小时更紧时的实话」）随之作废。ADR-0209 / 0239 / 0254 / 0255 / 0289 里所有「两扇窗」的界面描述，从此都只剩周窗一扇——判据（报剩余不报已用、色档按已用、清零不画倒计时、`null` 不画）原样成立

## 背景

订阅额度原来是两扇固定窗：周窗，加一扇上限为周窗 20% 的 5 小时窗（`plan.window5hLimitMicro = week × 0.2`），两扇都不超才放行。维护者要的是规矩本身只剩一条。#1386 的手机端先在设计上只画了本周（ADR-0323 决定 7），这一条把真规矩改掉。

## 决定

1. **5 小时窗整个拿掉，不是把上限调大。** 调大等于留着一扇永远不拦人的窗——它照样要在 DO 的状态里记、在冷启动重建里回放、在响应头里报，每一处都是「这扇窗到底还算不算数」的一次误读机会。`services/edge/src/quota.ts` 只剩周窗：`hold` 只比周窗、`view` 只回周窗、`remaining` 只回周窗与加购。
2. **旧 DO 落在 storage 里的 `open5hAt` / `used5hMicro` 两格留着不读**，不写迁移。多两个没人读的字段不会让任何判断变错；为它们写一段迁移，反倒是一次改「钱的状态」的机会。有一条用例钉着：一份 5h 那格早就「满了」的旧状态，照样按周窗放行。
3. **`/me` 照旧多下发一扇永远不拦人的 `h5`**（edge 的 `legacyWindows`：用了 0、上限与周窗相同、刷新时刻跟周窗走）。已经装在用户机器上的桌面版解析 `/me` 时两扇窗缺一不可——缺了整份快照解析成 null，等于「拿不到订阅状态」，托管那条路走不通。补这一扇之后旧版多画一只满格的「5h」表，而「最吃紧那扇」一有用量就轮到周窗，告警与倒计时都跟着周窗走——行为上就是只按周。新代码不读它（`parseBillingMe` 只认 `week`）。旧版都升级之后这一格可以删。
4. **响应头 `x-otto-window-5h-remaining` 不再发。** 旧客户端拿不到这个头就沿用 `/me` 那份（用了 0），不会误报耗尽；新客户端本来就不读。
5. **`usage_event.window_open_at` 不再写、不再读；`plan.window5h_limit_micro` 不再读。** 两列都留在库里（旧行里的值原样在），这次不跑 migration——删列是另一件事，而一张钱的表上的删列要单独算账。冷启动重建只按周段求和（`rebuildWindowSince` = 周段起点）。
6. **接力预算闸：分母换成周窗剩余，份额 0.5 → 0.1**（`RELAY_BUDGET_FRACTION_OF_REMAINING`）。原来是「5h 窗剩余的一半」，而 5h 窗上限 = 周窗 × 0.2，满额度时刹车点 = 周窗的 10%；照这个量级折算成 0.1，满额度时一次点火能花的钱与改动前逐字相同。照搬 0.5 的话同一件事能吃掉半周的额度，刹车等于松了五倍。
7. **界面**：上下文浮层「套餐额度」只剩一只表；设置页只剩一格；灵动岛页脚与告警点照周窗（`bindingWindow` 留着，只是只剩一扇可选——岛、浮层、告警点、设置页都从它取「主数字画哪扇」，哪天再多一扇窗改的只是这一个函数）；手机那句「5 小时更紧时的实话」删掉，订阅页脚注改成「越往上，每周的额度越多」。
8. **旧网关的窗名 `"5h"` 在新客户端当缺席**（`parseBillingError` 只认 `"week"`），界面照「额度用完了」说。`exhausted` 记号只留 `resetAt`，不再记是哪一扇。

## 后果

- **没有了「别一口气烧完」的节流**：5 小时窗原来让人没法在一个下午用掉一整周的额度。现在可以。这是维护者要的简单的代价。
- **部署顺序是 edge 先**：新客户端连旧 edge 时，5 小时的拦截会被说成「额度用完了」（窗名认不出当缺席）而界面上只有周窗、看起来还有余量；edge 先上就不存在这个组合。旧客户端连新 edge 行为正确（决定 3）。runtime 随后（决定 6 在 runtime 里生效）；桌面与手机随下一次发版。
- **旧桌面版会多画一只满格的「5h」表**，直到升级。
- 档位与周上限没动：同一个档位每周的额度与改动前相同。
