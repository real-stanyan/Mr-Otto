# ADR-0374：智能体要连应用时发连接卡——按钮由手机判断，连上和「不用了」都起一轮接着说

日期：2026-10-05 · issue #1666 · 维护者原话：「如果智能体办一些事需要外部应用登录的话，跳一个快捷方式的弹窗给用户，让用户点击进去快捷连接需要操作的应用」
设计与逐点依据见 `docs/superpowers/specs/2026-10-05-app-connect-card-design.md`，实施计划见
`docs/superpowers/plans/2026-10-05-app-connect-card.md`；本条只记决定与取舍。

## 背景

云端智能体办事要用某个连接器目录里的应用（Supabase、GitHub、飞书……）而主人还没连、或连着但登录过期时，今天只能在回复里
说一句「请去 我 → 应用 里连」，主人得自己找入口、连完再回来说一声。维护者要的是：智能体发现缺应用，会话里就出一张卡，主人点一下
就去连，正看着页面时还自动弹一张居中弹窗。选人卡（ADR-0361）已经给出了「会话里一张带状态的卡、折日志算开没开」的形状；手机端
`ConnectAppDialog` 已有完整的接入 / 重新登录流程；缺的是智能体侧的发卡通道，和卡点完之后「接着办」的回路。

## 决定

1. **显式工具 + 登录过期自动兜底**：`request_app_connect(app, why)`（`services/runtime/src/requestAppConnectTool.ts`，不过审批门——
   只在自己会话里画一张卡，真正的授权在主人手里，论证同 ADR-0358 决定 2）；另外 `pxTools` 调连接器拿到 edge 的 409
   `needs_login` 时，经 `onNeedsLogin` 回调自动发一张 `reason: "needs_login"` 的卡，并把工具错误文本换成「X 的登录过期了，已经在会话里
   请主人重新登录；这一轮别再调它」。两条路共用 `sessionService.offerAppConnect`：已经在工具里（只对 missing 成立）/ 已有开着的卡 /
   每会话每小时 3 张，三种情况都不再发卡，回给模型的那句话如实说没发。事件类型 `app_connect`（ignorable、模型不可见、持久化），
   生命周期照选人卡：发出 24 小时过期、同一会话同一应用发新卡则旧卡被顶掉，状态读时折（`src/shared/appConnect.ts`）。
2. **按钮由手机判断，不由 runtime 判断**：runtime 读不到主人的「云箱」——`/px/v1/cloud*` 对平台身份回 403（`edge.ts`），它只能读
   `/px/v1/grants`，那里只列状态正常、此人用得了的应用，登录过期的整台不进。所以卡里只存目录 id，手机拿自己的 `cloudView` 与这个
   工作区的授权算出「去连接 / 重新登录 / 打开 / 好了，接着办」四选一（`appConnectAction`）。runtime 只管一件事：这个应用此刻已经在
   智能体的工具里了，就不发卡、直接让它用。
3. **连上和「不用了」都起一轮**：主人点按钮发上行帧 `app_connect { connectId, outcome }`（`frameHandler` → `CloudSession.answerAppConnect`），
   落结局事件后写一条 `greeting: "app_connected"` / `"app_declined"` 的开场白（mentions 发卡那只）并 `coordinator.enqueue` 起一轮，
   智能体回一句话、接着办或改路。`connected` 同时清 `grantsSnapshot`，否则 60 秒内下一轮还看不到新工具。这条开场白算主人亲口
   （只有主人点得出来，工具又不在受监督轮里给）。**计划原文「忽略不起轮」改了**：不起轮的话这句话要么丢、要么当一条没人回的开场白挂着
   （重启补跑会把它当未答的话再跑），不如直接让智能体回一句。
4. **只在主场、非外联 / 车道、L0 / L1**：团队工作区、外联会话、私密车道不挂工具也不认点击（`answerAppConnect` 与挂载条件同一句判据）；
   受监督轮不给工具——朋友点起的轮不能替主人要授权；等级只有 L0 管理员和 L1 专员，且要有连接器域（`connectorsAllowed`）。409 兜底只认主人自己云箱里的应用
   （`hostUid === ownerUid`）：别人借来的应用过期了，轮不到这位主人去登。**409 兜底不排除受监督轮 / L2**（只受「主场 + 非外联 + 非车道」限制）：
   主人的应用登录过期迟早要主人去登，卡无害；代价是朋友点起的轮里主人也会看到一张重新登录卡。
5. **手机弹窗只认「看着它来的」**：卡到的那一刻主人正在这一页（页面与 app 都在前台）才自动弹居中弹窗，每张卡弹一次；
   进页时已有的卡、翻历史都不弹。走开（失焦 / 后台 / 重连）就作废基线，下一次「在场且日志到齐」时重取——离开期间到的卡回来不补弹
   （补弹等于翻历史），只剩会话里的卡。一次一张：弹最新那张，此刻符合的每一张都记成弹过。主按钮先收弹窗，等 `onExited` 再升
   `ConnectAppDialog`，不叠在正在退场的 Modal 上。判据全在 `src/shared/appConnectPopup.ts`（`popupCandidate` / `nextBaseline`）。
6. **协议 29 → 30**：新增上行帧 `app_connect`、下行帧 `app_connect_result`。

## 否决的

- **runtime 自己判「没接过 / 过期 / 没开给这里」**：判据读不到（决定 2），硬接要给平台身份开云箱读口，扩大权限面只为省手机一行判断。
- **选人卡那条路（点完不起新一轮，结果靠别处回到模型）**：选人卡点完直接拨电话，结果靠通话汇报回来；连接卡要「连上了接着办」，没有这样的外部回路。
- **只做 409 兜底、不做显式工具**：「根本没接过」不会产生 409，模型只能在回复里说一句了事。
- **桌面也画**：桌面云会话页的卡片类事件（选人卡、应用卡、任务卡）一律不画，单给这一种画旁白反而不一致；`hiddenFromCloudTimeline` 挡掉。
  桌面本地会话本来就有 `mcp_authorize`。
- **卡走推送的专门通道**：靠工具让模型说的那一句走现有回复推送，不另开一条。

## 代价与已知未做

- **协议 30：旧手机连新 runtime 被握手拒**、提示更新（同以往每次协议 +1）。**部署顺序：runtime → 手机热更新。** 无 migration。
- 团队工作区一期不发卡（工具回「团队里先不支持，让主人去 我 → 应用 里连」）；桌面不画。
- 每小时 3 张的窗在 runtime 内存里，重启清零（同 ADR-0358 的已知代价）。
- 离开期间到的卡回来不弹窗（决定 5），只剩卡；想连自己点。
- 目录里的 Supabase 连接器是只读的：接上也跑不了 migration，卡说的是「连上」，不是「能改库」。
- 预览期条目发卡时不筛（不知道主人是不是内测账号），接不上由接入弹窗当场说。
- 真机未验：弹窗叠 `ConnectAppDialog` 的实际观感、卡点完起一轮的往返延迟。
