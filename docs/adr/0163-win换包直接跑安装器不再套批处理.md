# ADR-0163：win 换包直接跑 NSIS 安装器，不再套一层批处理

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #662；**推翻 ADR-0081 / issue #314 的 win 席位实现**（更新器的席位化结构不变，换掉的只是 win 那一格的做法）；ADR-0075（OTA 自研换包的总设计）

## 背景

Windows 上走 OTA：下载完点「重启更新」，屏幕开始不停弹控制台黑框，框上写着 `find "<pid>"`。

原来的 win 席位（ADR-0081）照抄了 mac 的形状：写一个脚本、detached spawn 它、`app.quit()`，脚本轮询等本进程退干净，再动文件。mac 那边是 `/bin/sh`，win 这边是一个 `swap.cmd`：

```bat
:wait
tasklist /FI "PID eq %APP_PID%" 2>nul | find "%APP_PID%" >nul
if not errorlevel 1 (
  ping -n 2 127.0.0.1 >nul
  goto wait
)
"%SETUP%" /S
```

**「等一个 PID 退出」这件事，Unix 有 `kill -0`（内建、无子进程），Windows 没有对应物。** 只能靠外部命令，而外部命令在这里是致命的：

1. Node 的 `detached: true` 在 Windows 上翻成 `DETACHED_PROCESS`——新进程**既不继承父进程的控制台，也不给它建一个**。（`windowsHide` 补不上：MSDN 明写 `CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` 同时给出时被忽略。）
2. 于是这个 `cmd.exe` 是「没有控制台」的。控制台程序启动时若找不到可继承的控制台，Windows 就**给它新建一个**，窗口标题即命令行。
3. 循环每轮跑三个控制台程序（`tasklist` / `find` / `ping`），一秒一轮。用户看到的 `find "<pid>"` 就是其中一个黑框的标题。

也就是说：**这个 bug 不是脚本写错了，是「detached 脚本」这个形状在 Windows 上不成立。** 改脚本内容救不了它——只要还在 detached 的 cmd 里跑外部命令，黑框就还在。

同一处还埋着第二颗雷：`cmd /c` 的引号剥离规则（`cmd /?` 规则 2——命令行上引号超过两个时，剥掉首引号并删掉**最后一个**引号）。而三个参数全是带空格的路径（`…\Mr Otto\updates\…`、`…\Mr Otto\Mr Otto.exe`），参数没散架靠的是运气。

## 决策

win 席位不再生成脚本，直接 detached spawn **安装器本身**：

```
<下载下来的 NSIS 安装器> /S --force-run
```

`/S` 静默重装到注册表里记着的原安装目录，`--force-run` 装完拉起新版。

三件事随之消失：

- **黑框**：NSIS 安装器是 **GUI 子系统**程序，detached 起它压根没有控制台这回事。
- **等待循环**：「装的时候 app 在跑」是安装器本来就要处理的场景（用户双击安装包时同样会遇到），它自己会关掉旧版。我们照旧 `spawn` 完就 `app.quit()`。
- **引号地狱**：命令行上只剩安装器路径一个参数，走 `CreateProcess` 的正常转义，不经 cmd 的解析器。

mac 席位一个字不动：那边的 `/bin/sh` 脚本没有控制台这回事，而 `.app` 的原地替换（改名 `.bak`、移新版进来、失败挪回去）确实需要一个第三方进程来做——那不是安装器能替我们干的活。**两个平台形状不同，不是不一致，是各自平台唯一成立的做法。**

## 后果

- **失去了「等旧进程退干净」的显式保证**，改为信任 NSIS。取舍理由：这正是 electron-updater 在 Windows 上的做法（它同样是 spawn 安装器 + `app.quit()`），而 electron-builder 出的安装器必须能处理运行中的 app，否则双击安装包升级就是坏的。
- **回滚仍然全交给 NSIS**：装失败旧文件原样在，只是 `--force-run` 不会触发——最坏情况是用户手动打开旧版，与改动前同档。
- **前提若失效怎么办**：假如 NSIS 静默安装被证实不会等/杀在跑的旧版（真机上表现为「更新后版本号没变」），正确的补法不是把批处理请回来，而是让主进程在 spawn 之前先完成退出编排（例如先关窗口、等子进程收干净，再 spawn 安装器）。黑框来自 detached 的控制台继承规则，与等待逻辑放在哪一层无关。
- 这条路本机验不了（开发机是 macOS）。`tests/main/updaterCore.test.ts` 钉住的是**契约**：命令是安装器本身、参数是 `/S --force-run`、命令行里不出现 `cmd.exe` / `/c` / `.cmd`。真机验收留在 issue #662。
