# ADR-0110：正文里的「文件:行号」是可点的坐标，不是一段文字

- 状态：已接受
- 日期：2026-08-26
- 相关：issue #458（本次）、ADR-0031（Files/终端面板的只读旁路边界）、ADR-0092（Files 面板的数据源与三条安全边界）

## 背景

模型每天都在正文里指路：「修成 `src/loop/engine.ts:386` 那个形式」。
在这一版之前，这条路径在界面上就是一段普通文字，读的人要做三件事才能到达：
记住路径 → 去 Files 面板里一层层翻到它 → 在预览里数到第 386 行。

三步里每一步都可能出错，而第三步根本做不到：预览连行号都没有（更早的问题是
预览容器一直没挂 `md` 类，`app.css` 里 `.md pre` / `.hljs-*` 那一整段对它从未
生效，看到的是没有底色、没有配色的裸文字）。

也就是说，模型给出的是一个**坐标**，界面把它降级成了**一句话**。

## 决定

### 一、认路径这件事是纯逻辑，且后缀走白名单

`src/shared/fileRefs.ts`（零 IO，渲染层与测试共用，同 `shared/files.ts` 的分层）：
`scanFileRefs` 扫一段文本里的全部引用（带位置，切文本节点要用），
`parseFileRef` 判断"整串就是一条引用"（markdown 链接的 href 走这条），
`toWorkspaceRel` 把路径削成工作区相对路径。

判据是**误报的代价不对称**：漏认一个冷门后缀，用户还能用 Files 面板搜；
错认一个 `claude.ai`、`v1.2.3`、`@scope/pkg.js`，正文就变成满屏假链接，
点了只能报"文件不存在"——比不认更糟。所以后缀是一张看得见的白名单，
不是"带个点就算路径"。URL、含 `..` 的路径同样挡在门外。

### 二、标记在 rehype 这一层做，且必须排在默认插件之后

`src/renderer/src/lib/rehypeFileRefs.ts` 在 hast 上把命中的那几段换成
带 `data-file-ref` / `data-file-line` 的 span。

不在组件层用正则替换字符串：一段正文到组件手上已经是若干个 React 子节点
（粗体、行内代码各是一个），在那层做替换要自己重走一遍"哪些子节点是纯文本"。

两条装配上的硬约束，写在代码注释里也写在这里，因为**两条都不会报错**：

- streamdown 的默认 rehype 是 `[raw, sanitize, harden]`，而传 `rehypePlugins`
  prop 是**整个替掉**默认值。只写自己那一枚 = 顺手把消毒也关了。
- `sanitize` 按白名单削属性。排在它前面的话 `data-file-ref` 会被削掉，
  chip 当场退回一段普通文字——**所有单测照样全绿**。

代码块（`pre`）和已有链接（`a`）底下不认：前者随便一行都长得像路径，标出来是
满屏噪音；后者已经可点，再套一层就是两个可点的东西叠着。

### 三、跳转的落点是 Files 面板，面板仍然只读

点 chip = `openFileAt(path, line)`：削成工作区相对路径 → 开 Files 面板 →
选中文件 → 预览滚到那一行并高亮。

不新开编辑器、不调系统 `open`：那是"离开 Otto"，而这里要的是"在手边看一眼"。
（要用编辑器打开的路仍在——预览头上的「打开方式」菜单。）

ADR-0031 的边界不动：面板读到的东西不进事件日志、不进模型上下文。跳转只是
把面板挪过去，不改变谁看得见什么。要让 Otto 看某个文件，仍然走 `@` 塞进输入框。

落不到工作区里的路径（`/etc/hosts`）**照样开面板**，并在面板里说"不在当前工作区"。
静默吞掉的表现是"点了没反应"，用户只能猜是没实现还是文件没了。

### 四、预览的行号：先整篇高亮，再在 hast 上切行

`src/renderer/src/lib/codeLines.ts` 把高亮结果按 `\n` 切成一行一个
`<span class="code-line" data-line="N">`，跨行的元素在下一行原样再开一个。

不逐行高亮：hljs 的 token 会跨行（块注释、模板字符串），逐行高亮的表现是
块注释只有第一行是灰的。

行号走 CSS 的 `::before` + `attr(data-line)`，不塞进 DOM 文本——塞进去的话
选中一段代码复制，会把行号一起拷走。

## 代价

- 正文里多了一类可点的东西。误报的门是白名单，白名单要维护（新语言进来时补一条）。
- 预览里 `.md` 类是这次才挂上的，等于同时改了预览的观感（有底色和配色了）。
  这是修 bug 不是加样式：那段 CSS 本来就是写给它的。
- 大文件预览截断在 512KB，跳到未显示部分时只能提示"第 N 行在未显示的部分"。
  真要修得让 `filesRead` 支持按行窗口读，本次没做——没有第二个消费方之前那是提前抽象。

## 如果判断错了

- **白名单太窄**（模型常写的后缀没进来，chip 大面积不出现）：补白名单即可，
  判据不变。
- **误报仍然多**（比如把散文里的 `README.md` 也标成 chip 让人分心）：
  下一档是"只认带行号的引用"，`scanFileRefs` 已经把 `line: null` 和有行号分开了。
- **落点选错了**（用户其实想直接进编辑器）：`openFileAt` 是唯一入口，
  换落点只改它一处。
