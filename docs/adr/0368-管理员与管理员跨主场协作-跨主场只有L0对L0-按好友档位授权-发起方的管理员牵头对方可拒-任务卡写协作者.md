# ADR-0368：管理员与管理员跨主场协作——跨主场只有 L0 ↔ L0；按好友档位授权；发起方的管理员牵头、对方可拒；任务卡写协作者

日期：2026-10-05 · issue #1578 · 维护者原话：「个人对个人对话或者群聊，管理员和管理员之间可以协作完成一个任务。A 的管理员熟悉 A 的情况，
B 的管理员熟悉 B 的情况，当一个聊天页面发出同一个任务的时候，A @ 自己管理员说你去完成任务，由 A 管理员阅读上下文分析总结是否需要
和 B 管理员协作完成，如果需要一起完成则邀请对方一起完成。」四条补法在会话里确认（#1578 正文）。

## 背景

ADR-0363 让朋友的请求只到管理员；ADR-0358 的车道桥让两只「公开的智能体」互相说话；ADR-0367 把人这一侧收成只对人和自己的
管理员说话。缺的是智能体那一侧的跨主场规矩：桥的目标还按名字 / 公开智能体找，对方能说多少没有依据，任务没有「协作者」。

## 决定

1. **跨主场只有 L0 ↔ L0**：车道桥（`message_friend_agent` / `invite_collaborator`）落到对面时，对面名单里有管理员就一律交给
   管理员，点名别的只也改到管理员（runtime `laneBridge.ts` ④）。专员永远不出自己的主场。老车道（名单里还没有管理员）照旧按名字找。
2. **对方的管理员按好友档位回应**：主人给这位朋友的档位（ADR-0350，两边取小）写进公开车道里管理员的 brief（`collabAuthPrompt`）：
   仅聊天 = 只转述公开说过的话；可协作 = 事实直接答、动手回主人批；全部开放 = 小事可替主人定（花钱、承诺时间仍要批）。查不到档位按仅聊天。
3. **发起方的管理员牵头、对方是协作者、随时可拒**：新工具 `invite_collaborator(taskId, note)`，只有 L0 在公开车道里有——先
   `create_task`，再把邀请那句（任务 id / 标题 / 简述 / 谁牵头 / 附言）走桥发给对方的管理员，并落 `task_collab`。两只管理员不同时牵头同一个
   任务；对方说不方便就按没有继续、告诉主人。提示词里这段两边都加（`collabRolePrompt`，进 `delegationRolePrompt` 的管理员分支）。
4. **任务卡写协作者**：`task_collab` 是第七种任务事件（登记同前六种），折进 `TaskRow.collaborator`（不动状态），手机任务卡写
   「协作：小红的管理员」。**投影表没有这一列**：协作者只在日志折出来的那份里，状态行用不上。

## 没做 / 之后

- 群里 N 个人的协作：同一套，发起方的管理员可以邀多只，各按各主人的档位答——桥今天只认配对车道（pair），群里的桥另开。
- 对方不是 Otto 用户：只剩 message_friend / call_friend 给本人，没有协作一说（已有）。
- 跨主场的任务卡在对方那边不画（事件在发起方的日志里）；对方看到的是车道里那句「[协作邀请 t_…]」。
- laneTasks（#1565 的抽屉）把桥来的那句按 relay 当接力挂在当前任务下、smile 名字解析不到对方智能体的 id——另开 issue。
