# ADR-0265：云会话的回复像人说话——提示词改口径，界面按空行拆成几张气泡

- 状态：已接受
- 日期：2026-09-09
- 关联：#1132 / #989（上一版「说人话」，只挡住了 otto-* 围栏）/ ADR-0263（流式预览是累计快照，这里每帧重拆全靠它）/ ADR-0250（时间线上只剩最终答案，所以答案本身的形态成了全部观感）/ ADR-0235（云会话对齐本地会话——这次反过来：群聊有群聊的样子）

## 背景

维护者对着真机（mandy's bubble tea 工作区的云会话）的原话：

> 现在各个智能体的回答缺乏活人感，噼里啪啦一大堆专业术语，没有必要这样。回答得像个真人就好，如果消息过长，可以分段输出

截图上那条回复：`**3. 接下来想跟你俩对齐的两件事**`（星号原样露在气泡里）+ 两段「- 」清单 + 四五百字一口气说完；措辞是「对齐 / 落地 / 口径 / 影响面」。导出的日志里，「开发」给「设计」的那份交接说明 495 字、十一条「- 」，形状一样。

## 诊断

三条病，落在两个层面：

1. **提示词层**：#989 那段说的是「别用 JSON、表格、otto-xxx」，对着的是**围栏**。它没说「怎么像人」，模型于是退回它最熟的那套——加粗小标题、编号章节、长清单、一次交代全部细节。只说「别用」不给替代写法，是 #989 自己注释里就写明的坑，只是那次替代写法只给了「清单一行一件」这一种。
2. **渲染层**：云会话的气泡是纯文字（`BubbleContent` 上 `whitespace-pre-wrap`，不渲染 Markdown），所以模型写的 `**` 与 `#` 原样露出来。桌面本地时间线渲染 Markdown，同一个模型在两边写同一种东西，只有云这边难看——它不知道这边是纯文字，没人告诉过它。
3. **形态**：一轮回复 = 一条 `assistant_message` = 一张气泡。真人在群里不会一张气泡五百字，会说一句、停一下、再发一句。「分段输出」在群聊里的意思是**连发几条**，不是一条里分几段——一条里分几段今天就是这样，它没解决观感。

## 决策

### 1. 提示词说「怎么像人」，四句各对一条病

`src/session/deriveMessages.ts` 的 `PLAIN_TALK` 重写，只注入云会话（`session_created.cloud` 在场），本地一字不变：

| 那一句 | 对着的病 |
|---|---|
| 像同事在群里聊天：口语、短句、先说结论和下一步；别甩术语，非用不可就顺手用一句白话解释 | 术语堆砌 |
| 别一次把细节全倒出来——两三段说清主线就停，对方想细看再展开 | 五百字一口气 |
| 段与段之间空一行、一段只说一件事：群里会把每一段当成你连发的一条消息 | 一张气泡到底（见决策 3） |
| 群里显示的是纯文字：别用加粗、标题、编号章节、表格、JSON 当骨架（星号井号会原样露出来） | `**3. 小标题**` |

每一句都说得出替代写法。它跟着每一次云请求走，压在两百来字。

### 2. 界面按空行拆气泡，投影不动日志

`src/renderer/src/lib/chatBubbles.ts` 的 `splitBubbles`：空行分段，只含空白的行也算空行，代码围栏里的空行不算（脚本是交付物，切成两张就没法整段复制；没关上的围栏把后面全部留在同一张里）。终态 `AssistantMessageRow` 与流式预览 `PendingTurnLines` 共用一份 `AgentBubbles`——预览是累计快照（ADR-0263），每帧重拆一遍，前几张早就定形、只有最后一张在长，答案落下来时张数不变。

**事件日志一个字不动**：落盘仍是一条 `assistant_message`，拆是投影（Hard rule：投影可从日志推导）。turnLedger、去重、隐私闸、十一处事件类型穷举一处都不碰。

### 3. 提示词与界面说的是同一句话，两边各有一半

「段与段之间空一行，群里会把每一段当成你连发的一条消息」——模型负责空行，界面负责拆。任一边单独存在都不成立：只改提示词，人看到的仍是一张长气泡（空行在一张气泡里就是段落）；只改界面，模型不空行就永远一张。所以两边一起进同一个 PR，并且各钉一条断言：那句话在提示词里（`tests/session/deriveMessages.cloudSession.test.ts`），拆分判据在渲染层（`tests/renderer/chatBubbles.test.ts`，真渲染在 `CloudAssistantBubbles.test.tsx` / `CloudPendingTurnLines.test.tsx`）。

### 4. 否决的路

- **分隔记号**（让模型写 `---` 或 `<msg>` 当分界）：多一个模型要学的约定，学不会那一次露出来就是一坨记号；空行是模型本来就会写、写惯了的东西。
- **在 runtime 把一轮拆成多条 `assistant_message`**：改的是事实不是投影——十一处事件类型穷举、`openTurns` 的收口判据、去重、隐私闸全要跟着动，而「分开发」是**看**的事。
- **云气泡渲染 Markdown**（换成 Streamdown）：能消掉星号，消不掉「五百字一口气」；且本地那套卡片语汇（otto-* 围栏、文件 chip）会跟着进来，与 #989 的方向相反。留作独立议题。
- **人类成员的消息也拆**：人自己敲回车发出去的就是一条，一条里的空行是他的排版，不是「几条」。
- **本地会话跟着改口径**：桌面时间线渲染 Markdown、读者是开发者本人，`STRUCTURED_BLOCKS` 那边是有消费方（卡片）的。不动。

## 代价 / 已知未做

- 模型不空行就还是一张气泡——提示词是软约束，deepseek-v4-flash 真机上听不听，这次没跑过；提示词在 runtime，**要部署才生效**（#791）。
- 一行一件的清单不拆（没有空行）——故意的，一份清单是一条消息。
- 渲染层的改动要**发版**才到用户手里，提示词部署即生效，两处生效时间不同——中间那段「模型开始空行、界面还是一张」无害，一张气泡里的空行就是段落。
- 第二张起 `mt-1` 那 4px 与 `SpeakerRow` 的 `gap-0.5` 是 jsdom 里看不见的几何，没写成断言（同 ADR-0236 第 1 条），保鲜期是 `AgentBubbles` 头注。
- 真机一次没跑过。
