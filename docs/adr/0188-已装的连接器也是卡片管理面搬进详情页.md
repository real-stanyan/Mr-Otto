# ADR-0188：已装的连接器也是卡片，管理面搬进详情页

- 状态：已接受
- 日期：2026-08-29
- 相关：issue #753、ADR-0178（产品层叫连接器，协议层才叫 MCP）、ADR-0171（两层目录）、ADR-0185（点开是换页）、ADR-0184（目录扩到 82 条）

## 背景

一段真实对话：

> **用户**：连接器下面这些是 mcp 吗
> **答**：上下两半都是 MCP，区别在于在不在你的机器上……
> **用户**：所以是接通后的连接器就变为了 mcp？

这个误解不是用户的问题，是界面教的。同一页上，同一种东西长成两副样子：

- 上半：带品牌 logo 的卡片，说人话
- 下半：等宽字体的 id、裸 URL、`20 工具 · 0 资源 · 0 prompt`

`prompt` / `资源` 是协议层的词。ADR-0178 定的是产品层叫连接器、协议层才叫 MCP，
那几个词根本不该出现在这一屏。**界面把「同一个东西的两个阶段」画成了「两种东西」，
用户读出来的正是它画出来的意思。**

## 决策一：一套卡片语言，已装的放最上面

已装的那几台也用 `DirectoryCard`，置顶。点进去是同一张详情页。

## 决策二：两组，不是一组

- **已接通**：`connected`
- **待接通**：needs-auth / 连不上 / 已关闭 / 连接中

为什么不合成一组顶着「已接通」这一个标题：一张写着「连不上」的卡挂在「已接通」
下面是自相矛盾。为什么不把没接通的藏起来：那台就再也点不到了，用户连改配置的
入口都找不到——而「连不上」恰恰是最需要点进去的那一种。

## 决策三：管理面搬进详情页，下半那份清单删掉

启用开关 / 改地址与参数 / 重连 / 授权 / 删除 —— 原来是下半那份清单里的一个
`<details>`，现在住在详情页的「设置」一段里。卡片是索引，详情页是答案
（ADR-0185 定的分工）。

搬家是**原样搬**（`McpServerEditor.tsx`），逻辑一行没动：搬家和改逻辑分开做，
出问题时才分得清是哪一半的锅。

## 决策四：装过的不在下面的分类里重复出现

同一台 server 在一屏上出现两次，用户要先想明白「这两张是不是一个东西」——
而这正是本 issue 的病根。搜索时两边一起过滤（`filterInstalled` 与 `searchCatalog`
同一口径），搜 supabase 不会因为「它在上面那一组」就被搜掉。

## 决策五：目录里没有的那些，现造一条

手填的、从公开注册表装的，目录里都没有。`entryFromInstalled` 现造：名字用 id，
描述用它自己的地址/命令，图标缺席 = 首字母色块（长尾层的待遇，ADR-0171 第四节）。

**目录里有的那些，描述也换成它自己的地址**：这一组回答的是「我装的是哪一台」，
不是「这个产品是什么」。

## 决策六：连不上的那句错误翻成人话

SDK 抛的是 `MCP error -32000: Connection closed`。照原样贴在界面上有两个问题：
把 "MCP" 三个字母漏回了产品层，而且没告诉用户**该去改什么**——对着一条
`uvx nonexistent-thing` 的配置，它真正的意思是「这个包不存在」。

`humanizeMcpError` 只翻认得出的那几类（Connection closed / fetch failed /
ENOENT / ECONNREFUSED / timeout / 401·403），**认不出的原样保留**：一句看不懂
的英文，比一句自信的错误翻译有用得多。原文始终留在 `title` 里——翻译是为了让
用户知道该改什么，不是为了把证据藏起来。

## 顺带清掉的协议方言

- 「新建 MCP server」→「手动添加连接器」
- 「传输」→「连接方式」
- 「把指定目录暴露成 MCP 资源」→「把指定目录开放出来」
- `SpecSheet` 那张「传输 / 工具 / 资源 / Prompt」计数表整个删掉（详情页上半
  已经说了连接方式和工具数）；剩下的两张表标题改成「资源 / 地址」和
  「现成的问法 / 说明」

`mcp.json` 这个文件名**留着**：它是磁盘上真实存在的一个文件，用户可能要去改它。
说出一个真实路径不是漏方言，是给行动指路。

## 一处测试环境的坑（记下来免得下次再查一遍）

`tests/renderer/McpSettings.test.tsx` 里 `userEvent.click` 点不动那张
`div[role="button"]` 卡片：这一屏被 `<SidebarProvider>` 包着（真实 app 里也是），
它那个收起态的 Sheet 让 jsdom 算出来的 `pointer-events` 变成 `none`，userEvent
因此拒绝点击——**同一份文件里点普通 `<button>` 不受影响**，所以不是全局的，
排查时很容易看错方向。用 `userEvent.setup({ pointerEventsCheck: 0 })`。

真机上点得动：e2e 里开了一个真窗口点过（截图存档），这条不是产品缺陷。

## 被否掉的路

- **上面加一组卡片、下面那份清单留着**：同一台 server 在一页上出现两次，
  正是本 issue 的病根。
- **合成一组顶着「已接通」**：见决策二。
- **把没接通的藏起来**：见决策二。
- **管理面留在原地、卡片只做展示**：那就还是两套语言，只是换了个排版。
