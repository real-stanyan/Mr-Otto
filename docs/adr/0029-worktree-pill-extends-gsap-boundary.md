# ADR-0029：工作区改动浮窗；GSAP 边界从「只有牌桌」扩到「有编排的动效」

- 状态：已接受
- 日期：2026-08-19
- 相关：ADR-0024（GSAP 只用在牌桌）、ADR-0014（git 只读例外）、ADR-0010（shadcn/Tailwind）
- 授权：维护者 stanyan 在 2026-08-19 会话中明确指定「在输入框上面加浮窗提示 git 改动/文件增删改，
  优先用 shadcn 组件，用 gsap，按 apple design 做」

## 背景

会话里 agent 会写文件、删文件、跑 bash 改盘。事件日志记得下「调用了 write_file」，
但记不下「于是工作区现在脏成什么样」——后者不是日志的投影，只有 git 知道。
用户在打下一句话之前，需要知道刚才那一轮到底动了什么。

## 决定

### 1. 数据源是 `git status`，不是事件日志

新增 `GitGraphService.status()`（`git status --porcelain -z --branch --untracked-files=all`，
外加一次 `git diff --numstat HEAD` 贴行增删），解析层在 `src/shared/gitStatus.ts` 纯函数化。

这**不违反**「append-only 事件日志是唯一事实来源」：那条硬规则约束的是**会话事实**
（模型看见了什么、发生过什么），工作区脏不脏不是会话事实，是外部世界的现状。
同一个道理，ADR-0014 已经把 git 只读查询划在 app 功能这边（不是 agent 工具）。
渲染层的 `workTree` 因此单独存一份，并在每次 `tool_result` 之后（600ms 尾随防抖，
复用已有的分支/图刷新时机）与窗口重新聚焦时重问 git——「窗口重新聚焦」是因为
用户可能去别的编辑器改了文件，回来时浮窗不该还停在旧事实。

### 2. 关掉的浮窗靠「状态指纹」决定何时回来

`statusSignature()` = 分支 + 文件集合（路径/档位/是否暂存），**不含行增删**。
用户关掉浮窗后指纹不变就一直静音；文件集合变了才算「又发生了一件事」，允许重新出现。
把行数排除在外是刻意的：多敲一个字符不该把用户主动关掉的东西弹回来。

### 3. GSAP 的边界改写为「有编排的动效」，不再是「只有牌桌」

ADR-0024 把 GSAP 圈在牌桌里，理由是「一个卡片的进场用 GSAP 是杀鸡用牛刀」。这条浮窗
不是「一个卡片的进场」：展开是高度动画 + 逐行错开（stagger）+ 收起时反向跑同一条路径，
是一条**有先后依赖的编排**——正是 ADR-0024 认可 timeline 的那类场景。

于是边界从「牌桌」改成判据：**要编排（时间线上有先后依赖 / stagger）才上 GSAP，
单一属性的进出场继续用 CSS transition + `@starting-style`。** 本浮窗里也遵守这条：
箭头旋转、按压反馈仍是 CSS，只有进场/展开/收起走 GSAP。

代价与 ADR-0024 记的一样（多一套范式、JS 驱动会掉帧），另外多一条：判据比白名单更
容易漂移，「这算不算编排」会有争议。接受它，因为按渲染区域划边界本来就拦不住第二个
需要 timeline 的地方——这次就是。

### 4. 用户消息的附件从气泡里搬出来

同一批改动里，用户消息带的图片/文本文件不再塞进气泡内部，改为气泡上方的独立卡片
（`UserAttachments`）。附件不是「话」，是随话递过来的东西；塞进气泡等于把一张图当成
一句话的标点。只带附件不带正文时不再渲染空气泡。

## 什么情况下该推翻

- 如果浮窗被证明是噪音（用户总是关掉它），该退回到「只在改动数超过某个量级时出现」，
  甚至彻底删掉——它的价值全在「省下一次 `git status`」，省不下就不值这块地方。
- 如果 `git status` 在大仓库上把主进程拖慢（每轮工具调用都要跑一次），
  该换成 watch 文件系统增量维护，而不是加大防抖把浮窗变成滞后信息。
