# ADR-0244：云会话删得掉（协议 10）；侧栏行尾那颗动作按钮改成真居中

- 状态：已接受
- 日期：2026-09-07
- 关联：issue #1044；上游 ADR-0235（当时决定「不给删除」的那一条，本 ADR 推翻它）/ 0234（「删一条会话不该以你正开着它为前提」的判据，原样沿用）/ 0201（归档三层分工与收房那一段）/ 0243（「读不到 ≠ 不存在」这条纪律的又一处）/ 0236（Tailwind 字面量之间的算术为什么不写成断言）/ ADR-0002（删除 = 整会话物理抹除）
- 来源：维护者对着侧栏那条云会话行报的两条——「1. 点点点的 icon 没有居中显示 2. 没有删除的按钮」

## 背景

ADR-0235 把归档从会话头部搬进侧栏那条会话行的 ⋮ 菜单，并且在那儿写下：

> **菜单里没有「删除」**：0016 迁移把 `wss_delete_publisher` 钉死在 `kind='package'`，云会话故意删不掉（删了 VPS 上那份权威日志就成孤儿），给一颗点了必然失败的钮是撒谎。

这句话的**前半是事实、后半是当时没做**。0016 那条 RLS 管的是**客户端直连 Supabase** 的那条路——它防的是成员绕过 runtime 自己 `DELETE` 掉一行、把 VPS 上的日志变成够不着的孤儿。runtime 拿的是 service key，本来就绕 RLS；`EventStore.purge()` 也早就在（本机那颗「彻底删除」用的就是它，ADR-0002）。所以「删不掉」不是一条技术事实，是一条**没实现的功能**被写成了技术事实——正是 ADR-0134 点名的那种「读起来像调查结论、实际只是上一班没试」。

## 决策

### 1. 删除能力落在 runtime，不落在客户端

判据不变（0016 那条 RLS 一个字不改）：客户端仍然删不掉自己那行 `workspace_sessions`。删除走一条新的控制房帧，由 runtime 用 service key 执行——**因为只有 runtime 同时握着台账那行和 VPS 上那段日志**，而这两样必须一起消失。客户端能删一半的那个版本，正是 0016 当初要堵的洞。

### 2. 谁能删 = 谁能归档（owner 或建这条会话的人），不收窄成 owner-only

想过收窄：归档是「收尾，但还看得见」，删除把一群人（外加几只 agent）共同写的记录整段抹掉，这个差别真实存在。但三条把它按了回去：

- **云端的归档本来就没有回头路**（daemon 只捞 `archived=false` 的会话重开房间，ADR-0201），所以两件事都是单向门，「归档可以、删除不行」不是「可逆 vs 不可逆」的分界。
- 两颗钮**并排住在同一个菜单里**。判据不同就要另有一套解释，而界面上没有地方讲这套解释——用户只会看到一颗灰着的钮。
- 钱与用量的账**不在这条日志里**（`usage_event` / `usage_ledger` 是另外的表，service key 写、按 uid 读）。删掉的是对话，不是 owner 的账。

### 3. 控制房帧，不是会话房帧（沿用 ADR-0234/0235 的判据）

`delete` 帧带 `workspaceId` + `sessionId`，只在控制房接；会话房里出现视为越权（同 `create`/`config`/`archive`）。理由比归档那次更硬：**最想删的那批是已经归档的**，它们根本没有房间可开。这也是 `sessions.creatorOf` 存在的全部原因——`sessions.get()` 只认活着的房间，拿它当判据的话，功能对一半的用户是坏的。

协议 9 → 10（`delete` / `delete_result`）。握手是精确相等，**合完必须部署 runtime**，否则桌面一律 `version_mismatch`。

### 4. runtime 那三步的顺序，每一步都有一个具体的坏结局挡在后面

1. **先走一遍归档**（落 `session_archived` 并广播 → 停这一轮 → 收房间）：删除本身没有任何广播可当回执（房间收了、日志也没了），那条事件是房里的人**唯一收得到的信号**。
2. **等排空之后才 purge**：`purge` 不是锁，抹完照样 `insert` 得进去。engine 还在收口的时候抹表，这一轮剩下的事件会写进一张刚清空的表——删完之后凭空长出半条会话。收摊那一段（摘席位 / 等排空封顶 10s / 延一拍关房）因此抽成 `retireRoom`，归档与删除共用；**归档照旧不 await 它**，行为一字不变。
3. **先删台账那行、再 purge 日志**：反过来的话，删库失败留下的是「台账里有、日志空了」的会话，daemon 重启照样把它捞出来开房间，而没有 `session_created` 的日志一条 system 消息都投不出来（云端水獭不知道自己在 `/work`、不知道对面是一群人）。反向的残留只是 VPS 上一段没人引用的字节，无声无害。同理 **purge 抛了也算删成功**（`purge` 有一条 fork 保护会抛，issue #352）：台账那行此刻已经没了，对每一个人来说这条会话都已经消失，回 false 只会让人再点一次、撞上「这条会话不存在」。

### 5. 「这一刻读不到」是第三种结局，不许说成「不存在」

`creatorOf` 查询失败**往上抛**，不兜底成 `null`；帧处理那层单独回一句「这一刻读不到这条会话的信息，什么都没删」。说成「不存在」的代价很具体：人会以为已经删干净了，转头去别处找它——而它还好好地在那儿。同 ADR-0243（读不到 ≠ 没有），也同 ADR-0217 的 `unknown` 一态。

三种失败因此各说各的话：不存在 / 读不到 / 删库那一步没成。

### 6. 两个入口，不是一个

侧栏那条会话行的 ⋮（活着的那些）**和**工作区设置页底部「已归档的云会话」每行尾部那颗 🗑。只做前者的话，最想清掉的那批恰恰够不着——归档掉的会话不在侧栏里。判据两处逐字相同，服务端仍然自己判一次（渲染层不是安全边界）。

### 7. ⋯ 居中改在共享组件里，不在调用点

shadcn 的 `SidebarMenuAction` 把自己钉在 `top-1.5`，那是按默认 `h-8`（32px）算好的居中值；本仓的行几乎都是 `h-auto` + 自己的 `py`：云会话行 26px（⋯ 低 3px，维护者一眼看出来的就是这个）、好友行 26px、史前会话行两行高（✕ 贴在顶上）。

改成 `top-1/2` + `-translate-y-1/2`，三条 `peer-data-[size=*]` 变体一并删掉：固定高度的行结果一字不变（`h-8` 上 `top-1.5` 本来就等于居中），留着只会在下一个 `h-auto` 行上重新把它顶偏。**改在调用点是错的**——那样每加一行新的 `h-auto` 列表都要重新踩一次，而它不会报错，只会歪着。

## 否掉的选项

| 选项 | 为什么不 |
|---|---|
| 放开 0016 那条 RLS，让创建者直连 Supabase 删 | 那正是 0016 堵的洞：客户端删得掉台账那行，删不掉 VPS 上的日志，孤儿照旧 |
| 删除只对活着的会话开放（`sessions.get()` 当判据） | 归档掉的那批才是最常删的，而它们没有房间。功能对一半的场景是坏的 |
| 收窄成 owner-only | 见决策 2 的三条 |
| 「先归档才能删」两步走 | 「删除要求你先归档」是个谜题，不是纪律。归档那一步由 runtime 自己走 |
| 给 ⋯ 那颗单独加一行 `className` 修偏移 | 见决策 7 |
| 给 Tailwind 那两个字面量写一条断言 | 同 ADR-0236 第 1 条：扫源码的正则会在任何无害重构上翻红，保鲜期放在紧挨类名的注释里 |

## 已知代价

1. **协议进位 = 合完必须部署 runtime**，否则桌面握手就被拒（`version_mismatch`，且带上服务端协议号，桌面能说清是哪一边旧了）。
2. **一次都没在真机上跑过**——本 ADR 末尾那张验收清单一条都没验。
3. 台账那行删了、`purge` 抛了的那条路会在 VPS 上留一段没人引用的日志字节，**没有回收程序**（孤儿容器有 reconcile，孤儿日志没有）。
4. 删掉的是**共享**记录：群里其他人手上如果开着这条会话，他们收到的是 `session_archived`，界面上表现为「被归档了」，下一次刷新清单它才消失——**没有一条「这条会话被删了」的事件**（要有的话就得给一条即将消失的日志再 append 一条事件）。
5. `workspace_sessions` 那行删了之后，**`usage_event` 里按 session_id 记的账变成指向不存在的会话**（外键没有级联，本来也不该级联——钱的账不能因为有人删了对话就消失）。工作区用量表按 agent 不按会话，今天看不出来。
6. 归档区那颗 🗑 **没有撤销、没有软删**，与本机那颗「彻底删除」同一档语义（ADR-0002）。两处都只有一层原生 `confirm` 挡着。
7. 侧栏那颗动作按钮的居中改动**动的是共享组件**，好友区那两颗 ✕ / 🔑 与史前会话那颗 ✕ 跟着挪位（都是往对的方向挪，但都没在真机上看过）。

## 真机验收（一条都没跑）

1. owner 在侧栏 ⋮ 里删掉一条**活着的**云会话：房里的人看到 `session_archived`、房间收掉；侧栏那行消失；VPS 上 `${workspaceId}.db` 里那段 events 没了；`workspace_sessions` 那行没了。
2. 删一条**归档掉的**（工作区设置页底部那颗 🗑）：同上后两条。
3. 非 owner 非创建者：两处都看不见那颗钮；手工发一帧 `delete` 回 `denied not_authorized`。
4. 删的正是此刻主区开着的那条：主区退回去，不是停在一条已经不存在的会话上。
5. 侧栏那颗 ⋯ 与好友行那两颗按钮在真机上确实居中（这条是肉眼验收，没有断言）。
