# ADR-0246：云会话头部「模型」那一格只在**起不了 turn** 的时候出现

- 状态：已接受
- 日期：2026-09-07
- 关联：issue #1052；上游 #844（这一格的由来）/ #945（改成路由判定）/ ADR-0233（收窄成 hosted / blocked 两态）/ ADR-0232（真跑一轮取哪款：agent 白名单 → 网关第一款）/ ADR-0237（Auto：空白名单时每轮现判）/ ADR-0234（仓库为什么不在头部）
- 来源：维护者先问「工作区会话 header 显示『deepseek-v4-flash · 托管』是什么意思」，听完解释后——「把这段话去掉」

## 背景

那一格是 `modelStatusText(cs.modelRoute)`，三态各有一句话：

| 路由 | 画什么 | 说的是 |
|---|---|---|
| `hosted` | `deepseek-v4-flash · 托管` | 一切正常 |
| `blocked` | 「没有可用的模型」（红） | @Agent 起不了 turn，且有出路 |
| `null` | 「路由未知」 | 探测抛错，**但「有订阅的话 turn 照跑」** |

三分之二的时间它在用一个常驻标签说「正常」。更糟的是 `hosted` 那句还**不保证准**：探测递的是空白名单（`probeModelRoute` 的 `requestedModels: []`），拿到的是网关那张表的第一款 = 工作区默认款；而真跑一轮是按这只 agent 的白名单现取，白名单为空时还要过一次 Auto 分类（ADR-0237）。于是群里两只 agent 可以同时在跑两款不同的型号，头部那一格从头到尾写着第三款。

一个**永远在、又不保证准**的标签比没有更坏：它训练人去信一个会骗人的数。

## 决策

判据收成一句：**这一格只在起不了 turn 的时候出现**。

- `modelStatusText` 回 `null | { short, full }`，`hosted` 与 `null` 两态回 `null`（不画），`blocked` 原样留。
- `bad` 字段跟着删——能画出来的只有一种，颜色由调用方写死 `text-err`。判据只剩一处。
- 两个消费方一起改：云会话头部、工作区设置的仓库 tab「现状」那张 `<dl>`（那一行整行不出）。后者上半的正文已经写着「模型不用配：统一走所有者的订阅额度」，正常态再列一行「某某款 · 托管」既重复又不保真。

**为什么留 `blocked`**：它是这三句话里唯一**会挡住干活**的，而且有一条明确的出路（所有者订阅 / 续费 / 加购）。留住它，这一格就从「一个常驻的状态显示」变成「一件事出了才说话」——同 ADR-0235 ③ 把机器内务从时间线上藏掉、只留「拒绝」那条的判据。

## 否掉的选项

| 选项 | 为什么不 |
|---|---|
| 整格删掉（含 `blocked`） | 那样「所有者没订阅」在云会话界面上一个字都没有，人只会看到 @ 了没反应 |
| 留 `hosted` 但改成鼠标悬停才出 | 悬停 = 没人看得见（同 ADR-0209 那笔明写的账），等于删，却还留着一份要维护的文案 |
| 让它报**这一轮真用的**型号 | 那是 turn 级事实、每轮会变，头部是「这条会话是什么」不是「刚才那轮怎么跑的」；真要看，用量那张表按 agent 记着 |
| 保留 `null`（「路由未知」） | 它自己那句话就是「turn 照跑」——不可行动、也不是故障 |

## 已知代价

1. **订阅正常时，界面上没有任何地方说「这个工作区的 turn 走托管路由」**。仓库 tab 的正文提了一句「统一走所有者的订阅额度」，但不报型号。真要查此刻用了哪款，只有账号页的用量卡（按型号占比）。
2. `route === null`（runtime 探测抛错）现在**完全无声**——它本来也只在 runtime 日志里有痕迹，界面这句话没了之后，那条 `console.warn` 是唯一的信号。
3. 真机没验（同这一批其余几条）：要看的是「没订阅的工作区头部仍然出红字」这一条。
