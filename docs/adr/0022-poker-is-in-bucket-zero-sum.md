# ADR-0022：德州筹码 = 桶内 token，零和、桌注制、仅好友

- 状态：已接受
- 日期：2026-08-18
- 相关：#48，ADR-0021（按型号分桶）、ADR-0019（官方 key 走网关）

## 背景

筹码是**真 token 额度**（维护者 2026-08-18 决定，app 不公开发行，仅私人圈子）。
ADR-0021 刚把余额拆成 flash / pro 两个互不流通的桶，德州必须回答一个新问题：
一注押的是哪个桶的 token。另外三件事在动手前也必须定死，因为它们改的是钱的规则，
不是代码结构。

## 决定一：桌子声明档位，桶内结算

一张桌子建的时候定 `tier`（默认 flash），桌上所有人押的都是那个桶的 token，
输赢只在桶内转移。

考虑过的另外两条：

1. **统一筹码余额**。等于把 ADR-0021 封掉的套利口子重新打开：flash 输入
   0.28、pro 输出 2.19 USD/1M，差 7.8 倍；赢来的筹码换成 pro 输出比换成
   flash 输入值钱 7.8 倍，那不是牌技收益，是汇率差。
2. **单开 chips 桶，flash 按比例兑入**。兑换本身就是跨桶流动，同一个口子；
   且单向兑入会让筹码变成"不能换回推理"的假币，与"筹码是真 token"冲突。

桶内结算不引入任何新概念：德州只是同一个桶里的一次转账。

## 决定二：不抽水

平台一分不抽。两个理由，第二个更重要：

1. 从真实预付额度里抽成，性质上比"朋友之间分钱"更靠近经营赌场，而这里没有
   任何成本需要覆盖。
2. **不抽水让"一手牌所有人的账本增量之和 == 0"成为一条可自动断言的不变量。**
   引擎的模糊测试就是靠它抓 bug 的 —— 1200 手随机牌局跑下来，逮到两个
   靠读代码看不出来的错（见提交 2b64a1a）。抽水会让这条断言变成"和 == 抽水额"，
   而抽水额本身要另算一遍 —— 校验器和被校验者共用同一段逻辑，等于没校验。

## 决定三：桌注制，不设每日上限

单手最大损失 = 带上桌的那份筹码，天然封顶。买入有 min/max，桌下余额碰不到。

**明确没做**：每日净亏上限。维护者当面否掉了，理由是圈子小、桌注制已经封住
单手风险。代价写在这：一个人可以一晚上连续买入把整个桶输光，没有系统性刹车。

## 决定四：仅 accepted 好友可同桌

复用 #34 的 `friendships`。既是防陌生人，也是"私人圈子"这个前提的技术落实
—— 前提写在 issue 里是文字，写成入座条件才是约束。

## 什么情况下该推翻

- 决定一：某天两个桶的单价差收敛到可忽略（比如全部改成按请求计费），
  分桶本身就没意义了，德州跟着合并。
- 决定二：如果出现真实的运营成本需要覆盖（比如牌桌跑在单独付费的实时服务上），
  抽水才有正当理由；那时必须同时给出一条新的可自动断言的守恒式。
- 决定三：出现第一起"一晚输光后来找维护者"的实际纠纷，就该补每日净亏上限。
- 决定四：如果 app 改成公开发行，好友门不足以承担合规，整个功能要重新过一遍。
