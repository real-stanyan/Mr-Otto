# ADR-0338：消息推送走普通通知，读不到开关就不推；已读回执只画认得它的人

日期：2026-10-04 · issue #1442 · 维护者在会话里定的口径

## 背景

手机上只有智能体回电会响（VoIP + CallKit，ADR-0335）。聊天、@、智能体回话一律要打开 App 才看得见。
`push_devices.kind = 'alert'` 那一格从 0047 起就留着，但从没人登记过、runtime 也只取 VoIP 令牌。

## 决定

1. **消息走普通通知**（维护者选的）。回电不变，仍是 VoIP。已知代价照 #1428：开了 iPhone 镜像时，锁屏通知可能响在
   Mac 上。VoIP 推送只许用来报来电，拿它推消息会被系统杀进程、审核也过不了，所以没有第二条路。
2. **三类推送各一个开关**（智能体回答 / 有人 @ 我 / 朋友消息），存在账号上（`notify_prefs`，0049），不存在手机本地。
   推不推是服务端决定的，开关只放在手机上的话 runtime 读不到。没有那一行就是全开。
3. **每条聊天一个微信式「消息免打扰」**（`chat_mutes`）。开了就不推送；列表里未读只画点、不画数；页签角标不算它，
   除非有人 @ 我。键与手机列表的键逐字相同（`a:` / `g:` / `t:` / `j:` / `f:`）。runtime 用 `muteKeyFor`
   按 `ringChatKind` 那张表算，判据只有一份。
4. **团队群里智能体的回答只推给发话的那个人**（维护者选的）。规则是「这一轮答的是谁说的话，就推给谁」，
   用 `turn_ended.readUpToSeq` 划界，同 `turnLedger` 的收口判据。私聊和自己建的群里说话的本来就只有我和我拉进来的人，
   所以同一条规则就够，不用分情况。通话里说的话、通话 / 回电 / 外联的招呼不推，因为那一刻人正在电话里听着。
5. **读不到开关就不推**。开关或免打扰没查到时，宁可漏一条，也不能在人明确关掉之后还响：一次网络抖动把免打扰
   翻成了打扰，人没办法自己补救；而漏掉的那条打开 App 照样看得见。两份读数按人缓存 30 秒。
6. **人正看着这条聊天就不推**。云会话由 runtime 判：这个人连着这个房间就不推，同回电的 `isWatching`；手机切到后台
   会主动断开房间。朋友私聊不经过 runtime 的房间，所以在手机前台的通知处理器里挡（`openKeyNow() === alertKey`）。
7. **朋友消息由 runtime 订 `messages` 的 INSERT**（service key）。客户端直接往表里写，没有别的出口经过服务端。
   Realtime 断线期间写进来的不补推。
8. **朋友私聊的已读回执**（`friend_reads` + `mark_friend_read`）。只画在我发的最后一条底下，而且只在它就是整条线
   最后一条时画。**对方没有那一行就什么都不画**，不写「未读」：旧版本和桌面从不写这一行，否则用它们看过消息的人
   在这边会一直挂着一句假话。所以新版本打开私聊时，哪怕一条都还没读，也写一行 0。设置里「已读回执」关掉以后，
   我名下的回执置空、之后不再写数，对方那边就什么都不画。这个开关只管「别人看不看得到我」，不影响我看别人（单向）。
9. **`friend_reads` 从不删行**（同 0044）。Realtime 对 DELETE 不查 RLS，删一行就是把 `(reader, peer)`，
   也就是「谁和谁是朋友」，推给所有订阅者。`chat_mutes` 不进 publication，所以照常删。

## 代价

- 通知权限在登录后第一次回到前台时问。拒了以后设置页说清「这里开着也收不到」，并给一条去系统设置的路；App 自己改不了这一格。
- `sessionService` 的 `alert` 是可选的，缺席就一条都不推。它是否接上，靠一条读 `daemon.ts` 源码的断言保证
  （`tests/runtime/daemonPushWiring.test.ts`），因为 daemon.ts 进不了 vitest。
- daemon 重启时正在答的那几句照样推得到（装配时把种子日志喂进折叠）；但 realtime 断线期间的朋友消息不补推。
- 桌面不报已读，所以只在桌面上读过的消息，对方那边停在上一次手机报的位置。
- 部署顺序：先跑 0049，再部署 runtime，再发手机包。反过来时 runtime 读不到开关，按「读不到就不推」一条都不发；
  手机设置页那段开关不画。真机一次没跑过。
