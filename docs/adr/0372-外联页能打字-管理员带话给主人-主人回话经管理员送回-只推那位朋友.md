# ADR-0372：外联页能打字——朋友的话由管理员带给主人，主人在管理员私聊里回、管理员送回外联；外联回复只推那位朋友

日期：2026-10-05 · issue #1655 · 维护者原话：「可以和好友的智能体聊天，并且如果有需要好友的智能体会帮我和主人带话」
（截图：手机「雨姐 [继爸]」那一页 = 朋友的管理员给我打电话的外联会话，只有来电记录，底栏写「这是 Mingxuan Zhang 的智能体给你打电话的地方」，不能打字。）
设计与逐点依据见 `docs/superpowers/specs/2026-10-05-friend-agent-chat-relay-design.md`，实施计划见
`docs/superpowers/plans/2026-10-05-friend-agent-chat-relay.md`；本条只记决定与取舍。

## 背景

ADR-0337 的外联会话是智能体给好友打电话的地方：好友只在有一通外联进行时能 `say`，会话里没有工具、不注入记忆、不推送，输入栏
被换成说明条。spec `2026-10-03-agent-calls-friend-design.md` §13 把「好友主动找它」留作二期。维护者现在要的就是这一期：好友能在
这里和对方的智能体聊，聊到要主人拍板的事，智能体替好友给主人带话。管理员唯一入口（ADR-0367）、好友档位（ADR-0350）、跨主场档位口径
（ADR-0368）、车道桥只说话不掀审批（ADR-0358）、`message_friend` 的闸（ADR-0362）已经给出了所有零件。

## 决定

1. **落点就在外联页打字**：`say` 闸改成外联里只认那位好友、且此刻好友档位仍是「全部开放」（查不出按不放行），不再要求有一通电话在进行；
   主人在外联里仍不能说。每对每小时 30 句（`OUTREACH_CHAT_PER_HOUR_MAX`，runtime 内存窗，花的是主人额度）。重启补跑只丢落在一通电话
   之内的开场白（`outreachLiveAt`），打字聊的照常补跑。（spec §2.1）
2. **朋友 → 主人：`relay_to_owner(text)`**，外联会话里唯一的工具、只给管理员；客人点起的轮里不掀审批（只对自己主人说话、不动任何人的东西，
   论证同 ADR-0358 决定 2）。落地经 `outreachHub.relayToOwner` 找主人主场的管理员私聊，落 `greeting: "friend_relay"` 开场白起一轮，
   让管理员对主人说「X 让我带话：…」；这一轮受监督（正文是外人的话，进 `openingTraits.report`）；每对每小时 5 次。（spec §2.2）
3. **主人 → 朋友：`reply_to_friend(friend, text)`**，挂在主人主场的管理员上，与 `message_friend` 同闸（主人亲口、非监督轮）；只能回
   已有外联会话且档位仍「全部开放」的好友。经 `outreachHub.replyToFriend` 落 `greeting: "owner_reply"` 开场白、起一轮，管理员把主人的话
   转给朋友。（spec §2.3）
4. **推送只推那位朋友**：外联里的回复不再一刀切不推——只推给那位朋友、通话中不推，主人仍不收；列表 / 静音键用 `o:<sessionId>`。手机推送点开
   落外联页。（spec §2.4）
5. **管理员在外联里的提示词与记忆**：brief 带 `collabAuthPrompt("full", 朋友名)` 与新段 `outreachChatPrompt`（事实直接答、要拍板的事带话、
   不替主人答应；工具真挂着才提，#1206）；外联放开 wiki 快照，引言换只读版（`renderWikiPrompt` 的 `readOnly`），因为两把 wiki 刀在外联里都没挂。
   （spec §3）
6. **手机**：`outreachComposer` 朋友那侧回到输入框，主人那侧仍是只读说明条（改为「要回话，跟你的管理员说」）；空页文案换成
   「可以在这里和 X 说话，它打来的电话也记在这里」。（spec §5）

## 推翻 / 修订

- **ADR-0337 决定 2「好友只在通话中能说话」**：改为外联页随时可打字（决定 1）；通话中的 `say`（语音转写）路径不变。
- **ADR-0337「外联会话不注入记忆」那一条**：外联存在 = 主人给了这位朋友「全部开放」，与公开车道一致放开，引言换只读版（决定 5）。
- 不动 AGENTS.md：这是智能体 ↔ 它自己的主人，不是智能体 ↔ 智能体，不碰「不做通用多 agent 编排」那条窄口。

## 否决的

- **跳回好友私聊页**让朋友在那儿打字：维护者选了就在外联页（spec §0.1）。
- **新建 `outreach_relay` 事件类型 / 给 `outreach` 事件加 phase 值**：前者要登记进七张穷举表只为画一条灰注，后者会弄乱 `outreachFold` 按
  started / ended 折通话状态；带话的痕迹就是工具调用 + tool_result + 开场白，全在现成事件里。
- **单向带话**（只朋友 → 主人）：主人的答复没有回路，管理员只能说「已转告」就此断掉。

## 代价与已知未做

- 每小时窗（30 句 / 5 次带话）在 runtime 内存里，重启清零（同 ADR-0358 的已知代价）。
- 外联没有单独的免打扰开关；`o:` 键不进 `chat_mutes`（那张表的键是会话 id，外联的键是推送列表键）。
- 外联里没有「主动开一条」的入口，也没有回拨电话（spec §13 另一半）；主人在外联页仍只读，回话走管理员私聊。
- 外联里的朋友多了管理员能读主人 wiki 这条路（决定 5），只靠提示词约束它不外泄、靠「全部开放」档位兜底。
- 带话那条 `friend_relay` 开场白留在管理员私聊的上下文里：之后主人亲口起的轮也看得见朋友那几句原话（受监督的只是带话那一轮本身）——
  同 `dnd_report` 已接受的代价。
- wiki 快照不下发到客人设备：`workspace_wiki_loaded` 与拼着同一份正文的 `request_envelope.system`，对客人（`isGuest`：外联里的朋友、
  主场群的客人）换成同 seq 的空壳（`src/shared/guestView.ts`）。两个出口各裁一次：直播在 `daemon.ts` 的 broadcast、backlog 在
  `frameHandler.ts`。日志不动。不整条丢是因为客户端按 seq 数缺口（`gapNote`），丢了会挂一句「有 N 条没收到」。
- 挂断之后还飘来的语音转写（`say` 带 `voice`、此刻没有通话）拒成「这通电话已经结束了。」，不查档位、不占每小时窗；重启补跑丢「通话里
  落下的开场白」时豁免 `owner_reply`——落下它时主人已被告知「转告了」。
- 不动 schema、不动协议版本；老手机外联页仍只读、推送点开落默认页（不崩）。**部署顺序：runtime → 手机热更新。** 真机未验：推送点开跳
  外联页、两台手机来回一轮。
