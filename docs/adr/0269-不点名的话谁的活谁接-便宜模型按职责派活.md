# ADR-0269：不 @ 谁的话，谁的活谁接——便宜模型按职责把人类的话派给对口的 agent

- 状态：已接受
- 日期：2026-09-09
- 关联：#1153；ADR-0220（`[]` = 「我确认谁都没点」、发言先落盘再起 turn）、ADR-0237（Auto：便宜模型先判一手——本篇的先例）、ADR-0223（接力的两事件形状——本篇**否决**了照抄它）、ADR-0224（管理员是「没人对口」的兜底）、ADR-0252（只 @ 了人的那句发权威的 `[]`）

## 背景

维护者原话（2026-09-09）：

> 现在人类在团队中发消息一定要 @agent，被 @ 的 agent 才会有反应。做 agent 们会根据人类的需求自己接活。但不是人类一句话所有 agent 都抢活，agent 只接属于自己的活。现有的 @ 依然保留，人类可以指名道姓要谁干活。

改动前的三条事实：composer 发出去的话没 @ 任何人时带一个权威的 `mentions: []`，`say()` 只落一条 `chat_message`、不起 turn（ADR-0220 决策 2「不 @ 就只是群里说一句」）；开局卡走 `mention: true`，解析不出 @ 就回落名单第一只（管理员）；云会话的 system 提示词明写「@ 你的那条才会触发你的回合，其余的你看得见但不必逐条回应」。

三个要维护者拍板的点，会话里定了：**没人对口的活归管理员**（闲聊/问候/确认仍然没人接）、**开局卡走同一条路**（ADR-0218「一个开法」）、**派活失败要在群里说一声**。

## 决策

### 1. 判据是一次真实的分类调用，不是每只 agent 自己判、也不是全员起 turn

`say()` 解出零只人亲手点的 agent 时，用网关**最便宜那款**读一遍「名册（编号 + 名字 + 一句话职责）+ 最近 8 句群里说出口的话 + 这句话」，只要它回一串编号或 `none`。三条候选与理由：

- **每只 agent 各判一次「是不是我的活」**：字面上最像「自己接活」，但 N 次调用之外还有一致性问题——两只都说是（正是维护者不要的「抢活」）或都说不是，没有任何一层能仲裁；中央那一次看得见全部候选，才挑得出「最对口的那一只」。
- **全员各起一个 turn、不是自己的活就闭嘴**：N 条真花钱的 turn，且「闭嘴」本身要靠提示词自律——正是「所有 agent 都抢活」的形状。
- **关键词匹配职责**：零成本，但「属于谁的活」是语义不是字符串（「昨天卖了多少」对不上「运营」两个字），同 ADR-0237 否决启发式的理由。

输出要**编号**不要名字：名字要经过模型的嘴，多一字少一字就对不上，编号是我们自己发下去的、解析只认数字。分类器挑出的只数**封顶 3**（`DISPATCH_MAX_TARGETS`，截断不拒绝）：一句话真要三只以上接的情形几乎不存在，四只以上几乎必然是分类器过热。

### 2. 判完再落，单事件——不照抄接力的两事件形状

派出去的那几只落成**一条** `user_message{fromUid, mentions:[挑中的], dispatch:"auto"}`，与人亲手 @ 的那条走**逐字节同一条路**：`openTurns` 的排队/正在回复、`unseenUserTail` 不重采样、增量采样跳过、停止键、护栏、接力链首（`isHumanOpening` 只看 `mentions && !relay`，派活开场白天然是人话点火、depth 归零）、审批归发起人——全部免费拿到，`dispatch` 只是记号。

**否决了**「先落 `chat_message`（消息秒出）、判完再补一条隐藏的派活开场白」这种 ADR-0223 同款的两事件形状。它的病在**双答**：`chat_message` 不带 `mentions`，正在跑的那一轮 agent 会在下一圈增量采样里读到它并顺手答了；之后补上的开场白又给同一只排一个 job，再答一遍——#934 那个坑换个入口重演。单事件形状下这句话落盘时就带 `mentions`，运行中的 turn 按 #957 A-10 那条规则跳过它，只由它自己的 job 答一次。代价是**发送方自己的消息晚 0.3～1 秒出现**（`say()` 的回执等判定，桌面在回执到了才画那条消息、才清草稿），`DISPATCH_TIMEOUT_MS = 5000` 封顶，远小于桌面那侧 15 秒「不知道」的线（ADR-0228）。

判成「没人该接」落 `chat_message`——与改动前逐字相同，闲聊照旧是闲聊。

### 3. 何时不判：人已经在指名

正文里有任何 `@` token（哪怕解析不出——打错的名字、名单刚变过；`sayUnknown` 那句「有 N 个点名找不到」照说）、或 `memberMentions` 非空（只 @ 了人类成员，说给人听的，ADR-0252）→ 分类器一次都不调，走改动前的路。人已经决定了收件人，系统不该替他改主意。

agent 之间照旧只走 @ 接力（ADR-0223）：**不给 agent 的回复做派活**——那是自激，接力那三道刹车管的是 @ 链，管不住「分类器替 agent 的话找下一只」这种没有 @ 的链。

### 4. 判不出来一律回落今天的行为，但要说出口

网关非 2xx / 超时 / 答案认不出 / 探不到 / 名单降级——全部 `failed`（ADR-0237 那条纪律，`none` 只在分类器**明确**这么说时成立）：

- `mention: true`（开局卡 / 旧手机）→ 名单第一只接，开场白**不带** `dispatch` 记号，群里不出声——这就是改动前的第 ③ 级老语义，只是从「第一选择」退成「回落」；
- `mention: false`（composer）→ `chat_message` + 一句署名系统的话「这句话没派出去（原因），需要谁接的话 @ 一下」。改动前这里是静默，但改动前用户也不期待有人接；现在他期待，不说他就干等。判据同 ADR-0250：**人能据此行动**（@ 一下）的话才落在群里。三种「问不出订阅」各说各的话（ADR-0233 的措辞纪律：一次 edge 抖动不许写成「你没订阅」）。

**没订阅 / 订阅不活跃是第四档 `skipped`，回落但不出声**：那个团队一只 agent 都起不了 turn，云会话头部那行 blocked 已经在说这件事（ADR-0246），逐句再落一条「没派出去」是噪音——一个没订阅的团队里人与人聊天，每句话都会被系统插一嘴。与 `failed` 的分别只在要不要说：探不到（网关抖了，下一句就可能好）说，没订阅（常态）不说。

限速在**分类器挑出 n 只之后、落盘之前**问价（`budget(n)`，同 #957 B2-C1「价钱在判据的同一侧算」）。被拒时**话照落、只是没派出去**并说一声——人亲手 @ 被限速时整句拒收（改动前），派活被限速时不能因为系统自己的决定把人的话整句吞掉。

`resolveTargets` 拆成两级：`resolveExplicitTargets`（客户端算好的 `mentions` / 服务端从正文解析）+ 第 ③ 级回落。拆的理由是**顺序**：「人没点名」这个判据要在 ③ 之前问，否则 `mention: true` 的开局卡永远轮不到分类器。

### 5. 分类器读什么、以谁的身份、怎么记账

名册 = 此刻真名单（降级占位不进去，按 `failed` 走）；`admin` 那只标「没人对口的活归它」（稳定键，ADR-0224 的判据；名册里没有它才退回第一只 = 老语义的落点）。上下文 = 日志**尾段**（最近 200 条事件）里最近 8 句说出口的话：`chat_message`、人的 `user_message`（接力开场白与 engine 注的私话不算——同 `hiddenFromCloudTimeline` / `agentView` 的口径）、有正文的 `assistant_message`；每句 240 字、这句话 1200 字。名字/职责/发言人过 `promptSafe`，正文过 `promptSafeBody`（ADR-0226/0230 的两道闸在这里同样成立——分类器的判决决定谁花钱）。

以**团队所有者**的身份调网关（`x-runtime-secret` + on-behalf + workspace/session 头），**不带 agent 头**：这一次调用不属于任何一只，`usage_event.agent_id` 空串 = 未归因（ADR-0221）。照常落 `usage_event`、照常扣所有者的窗口——不做暗扣（同 ADR-0237 决策 5）。

### 6. 只改投影不改帧，协议不进位

`UserMessageEvent` 加可选 `dispatch?: "auto"`（缺席 = 人亲手 @ 的 / 接力 / 旧日志），不新增事件类型——新事件类型那十一处清单一处都不用碰。`say` 帧不变；旧桌面收到带 `dispatch` 的 `user_message` 照普通人话画（`UserMessageRow` 与 `ChatMessageRow` 本来就是同一张 `SpeakerRow`），行为正确，所以 `CS_PROTOCOL_VERSION` 不动。不带 `mentions` 字段、只发 `mention` 布尔的客户端走的是同一条路（今天只有开局卡与 `smokeAssembly` 那条冒烟；**手机端还没有云会话客户端**——`mobile/src` 里没有任何 `say` 帧，ADR-0134 验过，代码注释里的「手机端/旧桌面」说的是一类客户端不是一个存在的实现）。

提示词那句改成「@ 你的那条、以及没 @ 任何人但系统按职责派给你的那条，会触发你的回合」；composer / 开局卡的 placeholder 改成「不 @ 的话，谁的活谁接」。

## 后果

- **runtime 要重新部署**才生效（#791）；桌面只改了两句 placeholder 与事件类型声明，不发版也不影响正确性。
- 每条不 @ 的话多一次便宜调用（约 300～600 输入 / ≤64 输出 token，最便宜那款上不到 $0.0001，0.3～1 秒延迟）；Auto agent 被派到时再叠一次判难度（ADR-0237）。
- `DISPATCH_MAX_TOKENS = 64` 是给推理模型留的余量（ADR-0237 真机上 8 个 completion token 里 7 个是 reasoning）；便宜档换成一款思考更长的模型时答案可能被截掉，表现是群里多一句「没派出去（分类器没给出可识别的答案）」而不是静默——**真机一次没跑过**，这个数要靠真机校。
- 分类器只看最近 8 句：更早的上下文决定归属时会判错（判错的形态是「派给了不对口的那只」或「没人接」，都看得见）。
- `spentMicro`（接力预算的下界）漏掉这次调用，同 Auto 那条已知代价。
- 「派给了谁」在时间线上没有独立记号：人看到的是「运营 排队中」那行小灰字 → 输入指示器 → 回复，与人亲手 @ 的形态相同——这正是「agent 自己接活」该有的样子；要查「为什么是运营」去轨迹视图读 `dispatch` 字段。
- 已知未做：按团队关掉派活（今天没有开关，不 @ 就一定判一次）；分类器读成员显示名的 `memberMentions` 之外的「@人名但没被客户端认出」的情形（走 `sayUnknown`）；agent 回复触发派活（明确不做，见决策 3）。
