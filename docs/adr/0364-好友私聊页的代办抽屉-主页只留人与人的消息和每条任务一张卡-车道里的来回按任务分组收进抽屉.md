# ADR-0364：好友私聊页的代办抽屉——主页只留人↔人的消息和每条任务一张卡，车道里的来回按任务分组收进抽屉

日期：2026-10-04 深夜 · issue #1563（父）/ #1565（本条，P2）· 维护者原话：「这些对应的任务不应该显示在对话页面，会导致整个
对话框非常乱，应该在对话页面做一个抽屉，把这些任务和 AGENT 相互的聊天对话保留在这里。」四问拍板（#1563 评论）：主页
只留任务卡；抽屉按任务分组。

## 背景

ADR-0353 起，私聊页把两条车道（我的、朋友公开给我的）的每一句都 merge 进人↔人的时间线。只有一只智能体、偶尔 @ 一句时
还行；ADR-0363 之后代办是「朋友 → 管理员 → 下发 → 下一棒回」好几句一串，再加上打电话的总结，主页整屏都是智能体在说话，
人↔人那两句找不到。

## 决定

1. **一次请求 = 一条任务**（`laneTasksOf`，纯投影）：人点起的一句话、或一通打给智能体的电话开一条；之后智能体的回话、
   管理员的下发（接力开场白，标成 `handoff` 并记下给了谁）、下一棒的回话、挂断、打完电话的总结都归到它名下，直到下一句
   人话。没有人话在前的回话自己成一条（`startedBy: "agent"`）。招呼 / 汇报 / 总结那几种开场白是模型可见的内务，不画。
   全部从车道日志推导、不另落事实——硬规则里「任何投影必须可从日志推导」这一条照旧成立。
2. **主页每条任务一张卡**（`TaskCard`）：标题 = 请求第一行（截 40 字）/「打给 X 的电话」，第二行 = 谁在办 · 几条进展 ·
   状态（代办中 / 已回复 / 等回复，`laneTaskStatus`：还有人在答 = 代办中，与云会话状态行同一份判据），底下仍是那句
   「谁看得到」。卡按任务开始时间与私聊合成一条时间线，同一毫秒私聊在前。
3. **抽屉**（`TaskDrawer`，现成的 `BottomSheet`）：点卡打开，按 key 现找那条任务——抽屉开着时车道里新来一句，抽屉跟着长。
   过程用同一份 `LaneBubble` 画（搬成独立文件给两处共用），下发那一行底下写「下发给 X」。底下一格能接着说：朋友那条车道
   只对 TA 的管理员说（ADR-0363 的入口），我的那条对这条任务里出现过的那几只（没有就对带进来的全部）。
4. **粒度上的一个已知取舍**：电话里朋友说的每句话都是 `user_message`，会各开一条任务。P2 先接受——通话一结束总结就来、
   卡上看得出是电话；要合并得按「通话进行中」折叠，留给真机看过效果再定。

## 没做

- 不改事实层、不改协议、不改 schema；只需手机热更新。
- 桌面端不动（它不画车道）。
- 不做任务的「完成 / 归档」状态：卡上的状态是从日志推出来的，不另记。
