# ADR-0376：群聊座位制——每人带着自己的管理员；座位会话住在各自主场；别人使唤要主人点头

日期：2026-10-05 · issue #1682 · spec `docs/superpowers/specs/2026-10-05-group-seats-design.md` · 维护者原话：「不需要拉 AGENT 入场，每个人都带着自己的
AGENT。AGENT 与 AGENT 在群中可以相互协作，别人也可以使唤你的 AGENT，只不过需要你点头，这点针对 L0 级 AGENT。」拍板全文见 #1682 评论。

## 背景

runtime 日志（工作区 726f3113 的群会话 4cfbe736，2026-10-05 12:10–12:48Z）把 ADR-0325 的模型的问题全摆出来了：群只是群主主场里的一条
会话，客人「只能拉人」、带不进自己的管理员；客人 @ 谁都被改成群主的管理员（ADR-0367 第 1 条）；客人起的一轮每一把刀都弹给群主批、
写着「在等 Stan 批准」而 Stan 批不了；群里没有 `schedule_task`，两件提醒都没办成。

## 决定

1. **群 = 人的地方；智能体住在各自主场的座位里**。群（`chat_kind='group'`，名单带 `seats`）只记人说的话、各家管理员的回话与点头卡的镜像，
   不起任何 turn。每位成员在自己主场里一群一条座位会话（`chat_kind='seat'`），他的管理员在那里用他的额度、工具、记忆跑。两份日志靠
   进程内的桥（`seatHub`，同 `adminsBridge` 的形状）互相送话——智能体只能在自己主场跑（admins spec §1 已验），这是唯一不借别人电脑的做法。
2. **人进群，管理员自动在场**；没有拉智能体这个动作。座位 = 群里每个人（含群主）。
3. **谁 @ 谁**：主人 @ 自己的管理员 = 主人自己的一轮（与私聊同一套全套工具、免审批）；别人 @ 它 = 客人轮，**只有一把 `ask_owner`**，
   只能聊天；要动手调 `ask_owner` → 主人收到点头卡，接了落一条 `greeting: "seat_grant"` 的主人开场白起一轮（按主人的规矩、但不算
   「主人亲口」，替主人联系别人 / 定时 / 改设置照旧要主人亲口）。10 分钟没人点按过期。座位主人可以按群设「全部放行」：省掉卡，直接授权。
   一件事点一次头，不再一刀一卡。
4. **发起人按句子算**：座位里协调器按 (智能体, 发起人, 开场白种类) 去重，别人的话另排一轮，不折进正在跑的主人轮；镜像进来的群聊行不收紧监督。
5. **管理员之间协作**：回话里 @ 别家管理员 = 以本家主人的身份去使唤它，规矩同人 @ 它；深度 ≤ 6、一群每小时 ≤ 60 次（同车道桥）。
6. **旧群迁移**：有客人的主场群开房时转成座位制（`agents: []`、座位 = 群主 + 客人），落一句系统话；没有客人的「我和我的智能体」群不动。
7. **群主退群转给最早入群的人**（`groupOwnerUid`）；日志仍放在原群主主场，他不再在籍。
8. **协议 30 → 31**（welcome 多 `seats`；上行 `seat_decide` / `seat_policy`）；**migration 0068**（`seat` 那一支 + `group_session_id`）。

## 否决的备选

- **在群主的会话里替别家跑引擎**（同一条日志、借对方的 world / wiki / 额度）：对方的工具结果会落进群主主场的日志、广播给全群；
  `CloudSessionOpts` 里约 40 格都是按会话定的，改成按智能体定是整份 sessionService 的重写。
- **每家一份对等日志、没有正本**：建群 / 退群 / 名单都要 N 方对账，改动面大一个量级；拍板 K「群主退群转给最早的人」也说明维护者心里有一份正本。
- **客人轮照旧一刀一卡**：日志里已经证明不可用（卡给错人、2 分钟过期、群主看不到座位里的卡）。

## 代价

- 每次 deliver 把群聊增量镜像进座位，日志多一份；只在被 @ 时镜像，不 @ 的座位不写。
- P1 的 L1 在座位里干活、读得到镜像进来的群聊（拍板 F 要它看不到）——P2 的工位一起收。
- 原群主退群后日志仍在他主场：RLS 上他仍读得到那一行（`is_ws_member`），手机按名单不画；真要切断要把日志搬家，P1 不做。
- 部署顺序：0068 → runtime → 手机热更新。0068 没跑时建座位会话 insert 失败，被 @ 的管理员回一句「这会儿接不住」。
