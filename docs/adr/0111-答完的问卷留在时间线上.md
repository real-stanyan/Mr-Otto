# ADR-0111：答完的问卷留在时间线上

- 状态：已接受
- 日期：2026-08-26
- 相关：ADR-0018（不为 ask_user 加新事件类型）、issue #463

## 背景

`ask_user` 答完之后，活着的那张问卷卡（`QuestionnaireCard`）就消失了，时间线上只剩一行折起来的通用工具行「提问 <第一题> · N 题」，答案埋在折叠区里的一坨 `tool_result` 文本中。

问题不在于"少了点装饰"：**用户的回答是后面每一步的前提**。往回翻一段对话时，"模型当时问了我什么、我选的是哪个"决定了后面那些代码为什么这么写；把它收进折叠区，等于要求人点开才能看见自己说过的话。

## 决策

### 一、答完的那一步换成一张只读卡

`ToolFallbackWithLiveTail` 里加一支分支（同 memory / web_search / session_search 的先例）：`ask_user` 且有结果 → 画 `AnsweredAskCard`，解析不出来就落回通用工具行，不猜。

卡的外壳沿用 `elements/elicitation-form`：和活着的那张问卷卡是同一件衣服的两种状态（`request` → `accepted` / `declined`），读者不用学第二套长相。

**选项全画出来，只把选中的填实**——比只写答案多一层信息：当时的备选是什么、这个决定是在多大的空间里做的。自填答案画成虚线边框的单独一枚，不混进选项 chip：它不是模型给出的选项，画成实心 chip 等于伪造了一个选项。

### 二、答案从哪来：给 `formatAnswers` 补一个逆函数

问题那半边在 `call.args` 里，答案那半边在 `tool_result.output` 里——**两半各在各的事件里，投影时才合起来**。这正是 ADR-0018 当时的判断（不为问卷加 `question_asked` 事件，那是把同一件事记两遍）；这次的卡片是那条决定的下游验证：不加事件也画得出来。

于是 `formatAnswers` 需要一个逆函数 `parseAskUserResult`。两个函数放同一个文件（`src/shared/askUser.ts`），咬同一组字面量常量——一边改格式而另一边不改，`tests/tools/askUser.test.ts` 的往返用例当场红。

编解码从 `src/tools/askUser.ts` **搬进了 `src/shared/`**：渲染进程要读同一份答卷，而渲染进程不许 import 工具层（工具层是主进程的东西，同 `shared/sessionSearch.ts` 顶上那条理由）。`src/shared/askUser.ts` 因此从"纯类型"变成"形状 + 编解码"。

答案文本的切分有一处不可逆：选项 label 自带 `；` 会被切碎。因此配对时以 `args` 里的选项表为准（对不上的 label 补一枚 chip，不丢答案），而不是拿切出来的字符串当真理。

### 三、含答卷的工具组默认弹开

工具组默认折起的理由是"一屏五个 read_file 谁也不想逐个看"——那说的是模型自己干的事。**用户的回答不是模型干的事**，收进折叠区就回到了本文开头那个问题。

因此：这一组里出现"问过你、你也答了"的那一步 → 这组自动弹开一次（受控 state，不是 `defaultOpen`：答案是后到的，`defaultOpen` 只在挂载那一次读，而提问那一刻这组已经挂载了）。弹开之后用户想折回去随时可以。

代价：同组里挨着的读文件行会跟着露出来。assistant-ui 有"单独成行"的正路（`standalone-tool-call`，见 `thread.tsx` 的 `GROUP_PARTS_BY`），但它要走工具 UI 注册表，是另一件事；在此之前，多露几行远好过把回答藏起来。

## 后果

- 时间线上第一次能直接看见"我答了什么"，不用点开折叠区
- `src/shared/askUser.ts` 不再是纯类型文件；工具层从它 import `formatAnswers`
- 取消/中断的那次也画（`declined` 态 + 原因）——题面本身是发生过的事，不该被吞掉
- 三层各有测试：往返（`tests/tools/askUser.test.ts`）、配对（`tests/renderer/askUserCard.test.ts`）、真跑一遍（`tests/e2e/askUserAnswered.e2e.ts`）
