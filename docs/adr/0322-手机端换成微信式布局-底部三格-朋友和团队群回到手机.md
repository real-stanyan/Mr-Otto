# ADR-0322：手机端换成微信式布局——底部三格，朋友和团队群回到手机

- 日期：2026-09-27
- 状态：已采纳
- 关联：#1386（demo 已过，手机那一半）；spec `docs/superpowers/specs/2026-09-27-wechat-mobile-design.md`；demo `.demo/wechat/mobile.src.html`
- 关系：**推翻 ADR-0317 决定 1**（「一个原生栈，名册是栈底……没有底栏、没有第二个根」）与它后果里的「手机上没有好友了」。ADR-0293 决定 2（原生栈）、3（依赖只取 Expo Go 自带）、7（表单与确认用居中弹窗）与 ADR-0317 决定 2–6（像素脸的画法、`alive`、手机不画圆盘、云会话客户端在 shared、两条架构断言）原样成立。#1356 那一版的判据（谁排前面、藏哪些事件、派活线、先开口、语音编排）原样留着，换的是外壳

## 背景

维护者（#1386）：「干脆就做成和 WeChat 一样的布局……只保留把 Agent 作为联系人聊天使用的功能」；demo 过了之后：「按照设计稿做手机版，一口气全做完。」过 demo 时另外定了四条：团队、好友都留；底部三格「聊天 / 通讯录 / 我」；「不区分团队和群聊，都叫群聊，无论里面有几个真人」；额度「先只改设计」，真规矩不动。

ADR-0317 的第一层只回答「我有哪几只智能体」。微信式的第一层回答的是「谁在找我、我在跟谁聊」——智能体、朋友、群排在同一列里。这两个问题的答案形状不同，所以是推翻不是修补。

## 决定

1. **一个原生栈，栈底是底部三格**（`@react-navigation/bottom-tabs`，依赖早就装着）：聊天 / 通讯录 / 我。推进来的页盖住底栏（照 iOS 微信）。页签根的页头自己画（标题居中 + 右边一颗），推进来的页用原生导航条（只留返回箭头，有别的未读时箭头后面带数字）。
2. **朋友回到手机**：`friendships` / `messages` 的 RLS 与 realtime 早就在（0001），桌面天天在用；查询层照搬 #1356 删掉之前那份（a8145959^），补了往上翻页（`beforeId`）与「我收发过的最近一批」。Realtime 两条通道，哑了降级成 8 秒一次的轮询，通着时一次都不拉。
3. **团队的每一条云会话是一个群聊**，界面上不分团队群和主场群（维护者原话）。手机从没开过团队会话，协议、客户端、时间线判据都是同一份；**审批卡是这一版的一部分**——团队会话缺省要批（`sandbox_approval = ask`），不接审批就开团队会话，等于手机上发的每一句要动手的话都卡满十分钟。谁能批与桌面同一条（发起这一轮的人或群主），过期、拒绝收成一行小字。团队的成员管理不在手机上做：拉一个人进「这个群」其实是拉进整个团队（成员、连接器、几条会话共用），信息页照实写「成员由群主在电脑上管」。
4. **未读：朋友私聊数条数，其余画一枚点**。智能体私聊 / 群 / 团队群的库里只有「最后一句」一格（`last_ts` / `last_from`，0040），数不出条数（#1282）。「看到哪一刻」的游标存在这台手机上（kv-store，**按账号分键**，ADR-0187 的纪律），第一次读到时以此刻为基线——一装上满屏都是未读是最坏的开场。底栏角标与「聊天(n)」数的都是**有新消息的聊天有几条**，不是消息条数：一个数两种口径最坏。开着的那一条不画未读。
5. **按住说话发出去的是一句普通的话**，不带 `voice` 记号：那个记号的意思是「通话里说的」，带上它会被折进通话卡（ADR-0288）。松手时先 `pause()` 再停——原生模块的 `pause()` 会把手上那半句收成一条 `final`，所以**不改 Swift**（改了要重编开发版、要人重新点授权）。只在开发版里有（同电话钮，ADR-0320）。
6. **列表语汇换成微信的通栏**：整行铺满、分隔线从头像 / 文字右边开始、段头段尾小字。`ui.tsx` 的 `Group` / `Row` 跟着改，于是 A5 那几页（文件、应用、记忆、用量、订阅、设置）一起换——维护者要的是整套一致，两套列表语言并存才是代价。
7. **额度页只画「本周」一格**（demo 同款），但 5 小时那扇窗在真规矩里还在：**它比本周更紧、且已经到了要提醒的程度时，底下多一行实话**（`weekQuota` 的 `h5Note`）。不画的话，人会对着「本周还剩 81%」被拦住而不知道为什么。真规矩要不要去掉 5 小时，留给维护者（spec §9 第 2 条）。
8. **判据进 shared**：会话列表怎么拼、怎么排、角标怎么数、时间怎么写、游标怎么推，全在 `src/shared/wechatInbox.ts`（进 vitest）；桌面主进程改资料那套纯逻辑挪进 `src/shared/profileEdit.ts`（桌面改 import、行为不变），改密码的两句判据放在一起，最短长度用 `signInForm` 同一个 `MIN_PASSWORD`。

否决的：

- **新建「你的智能体 + 朋友」混在一起的群。** demo 画了，但今天智能体只住在个人主场里，朋友不是主场的成员；把朋友加进主场 = 让他们碰得到你的文件、记忆、连接器。那是产品与安全的决定，不该在「做手机版」里顺手做掉——「发起群聊」只挑智能体，朋友资料页和朋友私聊里都没有「拉进群聊」。留给维护者（spec §9 第 1 条）。
- **「有人 @ 我时通知」「智能体回话时通知」两行开关**：手机没有推送凭据那一层（ADR-0256 的已知代价），画出来就是点了不生效的开关（#722）。
- **在团队群里画未读条数**：拿不到（同第 4 条），画一个编出来的数比画一枚点更坏。

## 后果

- 未读只有朋友私聊是准的条数，其余是一枚点；换一台手机，已读游标不跟过去。
- 团队群在手机上只能聊、批、看，管不了成员。
- A5 那几页的样子跟着通栏一起变了。
- 手机端第一次开团队会话，审批卡是新写的——桌面那张卡的几条纪律（逐字段、谁能批）照抄，真机没跑过。
- iOS 不许在一个正在退场的 Modal 上再叠一个 Modal 或系统界面（相册），而失败的样子是**什么都不发生**：底部动作单与 ⊕ 菜单选中一样之后，等 Modal 的 `onDismiss` 才做（安卓没有它，退场放完隔一拍）。以后再加「选完接着开另一个浮层」的地方，照这两处写。
- 形象陈列馆的入口原来在名册右上，搬到了设置页底下（只在开发构建里有）。
- 真机一次没跑过；登录之后的流程 agent 跑不了（要人输密码），是用临时根组件 + 假数据在模拟器上（浅色、深色各一遍）过的，冒烟台不提交。
