# 0069 关闭他人 lane 的 context only handoff 不构成接管

- 状态：已接受
- 日期：2026-08-23
- 相关：issue #130（Protocol gap）、ADR-0048（并行班次）、ADR-0009（终止班次）、ADR-0005（handoff 住在 open issue 里）
- 层级：L1（改的是 AGENTS.md「On ending a shift」这条收工规则本身），维护者本会话内明确同意

## 背景

#130 记的是一次连着三班没留 handoff、也没有终止声明的不合规。#119 那一班关掉了一个
context only 的 handoff、把债务立成 #121 / #122 / #123 三个 Task issue，然后收工——
既没为自己开 handoff，也没声明终止。之后至少两班照做。

真正的问题不是这三班粗心，而是**规则里两条各自成立的话拼在一起会自洽地读成合规**：

- ADR-0048：context only 的 handoff 由第一个读到的班次读完关闭。
- 收工规则第 4 条：每班收工要为下一班开 handoff（除非声明终止）。

于是「我关掉了一个 context only handoff」能被读成「我接管了那条 lane 并且把它交接
完了」——主观上就是交接完成。规则里没有任何一句话拦住这个读法。

## 决定

**关闭他人 lane 的 context only handoff 不构成接管。**该班次仍须在收工时二选一：
为自己开一个 handoff issue，或按 ADR-0009 声明终止。没有第三条路。

写进 AGENTS.md 收工规则第 4 条。

## 理由

- context only 的语义就是「这条 lane 没有东西可交接」。读完它拿到的是上下文，不是
  接力棒——把它算成接管，等于说读一份通知就继承了别人的债务。
- 反过来说，正因为它不构成接管，这一班自己那条 lane 的账才必须自己交代：它做了事
  （#119 那一班立了三个 Task issue），做了事就有状态要传下去。
- 二选一而不是三选一：留出「什么都不做」的口子，等于把这条规则退化成建议。#130
  记的三次不合规全都长在那个口子上。

## 代价与推翻点

- 代价：读一个 context only handoff 之后，这一班收工时多一件事要做（开 handoff 或
  声明终止）。这正是想要的成本——它换来的是「每一班的状态都有落点」。
- 推翻点：如果将来出现「一个班次只读不做事」的常态（比如纯巡检班），为它开一个
  handoff 就是纯噪音。那时该加的是「零改动班次可以只声明终止」，而不是回到默认
  沉默。

## 没有一并做的

#130 还问了第二个缺口：重复不合规要不要升级。本次不动——现有规则下记一班和记三班
没有区别，而「升级」需要先有一个能自动判定的检查（#130 建议 2：把「无 handoff 且无
终止声明」做成 `gearbox-agents` 的一条 check）。判定归上游 Gearbox 的工具，不是这个
下游仓能单方面立的规矩；本 ADR 只关掉「读规则的人会自洽地误读」这一个洞。
