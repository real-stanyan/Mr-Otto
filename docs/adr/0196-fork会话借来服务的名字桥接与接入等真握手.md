# ADR-0196: fork 会话借来服务的名字桥接（share_grant_note）+「接入」等到真握手

日期：2026-08-30
状态：已接受
关联：issue #788，ADR-0166（好友前缀）、ADR-0177（分享连带借出）、ADR-0170（secret 只活在内存）

## 背景

真机第一次跑通「A 分享含 square 的会话给 B → B 一键接上 → B 的水獭继续干活」时，
水獭没有调借来的代理工具，而是工具报错后转头 `mcp_configure`/`mcp_authorize`，
想在 B 本地给 square 走 OAuth——「凭证不出 A 的机器」被模型自己绕开了。

两层原因，各自独立成立：

1. **名字对不上号。** fork 历史里的工具调用记的是 A 机器上的名字
   （`mcp__square__get_orders`）；借来的同一台服务在 B 按 ADR-0166 加好友前缀
   （`mcp__square_32c6716a__get_orders`）。工具描述里那句【好友代理】只有翻工具表
   才看得见，弱一点的模型按历史名字重试、失败、然后走本地自救。
2. **「接入」从来不等握手结果。** `proxyAcceptInvite` 起跑 guest 协调器后立刻回
   ok——「A 重启过（一次性 secret 作废，房间再也不开，ADR-0170）」「A 不在线」这两种
   失败都被报成成功。分享卡照着它把对话导入，用户以为接上了，工具表却永远是空的。

## 决定

**1. 新事件 `share_grant_note`：把对应关系焊进模型视野。**

导入连带借出服务的会话包时（且握手已接上），接收端在 fork 日志末尾落一条
`share_grant_note { note, friendUid, servers }`：

- `note` 存**渲染好的成品文本**（来源 ↔ 对应表 ↔ 「别本地配」的劝阻），不存原料。
  日志是历史：当年注入了什么就永远重放出什么，渲染代码将来改了旧 fork 不跟着变。
  文本由 `shareGrantNoteText` 用 `mcpToolName` 同一条流水线现算，不手拼字符串。
- 投影走 `project_instructions` 同一条通道：焊进围栏 system 尾部（compact 免疫——
  对应关系不是历史，是每轮都该在的事实），没有围栏 system 时退回 user 消息。
- **不带 `ignorable`**：它参与模型视野推导。旧版本跳过它 = 重建一个少了这句话的
  视野，宁可拒读（UnknownSessionEventError，处方是升级）。

**2. `proxyAcceptInvite` 等到握手完成再回答**（默认 12s，`acceptWaitMs` 可注入）。

超时 = 直说失败（话术点名两种最常见原因与解法）。台账（setBorrow）在等待前已落盘、
失败**不回滚**：同一个好友复用同一个频道，A 重发邀请后这条台账直接可用。

## 边界（已知的天花板）

- guest 侧 `isReady` 只证明「B 这一半握完了」：A 在线但**拒认持有证明**（伪造 secret）
  时 B 侧照样 ready——这道等待拦的是「房间根本没开」那一形态（A 重启/不在线），
  「A 拒认」的告知仍靠 A 侧不 pin、不推 grant 那条既有防线。
- 注记只在**导入那一刻**知道的授权范围上说话；A 事后改白名单（proxyUpdateGrant）
  不回写注记——工具表本身每 turn 现算，注记只负责「名字怎么对上」。

## 被否掉的路

- **借来的服务在 fork 会话里沿用 A 的原名（去前缀）**：正面撞 ADR-0166 的三条理由
  （同名碰撞静默丢刀、审批记忆按完整工具名、派发要认得出这是谁的）。
- **导入时改写历史里的工具名**：历史不可改写（append-only 硬规则），且 tool_result
  与 assistant_message 的 toolCalls 成对，改一半日志就在说谎。
- **靠工具描述让模型自己领悟**：真机已证伪一次（DeepSeek V4 Flash 走了本地 OAuth）。
