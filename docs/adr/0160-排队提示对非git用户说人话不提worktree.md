# ADR-0160：排队提示改成对非 git 用户说人话——不提 worktree，并给「换个文件夹」这条出路

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #653；ADR-0152（进程内互斥）/ ADR-0155（跨进程锁）的提示语；成因是 ADR-0157

## 背景

ADR-0152 拒绝第二条 turn 时那句话是这么写的：

> 继续的办法：等它跑完，或者让这个会话换一个文件夹（同一个仓库可以用 git worktree 开一份独立的工作目录）。

写的时候它是对的：那时候两只水獭指着同一个 git 仓库是常态，worktree 正是修法。

**ADR-0157 把这句话的读者换掉了。** 工作区在 git 仓里就自动开副本，两只水獭各自一份工作目录、根本撞不上——于是这条提示唯一还会出现的场合，只剩**工作区不在 git 仓里**。也就是说：这句建议在它唯一的读者面前是天书，而那位读者恰恰是把一堆文案放在一个文件夹里、这辈子没跑过 `git` 的人。

维护者的原话：不是所有用户都拿 Mr Otto 写代码。

## 决策

两条互斥（进程内 / 跨进程）的拒绝提示重写，三件事：

1. **不提 git 与 worktree。** 会读懂 worktree 的那批用户，已经被 ADR-0157 挡在这条提示的适用范围之外了——对着剩下的人说它，只有负价值。测试用 `not.toMatch(/worktree|git/i)` 钉住。
2. **先说这是设计，不是故障。**「同一个文件夹，同一时刻只让一只水獭动手——这是故意的，不是出错了。」没有这句，用户的默认解读是第二只水獭坏了，然后去重启、去重装、去提 bug。
3. **给真正的出路：换一个文件夹。** 文案类工作想并行，正常做法是两个文件夹各写各的，不是同一个文件夹里两只手。

原来那两处**共用的信息**（谁占着、哪个目录、锁会过期）一条不少。

### 顺带：占用方点名用标题，不用会话 id

「正在忙的会话：a7f3c1」对这条提示的读者等于没说。标题（`store.sessions()` 里已经有，
调用点本来就在读那张表）拿得到就点名——「给客户写提案（a7f3c1）」，用户立刻知道该去
看哪一只水獭。id 保留在括号里，诊断时还要用。还没自动命名的会话退回只报 id，不编造。

跨进程那半不做这件事：对方的 sessionId 属于另一个安装的日志库，本进程查不到它的标题。
那条提示本来就点的是程序名和进程号。

### 为什么把措辞抽成共用常量

`EXCLUSION_WHY` / `EXCLUSION_WAY_OUT` 导出自 `workspaceExclusion.ts`，跨进程那半 import 同一份。

不是为了省几行字。这两句原本各写各的，然后**其中一句漂了**——本 ADR 修的就是那次漂移。用户看不见「进程内」和「跨进程」的分界，他只知道自己被拦了两次、读到两段不一样的解释。共用一份让「口气一致」变成机制，而不是下一个人要记得的事。

### 为什么不建议 `git init`

技术上，`git init` 之后 ADR-0157 就生效，同一个文件夹里真能并行——这是这条提示唯一没说的出路。故意没说：

- 对不用 git 的人，`git init` 比 worktree 更像天书，只是换了个词的同一个错误；
- 它真正的代价在后面——副本要合回来，合回来会有冲突，而冲突的解法是 git 的解法。把人推进一个他没有工具解决的状态，比让他多开一个文件夹糟得多。

「给非 git 文件夹也做副本」是产品决定，不是文案修改，另开在 issue #654。

## 后果

- 非 git 用户被拦时读到的是可执行的下一步，不是术语。
- 想并行的正常路径被明确成「两个文件夹」——与产品此刻真正支持的能力一致。
- 代价：git 用户万一走到这条提示（副本创建失败退回原目录那条路径），读到的解释里没有 worktree。可接受——那种情况下 worktree 也不是他该自己动手的东西。
- 推翻这条的前提：#654 决定给非 git 文件夹也做副本。那时这条提示的读者又一次被换掉，措辞要跟着重写。
