# ADR-0180：连接器目录的标改透明底——纯黑的走 mask，其余保品牌色

- 状态：已采纳
- 日期：2026-08-29
- 关联：issue #720（本条）、#715（补齐 logo 的那次）、ADR-0171（连接器目录分两层）

## 背景

#715 给精选层那二十条补齐了 logo。当时的做法是把每个标画在一张**白色圆角方片**上，
理由写在 `EntryIcon` 的注释里：GitHub 和 Notion 的标是纯黑的，裸画在深色主题上等于
看不见；白底一条规则同时管住浅色和深色两个主题，不用给每个品牌各做一套深浅。

这个理由本身没错，它解决的问题是真的。但用起来才看见代价：深色主题下二十张白方片
排成两列，方片自己成了页面上最亮的东西，比它承载的标还抢眼——用户的原话是「logo
透明背景」。

## 决策

**去掉白片，标直接坐在卡片上。**「两个主题都看得见」这件事不再由一层底板兜住，
落回每个标自己，按**品牌色本身有没有信息量**分两档（`lib/mcpDirectory.ts` 的
`iconPaint`）：

| 档 | 谁 | 怎么画 |
|---|---|---|
| `mono` | github / notion / linear / square / miro / sentry / filesystem / fetch | `mask-image` + `background-color: currentColor`——只取形状，颜色跟主题前景色走 |
| `color` | 其余十二条 | 原样 `<img>`，颜色是标的一部分 |

分野的判据不是「深不深」而是「这个颜色说不说明问题」。GitHub、Notion、Linear、
Square、Miro、Sentry 的标就是纯黑或近黑，各家自己在深色背景上也一律翻成白的——
颜色不携带品牌信息，交给主题接管没有任何损失。文件夹和地球本来就不是品牌，同理。
反过来 Stripe 的紫、Figma 的五色、Supabase 的渐变，颜色是识别信号的一半，全走
mask 等于把它们统统画成灰的。

顺带三处：

- **`linear.svg` 换掉了。** 原来那张是「黑底圆角方片 + 白色标」的反白版。mask 只
  取 alpha，整块不透明的底板会让它变成一个实心方块。现在只留标本身，viewBox 收到
  实际边界。
- **`atlassian.svg` 的蓝色从 `#0052CC` 换成 `#2684FF`。** 前者在深色卡片底
  （`#1d1d1f`）上只有 1.87:1，是这一档里唯一真的看不清的。后者是 Atlassian 自己
  那支给深色背景用的 Blue 400，两边分别 3.60:1 / 4.73:1。这是换一个官方备选色，
  不是给它开特例。
- **`neon.svg` / `netlify.svg` 里的 `@media (prefers-color-scheme: dark)` 删了。**
  这两个块从来就不工作：SVG 当 `<img>` 加载，只看得见**系统**设置，看不见 app 自己
  那个主题开关，两者不一致时它给出的正好是错的那一档。neon 两档都是绿的所以没症状；
  netlify 的中心点会在系统深色 + app 浅色时翻成白的。删掉之后这个目录里再没有一张
  SVG 自以为知道当前主题。

## 一个不报错的坑：mask 的地址必须加引号

第一版交出去是**二十格里八格纯白方块**——`mask-image` 整条被丢掉了，只剩
`bg-current` 把 8×8 涂满。原因是小于 4 KB 的 SVG 被 vite 内联成
`data:image/svg+xml,` 加百分号编码的原文，裸写进 `url(...)` 里 CSS 解析器判它
非法，**声明整条丢弃**：不抛错、不进控制台、`<img>` 那一半照常显示。加引号
（`url("${src}")`）即可。

这个失败模式的形状值得记：它产出的不是空白或报错，而是一个**看上去像是设计**
的实心方块。所以 `tests/e2e/mcpDirectory.e2e.ts` 加了一条读 `getComputedStyle`
的用例——jsdom 不算 mask，vitest 那半边看不见这件事，只有真浏览器验得到。

## 被否掉的

- **把 SVG 内联进 DOM，让 `currentColor` 生效。** 能同时保住品牌色和主题适配，但
  这些文件里有 `<style>` 块，`neon.svg` 写的还是 `:root { fill }`——内联之后 `:root`
  就是 `<html>`，一张图标的样式泄漏成全局样式。为一个图标格子承担这个风险不值。
- **每个纯黑的标各做一套深浅两个文件，按 app 主题在 React 里挑。** 可行（app 主题
  在渲染进程读得到，不像 SVG 内部只读得到系统设置），但等于把八个标变成十六个文件，
  而它们要的只是「跟着前景色走」这一条——mask 一行 CSS 就是这句话。
- **给所有标统一压一个「两种底色都过得去」的对比度下限（3:1）。** 试过，Supabase
  的绿在浅色卡片底（`#f7f5ef`）上只有 1.80:1 会被判不合格，可它看得清清楚楚——
  亮度对比这一个数不度量色相差补上的那部分。硬套下限的结果是按数字去改品牌色，
  比原问题更糟。

## 后果

- 深色主题下卡片安静了，标之间的差异重新变成标本身的差异。
- 代价：`mono` 那八条丢掉了品牌色。这是自愿的——它们的品牌色就是黑，而黑在这里
  不可用。
- 新增一条精选条目时多一个判断：这个标是不是通篇近黑。判断失手的症状是深色主题下
  一格空白，**而空白不报错**，所以 `tests/renderer/mcpIcons.test.ts` 钉了三条：
  ① 目录里写了 icon 就得有那个文件 ② `color` 档的标不能通篇近黑 ③ `mono` 档的标
  里不能有整幅背景块（`linear.svg` 踩过的那个）。第三条已验证非空断言。
  逐个颜色的对比度不进门禁，理由见上一节最后一条。
