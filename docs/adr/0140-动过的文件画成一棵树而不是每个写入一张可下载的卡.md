# ADR-0140：动过的文件画成一棵树，而不是每个写入一张可下载的卡

- 状态：已采纳
- 日期：2026-08-26
- 相关：issue #582；ADR-0031（面板只读、不进事件日志）、ADR-0041（审批时改过的参数才是"写出去的那份"）

## 背景

`write_file` 每写成功一个文件，时间线上就跟一张文件卡：文件名 + 大小 + 下载按钮，内容整份 base64 带在 message part 里（`aui/toolArtifacts.ts` 的 `filePartFor`）。

三处不对：

1. **形状说错了话。** 那张卡是**上传附件**的形状——用户发图片给 agent 用的就是同一个组件。但这里的语义是「agent 刚在你磁盘上写了什么」。Mr Otto 是本机应用，文件就在盘上；"下载一份副本"不是读者在这一刻想做的事，"打开看看"才是。
2. **一次写多个文件时，卡片比它承载的信息长得多。** 三个文件三张卡竖着摞，占掉半屏，而每张卡只说了一个文件名。
3. **内容进了投影。** base64 是在 `toThreadMessages` 里算的，事件日志每落一条就整份重跑一遍——所以还得有个 256KB 的上限兜着，超了干脆不出卡（一次大写盘反而什么都不显示）。

## 决策

删掉 `filePartFor` 这条产物路径，改成工具组折叠头底下常驻一棵**文件树**（assistant-ui elements 的 file-tree 版式）：

- 数据源不变，仍然是事件日志里 `write_file` 的**实际执行参数**（ADR-0041）。`OttoToolGroup` 本来就在数这一组动了几个文件（折叠头那句「N file changed」），现在把那个 Set 留下来当树的输入，不再多算一份东西。
- 树只画**路径**，不带内容：base64 和 256KB 上限一起没了。
- 行可点 → `openFileAt(path)`，在 Files 面板里打开（只读，ADR-0031）。

两条形状上的取舍写在 `lib/fileTree.ts` 里，这里只记结论：

- **独生目录链压成一行**（`src/renderer/lib` 一行，不是三行）。每层一行会把留白摞成一堵墙，而那几行里没有一行是分叉。
- **工作区外的文件不进树**，各自单独一行、显示完整路径。把 `/tmp/x` 和工作区里的文件塞进同一棵树，树根就得是 `/`——那棵树的形状说的是磁盘的事，不是这次改动的事。

与上游 file-tree 的出入（`components/elements/file-tree.tsx` 顶部有同样的三条）：**没有 +N/−M**。上游那份是 PR 视图；本仓的 `write_file` 是整份覆盖，渲染层手里只有新内容没有旧内容，算不出增删。宁可不说，也不摆一个猜出来的数字——同 `tool-timeline.tsx` 当初不接 stats 的理由。

## 后果

- 下载没了。想把 agent 写的东西拿出去，路径是 Files 面板 / Finder / 终端——都在手边，而且拿到的是磁盘上的真实版本，不是投影里那份可能已经过时的副本。
- 一次写十个文件从"十张卡"变成"一棵十行的树"，而且这十行是**有结构的**：同一个目录下的改动挤在一起，一眼看得出这次动的是哪一块。
- 256KB 那条限制随之作废：多大的写盘都照样在树里出现（树只认路径）。
- `toolArtifacts.ts` 少了 mime 表 / basename / base64 三段辅助代码——它们只为那张卡存在。

## 被否掉的路

- **保留文件卡，只是折叠起来。** 折起来的卡还是卡，形状那条毛病没治；而且"下载"这个动作本身在本机应用里就是多余的。
- **树上挂 +N/−M。** 要么在渲染层读一次磁盘算 diff（投影里做 IO，越界），要么让 `write_file` 往事件日志里落行数统计（改 schema，为一行数字不值）。留白。
- **树画在消息流里（继续走 message part）。** 一个 part 只能画一个文件，跨 part 合不成一棵树；而工具组那一层本来就手握去重后的完整路径集合。
