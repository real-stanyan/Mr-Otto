# ADR-0239：账号页重设计 —— 额度按百分比、使用情况一张卡两半、名字点开才改

- 状态：已接受
- 日期：2026-09-07
- Issue：#1022
- 相关：ADR-0209（同一扇窗两个界面不能给出两个数）、ADR-0203（价目由服务端下发）、
  ADR-0176/0217（订阅与工作区闸）、issue #141（热力图只数主会话）

## 背景

账号页此前是三块：身份（头像 / 名字输入框 / 邮箱 / 退出登录）、订阅与额度、半年会话热力图。
维护者在设计稿上逐条定稿（HTML 模板，本次会话产出），本 ADR 记录其中**不是审美、
而是会影响正确性或可维护性**的那些判断。

## 决定

### 1. 两扇额度窗报「还剩百分之几」，不报 credit

大字是剩余百分比，条按**剩余**填充，精确 credit 进 `title`。三条理由：

- **报剩余** —— 用户问这个数就是想知道「我还能干多久」，而 `0.1 / 311.5` 要人当场做减法
  （`bindingWindow` 那段注释早就写着同一句话）。
- **条按剩余填** —— 原来那条填了 0.03%，在屏幕上和「组件坏了」长得一模一样；
  反过来画之后，闲着的时候它是满的。
- **一位小数、向下取整** —— `0.1 / 311.5` 的真值是 99.9679%，四舍五入写出来是 `100.0%`，
  把「刚烧了一点」和「一次没动」说成同一件事。向下取整之后 `100.0%` 只在真的一次没用过时
  出现，`0.0%` 只在正好用完时出现。

`remainingPercent` 在 `limitMicro <= 0` 时回 100，与 `windowPercent` 的「已用 0%」互为补角：
两个函数对同一扇窗不能给出互相矛盾的答案。

**色档仍按「已用」判**（`quotaTone`，阈值与上下文浮层共用，ADR-0209），画出来的是剩余 ——
同一件事的两个说法，判据只能有一份。**充足时条是中性灰不是品牌蓝**：一根横贯整卡的蓝条会把
「一切正常」画得比「快没了」还响；颜色在这张卡里只用来说「出事了」。

**浮层（`PlanQuotaSection`）这次没跟着改**，仍报 `已用 / 上限`。两处报的是同一个事实的两种
说法而不是两个数，所以不违反 ADR-0209；但口径不一致本身是债，记在 issue 里。

### 2. 扣款失败 / 额度用完从一句灰字提升成带动作的横幅

原来 `· 扣款失败` 缀在 11px 小标题后面 —— 一个会让人停止付费的事故写得比「加购 $10」还轻，
而且没有任何一条可走的路。现在各是一条 warn/deny 底色的横幅，右边一颗按钮
（更新支付方式 → Portal；去配 key → 模型配置页）。

### 3. 未订阅那一屏补一张 Free 卡

Free **不是**服务端 plan 表里的一行，是「没有订阅」这个状态本身的名字，价格 $0 由定义得出 ——
所以它不受 ADR-0203「价目由服务端下发」那条约束（那条管的是会变的价）。

它**不是一个可买的东西**，所以：虚线边框、底色沉一档、**不给主行动按钮**，只留一颗
「去配 key」。画成第四张可买的卡会让人去点它。

能力行只画 `capabilities.image`。**「视频」整个去掉**（产品上暂时不做）。
**「工作区」那枚 chip 这一轮不画** —— 见下面「不做的」。

### 4. 名字平时是一行字，点它才变输入框

改名一辈子一次，而那个框天天占着这一页最上面最重的一块。规矩和头像一致：点它改它，
平时不摆出「待办」的样子。

编辑态由 `ProfileCard` 拿着、不在 `ProfileEditor` 里：撤销/保存之后要退回一行字，
而只有外面知道「改回去了没有」。`nameEditing` 缺省 `undefined` = 永远输入框 =
首登引导弹窗那条路一字不变。

邮箱与退出登录收进同一行，退出登录降成幽灵钮 —— 它是这一页最少用、最不该被误点的动作，
原来却是唯一带边框的按钮。

### 5. 「使用情况」是一张卡两半，中间一条发丝线

左：会话热力图。右：本周各模型的 token 占比。

- **要么有线要么就该是两张卡** —— 中间那片没交代的空地是最难看的第三种（分法与订阅卡里
  两扇窗一致）。
- 两半共用一副骨架：标题行 / 内容 / 一行脚注，脚注靠 `mt-auto` 压到底，于是两边高矮不齐
  也不散架；热力图在头脚之间垂直居中，右边型号多几行不会把左边拽歪。
- **两半的口径不同，各自说出口，不硬对齐**：左只数这台电脑上你自己开的**主会话**
  （子会话不算，#141；云端工作区会话从不写本机日志，所以不在图里）；右算**所有**计费调用
  （含子会话派出去的、含已归档会话）。两个数摆同一张卡上必然被读成该对得上。

### 6. 用量按**型号**归并，只报占比

`modelShares` 是新的纯投影，与邻居分工：`usageStats` 按厂商按天（模型配置页的柱状图）、
`deriveUsage` 按一个会话（浮层的花费面板）、这边按整库按型号只报占比。

三条判据都是为了绕开审计在 `usageStats` 那条路上查出来的坑（本次会话用维护者真库验过）：

- **按型号 id 归并，不按厂商**。`usageStats` 里 `describeModel` 认不出的型号整行 `continue` ——
  那条规则在按厂商归并时是对的（硬塞进某一家会让那家的数字凭空变大），代价却是本机真实存在的
  调用**静默消失**，界面上没有任何地方说这件事（真库里 `glm-4.5-flash` 那批就是这么没的）。
  按型号归并没有归属问题：认得出用显示名，认不出用裸 id，一行都不丢；`provider` 为 `null` 时
  画一枚中性方块 —— **硬塞一枚别家的 logo 比不画更坏**。
- **只报占比，不报 token 数也不报钱**。钱那一列要同时处理 `$`（自带 key）、`credit`（托管）、
  `—`（查不到价）、`托管`（没记到）四种写法，占比只有一种；这也顺带绕开了 `modelPricing`
  里缺键的型号（本机 `k3` 查不到价，那是另一条 issue）。代价写在脚注里：
  **占比按 token 算不是按钱算** —— 一款便宜模型的 token 和一款贵的一样大。
- **不静默截断**：前 5 款之外的合成「其余 N 款」一行报出来（AGENTS.md：no silent caps）。

`tokens = prompt + completion`，**不加 cached**：后者是前者的子集（`llmGateway` 计价用
`Math.min(cached, prompt)`），加上就是重复计数。

### 7. 用量窗口能对齐额度窗就对齐，对不齐就换标签

`weeklyUsageWindow` 从 `me.windows.week.resetAt` 反推起点；没有活跃订阅时服务端压根不下发
windows，于是退回滚动 7 天，**标签跟着从「本周用量」换成「近 7 天用量」**。两半摆在同一张卡上，
一个说「本周」而实际是「最近 7 天」的话没人分得出来，而这两段时间在周中差着好几天。

快照过期（窗口在用户盯着这一页时清零了）时从 `resetAt` 起算而不是再减一周 —— 减一周会把
上一扇窗的调用算进这一扇。

### 8. 热力图元件只画图，不画卡

`elements/activity-graph.tsx` 原来自带卡壳 + 标题行 + 总数。现在卡壳归调用方（它装着两半），
元件只画图。同时补了三件事：

- **月份刻度**（上游有 `MonthLabels`，之前没接）：26 列没有刻度时「那一簇蓝的是几月」答不出来。
  刻度**跨 3 列 = 与最小间距同一个数**：跨度大于间距时撞上的那个会被 grid 挤到第二行，
  而那一行是定高的 —— 第二行整个溢出压在格子上（设计稿上「3月」比后面几个高一截就是这个）。
  刻度行的左留白写死成「星期列宽 + 一个 gap」，不靠字宽碰运气（换成中文单字之后字宽就变了）。
- **星期名走中文**（上游 `DAY_SHORT` 是 Tue/Thu/Sat）。
- **格子 9px → 12px**，且 `w-fit` 收住：上游 `Grid` 写死 `grid-template-columns: repeat(N, 1fr)`，
  在占满宽度的容器里 1fr 会把格子摊成长方块；收成 `fit-content` 之后 1fr 落回格子自己的 12px。
  每个格子还按 `cell.column/row` **显式落位**，不赖 DOM 顺序 —— 上游哪天改了 cells 的排列顺序，
  隐式流会把整张图转置，而且不会报任何错。

## 不做的

- **「工作区」进档位**（Pro/Max 有、Lite 与 Free 没有）。设计稿画了那枚 chip，但它不能单独做：
  `PlanInfo.capabilities` 今天只有 `{ image, video }`，要加字段（plan 表 + 类型 + 下发）；
  ADR-0217 的 `workspaceAccess` 判据要从「有活跃订阅」收窄成「档位 ∈ {pro,max}」，
  **界面那道和 RLS 那道都得改**（界面判据跑在用户机器上，真正拦住的是 RLS）。
  **只画 chip 不改闸 = #722「撒谎的勾」的一般形式**。另外「存量 Lite 用户已建好的工作区怎么办」
  是产品决定（继续能用 / 转只读 / 到期失效），维护者尚未拍板。单开 issue。
- **`billedUsage` 的 SQL 加 `route` / `creditCostMicro` 两列**。原计划要它们是为了画钱那一列；
  钱整列去掉之后就不需要了 —— 少改一处 SQL。哪天要按「托管 / 自带 key」拆开统计再加。
- **浮层那半跟着改百分比**（见决定 1 末段）。

## 后果

- 额度那两扇窗从此不出现 credit 数字；要对账的人靠悬停。
- 账号页多一条 IPC（`usageByModel`），投影在主进程做 —— 同 `usageByProvider` 的纪律：
  一次 IPC 传聚合结果，不把几万行原始用量搬过桥。
- `SessionActivity.tsx` 删除（唯一消费方就是账号页），热力图的调用点收敛成一处。
