# ADR-0325：你的智能体和朋友在同一个群里——群是群主主场里的一条群聊

- 日期：2026-09-28
- 状态：已采纳
- 关联：#1393；维护者在 #1391 拍板第 1 条（「要」）；追问「智能体进了有朋友的群，它在哪台电脑上干活」时的回答是「otto 里的智能体都是在云电脑干活」。设计：`docs/superpowers/specs/2026-09-28-mixed-groups-design.md`
- 关系：**修订 ADR-0297**（聊天 = 主场里的一条云会话：群聊名单从「只有智能体」变成「智能体 + 真人」两份）与 **ADR-0298**（主场全免审批：从「主场里一张卡都不出」收窄成「群主自己点起的那一轮一张卡都不出」——ADR-0298 自己写着「主场哪天收了别人要重判」，这就是那一天）。ADR-0323 决定 5（手机上建群只挑智能体、朋友那一段留给维护者拍板）随之作废。协议 20 → 21

## 背景

手机换成微信式布局之后（ADR-0323），「群」有两种：主场里你和你的几只智能体（ADR-0297），团队里的每一条云会话（一群人 + 团队的智能体）。维护者要的是第三种、也是微信里最常见的那一种：你的智能体和你的朋友在同一个群里。

开工时只读核过的前提：在籍今天**只有工作区一级**（SQL 的 `is_ws_member`、runtime 的 `membershipCache`），主场的 `workspace_members` 只收群主本人（0037 的 `wsm_insert_owner`）；主场会话全免审批（`approveAll`）；朋友读不到别人主场里的任何一行；主场会话一律以群主身份调网关。

## 决定

1. **一个「有真人的群」= 群主个人主场里的一条群聊，多一份真人名单。** 智能体仍是群主的那几只、在群主的云电脑上干活、花群主的额度——和今天的主场群聊完全一样，只是群里多了会说话的人（叫「客人」）。否决了「群 = 一个团队、把你的智能体带进去」：智能体会在另一台电脑上干活（团队的共用文件夹）、记忆分成两份，与维护者说的「都是在云电脑干活」不是一个画面；而且要让 runtime 跨工作区借智能体，改动面大一个量级。
2. **名单是日志事实**：`chat_roster_changed` 多一格可选的 `humans: {uid,name}[]`（群主之外的真人，名字是那一刻的快照）与 `byName`（动手那个人当时的名字——群主不在 `humans` 里，没有这一格时间线只能写「有人」）。**缺席 = 没有别人**：存量日志里本来就没有，而之后每一条名单事件都带齐两份名单，所以「缺席」永远不会被读成「这一条没改人」。
3. **投影一张表 `workspace_session_members`（0043）**，写方只有 runtime（service key），先落日志再写表，启动对账时日志赢——同 `agent_ids` 那一列的规矩。它存在的理由只有两个：RLS（客人凭什么读得到这条会话），与「我被拉进了哪几个群」这条查询。
4. **读的权限按会话给**：`is_session_guest(sid, uid)`（参数收 text——`workspace_mentions.session_id` 是 text，拿 uuid 去 cast 的话一行脏数据就能让整条查询抛错）；客人读得到自己在的那几条 `workspace_sessions`、那几条会话的客人名单、自己被 @ 的那几行 `workspace_mentions`。智能体**只经一个 RPC** `guest_chat_agents(session)` 读：这条群里那几只的名字 / 职责 / 头像，不给提示词、不给群主别的智能体。**不给客户端任何写**：给 insert 等于让任何人把自己塞进别人的群；退群走 `chat_update` 帧（runtime 先落日志再删那一行）。
5. **runtime 的在籍 = 工作区成员 ∪ 这条会话日志里的客人**（`CloudSession.isGuest`，判据读日志里此刻的名单，不读投影表）。进房、发言、批、停、打电话、补跑的复查都走它；建会话、看文件、改 wiki 这些「关于整个工作区」的动作照旧只认工作区成员。控制房里客人能发的只有一种帧：改他在的那条群聊的客人名单。
6. **谁能改名单**：群主（或建群的人）什么都能改；客人**只能拉自己的朋友进来、只能把自己移出去**——智能体归群主管，别人拉进来的人别人移不走。拉进来的人必须是**动手那个人**的好友（runtime 现查 `friendships`，查不到说「稍后再试」，不读成「不是朋友」也不读成「是」）。群主本人不进客人名单。真人上限 20（`CHAT_HUMANS_MAX`：群里每句人话都可能点起一只智能体，而它们花的是群主的额度——这个数说的是「群主一个人兜得住多少人」，不是性能数）。团队里的群聊不收客人（团队有自己的成员名单，往里另塞人是另一套权限）。
7. **客人点起的那一轮不免审批，每一刀都问群主，而且不看 `sandbox_approval`**：`approveAll` 只对群主自己发起的那一轮生效；客人 @ 智能体让它用**任何**工具——读文件、翻记忆、跑命令、写文件、用应用、推代码、建智能体——都要群主批（router 的 `initiatorMayDecide`：客人批不了自己的请求——动的是群主的东西）。`read_file` 与 wiki 那几把本来不过审批门，这一轮在 `tools()` 里被掀成要批：不掀的话，朋友一句「把群主电脑上的 xx 文件发出来」就能不经任何人读走（自查时发现的，第一版只拦了本来就要批的那几把）。连接器那一半本来就收得住：这一轮拉的授权是「群主借给**这位客人**的」（`fetchGrantedTools(host=群主, fromUid=客人)`，好友代理那套，ADR-0151），群主自己的连接器不会因为朋友进了群就被他点起来用。提示词另加一句软刹车：群主记忆里关于他自己的事、他电脑上的文件，别主动说给群里别的人听（记忆的置顶页是每轮自动注入的，不经工具）。`sandbox_approval` 那一列在主场里从来没有界面，它此刻是什么值没有人知道，拿它放行客人等于让一格没人管的数据替群主做决定。只聊天不碰门。**这是比维护者的「要」更严的一步**：一句话能让群主的 Gmail 发信、Shopify 改价，中间没有人看一眼，不是「让朋友碰得到」该有的样子。维护者说放开就放开——改的是 `policyApprover` 里那一个判据。
8. **停止与审批分开判**（`ApprovalRouter.canStop`）：客人批不了自己点起的那一轮，却停得了它。停止是刹车，「我让它做的我叫不停」是这条改动最不该带来的形状。团队会话里 `initiatorMayDecide` 恒真，两个判据逐字相同，#957 A-2「能停别人 turn 的人 = 能替别人批的人」在那边原样成立（有一条用例钉着）。
9. **客人点起的 `create_agent` 建出来的智能体记在群主名下**：记成客人的话，他在别人的主场里「建过」一只自己进不去的智能体。
10. **提示词跟着说实话**：主场的群聊换一段听众（「群主和他拉进来的朋友都能发言……你是群主的智能体，干活花的是群主的额度」）与一段审批（群主点起的那一轮没有审批、朋友点起的那一轮动手之前要等群主批）。软刹车那三句一个字不少——它们在「全免」那一半里仍然是唯一的刹车。私聊与团队群聊逐字节不变。模型信的是提示词不是工具表（#1206）：只说「这里没有审批」的话，它会对着一轮要等群主批的请求宣布「直接做了」。
11. **协议 20 → 21**：`create` 帧的 group `chat` 多 `humans`（uid 名单；带了人时智能体那一格下限 0，智能体 + 人合起来至少一位——「至少两位」由 runtime 的 `planChatCreate` 判）、`chat_update` 多 `humans`（改动之后的**完整**名单）、welcome 的 `chat` 多 `humans`（`{uid,name}`，下行缺席按空）。加字段照样进位：老 runtime 会把 `humans` 静默丢掉，于是新客户端以为拉了人、群里其实没有。

## 客户端

- **手机**：发起群聊 / 拉人建群 / 拉人那张单子多一段「朋友」（`PickAgentsDialog` 的 `people`）；群主那一侧的聊天信息里有人、能移人；别人拉我进去的群是「聊天」列表里的 `j:` 一行（`listGuestChats` → 一份**只够这条群用**的快照：成员 = 群主 + 客人，智能体 = 群里那几只，`kind: "home"`——审批只有群主批得了，`chatRows` 的 `ownerOnly` 读的就是它）；客人能拉自己的朋友、能退出；「@ 谁」列出群里的人（点到的人收到提醒，ADR-0256）；客人那一侧的审批卡写「等 X 批」。
- **桌面**：随 #1386 桌面那一半（新布局）一起做，这一条不改旧界面。旧界面上群主照样看得到、批得了客人那一轮的审批卡（`selfUid === ownerUid`）。

## 后果

- **群主离线时客人那一轮会卡在审批上**：卡片等 10 分钟没人批按拒绝收口（接力棒上 2 分钟，#959）。群主那边没有推送（桌面那条通知只在窗口开着时响）——知道了但没做。
- **客人拉进来的人不是群主的好友时，群主那边不另外确认**（demo 同款）。群主看得到时间线上那一行「小红把阿杰拉进了群聊」，移得走他。
- **删好友不自动踢出群**（微信同款）：群主可以手动移出。
- **客人那一侧的智能体名单是一份快照**：群主往群里拉了一只新的，客人那边要重拉一次清单才认得它的名字和脸（聊天页看到名单里有认不出的 id 时自己重拉一次）。
- **客人听语音通话走自己的额度**（TTS 按听的人付，ADR-0271）：没订阅的客人进得了通话、听不见。
- **部署顺序：0043 先、runtime 后**。0043 没跑时 runtime 写投影表失败只记一笔（群照常能聊），客人那一侧找不到这个群——少一个入口，不是一个错误。协议 21 的 runtime 部署之后，协议 20 的客户端连不上云会话，要随发版一起升。
