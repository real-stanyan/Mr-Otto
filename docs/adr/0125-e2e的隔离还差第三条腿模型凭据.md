# ADR-0125：e2e 的隔离还差第三条腿——模型凭据

- 状态：已接受
- 日期：2026-08-26
- 关联：issue #480；ADR-0076（真机验收清单落成 e2e 用例，隔离那两条腿在那里立的）

## 背景

`tests/e2e/harness.ts` 的头部注释一直写着「不碰网络、不碰模型：没有 key 就没有出网的路」。这句话在**任何装过 `.env` 的开发机上都是假的**。

主进程开机时有一行：

```ts
// src/main/index.ts
loadDotEnv((p) => readFileSync(p, "utf8"), join(process.cwd(), ".env"));
```

而 Playwright 起 Electron 用的 `cwd` 就是仓库根。于是仓库根那份 `.env`（本机开发用，`.gitignore` 里，通常有一把真的 `DEEPSEEK_API_KEY`）原样进了 e2e 进程的环境。HOME 换了、OTTO_PROFILE 换了，**第三条读 key 的路没人管**。

后果不是「多读了个变量」：

- e2e 每跑一次开会话的用例就**真的打给厂商、真的花钱**；
- 验收结果**随模型心情变**——#480 就是这么红的：模型答了话、要调 `bash`、停在审批门上不动，`status` 一直是 `running`，顶栏那颗分支下拉被 `disabled` 按了整整 30 秒，`branchSwitch.e2e.ts` 超时。测试断言的是「切分支留痕」，挂掉的原因却是「模型今天想跑个命令」。

`keylessReplay.e2e.ts` 里那句 `env: { DEEPSEEK_API_KEY: "" }` 是这个洞的局部补丁——一次一个用例地补，补漏了就是静默出网。

## 决定

隔离补上第三条腿：`launchOtto` 在起进程前把**本仓认识的每一个 provider key 环境变量**置成空串，排在 `opts.env` 之前（用例仍能自己塞假 key）。

`loadDotEnv` 的语义是「只补空缺」（`process.env[k] === undefined` 才写），所以置空串就足以挡住 `.env`，不需要改产品代码，也不需要把 `cwd` 挪走（挪 cwd 会牵动别的按 cwd 取相对路径的地方，代价更大且更难说清）。

`OTTER_MODEL` 一并置空：它不是凭据，但同样让「默认开哪款模型」跟着开发者本机偏好走。

## 名单从产品代码里 import，不手抄

`providerKeyEnvs()` 直接从 `src/shared/providerCatalog.ts` import，**刻意与同文件里 `CONFIG_DIR` 的先例相反**（那一条写着「刻意重写一遍而不是 import」）。

两者的失效方式不同，所以结论相反：

| | 抄一份 | import |
|---|---|---|
| `CONFIG_DIR` | 产品改了目录名 → 这里当场红一条（**fail-closed**，而且这正是它想要的：黑盒该按用户看到的路径断言） | 跟着一起改，悄悄继续绿 |
| provider key 名单 | 目录里新增一家厂商 → 这里**静默漏掉它**（fail-open，又一次真出网） | 名单永远完整 |

黑盒原则让位于 fail-closed：一条漏网的 key 不会让任何测试变红，只会让它们悄悄开始花钱。

## 代价 / 会推翻它的前提

- e2e 从此**跑不了真模型**。想对着真厂商跑一次的人得自己在用例里传 `env`——这是刻意的：那种跑法不该是默认。
- 依赖 `loadDotEnv` 的「只补空缺」语义。哪天它改成「覆盖」，这道闸就失效了——`tests/main/` 里那条 loadDotEnv 的单测钉着这个语义。
- 如果将来产品改成从别处读 key（比如 keychain），这一条挡不住，得再补一条腿。
