# ADR-0367：管理员是唯一入口——人只对人和自己的管理员说话；谁在场、谁干活、要不要雇人由管理员定；人保留删人、改设置的权力

> 原为 ADR-0366（#1571 第 2 步合并前被另一条 lane 占了号，按 ADR-0074 改号）

日期：2026-10-05 · issue #1571（第二轮拍板，评论 2026-10-05）· 维护者原话：「每个聊天窗口不管是对个人还是对群聊，用户只能 @ 对方或者
自己管理员，发生的任何事都应该由管理员判断任务是否下派或者由自己完成，用户不再参与创建 Agent。创建 agent 由管理员根据实际情况创建，
等级还是按现有的，L1 被创建的 Agent 保留在 Agent List 中，对话中如果需要 L1 级 Agent 参与，由管理员拉入对话，而非个人。」

## 背景

ADR-0365 定了三级与「派活只能往下」，但入口仍是多个：主人能 @ 任何一只、能自己建人、朋友那一侧有公开智能体 / 代办目标 / 车道朝向 /
名片 / 共有七个概念。每多一个入口就多一套闸，用户讲不清、维护者也要靠 ADR 才记得住。

## 决定

1. **人只对人和自己的管理员说话。** 主场里没点名的话一律到管理员（`say` 不再让分类器在几只之间挑）；主场群里的客人点谁都改成管理员
   （ADR-0363 那道闸从公开车道扩到主场全部会话）。团队会话（没有等级）照旧。
2. **谁在场由管理员定。** 管理员用 `bring_agent` 把专员拉进这条对话（落 `chat_roster_changed`，与主人在设置页改名单同一条事件；
   管理员那条私聊也允许长名单，admin 恒排第一），`dismiss_agent` 请出去。**拉进来之后人在这条对话里可以直接回它**（对话权跟着在场），
   请出去之后又不能。只能拉 L1：L2 由它的上级在自己那条线上用。
3. **人不再建智能体。** `create_agent` 只有 L0 有（原样），主场里加三条护栏：域必填且合规；**一域一只**（那个域已有专员就拒、让它派给
   现有的）；每主场专员上限 8。子工（tier 2）的上级必须是专员。建成在对话里落一句「管理员新雇了…」让主人看见。
   这一条取代 ADR-0365 第 4 条「提议建一只、主人点一下」。
4. **对外的刀只有 L0 有**（打给朋友 / 给朋友发私聊 / 车道桥）：管理员是双向的唯一入口。动手的刀（读写文件 / bash / git / 连接器）
   按 ADR-0365 的域面圈，不在面里的**不装**。
5. **分级那一段提示词进 brief**（`agent_briefed.instructions`），只在主场：模型看见的就是日志里那一句；名单变了会重新 brief。
6. **缺管理员自愈**：名单查询见不到 `admin` 就 `ensureAdmin` 补一只再查一次（0021 的触发器只管新建的主场）。
7. **人保留**：删除（除管理员）、改设置（名字 / 形象 / 声音 / 定时任务）、在设置页改群名单。
8. 被取代的入口（入口藏掉、代码留，手机那一步 #1571 第 4 步做）：公开智能体选择、名片 / 共有、给对方公开智能体打电话（改成打给
   对方管理员）、长按派一只（改成派给管理员）、新建智能体弹窗。

## 否决的备选

- 人被允许召唤 L1（只是提示它先问管理员）：那入口又成了两个，与第 1 条矛盾。
- 管理员自己建人不设护栏：会建出一堆同域的；一域一只 + 上限是最小的护栏。
- 「管理员」按 agentId 认而不按等级认：生产里 admin ⇔ tier 0 用 check 钉死（0060），两种认法等价；runtime 按等级认让夹具能把任何
  一只标成 L0 测对外那几把刀本身。

## 代价

- 简单事也先过管理员一轮（它判「一句话能答完」就自己答）：固定多一跳的延迟与费用。缓解：管理员用快模型。
- 0060 没跑的库上，没域的专员只有只读面（「未分配」域）——部署顺序必须 0060 → runtime，写在 0060 头注与 spec §7。
- 外联 / 定时任务等「专员替主人对外」的旧路径（ADR-0337 / 0362）在主场里只剩管理员能走；tests 里对应的夹具改成 L0。
