# ADR-0248：订阅用户不许自带 API key —— 藏界面不算，路由那一侧才是这条规矩

> 原为 ADR-0246（撞号，ADR-0074：编号在合并时认领）。提交信息与 PR 里写的 0246 指的就是这一份。

- 状态：已采纳
- 日期：2026-09-07
- 关联：#1051；ADR-0233（云会话那一半，同一条纪律）、ADR-0176 决定二（托管优先于自带 key，本 ADR 把它推到底）、ADR-0244（选单分两组，本 ADR 让两组从此不并存）、ADR-0237（`me.models` 从便宜到贵有序）、#722（撒谎的勾）、#1040（无法执行的建议）
- 来源：维护者原话 ——「订阅用户不可以使用自带 api key，只要成为了订阅用户，在设置里不显示模型配置和子智能体」（配图 = 输入框那枚选单里的 DeepSeek / 智谱 GLM / Ollama 三组）

## 背景

ADR-0233 已经对**云会话**定过同一条口径，理由写得很直白：自带 key 那条路存在一天，
「额度用完悄悄改烧你自己的账号」这个静默失败模式就存在一天。这次是同一条纪律落到本机。

## 决策

### 一、真正生效的是 `routeModel`，不是选单

`routeModel` 里订阅这一侧从三态收成两态：**hosted / blocked，没有 direct**。

只藏界面是不够的，而且藏得再干净也不够：

- 存量会话里选着的老型号（`model_changed` 的投影）照旧会走到自带 key；
- 代读员、后台小模型、子智能体各有各的取模型的路，一条都不经过那枚选单。

所以这条规矩**只有一个真正的落点**，就是那两条 `return direct`。界面那几处是为了别让人
选一个必然 blocked 的东西，不是闸门本身。

**Ollama 也在射程内。** 它不要 key、也不花钱，留着它看起来无害 —— 但那会留下一条
「选单里没有、路由却通」的路，而这条规矩的全部意义就是让两边说同一句话。

判据挂在 `hosted.subscribed` 上，所以**没装配托管的那些装配**（探针 / 测试 / 裸装配）
行为一字不变。

### 二、blocked 的措辞里不许再出现「填自己的 key」

订阅用户看到的每一条 blocked 都不许再指一条已经关掉的路 —— 一句无法执行的建议比不给
建议更糟（#1040 那一族）。四种分开说：

| 情形 | 说什么 |
|---|---|
| 额度用完 | `订阅额度已用完，HH:MM 恢复。等不及可以在账号页加购。` |
| 订阅不供这款 | `订阅额度不供 X，在输入框那枚选单里换一款订阅供的模型。` |
| 档位没开多模态 | `X 要读图，当前订阅档没开多模态（升档）。` |
| 拿不到 JWT / 网关地址 | `连不上订阅网关（多半是网络或登录状态），稍后再试。` |

最后一条**以前是悄悄退回自带 key 的**，现在必须说出口。它也不许写成「你没订阅」——
那会让一个正在付钱的人去点续费解决一个不存在的问题（同 ADR-0233 把三种 blocked 分开）。

账号页那条「额度已用完」横幅同理：`配了自己的 key 会自动切过去` 这句话已经不成立，
换成真正点得动的那颗 —— 加购。

### 三、`route_changed` 对订阅用户不再落

`onReroute` 里那句 `if (next.kind === "blocked") return` 每次都成立了。**不落事件恰恰是
对的**：落一条「本次起用的是你自己的 key」就是宣布一件没发生的事，而它宣布的正是
ADR-0233 点名不许发生的那件事。没订阅的人照旧落。

### 四、设置里收起「模型配置」与「子智能体」

- **模型配置**：整页就是配自带 key 的地方。
- **子智能体**：整页的可配项（型号 / 挡位 / 工具白名单）都建立在「你自己挑一款模型」之上。

**收起来 ≠ 关掉功能。** 内置子智能体照常派活、照常走订阅额度 —— 为此
`subagentRunner` 与 `createChildAgent` 补上了 `hosted`（见决策五）。

守卫放在 `openSettings` 这个**入口**上，不只在导航里过滤：主进程的深链、齿轮的落点、
会话 ⋮ 里那一项都从这条路进来，只滤导航等于「列表里没有、按钮却跳得进去」。三处
共用 `settingsSections` / `settingsSectionVisible` 一份判据。

### 五、三条「不是主模型」的调用一并接上托管

不接的话，这条规矩会把它们从「悄悄烧你的 key」变成「彻底不工作」：

| 路径 | 改动前 | 不改的后果 |
|---|---|---|
| 子智能体（`subagentRunner` / `createChildAgent`） | 没传 `hosted`，只走自带 key | 订阅用户派一次活必然 blocked |
| 代读员（`createVisionBridge`） | 调 `routeModel` 但不喂 `hosted` | **每条带图消息整个 turn 失败** |
| 后台小模型（`createCheapAdapter`） | 直接读 `process.env` 里的 key，整条 `routeModel` 都绕过去 | 三个外挂静默不跑 |

后两条另有一个模型选择问题：出厂默认 `glm-4.6v-flash` / `glm-4.7-flash` 都是免费档、
**网关不供**。所以补了两个纯函数 `visionModelFor` / `helperModelFor`：订阅用户取订阅
供着的那几款里最便宜的一个（`hosted` 从便宜到贵有序，ADR-0237），代读员那条额外要求
带眼睛。**没订阅、或订阅里挑不出来 → 原样返回**，让 `routeModel` 去把「缺什么」说成
人话，而不是在这里悄悄换一款。

顺带补上一个存量的洞：`createCheapAdapter` 一直是直接读 env 的，于是**没配 key 的订阅
用户三个外挂从来没跑起来过**。

### 六、选单两组从此不并存

ADR-0244 立的「上面那组不额外花钱，下面那些烧自己的 key」这句话仍然成立，只是两组
**不再同时出现**：订阅了只有上面那组，没订阅只有下面那些。当初为并存写的那道「订阅供的
从厂商组里摘掉」的去重因此没了消费方，一并删掉 —— 留着一段跑不到的代码，下一个人会
以为它还在保护什么。

## 代价（明写）

- **存量订阅用户手上留着一款网关不供的老型号时，那条会话下一轮就 blocked**。不自动
  换一款：换型号是要落 `model_changed` 的动作，替用户做等于替他改了会话的事实。
  触发器照旧显示那一款（补一条只给触发器看的条目），blocked 的措辞直接指向选单。
- **代读员 / 小模型两页收起来之后，它们存的值订阅用户改不到了**。值仍然生效，只是
  `visionModelFor` / `helperModelFor` 会在订阅那一侧覆盖它。
- **本机 Ollama 对订阅用户不可用**。免费、离线、不花钱 —— 但见决策一。翻回去的方法
  是一行：`modelMenu.ts` 那个 `if (subscribed) return` 与 `routeModel` 里 `keyless`
  那条的 `!subscribed` 一起放开。
- 辅助调用现在每次多一次 `accessToken()`（内存里的 session，不是网络往返）。

## 什么前提失效会推翻它

- **产品口径变了**：这条从头到尾是维护者定的，不是技术推出来的。技术上唯一强的论证
  是决策一那半句（藏界面不改路由 = 静默失败），它约束的是「怎么做」，不是「做不做」。
- **网关开始按档位供不同的型号**：今天 `me.models` 是全局路由表去重的结果；哪天它变成
  「你这一档供哪几款」，`visionModelFor` / `helperModelFor` 挑出来的那款可能不在这个人
  的档里，两个函数都要跟着改。
- **有人要「订阅 + 自带 key 混用」**（比如想用 Claude 而网关不供）：那时要回来的不是
  `direct` 那条路本身，而是一个说得出理由的开关 —— 且它必须解决 ADR-0233 那个问题：
  额度用完的那一刻，谁来告诉用户「接下来烧的是你自己的账号」。
