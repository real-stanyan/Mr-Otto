# ADR-0233：云会话不可以自带 key——统一走工作区所有者的订阅额度

- 状态：已接受
- 日期：2026-09-06
- 关联：issue #981；**推翻** ADR-0202（模型 key 跟着工作区走）与 ADR-0203 决定 D4 在云会话上的改道（额度用完改走自带 key）；上游 ADR-0217（扣所有者、非订阅用户建不出工作区）/ 0232（型号优先级链，中间那级随本 ADR 删掉）
- 来源：维护者在 dev 真机上看到「云会话配置」卡还留着 baseUrl / 型号 / API key 三格，定的产品口径：「不可以自带 key，统一使用订阅额度」

## 背景

ADR-0217 之后云会话的路由是三级：所有者有活跃订阅 → hosted；否则工作区自带 key（ADR-0202）；都没 → blocked。托管额度 429 时还会改道自带 key（ADR-0203 D4）。桌面那张「云会话配置」卡上的三格与「云端不提供公共 key——填谁的 key 烧谁的额度（#844）」那句，是 ADR-0217 之前的话，读起来像必填。

自带 key 这条路留着的代价不只是文案：

- **静默失败模式**：额度用完那一刻悄悄改烧所有者自己的 key，界面上只有一条 `route_changed`。所有者以为在花订阅，账单说的是另一回事。
- **成员可改的字符发给所有者的 provider**（#957 D2）：白名单型号名与自带 key 路的交叉一直要靠「型号名相同才改道」这类补丁封着。
- **一份别人的凭据躺在 VPS 上**（`workspace-config.json` 里的 `apiKey`），而它的存在理由只是「订阅之外的兜底」——而 ADR-0217 已经让「没订阅」建不出工作区。

## 决策

1. **路由只有两态**：`decideRuntimeRoute` 回 `hosted | blocked`。blocked 三种措辞分开：所有者没有活跃订阅（该去订阅）、这一刻查不到订阅状态（稍后再 @，别去点续费）、额度用完（等窗口刷新或加购）。`RuntimeRoute` 与 `HostedRuntimeAdapterDeps` 去掉 `workspace` / `cfg` / `onRouteChanged`。
2. **额度用完不改道**：`onReroute` 只记 `resetAt` 进会话级 `RouteMemo`（`exhaustedUntil`），端点原样交回去让 openaiCompatible 抛**原错**（带 resetAt 的那条）；窗口内的下一个 turn 直接 blocked、一次网关都不打；没给 `resetAt` 就不记（猜长了会在额度恢复之后继续把 turn 挡在门外）。`route_changed` 事件类型留在 schema 给旧日志重放，runtime 不再落它。
3. **协议 7**：`config` 帧去掉 `model`，welcome / `config_result` 去掉 `model` 一格，`CsModelRoute` 去掉 `workspace`，`validateModelConfig` / `CsModelState` 删除。减字段也进位——握手是精确相等，而「新桌面画着一格永远为 null 的模型配置」正是要消灭的假话；已装桌面是协议 4，本来就连不上协议 6 的 runtime，没有存量客户端要兼容。`decodeCsUp` 对老客户端多发的 `model` 字段直接忽略（不判无效、不透传）。
4. **存量凭据剥掉**：daemon 的 `workspaceConfigStore.loadAll` 读到记录里的 `model` 当场删掉并回写（打一行日志）。不等下一次 `save`——一个工作区可能再也不会被 config 一次，那把 key 就永远留在那儿。
5. **桌面**：「云会话配置」卡改名「仓库配置」，只剩仓库地址 + PAT；头部模型那一格 `modelStatusText(route)` 只读路由（hosted：型号 · 托管；blocked：红字说所有者的订阅 / 额度；null：路由未知、不说死）；用量表空态 blocked 时说清楚为什么没数。智能体 tab 型号栏文案去掉「工作区自带 key 时…」那句。
6. **型号优先级链缩成两级**（修订 ADR-0232 决策 3）：agent 白名单按顺序 → 网关第一款。

## 后果

- 所有者退订 / 额度用完 = 这个工作区所有云会话起不了 turn，界面与群里各有一句人话；没有「悄悄换条路」。
- 运维文档 `docs/runtime-vps.md` 第 14 条改成验「没有 model 字段、没有配 key 入口」。
- runtime 与桌面必须一起发（协议 7）；本 PR 合并后先部署 runtime，dev 桌面重启即可，正式桌面等发版。
- 没做：按 agent 或按工作区选「允许自带 key」的开关——产品口径是一刀切，开关本身就是那条路。

## 验收（真机，UNVERIFIED）

1. 新建云会话：页头「<型号> · 托管」，「配置仓库…」卡上没有任何 key 输入框。@Agent 直接跑。
2. VPS：`workspace-config.json` 里没有 `model` 字段；启动日志有「剥掉 N 个工作区的存量自带模型 key」（首次）。
3. 所有者退订（或用没订阅的账号当所有者的旧工作区）再 @Agent：群里一条「工作区所有者没有活跃订阅」，页头红字「没有可用的模型」。
4. 额度打满（或在 edge 上把窗口调小）：第一条 turn 报「额度用完」并带 resetAt；窗口内第二条 turn 报同一句且 runtime 日志里没有新的网关请求。
