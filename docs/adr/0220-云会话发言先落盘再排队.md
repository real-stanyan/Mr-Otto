## 背景

1a（ADR-0219）把服务端骨架装好了：`workspace_agents` 表、每只 agent 一台 engine、
`agentView` 隔离、串行队列、`cs_say` 加 `mentions`。验收标准是「跑得起来，桌面界面上
还看不见任何变化」。**1b 是点亮那一半**：composer 的 @ 选人 chip、时间线上「谁说的 /
说给谁 / 谁还没回」、工作区设置页的 agent 增删改 + 型号白名单。

界面一接上，1a 自己记着的两处偏差就从「今天走不到」变成「今天必踩」，issue #932 把
它们连同另外两条一起列成四个坑：

| 坑 | 症状 | 1a 里为什么没暴露 |
|---|---|---|
| ① 改型号静默不生效 | `engineFor` 命中缓存直接返回，adapter 在这只 agent 第一次开口那一刻定死 | 型号白名单还没有界面能改（ADR-0219 偏差 b 原话：「1b 一旦让用户能改，必须修」） |
| ② 排队中的话日志里零字节 | 队列是纯内存数组，`say()` 收下 ≠ 记下了；daemon 重启，那句话连一个字节都没进日志 | 没有界面画「排队中」，也就没人发现那个状态没有事实来源（ADR-0219 决策 4 的代价段已如实写下） |
| ③ 排队期间 agent 被删 | `runJob` 静默 `return` | 没有 CRUD 界面，删不掉 |
| ④ 客户端 `mentions: []` 被无视 | `resolveTargets` 判据是 `mentions?.length`，空数组被当成缺席、回落去解析正文 | 客户端还没有 chip 输入，发不出空数组 |

四个坑里 ② 不是一个补丁能盖住的，它要求把「一句话的生命周期」重排一遍——本 ADR
的主体就是这次重排，其余三条是它周边的收口。

## 决策

### 1. 发言先落盘再排队，turn 从日志起跑

`services/runtime/src/sessionService.ts` 的 `say()`：只要 `resolveTargets` 解出非空
名单，**当场** `store.append` 一条 `user_message{content: "[label]: text", fromUid,
mentions}`，然后才把每一只 target `enqueue` 进协调器。1a 是反过来的——先排队，等
`runJob` 真轮到时由 `engine.runTurn()` 落开场白。

engine 因此多一个入口：`LoopEngine.runLoggedTurn(opening: UserMessageEvent)`
（`src/loop/engine.ts`），对一条**已经在日志里**的 `user_message` 起 turn，与
`runTurn` 共用 `runFrom` —— turn 的身份（`currentTurnId = opening.seq`）、收口、
`finally` 清场一个字不差，只差「开场那条谁来落」。这是追加，不改既有语义；本机会话
那条路一行没动。

`TurnJob` 跟着换形状：`{ agentId; fromUid; opening: UserMessageEvent }`，`label`/`text`
两个字段删掉——**那句话现在只存在于日志里一处**，job 拿着的是它的引用不是它的副本。

「排队中 / 正在回复 / 答完了」于是是日志的投影，不是内存队列的状态。投影写在
`src/shared/turnLedger.ts` 的 `openTurns(events)`：点名的 `user_message` U →
它之后那只 agent 有没有动静 → 有没有它的 `turn_ended`。三种事件形状的配对，纯函数
零 IO。**两端共用这一份**：runtime 装配末尾按它补跑，渲染层按它画状态行
（`PendingTurnLines`）——两处各写一遍迟早分家（`agentMention.ts` 同款理由）。

重启补跑落在 `createCloudSession` 返回之前：`openTurns(seed)` 里 `queued` 的重新
入队，**`running` 的也重排**（它的 turn 在上一个进程里没收口，这里再跑一遍；日志
会多出一段重复的尝试，但比一行永远转圈的「排队中」诚实）。已归档的不补。两条日志
是刻意的：补跑是一次**没有任何人发起**的模型调用、可能真花钱，不打这行的话
「daemon 一重启就自己跑了一轮」在运维那边完全不可见；被跳过的那几条（缺 `fromUid`
或开场白不是 `user_message`）另打一条 `console.warn`——它们**仍然停在「排队中」**，
不说一声的话界面上那行转圈在服务器日志里没有任何对应物。

连带删掉的三样，都是「落盘取决于跑不跑」这个旧前提的残骸：
- 1a `finally` 里那套补偿排空循环 + 它的两处 `logChat(..., true)`；
- `say()` 里「三种 `decisions` 组合分别补不补 `chat_message`」的整段判断（ADR-0219
  决策 3 的 ② 就是在补这个洞——洞的成因是落盘挂在执行上，现在成因没了）；
- 排空循环抽成具名 `drain()` 且**每个 job 各自 catch**：一只抛错不再让排在后面的
  那只被整队丢弃。`logChat` 只剩「没点名」一个调用方。

**排队本身仍然纯内存、重启仍然丢。** 这一节兜住的是「开场白在日志里，重启能按
`openTurns` 找回来补跑」，不是「队列持久化」——两件事不要混。

### 2. 客户端给了 `mentions` 就以它为准（坑 ④）

`resolveTargets` 的第①级判据从 `mentions?.length` 改成 `mentions !== undefined`。
`[]` 是一句「我确认谁都没点」，与「这台客户端算不出 `mentions`」（字段缺席）是两回
事；前者回落去解析正文，就是**界面上写着「没 @ 任何人」而服务端认为 @ 了**。新桌面
的 chip 行与发送用的是同一次 `parseMentions` 的结果（`CloudSessionPage.tsx` 里一个
`useMemo`，不是两次调用），所以「界面说给谁」和「服务端跑谁」不可能分家。

**老客户端一个字节都不受影响**：手机端和旧桌面根本不发这个字段，走的还是②正文解析
/③布尔老语义那两级。渲染层那侧的布尔与数组同源——`store.ts` 的 `cloudSay` 里
`mention = mentions === undefined ? true : mentions.length > 0`，开局卡不传数组（走
`undefined` → 老语义），composer 总是传。

**推翻它的前提**：手机端也做了 chip 输入的那天，`mention` 布尔字段就可以退役，
`resolveTargets` 的②③两级跟着删——ADR-0219 偏差 a（服务端正文解析压过
`mention: false`）会随之自然消失。在那之前它原样留着，见「代价与天花板」。

### 3. adapter 每 turn 现取（坑 ①）

`engineFor` 命中缓存时也调一次 `hit.setAdapter(opts.adapterFor(spec))`，然后才返回。
**不比对「变没变」**：比对的判据一漏就是安静地继续用旧型号，而 `setAdapter` 是纯
赋值，白设一次不花钱。

这是 ADR-0202「每次 `chat()` 现读，因为会话房是长命的」在 **agent 粒度**上的重申——
同一条教训在这个新粒度上又踩了一遍（ADR-0219 偏差 b 记着这件事，并点名 1b 必修）。
失败模式是静默的：不报错、不落日志，只有账单会说话。

天花板：换的是**下一 turn** 的 adapter（`engineFor` 在 `runJob` 起跑前调）。跑到
一半的那台 engine 手上的 adapter 不换——「半途换 adapter 对进行中 turn 的影响」是
另一个问题，本切片不碰。

### 4. 删掉的 agent 要留痕：一条它自己的 `turn_ended{error}`（坑 ③）

排队期间这只 agent 被删了，`runJob` 从 1a 的静默 `return` 改成：

```
turn_ended{ outcome: "error", agentId, error: `智能体 ${agentId} 已不在这个工作区，这句话没人接` }
```

**为什么不是一条 `chat_message`**：`openTurns` 的收口判据是「这条 U 之后有没有**这只
agent 的** `turn_ended`」，而 `chat_message` 不带 `agentId`，收不了口。不收口 =
界面上永远「排队中」+ 每次 daemon 重启都把它重新排上跑一遍。留痕的形状必须让**推导
收口**，不是让人看见——人看得见只是顺带的。

错误文案用 `agentId` 不用名字：名字已经查不到了（就是因为它被删了），别为一条错误
信息再去猜。代价是用户看到的是一串 id。

### 5. 「答两次」的裁决：不变量在 `say()`，护栏落在 `unseenUserTail`

决策 1 有一个当场就冒出来的后果：**同一只 agent 在 turn 跑着的时候被再次 @，会答
两遍**。路径是——这条话现在当场落盘，于是 ① 正在跑的那一轮说完话时，engine 的
`unseenUserTail`（ADR-0205 的机制）在日志尾上看见一条点了自己的新消息，**在同一个
turn 里又采样一圈**答它；② 协调器里排着的那个 job 轮到时又正经跑一轮。结果是一次
多余的模型调用（两轮读的都是整份日志，答案不会错、日志也不矛盾，只是多花一次钱、
时间线上多一段）。1a 走不到这条路——那时这句话要等它的 job 起跑才落盘，第一轮的
日志尾上什么都没有。

**第一版修法被复审否决，理由值得记下来。** 那一版是在 `runJob` 起跑前查日志：
`opening` 之后已经有这只 agent 的 `assistant_message` 且已经有 `turn_ended`，就当
「模型已经看见并答过」跳过这一轮。它有两个**静默丢消息**的洞：

- **`turn_ended` 不只有 `completed`。** `aborted` / `error` 同样满足「已 turn_ended」，
  于是一条从没被回答的话会被当成答过了跳过——不报错、不留痕。
- **`concludesTurn` 那条路返回时不查尾。** `engine.ts` 的 `loop()` 里
  `if (concluded) return;` 是直接返回，不像「模型这步没要工具」那条路会先
  `unseenUserTail(log)` 再收口。也就是说这个 turn 的模型**确实没看见**新消息，而它
  留下的 `assistant_message + turn_ended{completed}` 会让日志推断得出「看见了」。

采纳的是 engine 里的一行：`unseenUserTail` 对**带 `mentions` 的 `user_message` 一律
不重采样**（`return false`）。判据从「点的是不是我」改成「只要点了名就不算我没答
的」，靠的是决策 1 立起来的一条不变量——

> 每一条带 `mentions` 的 `user_message` 在 `say()` 落盘那一刻**就已经有一个 turn
> 归它**：要么是它自己排的那个 job，要么去重命中、并进了那只 agent 还排在队里的
> job（那一轮开跑时读的是整份日志，这句话在里面）；daemon 中途死掉那种由装配时的
> 重启补跑接住。

早退那一行**逐字未动**：没配 `agentId`（本机会话）、或这条没点名（群里随口一句、
ADR-0205 的后台结果回注、ADR-0212 的护栏注入）照旧算「我没答的」——那两条 ADR 靠的
就是它。

**残余代价，如实记**：一个**还在跑工具调用**的 turn，下一圈增量快照里照样看得见这条
新消息，可能赶在它的 job 起跑前把它答了。那是一次浪费的模型调用，**不是丢消息**
（job 仍然会跑、日志仍然完整）。修法要么在 `enqueue` 侧（这只正在跑就当去重命中），
要么给 `unseenUserTail` 再加一条「这条已经有排队中的 job」的判据——两者都要跨模块
递信息，超出本切片边界，记 #934。重启补跑没有次数上限（一条能把 daemon 打死的 turn
会无限重跑、每次都扣 owner 的钱），记 #933。

### 6. @ 选人弹层走 Radix `Popover`，不是 `absolute bottom-full`

计划里写的定位方式是错的，而且**错在最高频的那一格**：这一页整个装在
`CloudSessionMain` 的 `overflow-y-auto` 里，新会话只有一行「还没有消息。」时 footer
离滚动容器上沿不到 90px，`absolute bottom-full` 画出来的列表高过这段距离的部分会被
裁掉，**而且滚不到**（往块起始方向溢出的内容拿不回来）。三只 agent 就削掉一行。

改成 `Popover`（portal 到 body + `avoidCollisions` 自己翻转）之后：`PopoverAnchor
asChild` 包住 textarea（Radix 的 Slot 合并 ref，`boxRef` 照旧拿得到 DOM 节点，
`setSelectionRange` 那条路不变）；键盘**全部**仍由 textarea 的 `onKeyDown` 管，一个
键都不交给 Radix（它会拿方向键去做菜单导航）；`onOpenAutoFocus` / `onCloseAutoFocus`
双双 `preventDefault()`——这个列表是 textarea 的附属显示，人还在打字，焦点一步都不
许挪。

**`onBlur` 是故意没有的**，这一条要写在代码里也写在这里，不然下一个人看见「失焦不
关」会当成漏做再补回来。`dismissedAt` 承载的是「这个 @ 我不要了」这个**判断**，而
切窗口不表达那个判断：alt-tab 出去再回来，光标一个字没动 → `picking` 恒为 null →
接着打字列表再也不出来，人只能换行躲开。该关的两条路都有人管——指针点到外面走
`onInteractOutside`（Radix 的 DismissableLayer 把 pointerdown-outside 与 focus-outside
一起归到这个回调；**点回 textarea 本身要 `return`**，它是这个弹层的锚，算成「外面」
就造出「点进 @ 查询词中间就再也不弹」的死角）；键盘出不去（弹层开着时 Tab /
Shift+Tab 被 `onKeyDown` 拦去选人，焦点挪不动）。

进出场动效**手写 keyframes 落在 `app.css`**，按 `[data-slot="popover-content"]` 挂。
理由同弹窗那段：shadcn 的 `animate-in` / `zoom-in-95` 一族在本仓库是**死类名**（只
`@import "tailwindcss"`，没装 tailwindcss-animate，`ui/dialog.tsx` 顶部那段注释已经
点名警告过，这次照样有人踩了一遍：先给一个根本不存在的动画加了 `motion-reduce:
animate-none`）。挂 slot 不挂 class，所以全仓库三个 Popover 消费方（`ThinkingPicker`、
`assistant-ui/model-selector`、云会话的 @ 选人）一起吃到，不用逐处补；`ui/popover.tsx`
一个字没动。reduced-motion 那档**换动画名**（换成只有透明度的 `dialog-overlay-in/out`）
而不是把时长压到 1ms——压时长等于硬切，而「减少动效」要的是别缩放别位移，不是别有
过渡；判据抄紧邻的 `.dialog-content` 与 `.menu-pop`，三处一个写法。

CSS 既不过 `tsc` 也不过 `vitest`（括号写错门禁照样全绿），所以那一轮额外真跑了一次
`electron-vite build` 并在产物里确认 keyframes 没被 purge 掉。

### 7. 两处 placeholder 的不对称是保留的

- 开局卡（`CloudWelcome`）：「要它做什么？**不 @ 谁的话由管理员接**。回车发送」
- composer（`CloudSessionPage`）：「输入 @ 点名智能体；**不 @ 就只是群里说一句**」

两句话说的是相反的事，但**各自都对**：开局卡那条路不带 `mentions` 字段（走
`undefined` → 决策 2 的③级老语义 → 名单第一只 = 管理员），composer 那条路总是带
数组（`[]` = 谁都没点 = 只落 `chat_message`，没人起 turn）。统一成一句话必然有一处
撒谎，而这两个框离得远、不会并排出现。哪天手机端也上了 chip 输入、布尔字段退役，
这两句才该合并成一句。

## 否决的备选

| 备选 | 为什么否 |
|---|---|
| 往 cs 协议里加一个 `queued` 回执帧 | 那是**内存状态的另一份拷贝**：daemon 重启，服务端那条队列不存在了，而客户端手上还挂着一条「排队中」——比不显示更糟。真正缺的是事实来源，不是一条通知 |
| 把 `chat_message` 当排队记录（排上队先落一条，跑起来再落 `user_message`） | 同一句话落两遍。ADR-0219 决策 4 已经量过这个坑：`deriveMessages` 把 `chat_message` 投影成 `{role:"user", content:"[label]: content"}`，与 `user_message` 走完 turn 后的形状**完全相同**——不是日志变胖，是模型把同一句指令读两遍、时间线画两遍 |
| `runJob` 起跑前按日志推断「已经答过就跳过」 | 两个静默丢消息的洞，见决策 5：`turn_ended` 不只有 `completed`；`concludesTurn` 那条 return 不查尾。修一个能省一次调用的问题，换来一个会丢消息的问题 |
| 弹层自己 `absolute bottom-full` 定位（计划原文） | 被滚动容器裁掉且滚不到，最高频的新会话那一格最严重。见决策 6 |
| textarea 的 `onBlur` 关弹层 | 把「切窗口」当成「我不要这个 @ 了」。见决策 6 |
| `engineFor` 里比对「型号变没变」再决定换不换 adapter | 判据一漏就是安静地继续用旧型号，而白设一次 adapter 不花钱。见决策 3 |

## 代价与天花板

| 面 | 结果 |
|---|---|
| 日志形状 | 同一句话的 `user_message` 现在**早于**它的 turn 落盘（1a 是同时）。`SessionEvent` schema 只加了两个可选字段（`fromUid` / `mentions`，Task 1 已加宽），旧日志照常重放：没有 `mentions` 就进不了 `openTurns`，等于保持旧行为 |
| engine | 多一个入口 `runLoggedTurn`（追加，不改既有语义）；`unseenUserTail` 多一条判据，早退那行逐字未动 |
| 队列 | 仍然纯内存、重启仍然丢。兜住的只是「开场白在日志里，重启能补跑」 |
| 重启补跑 | 没有次数上限（#933）。`running` 的那些会被重排，日志因此多出重复的尝试段——刻意的取舍 |
| 多余的模型调用 | 工具调用中途被再 @ 的那条路仍可能多答一次（#934），是浪费不是丢消息 |
| ADR-0219 偏差 a | **原样保留**：`mentions` **缺席**时服务端仍会解析正文，于是一条 `mention: false` 但正文含 `@管理员` 的旧客户端消息仍会起 turn。1b 只收紧了「客户端给了 `mentions`」那条路（决策 2）。手机端上 chip 输入之后这一级才该删 |
| ADR-0219 偏差 c | **原样保留**：`supabase/migrations/0021_workspace_agents.sql` 至今没在生产库执行过，本切片也没执行。设置页的 agent CRUD 界面装好了，但表没建之前 `queryAgents` 仍会回落到单条「管理员」占位 |
| 手工冒烟 | **一次都没跑**（Task 4 / 9 / 10 的报告都如实记着）。前置条件是登录账号 + 有订阅的工作区 + VPS 上活着的 runtime daemon（#913 记着那台的握手曾静默失败七小时）。纯逻辑有单测覆盖，渲染时机、光标/焦点时序、弹层翻转、动效观感全部 UNVERIFIED |
| 已知未修 | 全角 ＠（U+FF20）认不出（#935）；`user_message.origin` 全仓没有换皮，护栏注入/后台回注在云时间线上画成匿名人类气泡（#936） |

## 推翻它的前提

- **若「排队本身也要能重启后活下来」被证明必须做**（#933 表明补跑不是免费的，而
  纯内存队列在多 agent 工作区里丢的不止一条），决策 1 的一半要往前推：队列本身落盘
  或落表。届时 `openTurns` 从「投影」变成「事实的一部分」，「一句话一条事件」
  （ADR-0219 决策 4）的判据要重新设计——「排队中」那时是一句话的一种状态，不再是
  「有没有起 turn」两态。
- **若增量快照那条多答一次（#934）在真机上变成常见浪费**，修法不是把决策 5 的护栏
  收得更紧（它已经堵住了能靠不变量堵的全部），是在 `enqueue` 侧让「这只正在跑」当作
  去重命中——那要把协调器的状态递进 engine，是一次真的耦合，值不值得由真机数据说。
- **若决策 5 的护栏被证明太宽**（有人真的希望正在跑的那一轮把新点名的话一起答了，
  而不是排队等下一轮），退回的方式同样是 `enqueue` 侧的去重，不是把
  `unseenUserTail` 改回「点的是不是我」——那样等于把「一句话一个 turn」的不变量拆掉。
- **手机端上 chip 输入的那一天**，`mention` 布尔字段退役：决策 2 的②③两级删掉，
  ADR-0219 偏差 a 消失，决策 7 的两句 placeholder 合并成一句。
- **若手工冒烟（至今一次没跑）在真机上翻出弹层定位/焦点/动效的问题**，决策 6 的
  Radix 那半可能还要再调；但「不能自己 `absolute` 定位」这条结论不受影响——它的依据
  是滚动容器的裁切，不是 Radix 好不好用。
