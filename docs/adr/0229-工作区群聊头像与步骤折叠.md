# ADR-0229：工作区群聊的头像与 agent 步骤折叠——agent 头像按 agent_id 派生不落库、成员头像随成员表批查、中间步骤折成一行只画最终答案

- 状态：已采纳
- 日期：2026-09-06
- 关联：issue #971；先例 ADR-0093（好友头像统一走 shadcn Avatar）、ADR-0220（云会话时间线的署名与归属，`cloudTimeline.ts`）、ADR-0224/0225（`workspace_agents` 的形状与每工作区 32 只上限）；编号按 ADR-0074 在合并前复核

## 背景

维护者拿着 13 张自己生成的像素人像提了三件事：① 工作区里的智能体各有一张头像；② 群聊里不同人类成员发消息时各显示各的头像，多人群聊好区分；③ 「智能体发言时不需要在 UI 里显示思考过程，只需要显示最终答案，不然整个页面看起来太长太乱」。

现状：云会话时间线（`CloudSessionPage.tsx`）三种气泡只有一行文字标签；`WorkspaceMemberRow` 没有头像字段（`fetchProfileLabels` 只查 `profiles.name`）；`workspace_agents` 没有头像列。「思考过程」在这条时间线上指的**不是** `reasoning` 字段（那从来没画过），而是一轮里每条带 `toolCalls` 的 `assistant_message` 都画成一条气泡 + 几行工具行——一轮跑十次工具就是十条气泡，最终答案淹在里面。

## 决策

### 1. agent 头像**不落库**，按 `agent_id` 哈希派生到 13 张内置图上

`src/renderer/src/assets/agent-avatars/01..13.png`（脸居中裁成 128px 方图，每张约 22KB）随渲染层打包；`agentAvatarSlot.ts` 是纯逻辑：管理员固定第 7 张（它是唯一在所有工作区都存在的 agent，固定一张脸让「管理员」跨工作区认得出来），其余 FNV-1a(agent_id) mod 13；同一工作区内撞上的按名单顺序（服务端 created_at 升序）往后挪一格；超过 13 只时重复不可避免，回天然坑位（稳定优先于唯一）。

**否决「给 `workspace_agents` 加一列 + 表单里挑」**：头像是纯展示，13 张对每工作区 32 只的上限够用；加列意味着一次要在 Supabase SQL editor 手动执行的 migration（0025 到今天还没在生产跑，#970）、建/改 agent 的表单多一格、`create_agent` 工具多一个参数、runtime 多一处校验。派生比落库便宜一个量级，且**存量 agent 立刻有脸**，不用等谁去设置页挑。真到要自定义头像那天，加列 + 「有值用值、没值派生」是向后兼容的，今天这条路不堵它。

**为什么哈希 `agent_id` 而不是名单下标**：下标在删掉一只之后让后面所有人换脸；`agent_id` 是 migration 0021 特意与 `name` 拆开的那个稳定键（改名不断记忆、不断账，现在也不换脸）。已知代价：曾因撞脸而挪过位的那只，在被它撞的那只删掉之后会挪回原坑（换一次脸）——只在撞过的那对之间发生，删 agent 本来就罕见，接受。

### 2. 成员头像随成员表批查进快照

`WorkspaceMemberRow` 加 `avatarUrl: string`（没设过 / 查不到 = 空串，渲染层退回首字母，不必判 null）；`fetchProfileLabels` 改成 `fetchProfiles`，`select("id,name,avatar_url")` 一次查两样；`assembleSnapshot` 的注入函数从 `labelOf: uid → string | null` 换成 `profileOf: uid → MemberProfile | null`，`name` 空串与查不到同样退回 uid 前 8 位（`profiles.name` 是 `not null default ''`，之前的 `if (row.name)` 判的也是这个）。头像是 `profiles.avatar_url` 那一列的 data URL（ADR-0093 的存法，上限 `AVATAR_MAX_CHARS`），好友列表本来就是这么查的，这里只是多查一张表里的同一列。

### 3. 群聊气泡统一走 `SpeakerRow`：头像 + 标签行 + 气泡，三种气泡一份骨架

`ChatMessageRow`（闲聊）/ `UserMessageRow`（点火那句）/ `AssistantMessageRow`（agent 回复）原来各自画一摞 `flex-col`，现在共用 `SpeakerRow`：头像与**标签行**顶对齐（不是 `MessageAvatar` 默认的贴底——长消息上贴底的头像会掉到看不见的地方），自己发的头像画在右侧。**自己发的也画头像**：靠右已经说明是我，但维护者要的是「每个人各自的头像」，多人群里每一行都有脸比「有的有有的没有」整齐。agent 头像**不开** `image-rendering: pixelated`：128px 缩到 24px 时一格像素只剩一个多屏幕像素，最近邻会整行整列丢掉（眼睛可能直接没了），平滑缩放反而认得出是谁。

### 4. 中间步骤折成一行、只画最终答案——渲染层的分组，不动日志不动投影

`foldAgentSteps(events)` 按 `agentId` 各开一段 run：碰到「步骤」（要了工具的 `assistant_message`，或一个字没说的）就攒进当前 run 并标 hidden；碰到「答案」（有正文且没要工具）或这只 agent 的 `turn_ended` 就收口，fold 挂在收口那条事件的 seq 上，渲染层画在它前面；事件流走完还没收口的段进 `open`，画在时间线末尾、排队/正在回复那几行之前，摘要写「正在处理」。折叠行是默认收着的 `<details>`（样式同 `SystemNoteRow`：审计性质的旁白，无动效），展开是每一步的正文 + `ToolActivityLine`——**一个字都不丢**。

**否决「隐藏干净、连折叠行都不画」**：本仓的一条纪律是「即使模型这一轮一个字没说，用户也能看见它干了什么」（`AssistantMessageRow` 头注）——一行淡字 + 展开才有全文，满足「页面不长不乱」而不放弃那条纪律；审批卡照旧贴着输入区，不受折叠影响。**否决「在 `deriveMessages`/`agentView` 那层做」**：那是模型上下文的投影，与这里给人看的分组是两个问题；日志一个字节不动是硬规则，这条改动纯在渲染层。

`turn_ended` 与步骤按 `agentId` 配对，两边都缺席（旧日志/单 agent 会话）自然配上；旧日志的推导结果与新日志同一套规则，不需要版本判断。

## 后果

- 三处新纯函数各有单测（`tests/renderer/agentAvatarSlot.test.ts`、`cloudTimelineLabels.test.ts` 的 `foldAgentSteps` 段、`tests/shared/workspaces.test.ts` 的 avatarUrl 用例），`AGENT_AVATARS` 的张数与坑位数由测试钉住——少放一张 png 是 `undefined` 的 src 而不是报错。
- `WorkspaceMemberRow` 加了必填字段，所有构造快照的测试夹具跟着补 `avatarUrl: ""`；手机端不 import 这份类型（tsconfig 排除 `mobile/`），不受影响。
- 智能体名单页（`WorkspaceAgentsTab`）每行也画同一张脸——人在群里认脸、来这页改配置时对得上号。
- 已知未做：头像不可自定义（见决策 1 的回旋余地）；折叠行的「N 步」在一轮里同一只 agent 被再次 @ 而没收口时会把两轮算成一段（同 `openTurns` 头注已知不精确的那一格，事件上没有 turn id）；本机 `Timeline.tsx` 那条时间线不折叠（单 agent 会话本来有 assistant-ui 的工具组折叠）。
