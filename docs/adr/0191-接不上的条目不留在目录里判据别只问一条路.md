# ADR-0191：接不上的条目不留在目录里 —— 而"接不上"这个判据别只问一条路

- 状态：已接受
- 日期：2026-08-30
- 关联：issue #766、#733（原判据）、#697（手填 client_id）、ADR-0190（blocked 机制）、ADR-0184（目录的实测判据）

## 背景

用户：「把连接器里面类似 GitHub 这种连不上的全去掉」。

照字面做的话，GitHub 会被删掉。但它**不属于连不上的那一类**——这是执行这条要求的过程中
才发现的，而发现的方式恰恰是这条 ADR 要记的东西。

## 判据错在哪

ADR-0184 给目录定的判据是：**拿仓里那份 SDK 跑一遍授权前半段**，走到"浏览器该开了"才算数。
这条判据本身是对的（它挡住了抄社区清单抄错的那类问题），但它有一个没写出来的前提：
**这台 server 只能用 OAuth 连**。

于是 #733 的流程是：跑 `auth()` → 动态注册那一步失败 → 记下"接不上" → 收工。
**从来没试过还有没有别的门。**

实测（`gh auth token` 的输出直接当 bearer 打过去）：

```
POST https://api.githubcopilot.com/mcp/   Authorization: Bearer gho_…
HTTP 200 → 44 个工具
```

GitHub 的 MCP server 收任意来源的 bearer token。而 Mr Otto 早就支持 `headerTemplates`
（`Authorization` → `Bearer {…}`）。**这台从头到尾都能连，我们只是没敲那扇门。**

这跟 ADR-0190 的两次修正是同一个家族的错：**在一个环节上得出结论，就当成了整件事的结论**
（抽了函数没接调用点 / 加了判据没接第二个渲染点 / 试了一条授权路就断言"接不上"）。

## 决策

### 一、"接不上"的判据加一句：还有没有别的门

给一台 server 下"接不上"的结论之前，至少要问两条路：

1. OAuth（ADR-0184 那条：拿真 SDK 跑一遍）
2. **bearer token** —— 拿一个假 token 打一发 `initialize`，读 `WWW-Authenticate` 怎么说：

| 回什么 | 结论 |
|---|---|
| `error_description="Invalid token"` | 收任意来源的 token，**能连**，只是这个假 |
| `"token was not issued by X OAuth"` | 校验签发方，只认自家 OAuth 签的 |
| `scope="…", authorization_uri=…` 而没有"token 无效"字样 | 纯 OAuth |

这一发不需要任何凭据，成本是一条 `curl`。

### 二、目录里不留接不上的条目

| | 结果 |
|---|---|
| GitHub | 改成 `auth: "token"` + `headerTemplates`，**留下** |
| Asana | `"Invalid token signature - token was not issued by Asana OAuth"` —— 只认自家 OAuth，**删** |
| Figma | `scope="mcp:connect"` 纯 OAuth，DCR 端点还 403，**删** |

一条永远接不上的目录条目价值是负的：它占着搜索结果、诱导用户点进去、还要一整套
（ADR-0190 那套）机制去解释自己为什么不能用。ADR-0190 当时说"删掉等于把问题藏起来"——
那句话在**问题可能被解决**时成立（#697 一落地 GitHub 就活了），在**这条路根本不通**时不成立。
Asana / Figma 等的是 #697，那就等 #697 落地时再加回来，而不是先摆在那儿写一句道歉。

### 三、`blocked` 机制留着，但使用者归零

字段、UI 分支、ADR-0190 全留。下一台被发现接不上的 server 还要用它，而"发现之后怎么说"
这件事已经想清楚了，不该因为此刻没人用就拆掉。

门禁那条断言从"那三条挂着 blocked"翻面成**"此刻一条 blocked 都没有"**。它不是在禁止
`blocked` —— 是让"目录里躺着一台接不上的"必须有人**把断言改红了才能进来**，顺手把上面
第一节那个判断（是真没路，还是只试了 OAuth 那一条）逼到那一刻去做。

## 代价与边界

**验过的**：`gh auth token` 那种 token（`gho_`）能连；配置经 `configFromEntry` 拼出来的
请求头是对的（单测钉住）；**真机走 app 自己那条路连上了，详情页显示「已接通 · 44 个工具」**。

**没验的**：经典 PAT / fine-grained PAT 行不行。参数说明里两条都写了，把 `gh auth token`
放在前面——那条是验过的。哪天有人报 PAT 连不上，改的是参数说明，不是又一个 `blocked`。

**没做的（是判断不是遗漏）**：有 `gh` 的机器上，让水獭直接敲命令行其实比走这台连接器更好——
那 44 个工具超过 `exposure.ts` 的阈值 12，会全部 `deferred`，模型得先 `tool_search` 才能调，
反倒比 `direct` 的 `bash` 多一轮往返；而 `gh` 的 token 在系统钥匙串里，比 `mcp.json` 里
一把明文 PAT 安全。但连接器面向的是**没装 gh 的那一半用户**，那才是它存在的理由。
"这台机器上已经有更好的本地路径"是目录缺的一个概念（filesystem / postgres / playwright
都是同一类），单独开 issue，不在这条里做。

## 测试怎么跟着改

blocked 的 UI 覆盖原来借"目录里的 GitHub 是 blocked 的"当支点，GitHub 一改这四条一起红。
搬到 `tests/renderer/McpConnectorPage.test.tsx`，拿**合成条目**直接渲染详情页——判据不再
随目录内容漂移。同理 `mcp_catalog` 那条改成直接测导出的 `render()`。

这本身是个教训：**用真数据当测试支点，等于把"这条数据长什么样"焊进了断言**。
测行为的用例应该自带数据。
