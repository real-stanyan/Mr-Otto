# ADR-0174：平台按模型独立比价，但 cache 粘性优先于比价

- 状态：已接受（stanyan 会话指示，issue #696）
- 日期：2026-08-29
- 相关：ADR-0173（订阅计量）、ADR-0175（托管 / BYOK 双模式）、
  `src/shared/modelPricing.ts`（客户端显示用的价表，与本 ADR 说的服务端权威价表是两份）

## 背景

产品决定「全用中国模型、全走境内一方站、什么平台便宜用哪个平台」。

「什么平台便宜用哪个」听起来像是选一个最便宜的平台，实测不是这样。

## 决定

### 1. 「便宜」是按模型算的，不是按平台算的

实测（2026-08-29，¥/百万 token）：

| 模型 | 硅基流动 in/cache/out | 一方官方站 in/cache/out |
|---|---|---|
| DeepSeek V4 Flash | 1.00 / 0.02 / 2.00 | 1.00 / 0.02 / 2.00 |
| **DeepSeek V4 Pro** | **12.00 / 1.00 / 24.00** | **3.00 / 0.025 / 6.00** |
| GLM-5.1 | 6.00 / — / 24.00 | 6.00 / 1.30 / 24.00 |
| Kimi K2.6 | 6.50 / 1.10 / 27.00 | 6.50 / 1.10 / 27.00 |

聚合平台在旗舰模型上不便宜，DeepSeek V4 Pro 贵 4 倍、cache 贵 40 倍。
那些「聚合平台便宜 30–70%」的说法指的是另外两类东西：官方没有的小尺寸开源
SKU（是**不同的模型**，不是同一个模型的折扣），以及走逆向接口的中转站。

**结构规律：自研模型在自家一方站最便宜。** DeepSeek→DeepSeek 官方、Qwen→阿里
百炼、Doubao→火山方舟、GLM→智谱、Kimi→月之暗面、MiniMax→MiniMax 开放平台。
要开的是六个一方站账号，不是找一个最便宜的聚合站。

聚合平台按两个用途接，不按「更便宜」接：**官方没有的小尺寸 SKU**、以及
**故障时的 failover 通道**。

### 2. 模型与路由是两层

```sql
model(logical_id, tier, capabilities)         -- "deepseek-v4-pro"
route(logical_id, platform, endpoint, wire_model,
      price_in, price_cache, price_out, currency,
      effective_from, effective_to,           -- 时段价 / 促销
      quantization,                           -- 'none' | 'int8' | 'unknown'
      tpm_limit, rpm_limit, concurrency,
      health_score, priority)
```

一个逻辑模型挂 N 条 route。

### 3. 选路四步，顺序不能换

1. **过滤**：`quantization = 'none'` + 健康 + 未撞限流
2. **粘性优先**：本 session 上一次用的 route 若仍可用，**直接返回它**
3. **比价**：无粘性时按**有效混合价**排序（不是标价 —— cache 价权重最大），取最低
4. **failover**：只在真失败时换站，换站后短时间内不来回跳

**第 2 步是整个设计的重点。** 天真的「每次请求选最便宜的」会让 prompt cache 永远
不命中；cache 在 DeepSeek 上是 120 倍的价差（¥3 → ¥0.025），任何比价收益都补不回
换站丢掉的 cache。agent 循环的前缀复用率极高，cache 命中率是毛利的主变量，不是
优化项。

同理，**升档（换 tier）只能在 turn 边界发生**，不能在一个 turn 中途换；且会话越长
（cache 越值钱），升档的实际门槛越高。

### 4. 三条红线

- **逆向接口的中转站一律不接。** 那类平台便宜是因为走非授权通道 —— 封号风险、
  版本不同步、数据条款不明。整个业务压在上游能不能用上，不能压在一个随时被封的
  灰色通道上。判据：**能不能在厂商官网找到这家的授权 / 合作声明**，找不到就不接。
- **量化版不能静默替换官方版。** 聚合平台的低价常常来自 INT8/INT4 量化，在长上下文
  和工具调用上掉质量。`quantization` 字段必填，`unknown` 一律当量化处理、不进主力池。
- **没有 cache 定价的 route 不进主力池。** cache 是 30–120 倍的差价，一条没有 cache
  的 route 单价再低也算不过来（硅基的 GLM-5.1 就是这个情况）。

### 5. 价表是 DB 行 + 定时核对，不是代码常量

证据：2026 上半年国产厂商降价 6 次（3 次永久），DeepSeek 2026-08-16 又调了价 ——
**两个月的价表就已经是错的**。周级抓各家定价页做 diff 告警。

`src/shared/modelPricing.ts` 那张手抄表**保留不动**，它服务的是客户端 BYOK 模式下
页脚那个「这一次大概花了多少」，与服务端权威价表是两份东西、两种可信度。
（那张表的头注已经写明「手抄，会过期」，抄表日期比价格本身重要。）

### 6. 六个一方站的余额告警

境内是预充值对公，不是信用卡自动扣 —— 烧穿 = 全站挂。`src/main/providerBalance.ts`
已经能查 DeepSeek / Moonshot 的余额端点，把这套搬到服务端、补上智谱 / 百炼 / 火山 /
MiniMax，低于 N 天用量就报警。这是零新增设计的现成件。

## 会被推翻的前提

- **价格是查来的，不是测来的。** 上面那张对比表来自 2026-08-29 的公开定价页，
  必须开控制台核实一遍再写进 route 表 —— 尤其 DeepSeek V4 Pro 境内 cache ¥0.025
  这个异常值（见 ADR-0173 的同名章节）。
- **「境内 CNY 价没有错峰折扣」尚未确认。** DeepSeek 官方英文页只写了 USD 那档的
  peak/off-peak（高峰 = 01:00–04:00 + 06:00–10:00 UTC，仅周一至周五，其余 79% 的
  时间是半价）。若境内 CNY 价也有这一档，价表必须带时间窗，成本还能再降近一半。
- **「自研模型在自家站最便宜」是当下的观测，不是定律。** 一方站涨价、聚合站补贴
  都会翻转它 —— 这正是价表要做成数据 + 定时核对的理由，规律变了 route 表自己会
  反映出来，不需要改代码。
