# ADR-0336：手机上接的应用封存在同一只箱的第二个键；撤销一律授权先删、目录行后删

- 状态：已采纳（2026-09-30）
- Issue：#1430；spec：`docs/superpowers/specs/2026-09-30-mobile-connectors-design.md`；计划：`docs/superpowers/plans/2026-09-30-mobile-connectors.md`

## 背景

手机上要能直接「接入应用」：点一下 → 浏览器登录 / 粘 token / 直接连 → 这个应用进本账号的云端连接器，自己的智能体马上能用，
还能在手机上开关「借给团队」。桌面那条路（ADR-0197）是桌面把凭据整箱上传到 edge 的 Escrow DO，手机没有那台本机 `McpHub`，
也没有回环地址可以接 OAuth 回调，所以凭据的来源、续期、撤销都得在 edge 这一侧闭环。

## 决定

1. **同一只 Escrow DO，第二个封存键 `cloud`，一个键一个写者。** `sealed` 仍是桌面整箱上传的托管服务（桌面的 PUT / DELETE
   只碰它），`cloud` 只归新加的 `/px/v1/cloud*` 端点写。DO 的 `grants` / `call` 两个 op 把两个键合成一份 `EscrowDoc`
   （`mergeEscrow`）再过原来的 `pxGate` / `grantedView`——判据（主场要所有者本人、团队要同在籍、每次调用记审计）一个字不变，
   runtime 的取工具与调用路径也不变。否掉的是「另开一只 DO / 另一张表」：三道闸要复刻，两处审计要对账。
   两个键不撞写的前提是各有唯一写入路径，且 `cloud` 的读改写是「**外呼在前、读改写在后**」：所有网络调用（发现、注册、换 token、
   `tools/list`、续期）都在 `blockConcurrencyWhile` 之外做完，临界区里只有存储读写。DO 在外呼的 `await` 处会交错处理别的请求，
   临界区里混进一次 `fetch`，这条前提就破了。`GET /px/v1/cloud` 永远是无凭据视图（不带 url / headers / oauth）。
2. **OAuth 全在 edge 做，回调走 edge 自己的 https；v1 不做手填 client。** 发现（RFC 9728 → 8414）→ 动态注册（RFC 7591，
   按 public client 申请）→ PKCE S256 → 回调换 token。回调地址写死成生产的 `DEFAULT_EDGE_BASE_URL` + `/px/v1/cloud/callback`
   （`worker.ts` 里不读环境，`wrangler dev` 起的本地 edge 向厂商注册的也是这个生产地址——本地跑不完一整轮登录，回调会落到生产），
   回调之后 edge 302 到手机拦截的深链 `mrotto://connector-done`。请求形状三条（终审 M7）：`resource` 参数取资源元数据
   （9728）声明的 `resource`，没有才用接入 URL，记进 pending 与落箱的凭据、换 token 与续期都带同一个；`scope` 只取资源元数据的
   `scopes_supported`，没给就不带（授权服务器那份是它支持的全集，不照搬）；厂商若仍回了 `client_secret`，它随
   `clientInformation` 封进箱，换 token 与续期按 `client_secret_post` 带上。每一发外呼（发现、注册、换 token、续期、接入时的
   `tools/list`）15 秒上限，超时落进各自原来的失败形状；调用路径（`pxMcpCall`）不加。`state` = `<uid>.<32 字节随机>`，10 分钟、一次性、查到即删，
   pending 每人最多 5 条，`/cloud/connect` 每人每分钟 10 次。最终 URL 由 edge 按自己手上的 `MCP_CATALOG` 拼且必须 https，
   手机只报 `catalogId` + 参数值。不支持动态注册的应用（如 HubSpot）手机上接不了，明说「去电脑上接」；手填 OAuth client（#697）
   留作独立的大件。
3. **撤销顺序处处一致：授权先删，目录行后删；对缺席服务关授权算幂等成功。** spec 原文 §6「关」与 §7「断开」写的是先删目录行，
   §6.1 桌面写的是先撤授权，互相矛盾。取后者：半路失败时留下「目录行在、授权没了」（团队设置页看得见、智能体拿不到刀、
   再点一次即清）；反过来留下的是「目录没了、授权还在」的暗门，谁都看不见。接入方向相反——**箱先于目录**（没有箱的目录行
   会展示一台用不了的应用）。为让「再点一次即清」成立，`POST /cloud/grant {on:false}` 对箱里已经没有的那台回成功
   （目标状态已达成），而 `on:true` 仍 404；不这么做，桌面撤回就得靠匹配错误文案去认「已经没了」（与路由 404 同文案），
   一次断开中途失败的应用会让桌面撤回永远卡死。`DELETE /px/v1/cloud/:id` 同理：箱里已经没有这台时回成功（终审 M2），
   手机上「断开」只做完一半时再点一次才真能把剩下的目录行删完。手机「借给团队」打开时目录行写失败，把刚开的授权关回去
   （尽力而为，抛的仍是目录行那个错，终审 M3）——否则留下的是界面上「借给团队」关着、授权却开着的那条暗门。
4. **runtime 的工具名封顶 64 字符，尾部带哈希。** `px_<uid8>_cloud-<id>_<tool>` 比桌面那条多 6 个字符，而 `pxTools.ts` 的
   `safeName` 从来没管过长度：超过 64 的工具名会让整次请求被模型厂商拒掉（一轮直接失败，不是少一把刀）。所以 spec 原来写的
   「runtime 不改、不用重新部署」不成立，改为工具名封顶（超长时截断加哈希尾，仍确定性、可回到原工具名调用），
   **runtime 要重新部署一次**。
5. **续期结果三态。** `refreshCloudOAuth` 回 `ok` / `dead` / `transient`：408 / 429 以外的 4xx 或凭据材料缺失 = `dead`，
   标 `needs_login`；网络 / 超时 / 5xx / 408 / 429 / 回包读不懂 = `transient`，**不标**任何东西，这一次调用回 502 「这个应用暂时连不上，稍后再试」——
   凭据没有任何证据说它坏了，不许因为一次抖动就让人重登。读改写时比对 `refresh_token`：别的请求已经换过就不覆盖。
   `needs_login` 的应用不进 `/grants` 的工具清单（智能体看不到一把必然失败的刀）；对没有授权的调用方，`needs_login` 与
   「这台不存在」同一句话，**不泄露存在性**。重新登录复用同一个 `serverId`，覆盖凭据与工具清单，授权保留。
6. **深链只是信号，手机从 `GET /px/v1/cloud` 渲染。** `mrotto://connector-done?...` 任何 App 都能构造，手机不信它带的内容，
   只把它当成「去重拉一次云端视图」的触发；成功与否、要不要提示，都以拉回来的无凭据视图为准。手机不存任何应用凭据；
   退出登录不清 `cloud`（凭据本来就只在云端）。

## 上线顺序

1. 部署 edge（`npm run deploy:edge` 或 `npm run release` 里那一步；自检看 `/healthz` 的戳）。不跑 migration。
2. 部署 runtime（决定 4 的工具名封顶）。
3. 跑探针 `npx tsx scripts/probe-cloud-oauth.mjs`：用 edge 的 https 回调逐条重跑目录里 OAuth 应用的前半段（发现 → 动态注册），
   FAIL 的按原因填进 `src/shared/mobileConnectors.ts` 的 `MOBILE_OAUTH_BLOCKED`，结果与日期写进 #1430 评论。
   **只在上线前跑一次**：注册会在约 47 家厂商那边真的留下 OAuth client。
4. 桌面发版（`cloud-` 行撤回走 edge）。
5. 手机打包。真机验：Notion（OAuth）、GitHub（token）、Context7（免登录）各接一次，智能体各调一次；借给团队后团队里的
   智能体调一次；断开后调用被拒；把其中一台的 refresh_token 手动作废后调一次，确认手机上出现「点一下重新登录」。

edge 必须先于桌面 / 手机、runtime 必须先于手机：反过来，新客户端会对着还不认识 `/px/v1/cloud*` 的 edge 报错，
或让智能体拿到超长工具名。

## 代价与已知未做

- 团队被解散 / 我被踢出后，`cloud` 里那条团队授权不会自动清（团队闸要在籍，不越权；手机详情页里那个团队也不会再列出来，
  所以也关不掉）。**我重新被拉回那个团队时，这条授权悄悄重新生效**，而团队的目录表里没有对应的行——团队设置页上看不见它，
  团队里的智能体却拿得到这把刀（终审 I-3）。故意没做「视图 / 调用时按在籍对账顺手清掉」：在籍查询走 Supabase，一次抖动
  就会被读成「不在籍」，而这个动作是删除——会把真实有效的授权无声删掉，比留着一条要重新入团才会生效的授权更坏。
- 桌面起名时保留 `cloud-` 前缀（终审 I-2）：设置页新建（`mcpServerIdError`）与智能体的 `mcp_configure`（只挡 upsert，删照删）
  都拒这种名字，目录安装撞上保留前缀时换成 `cloud_` 开头。原先这里写的「目前没有桌面路径会生成这种 id」**不成立**——两条路
  都能生成，生成之后桌面撤回会走 edge、本机那份授权 + 密封箱原样留下。所以 `withdrawConnector` 另做了一层纵深防御：本机台账
  里列着同名的就连本机那一半一起撤（顺序仍是授权先、目录行后）。挡不住的是闸之前就已经存在的 `cloud-…` 桌面托管服务：
  它在 `mergeEscrow` 里仍会与手机接的同名那台撞（先出现的赢），留待真出现。
- **智能体在团队会话里够得到我主场里的全部应用，哪怕我没借给那个团队（终审 I-4，#1431）。** runtime 取工具
  （`fetchGrantedTools`）与调用（`/px/v1/call`）都不带这一轮所在会话的团队 id，edge 按「调用者与我同在籍的全部团队」算适用授权；
  我在团队 T 里起的那一轮，`workspaceOk` 里含我的主场，于是主场授权的每一台（手机接的应用都自动带主场授权）都成了 T 那条会话里的
  工具，输出落进团队共享的日志——「借给团队」关着也一样。审批仍到我这里、别人拿不到我的凭据，不是越权，但是越界。桌面主场授权
  本来就这样，手机接的应用把它放大了。修法方向：runtime 带上会话的团队 id，edge 只认这个团队的授权 + 好友授权。
- **授权链接可以被转发（终审 I-5，#1432）。** 手机拿到的 `authorizeUrl` 若被发给别人、由别人登录，那人的厂商凭据会落进
  **转发者**的箱（`state` 绑的是发起者的 uid）。桌面走本机回环回调，没有这个问题。缓解方向：edge 在跳去厂商之前先过一页
  「你正在把这个应用接到 某某 的 Mr Otto」，和 / 或把 pending 的 10 分钟缩短。
- 手机上接的应用在桌面团队设置页只标「手机上接的」，看不到连没连上；桌面接的应用手机上也只列不看状态（#1376 剩下那半）。
- 手机 v1 只借整台，不能按工具收窄；`tools/list` 不翻页（`nextCursor`）；同一份 access token 的 401 无法区分是新登录前还是
  后的（重新登录与并发调用交错时，极小概率把刚登录的标成 `needs_login`，下一次调用自愈）。
- 探针会在各厂商那边留下注册过的 client。
- 真机一次没跑过；OAuth 登录只能真机验。

## 推翻前提

- 目录里大部分 OAuth 应用支持动态注册且接受 https 回调——目录注释说的「实测过前半段」是用本机回环地址测的。换成 edge 的
  https 回调后逐条不成立的，标 `MOBILE_OAUTH_BLOCKED`，手机上明说去电脑上接；若一大半都不成立，这条路的价值要重判
  （改做手填 client 或经由桌面）。
- `sealed` 与 `cloud` 两个键不撞写：各有唯一写入路径，且 `cloud` 的读改写在不含外呼的临界区里。临界区里一旦混进外呼，
  这条前提就不成立。
- runtime 的工具名封顶已上线：手机接的应用的工具名比桌面那条长，没有封顶就会让整轮请求被模型厂商拒掉。
