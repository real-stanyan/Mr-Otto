# ADR-0075: OTA 更新走自研换包，不用 electron-updater

日期：2026-08-23
状态：已接受（issue #262）

## 背景

用户装完 1.0.0 之后没有任何升级通道——发新包只能重新传 dmg、让人手动装。
标准方案 electron-updater（Squirrel.Mac）在 macOS 上强制校验 Developer ID
签名，而本项目没有 Apple Developer 账号、只做 ad-hoc 签名（ADR-0026）——
autoUpdater 一启动就报签名错误，这条路在买账号之前是死的。

## 决策

自研换包更新，四件套：

1. **更新源 = GitHub Releases**（仓库 public，API 免鉴权）。每个 Release 三个
   资产：dmg（首次安装）、`-arm64-mac.zip`（换包下载）、`SHA256SUMS`。
2. **主进程更新器**（`src/main/updater.ts` 编排 + `updaterCore.ts` 纯逻辑 +
   `updaterHost.ts` 真实依赖）：启动 30s 后 + 每 6h 查 `releases/latest`，
   有新版就静默下载 zip 到 `userData/updates/`、按 SHA256SUMS 校验、
   `ditto -xk` 解包待命。**换包只在用户点「重启更新」后发生**：spawn detached
   脚本 → app 退出 → 脚本等进程消失 → 旧 .app 改名 `.app.bak` → 新 .app 移入
   → `open` 拉起。`.bak` 留作手动回滚。
3. **降级路径**：App Translocation（只读路径运行）或 .app 父目录不可写时，
   不尝试自动换包，只提示新版 + 一键开 Release 页。开发模式整个更新器不启用。
4. **发布 = 本地脚本**（`scripts/release.mjs`，`npm run release -- patch|minor|major`）：
   强制 main + clean → `npm version` 升版打 tag → `dist:mac`（dmg+zip）→
   生成 SHA256SUMS → `gh release create` → push。单人项目，本机就是唯一构建
   环境（Swift island + native 模块），不引 CI 发布管线。

## 为什么能绕开 Gatekeeper

quarantine 标记是"浏览器等下载器"打的；app 自己用 fetch 落盘的文件没有这个
标记，换上的新 .app 按本地程序对待，不再触发首次放行流程。这正是首次安装
要手动 `xattr` 而 OTA 之后不用的原因。

## 信任边界（明确接受的风险）

- SHA256 校验只防**下载损坏**：校验文件和 zip 同源（同一个 Release），攻破
  GitHub 账号的人两个都能换。真正的防篡改要靠签名公证——买了开发者账号后
  整个自研方案应被 electron-updater 替换（见下）。
- HTTPS + GitHub 账号安全是全部的信任根。
- 换包非原子：脚本在 mv 失败时把 `.bak` 挪回去，最坏留下一份能跑的旧版。

## 什么时候推翻本决策

买 Apple Developer 账号、接上公证（ADR-0026 同时作废）那天：
electron-updater + 正式签名从各方面优于本方案（差量更新、原子换包、
系统级信任链），届时删掉 updater 三件套换标准件，Release 资产形状照旧可用。

## 替代方案

- **提醒式更新**（只提示 + 开下载页）：最稳但每次升级都要用户手动 xattr 放行，
  体验倒退，作为降级路径保留而不是主路径。
- **现在就买开发者账号**：99 USD/年，MVP 阶段不掏；决策上面已留好回头路。
