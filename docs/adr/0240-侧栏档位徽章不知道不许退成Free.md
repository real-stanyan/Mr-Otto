# ADR-0240：侧栏档位徽章 —— 「不知道」不许退成「Free」，每档一个颜色两处共用一张表

- 状态：已接受
- 日期：2026-09-07
- Issue：#1030
- 相关：ADR-0239（账号页那张订阅卡，Free 的定性与 warn 横幅）、ADR-0217（`workspaceAccess`
  为什么必须有 `unknown` 一态）、ADR-0209（同一扇窗两个界面不能给出两个数）、issue #865
  （canceled 算没订阅）

## 背景

维护者要求：侧栏左下角用户名右边显示当前档位，Free 灰 / Lite 绿 / Pro 蓝 / Max 橙。

档位这件事此前只在账号页出现一次（订阅卡的档位行）。搬到侧栏之后它变成**常驻**的，
于是两个原来不必回答的问题冒出来了：还没查到的时候画什么、同一个档在两块屏幕上
是不是同一个颜色。

## 决定

### 1. `planBadge(me)` 回 `null` 表示「还没查到」，与 `"free"` 是两回事

`billing` 是主进程推上来的快照，冷启动那一瞬间渲染层手上必然是 `null`。把这一态
并进 Free，就是对着一个正在付 Max 的人说他没订阅 —— 与 ADR-0217 里
`workspaceAccess` 为什么不能把 `unknown` 并进 `no_subscription` 是同一条：
「不知道」和「没有」长得一样，而这两件事该说的话相反。

这枚徽章的两个失败方向不对称：**少画一格没人损失什么，画错一格是在撒谎**。
所以 `null` = 一格都不画。

### 2. 有订阅 / 没订阅的判据与账号页共用同一份

`planBadge` 里那三条（`plan === null`、`status === "none"`、`status === "canceled"`）
逐字就是 `BillingSettings` 原来那条分支条件，现在两处读同一个函数。
`canceled` 算没订阅是 #865 定的（退订过的人该看到价目卡，网关那侧
canceled→checkout 本来就放行，ADR-0203 决定 18）。

差别只在 `me === null` 那一格：账号页两种情形都画价目卡（一个画骨架一个画真价目），
侧栏必须分开。所以 `null` 的分叉留在调用方，判据本身只有一份。

`BillingSettings` 那条 `if` 里多留了一个 `me.plan === null`，它对 `planBadge` 是
多余的（已经算进 `"free"`）—— 留着是给 tsc narrowing 用，下面 `upgradeCards`
要的是 `PlanId` 不是 `PlanId | null`。

### 3. `past_due` 仍然报它原来的档

扣款失败不改变「你订的是 Pro」这个事实。「出事了」那句话由账号页那条 warn 横幅说
（ADR-0239 决定 2）—— 它带得动一颗「更新支付方式」按钮，一枚 24px 高的徽章带不动，
而一个没有出路的警报只会让人干着急。哪天要让侧栏也报警，它就得多一态，不是把
现有的颜色借去用。

### 4. 四色取现成的语义色 token，代价写在组件头上

`--muted-foreground` / `--ok` / `--brand` / `--warn`。四个都已经在亮暗两套主题里
调过对比度，自造四组十六进制等于把这件事重赌一次。

代价：`--warn` 在本仓别处的意思是**「出事了」**（扣款失败横幅、额度告警条）。
Max 借的是它的橙色不是它的语义。这条写进 `PlanBadge.tsx` 的头注，附带那句
「哪天要把警告橙调得更刺眼，先想起这里还挂着一个最贵的档」—— 那一天就是把 Max
拆出自己那格颜色的时候。

### 5. 账号页那枚徽章的颜色跟着改：从「past_due 橙 / 其余蓝」变成每档一色

原来的二元色档在四色方案下自相矛盾：Max 本身是橙的，于是「橙 = 扣款失败」和
「橙 = Max」压在同一个像素上，两个都说不清。改成每档一色之后，事故信号全部由
下面那条横幅承担（它本来就在，且带按钮）。

同时改成一个 `PlanBadge` 组件两处用。抽它出来不是为了省几行 JSX，是为了让
「Lite 是什么颜色」这个答案**只能有一份** —— 两张色表改一处忘一处不会报错，
只会让同一个账号在两块屏幕上是两个档。几何两处不同（侧栏 `sm` / 账号页 `md`）
是应该的：一个挤在 24px 的行里，一个在设置页的卡上。

### 6. 徽章紧贴名字右边，不靠右对齐到行尾

名字那格从 `flex-1` 收成 `min-w-0`，多出来的宽度让给后面一个 spacer。名字长到
要截断时，徽章跟着被推到远处比留在名字旁边更难读 —— 它说的是这个人的事。

### 7. 侧栏补一次 `loadBilling(false)` 种子

`billing` 的更新源是主进程 push（`onBillingChanged`）+ 登录态变化时的
`loadBilling(true)`。但**冷启动那一次推送可能早于渲染层订阅**，那一发就丢了，
`billing` 会一直停在 `null`，徽章永远不出现。

补的这一次是 `refresh: false` —— 主进程那侧只 `hostedQuota.snapshot()`，
不打网络（同 `NewWorkspaceDialog` 开窗时补拉的路子）。

## 后果

- 侧栏这一行多一个消费方读 `billing`；它此前只有设置页与工作区弹窗读。
- 账号页订阅卡的档位徽章视觉上变了（颜色按档 + 不再全大写）—— 这是 ADR-0239
  刚定稿那张卡上唯一被动的一格。
- 工作区档位闸（#1024）落地那天，这枚徽章是「你这一档有没有工作区」的现成锚点，
  但它今天**不表达能力**，只表达档位。
