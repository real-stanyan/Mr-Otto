# ADR-0154：lane 纪律从规则变机制——worktree 凭据、开工撞车检索、WIP 提交

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #632；ADR-0148（开工查撞车）、ADR-0149（一次性 worktree）、ADR-0150（lane 工具）、#543（stash 栈共享的那次事故）

## 背景

ADR-0148/0149/0150 之后，仓库侧还剩三条**规则有、机制无**——写在 AGENTS.md 里，但没有任何东西在动手那一刻拦住：

1. **worktree 复用**。ADR-0149 说「一次性」，但当时只是一句话。本仓真实发生过跨任务复用：同一个目录先后服务 #611 → #617 → 好友代理，每次 `git checkout` 换活。一个会切分支的长期 worktree **就是第二个主 checkout**，互斥等于关掉。
2. **stash 栈共享**。worktree 隔离文件和 HEAD，但 `.git` 共享——stash 栈也共享。这是模型唯一的漏点，#543 现象 2 就是另一条 lane 的 `pop` 弹走了不属于它的改动。
3. **开工查撞车**（ADR-0148）。纯靠自觉：要求下一班在领任务前搜同主题的 issue 和分支。

## 决策

### 1. worktree 带凭据，pre-commit 核对

`npm run lane` 建好 worktree 后，把分支名写进它的**管理目录**（`.git/worktrees/<名>/lane-branch`）——在工作树之外，不会被提交，也不会随分支走。

`pre-commit` 在 linked worktree 里多核一件事：当前分支 == marker 吗？对不上 = 换活干了，拒绝并指路 `npm run lane`。

**没有 marker 就放行**（手工 `git worktree add` 开的）。宁可漏判也不制造假阳性：一条误报会让人给整个钩子加 `--no-verify`，那等于把三条机制一起关掉。

### 2. 撞车检索挪到「开 lane」这个必经动作上

`npm run lane` 在建之前先搜同名 issue（**含 closed**）与分支，命中的直接摆在面前。

规则本身没变（ADR-0148），变的是**它挂在哪**：从「下一班记得去搜」变成「开 lane 时自动发生」。这是本 ADR 三条的共同形状——不新增义务，把已有义务挂到一个人本来就要做的动作上。

**只报告不拦**：判断「这条命中是不是同一件事」是人的活，脚本没资格替他决定。`gh` 没装/没登录/离线 → 安静跳过，绝不因此挡住开工。

### 3. `npm run wip` 把用 stash 的理由拿掉

git 没有 stash 钩子，拦不住。但可以让人不需要它：在自己的一次性 worktree 里，未提交的改动**没人碰得着**，「先存起来」一个普通提交就够，而且提交在自己分支上，别人的 `pop` 够不到。

输出里印撤销办法（`git reset --soft HEAD~1`）和一句为什么别用 stash。钩子照跑——在主 checkout 上被拒是**对的**，那正是 ADR-0149 要挡的事，不该被一条图省事的命令绕过去。

## 天花板（不假装解决）

- **切分支本身永远拦不住**：git 没有 pre-checkout 钩子。能拦的只有提交。marker 机制也一样——它在你提交时才说话，切的那一下它不知道。
- **`--no-verify` 永远能绕**：这是故意留的逃生门（ADR-0149）。机制给「忘了」兜底，不给「明知故犯」上锁。
- **stash 仍然可用**：只是多了一条更顺手的路。想用 stash 的人照样能用，规则那一句还在。

三条都是「降低发生率」，不是「杜绝」。写清楚比假装解决重要——下一班不该以为这些是密不透风的。

## 为什么不选另外两种

| 候选 | 否决理由 |
|---|---|
| `post-checkout` 钩子检测换活、自动切回去 | 自动改用户的 HEAD 是比问题本身更危险的行为。而且 `post-checkout` 是事后的，切已经发生了 |
| 把 marker 写进工作树里的文件（`.lane` 之类） | 会被提交、会随分支走、会进 diff。管理目录才是「属于这个 worktree 而不属于这份代码」的正确落点 |

## 后果

- 接受：`npm run lane` 多一次 `gh` 调用（几百毫秒），离线时无声跳过。
- 接受：手工开的 worktree 不受 marker 保护——想要保护就用 `npm run lane`。
- 接受：多两个脚本入口（`wip`）要维护。
