# ADR-0249：云会话里 agent 干活的痕迹只剩一枚**输入指示器**——步骤折叠头撤掉，接力 @ 空了那句系统旁白也撤掉

## 背景

那张截图上，一条 agent 回复的上下各挂着一行小灰字。两行都是**机器的内务**，读者是「工作区里各行各业的人」（ADR-0235 的原话），而不是在读一份审计日志：

- 上面那行是 ADR-0229 的折叠头。它报的是**干活的量**（几步、几次工具调用）——一个读者既不能据此判断进度、也不能据此做任何事的数；「一步一次工具调用」尤其是句废话。
- 下面那行说「@ 了 4 个名单里没有的名字」。写下那几个 @ 的是**模型**，不是人。

ADR-0229 当时明确**否决**过「隐藏干净、连折叠行都不画」，理由是本仓有条纪律：「即使模型这一轮一个字没说，用户也能看见它干了什么」。那条纪律成立的前提是——**没有别的东西在说「它在忙」**。这次维护者给的那枚输入指示器正好补上了这一格，前提不再成立，所以否决可以翻。

## 决策

### 1. 中间步骤整段不上时间线，判据合进 `hiddenFromCloudTimeline`

`foldAgentSteps` / `agentStepsSummary` / `AgentStepsFoldRow` / `ToolActivityLine` 全删。留下的只有 `isAgentStep`（「要了工具的、或一个字没说的 `assistant_message` = 步骤」），它成了 `hiddenFromCloudTimeline` 的第 ⑥ 条。

**为什么合进那一个函数**：改动前渲染循环要连问两道——`hiddenFromCloudTimeline(e)` 与 `folds.hidden.has(e.seq)`。同一个问题（「这一行画不画」）两份判据，迟早分家。合完之后 `foldAgentSteps` 返回值里剩下的 `hidden` 恰好等于 `{e : isAgentStep(e)}` 这个纯谓词——那台状态机的全部存在理由就是**给折叠头算摘要**，头没了，机器也不用留。

顺带由构造保证掉两条死支：`AssistantMessageRow` 从此只可能收到「有正文且没要工具」的那一条，于是 `hasText` 判断和 `toolCalls.map` 两段永远跑不到，删（同 ADR-0214 那条纪律——把「只有一个」变成结构上的事实，而不是两处条件对齐）。

### 2. 等待过程改用 assistant-ui 的输入指示器，长在回复要落的位置上

`src/renderer/src/components/elements/typing-indicator.tsx` 是 registry 抄件（改动一览写在文件头，同 `agent-status.tsx` 那批的规矩）。唯一一处非机械改动：`aria-label` 从写死的 "Assistant is typing" 开放成 `label`——云会话是**群聊**，同一刻可能有好几只在打字，读屏软件念四遍同一句等于没说。

消费方是 `PendingTurnLines`（时间线末尾那几行，事实来源仍是 `openTurns`，ADR-0220）。它现在**把两个状态画成两种东西**：

| `OpenTurn.state` | 画什么 | 为什么 |
|---|---|---|
| `running` | `SpeakerRow`（头像 + 名字）+ **`muted` 气泡里一枚 bare 输入指示器** | 那只 agent 此刻正在攒话。气泡与 `AssistantMessageRow` 那张**逐字同款**：答案落下来时人看到的是同一张气泡里点变成了字，不是一个东西消失、另一个东西出现 |
| `queued` | 照旧一行小灰字「广告 排队中…」 | 它一个 token 都还没跑。给它画打字气泡就是说了一句假话——#722 那个撒谎的勾的一般形式 |

两者的分别因此是**结构性的**（有没有气泡），不是改动前那套「跳的点 vs 不跳的点」——后者在一屏里要盯着看才分得出。

「停止」挪到名字那一行。`queued` 那支不画它不是漏了：`stopButtonRows` 本来就只收 running，改动前那行上的判断永远是 false。

### 3. 接力里「@ 了名单外的名字」那条系统旁白撤掉；`say()` 那条同名的孪生兄弟**留着**

两条话字面几乎一样，判据只差一个词：**谁写的那个 @**。

- `relayAfterTurn` 那条（#957 A-6）：写的是**模型**。群里没有任何人做错了事，也没有任何人在等一个不会来的回复——一只 agent @ 了不存在的名字，外部表现与它压根没 @ 任何人完全同形。留着只是给时间线加一行没人能据此行动的内务话，而且它是**模型可见**的（`chat_message` 在 `agentView` 里是 `keep`），下一轮的模型读到的也是同一句废话。**删。**
- `say()` 那条（「有 N 个点名在名单里找不到」）：写的是**人**。他刚 @ 完就会开始等一个永远不来的回复，那句话是他唯一的信号。**留。**

删掉它连带删掉了围着它搭的那一整套栏杆（只回显数量不回显 token 原文、降级名单不说话）——那套东西守的是「一只 agent 能以系统的名义对全场说话」这个面（#957 E2-3），面没了，栏杆也就不用留。相应的三条用例没有删，改成守更强的那句：**一条署名系统的发言都不落**（判据挂在事实上，不挂在会改的文案上）。

## 否掉的选项

| 选项 | 为什么不 |
|---|---|
| 折叠头保留、只是默认更淡 | 维护者要的就是「不用显示」；而且淡到看不见的东西还得维护一份文案（同 ADR-0246 对「悬停才出」的否决） |
| 在渲染层按文案匹配把那条系统旁白藏掉，日志照旧落 | `chat_message` 没有可用的判别字段，只能正则匹配一句带插值的中文——文案一改闸门静默失效，而这类静默失效正是本仓反复付账的那种（`daemon` 看门狗那条同理） |
| 给 `chat_message` 加一个「内务」标记，渲染层照它藏 | 要改的仍然是 runtime（同样要重新部署），却换来一个新字段 + 一处要长期维护的表态；而这条话本身没有留下来的理由 |
| `queued` 也画打字气泡，靠动画速度区分 | 见决策 2 的表——那是撒谎的勾 |
| 指示器画成 registry 默认的 `bubble` 变体（`paper` + 全圆角） | 那是第二种气泡外观，摆在 `muted` 气泡正上方，读起来像另一类东西；这里要的恰恰是「同一张气泡」 |
| 给指示器加入场动效 | 本仓的时间线是刻意静止的界面，没有入场/交错动效这一档预算（同 `agent-status.tsx` 改动 ②） |

## 已知代价

1. **工具调用在云会话时间线上从此没有任何痕迹**。跑了十条 bash 的一轮，群里看到的是「一枚打字气泡 → 一段答案」。`turn_ended{error}` 那行还在，被拒的审批也还在（ADR-0235 ③）——但一轮**只跑工具、一个字没说**且顺利收口的 turn，收口后什么都不留。这是维护者点名要的形状，不是漏做。
2. 一只 agent 落下最终答案到 `turn_ended` 之间有一个极短的窗口，答案与打字气泡同时在屏上（`openTurns` 要 `turn_ended` 才收口）。改动前的「正在回复…」有同样的窗口，这次没有变好也没有变坏。
3. **接力 @ 空了这件事在界面上完全无声**，只剩 runtime 那侧的行为（不接力）。真要查是哪一棒断了，得读日志里那条 `assistant_message` 的正文。
4. 决策 3 落在 `services/runtime/`，**要重新部署 VPS daemon 才生效**（#791 那条老账：runtime/edge 的部署不跟发版走）；决策 1、2 跟桌面发版走。两半各自生效，中间那段时间里那条系统旁白还会出现——它只是一行字，不构成半成品状态。
5. 真机没验（同这一批其余几条）：要看的是「一只 agent 在跑时那枚气泡真的在跳、答案到了就地换成字」，以及深色模式下 `bg-foreground/40` 的点在 `muted` 气泡上对比够不够。
