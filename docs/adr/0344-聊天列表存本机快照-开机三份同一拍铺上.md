# ADR-0344：聊天列表存本机快照，开机三份同一拍铺上

日期：2026-10-04 · issue #1471 · 维护者：「现在软件开机，会出现对话框加载慢，一个一个往出蹦，做成本地存储」

## 背景

手机「聊天」列表由三份数据拼成：主场（智能体私聊 / 群 + 最后一句）、团队群（+ 客人群 + @ 提醒）、朋友（+ 最近消息）。
三份各自从网上拉、各自先后到，而列表只等主场那一份就开画，于是开机时先出现几行，再一行一行插进来。

## 决定

1. **存一份按账号的本机快照**（`src/shared/inboxCache.ts` 编解码 + `mobile/src/inbox/inboxCache.ts` 接线；存储同聊天页缓存
   ADR-0334 用的 `expo-sqlite/kv-store`）。开机读一次，三份同一拍铺上；网上那份到了再整份替换。三份任一变了就防抖 1 秒存一份。
2. **缓存永远只是「还没拉到之前」的替身**：网上那份已经到了（`loaded`）就不铺；版本 / 账号对不上、读不出、形状不对一律不用。
   宁可多等一次网络，也不画上一个账号或旧形状的列表。读完快照之前不存，以免开机那一刻的空状态把好好的快照先盖掉。
3. **退出登录清掉这个账号的那一份**（本机数据跟着账号走，ADR-0187 / 0334）。
4. **列表等三份到齐才一起画**，第一次装上没有快照时最多等 2.5 秒（`FIRST_PAINT_CAP_MS`），过了就有什么先画什么。
5. 朋友的最近消息只存最新 300 条（列表只要最后一条与未读数）。

## 代价

- 开机那一下画的是上一次的样子：期间别人发的新消息，要等刷新回来才出现（通常一两秒）。
- 快照存了智能体名册、群名、最后一句的摘要和朋友最近消息的正文，跟聊天页缓存同一个级别；退出登录即清。
- 纯 JS 改动，走热更新（ADR-0340）。真机没跑过（要登录）。
