# ADR-0130：项目指令焊进围栏 system，而不是加进 compact 的重注入名单

> 原为 ADR-0129 —— 合并前 main 上先落了同号的「退掉 damian 的 VPS」（ADR-0074 的改号规矩）。commit 信息改不了，这行是让旧引用还能解析的那把钥匙。

- 状态：已接受
- 日期：2026-08-26
- 关联：issue #527（发现）、#353（项目指令注入）、#524 / #525（用量口径）、ADR-0066（skill 随清场重注入）

## 背景

`project_instructions` 事件**整个会话只落一次**（`agent.ts`，新建会话时；resume 不追加，不改写历史会话的模型视野）。投影层此前把它注入成一条 **user 消息**。

而 `context_compacted` 的投影是清场重来：`messages.length = 0`，只把围栏 system 消息抬回来，再依次注入摘要、**已启用的 skill**（ADR-0066）、当前请求原文。

于是：**压过一次之后，AGENTS.md / CLAUDE.md 就永久离开了上下文**——除非摘要模型恰好复述了它们，而那不是能指望的事。

不对称在通道上，不在决定上：记忆（`memory_loaded`）是焊在 `systemMessage.content` 后面的，system 幸存它就幸存；项目指令走的是 user 消息那条路，所以死。没人决定过项目指令该被压掉，它只是掉进了另一条通道。

本机日志里 `context_compacted` 一共 6 次，压得最多的那个会话（5 次）是 #353 之前的老日志、根本没有 `project_instructions` —— 也就是说**这个洞至今一次都没真咬到人**。但 k3 是 1M 窗口才不容易压，换 GLM-4.6 / Claude 那种 200K 窗口就压得动了。

## 决定

**把项目指令焊进围栏 system 消息**（`systemMessage.content += ...`），走记忆那条通道，而不是往 `context_compacted` 的重注入名单里再加一项。

没有围栏 system 消息时（旧日志缺 workspace / 裸装配）**退回 user 消息**，不整份丢掉——与记忆刻意不同：记忆在那种日志里是直接丢的（锦上添花），项目指令是任务的前提，宁可退化也不能没有。

## 理由

- **项目约定不是历史，是围栏。** compact 压的是"发生过什么"，不该压"这个工程的规矩是什么"。后者跟工作目录认知（`systemPromptText`）同一性质，而那一条本来就在 system 里。
- **加进重注入名单只修当前这一处。** 名单是枚举：下一个新增的注入类事件（又一种"每轮都该在"的东西）还会掉进同一个坑，然后又要发现一次、修一次。焊进 system 是让它**天然免疫任何清场**，不依赖清场那段代码记得它。
- **代价可接受。** 上下文里多出的 token 一个都不多——它本来就每轮都在（本仓自己那份 24K 字符 ≈ 6.4K token），只是换了个位置；换了位置反而更靠前、更稳定，prompt cache 的前缀不会因为它挪动而失效。
- 摘要提示词里"请保留项目约定"那条路被否掉：把"保没保住"交给摘要模型是不确定的，而这件事必须确定。

## 代价与影响

- **投影字节变了**：项目指令从"第 N 条 user 消息"变成 system 尾部的一段。既有会话下一次投影就换了形状——这是刻意的，不是 regression。`tests/session/deriveMessages.instructions.test.ts` 钉住新形状。
- **用量口径跟着改**：`contextEstimate.instructionsTokens` 不再在 `context_compacted` 处截断（ADR 之前那版会在压缩后报 0）。留一处已知偏差：旧日志 + 压过 + 缺 workspace 三件套同时成立时会多报一份——不为这个把口径拆成两套尺子。
- 弹窗仍然把「项目指令」单列一栏（#524），尽管它现在物理上住在 system 消息里：这一栏回答的是"每轮固定要付多少"，把 6.4K 混进"系统提示词"那 800 里同样是误导。

## 什么前提失效会推翻它

如果将来项目指令变成**会话中途可变**的东西（比如支持热重载 AGENTS.md、或按当前工作目录切换不同的指令集），"焊进 system 一次"就不再成立——那时它得变成可撤换的注入，重注入名单那条路反而更合适。
