# ADR-0105：输入框指令的判定只有一份

- 状态：已接受
- 日期：2026-08-25
- 关联：issue #438

## 背景

`$skill` 这套语法有两头：输入框里把它**画成 chip**（`ottoDirectives.ts` 的 `makeFormatter.parse`），回车时把它**认成指令头**（`App.tsx` 的 `submit()`）。两头是各写各的：

- 画：扫整串找 `$`，名字在已安装名单里就画
- 发：`if (text.startsWith("$"))` —— 只认行首

于是「用**$apple-design** 重新设计右边的布局」在输入框里亮着像被认出来了，回车却按纯文本发走。模型收到一个它不认识的 `$apple-design`，只能猜：去搜历史会话找这个 token 的定义、找不到、再回头问用户要什么风格。全程假动作，而用户看到的界面从头到尾都在说「认出来了」。

## 决定

**同一个 sigil 的判定只有一份实现，画和发共用它。**

具体到 `$skill`：抽出 `findSkillDirective(text, skillNames)`，和 `makeFormatter` 共用 `readName`（同一套「一路吃到底再回头比名单」的最长优先规则）和同一份已安装名单，扫全串。`submit()` 调它，不再自己解析。

两条附带的语义：

- **正文 = 原文摘掉 `$名字(参数)` 这个 token，别的字一个不删**。「用$apple-design 干活」的正文是「用 干活」。摘完只把接缝处的连续空白折成一个。
- **第一个命中的名字算数**，一句里写两个，后面那个留在正文里当字面量。

行首那条老路逐字节不变：token 在最前面，摘掉再 trim 等于旧的 `slice(space + 1)`。

## 理由

反方案是让画的那头对齐发的那头（`$` 只在行首才画 chip）。它同样能消掉不一致，而且更保守。没选它，因为它把用户这次的写法判成错的、只是让错误更早可见；而 skill 名在已安装名单里、用户又特意打了 `$`，当指令是唯一合理解读 —— 正文里真要提到 skill 名，本来就该写引号而不是 `$`。

更要紧的是这条：**界面骗人比功能没生效更坏**。功能没生效用户会重试，界面说生效了用户会去怪模型 —— 这次就是，模型被逼着做了三步假动作，看起来像它笨。任何「有高亮预览 + 有解析」的语法都该只有一份判定，这是本 ADR 想立下的一般规则，不止 `$skill`。

## 后果

- 新增 `findSkillDirective`，`submit()` 的解析逻辑搬进它。`tests/renderer/ottoDirectives.test.ts` 里有一条**锁步测试**：同一批文本，`parse` 画成 chip 的和 `find` 认得出的必须一一对应 —— 两头再分家就在那里红。
- `tests/e2e/skillDirective.e2e.ts` 从真输入框打字验到假模型收到的请求体（skill 正文有没有进 messages）。已实测：撤掉 `App.tsx` 那半边它就红。
- 顺带修好：`$名字(带 空格 的参数)` 现在能用了。旧写法在首个空白处就把 token 切断，参数里不能有空格。
- 仍然管不了的：名字打错**且不在行首**（`用$aple-design …`）照旧按普通文本发走，没有名单可比对。但 chip 也不会亮 —— 用户看得见它没被认出来，这正是本 ADR 要的那个性质。
- `/命令` 和 `@路径` 暂未收进同一套判定：`/` 本来就只在行首有意义（它是本地动作不是注入），`@路径` 没有名单、靠形状判定（见 ottoDirectives.ts 的注释）。真要统一，得先给它们各自想清楚"一份判定"是什么形状，不在本 ADR 范围内。
