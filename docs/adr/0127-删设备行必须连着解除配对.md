# ADR-0127：删设备行必须连着解除配对；一份安装 = 一台设备

- 状态：已接受
- 日期：2026-08-26
- 相关：ADR-0094 / 0095（远程投影与 TOFU 配对）、
  `src/shared/remote/devices.ts`、`src/shared/remote/deviceLabel.ts`、
  `supabase/migrations/0011_remote_devices.sql`

## 背景

`devices` 目录里出现了两行一模一样的「iPhone」，同一台手机，两个不同的安全码。

不是 bug。身份存在 `expo-secure-store`（iOS Keychain），Keychain **按 bundle id 隔离**：
Expo Go 是 `host.exp.Exponent`，自己打的 app 是 `com.stanyan.mrotto.mobile`。新 bundle
读不到旧条目，`mobile/src/identity.ts` 的 `fresh()` 就地生成新的 deviceId 和新的密钥对
——**新的一行本来就该出现**。安全码是 `fingerprint(我的公钥, 对端公钥)`，对端公钥换了，
六位数当然跟着换。

真正的毛病有两个，都在目录这一侧：

1. 手机端把 label 写死成 `"iPhone"`（桌面用的是 `hostname()`），两行长得一样
2. **目录里没有过期这回事**。卸载不会通知任何人，`last_seen` 只是一个时间戳。
   行只会堆着

## 决定

### 1. `forget(deviceId)` 删行，**删到已配对那台时连 pin 一起清**

这条是删除这个动作的意义所在。行删了而 pin 还在 = 「删掉了但仍然信任它」——
那不是撤销，只是从列表里藏起来，而用户按下删除时想要的是前者。
为此 `PinnedPeerStore` 加了 `unpinPeer()`，两端的实现都跟上。

顺序是**先删库、再清 pin**：删失败就整个不生效。反过来的话会留下「没配对、也没删掉」
的中间态——用户看见的还是同一行，却已经连不上了，而且没有任何提示解释为什么。

RLS 不用动，migration 0011 里 `devices_delete_own` 早就有。

### 2. 删的是**目录行，不是设备**

装着 Mr Otto 的设备下次打开配对屏会重新登记自己，行会回来。这是对的：目录的语义是
「现在有哪几台」，不是「曾经有过哪几台」。能被真正清掉的是卸载了的那些安装。
UI 文案必须把这句说出来，否则「删了又回来」会被当成 bug。

### 3. 一份安装 = 一台设备，label 要让人分得出

`src/shared/remote/deviceLabel.ts`：真名 → 机型 → 「手机」逐级降级，
`（Expo Go）`/`（模拟器）` 只在需要区分时加。两条不查就会写错的：

- **iOS 16 起 `Device.deviceName` 读不到真名**。没有 user-assigned-device-name 权限的
  app 拿到的是机型通名「iPhone」——直接用它等于什么也没改。所以读到通名要退到 `modelName`
- 区分 Expo Go 用的是 `Constants.appOwnership`，不是官方推荐的 `executionEnvironment`。
  后者把 Expo Go 和 dev-client 归成同一个 `storeClient`，而要分的恰好是这两个。
  代价：`appOwnership` 标了 deprecated，某个 SDK 之后可能没有，届时退化成不加后缀

拼接逻辑放共用层（能测），平台读数留在 `mobile/src/deviceLabel.ts`（要真机才有）。

label 只进 Supabase 的 `devices` 表，**不进 hello 帧**——hello 是明文过中继的，
所以那边用的一直是随机 deviceId（同 ADR-0095 的理由）。

## 代价

- `DevicesApi` 和 `PinnedPeerStore` 各多一个方法，两端四处实现都得跟上。
  换来的是 `forget` 只有一份，而「删了要不要解除配对」这个判断只写了一遍
- 手机端多两个原生依赖（expo-device / expo-constants），Expo Go 里都有，
  但自己打的 app 要重编一次

## 什么前提失效会推翻它

- Keychain 变成跨 bundle 共享（App Group / keychain-access-groups）——那时同一台手机的
  多份安装可以共用一个身份，重复行从源头就没有了，label 后缀和删除入口都只剩清理旧数据的作用
- 目录改成有 TTL（比如 90 天不上线自动删）——那时手动删就退化成一个快捷方式
