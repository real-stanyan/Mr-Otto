# 0075 真机验收清单落成 e2e 用例（隔离的 HOME + 假模型）

## 背景

四张「真机验收」清单（#123 / #142 / #147 / #169）在 issue 里挂了三个多月，
共同的卡点写的是同一句话：**「实施 agent 跑不了 Electron GUI」**。ADR-0058 已经
判过这件事的根因是缺第三层验证，并落了 `tests/e2e/` 的两条冒烟。但清单本身没动
——它们仍然是给人照着点的。

跑得了。Playwright 起的是真 Electron、真主进程、真磁盘。缺的从来不是能力，是两样
让「照字面跑清单」变得安全、确定的东西。

## 决定

### 1. 隔离靠换 `HOME`，不靠 mock

清单里有「确认文件落在 `~/.mr-otto/agents/`」这类条目，照字面跑会往开发者本人的
配置目录里丢文件、甚至覆盖同名定义。所以 `tests/e2e/harness.ts` 起 app 时把 `HOME`
换成一次性临时目录：主进程所有配置路径都走 `configDir(homedir())`，而 node 的
`os.homedir()` 在 POSIX 上优先认 `$HOME`，于是 `~/.mr-otto/agents`、`~/.claude/agents`、
skills 一起搬进临时目录。**注意 Electron 自己的 `app.getPath("home")` 不认 `$HOME`**
（走 NSHomeDirectory），所以 userData 另外用一次性随机 `OTTO_PROFILE` 隔离，跑完
两边都删。

不 mock 文件系统：mock 掉之后「文件到底落在哪一层」这件事就又变成读代码了，而那
正是清单要验的东西。

### 2. 「派活」那一段接一台假模型

清单里最值钱的几条（派活卡、点正在跑的那一下、中断、子会话日志里有没有前置词）
都要求模型真的调一次 `task`。对着真厂商跑要钱，而且**不确定** —— 模型今天愿意调
`task`、明天说「我直接帮你看吧」，验收就成了掷骰子。

`tests/e2e/fakeModel.ts` 是一台只讲 OpenAI 方言 `/chat/completions` 的本机服务，
响应器拿到整个请求体自己决定这一轮吐什么。端点靠 provider 的 `*_BASE_URL` 顶掉
（`shared/providerCatalog.ts` 本来就为自建代理留了这个口子），所以从 `routeModel`
到 adapter 到 engine 到子会话落盘跑的都是真代码，假的只有对面那台服务器。key 一并
顶成假串：e2e 继承整个 `process.env`，开发机上真配着 `DEEPSEEK_API_KEY`，不顶掉
的话哪天 baseUrl 没生效真 key 就发出去了。

### 3. 判据下沉到「说谎不了」的那一层

清单原文常常是界面语言（「vim 里画面不歪」「看得清」）。落成用例时**验它的成因**，
不验它的观感：

- 「拖宽面板 vim 不歪」→ 从 PTY 里问 `tput cols`，不从 DOM 上量
- 「深浅色看得清」→ 断言文字色不透明、不与卡片底色同值 + 两张截图给人看
- 「子会话工具受限」→ 读假模型收到的那一份 `tools`，那就是模型看到的全部

### 4. 剩下什么给人

三类，写清楚理由，不含糊成「待验收」：

- **要真账号/真人的**：全新 Google/GitHub 账号走 OAuth（#123 的 #100）、两个互为
  好友的真账号（#169、#123 的 #94）
- **工具够不着的**：双击装好的 `.app` 点开终端 —— Playwright 的 `electron.launch`
  靠 `NODE_OPTIONS` 往主进程塞桥接代码，打过包的 Electron 明确忽略它，launch 永远
  不返回。改成钉住这条真正怕的静态事实（spawn-helper 在、可执行、ad-hoc 签名有效）
- **手感**：动效好不好看。截图能证明「没坏」，证明不了「好」

## 接受的代价

- e2e 不进 gate（要先 build，十几秒起步；打包那条要几分钟），仍按 ADR-0058：
  GUI 改动的 PR 贴它的结果
- 假模型让「模型会不会这么答」退出验收范围。那本来也不是这四张清单要验的东西
- 清单里有六条**已经过期**（验的是被 ADR-0052/0056 撤掉的功能、或内置子智能体加进来
  之前的行为）。落用例时按现状重写，并在用例注释里写明原文过期在哪 —— 清单不是
  规格，代码才是

## 推翻它的前提

如果哪天 e2e 的维护成本高到「改一行 UI 要修五个用例」，说明判据又贴回了观感层
（选择器绑在 class 上、断言绑在文案上），该退回去按「验成因」重写，而不是删掉这一层。
