# ADR-0186：turn 内的工具表只长不缩

- 状态：已接受
- 日期：2026-08-29
- 相关：issue #750、issue #6（工具表改成每 turn 现算）、issue #348（exposure 三态）、ADR-0184（目录扩到 82 条）

## 背景

用户说「看看我 Square 店铺里面有哪些商品」。水獭用 `mcp_configure` 把 Square 接上、
授权也过了，然后说：

> ✅ Square 已经接好了，授权也通过了。
> 不过新工具要等你的下一条消息才生效——你随便回一句（比如「好了」），我马上就把
> 店铺里的商品列出来给你看。

用户要的是商品清单，不是一次「请再说一遍」。

这不是模型犯傻：`mcpNewToolsNotice` 就是这么写的，而它这么写是因为实现确实如此——
`LoopEngine.rebuildTools()` 每个 turn 开头跑一次，turn 内工具表冻结。

## 那条冻结原本在保护什么

`LoopEngineOptions.tools` 的注释写着理由：

> 模型看到的声明表和 dispatch 时查的 toolsByName 必须是同一份。turn 中途换表，
> 模型按旧表发出的调用会在新表里查不到，收到一句"未知工具"。

这条不变量是对的，而且是最难查的一类失败——工具明明存在过。

但它只被**缩**破坏。**长**不会：加进来的名字不会让任何已经发出去的调用失效。
冻结是一把过宽的锁：为了防住"缩"，把"长"也一起禁了。

## 决策

`loop()` 每圈模型调用前跑一次 `refreshToolsKeepingNames()`：

- 以 provider 现在这份为准（`agent.ts` 的 `buildTools` 本来就是每次现算的）；
- **旧表里有、新表里没有的名字，一个都不删**，补回表尾。

于是：

- **新连上的 server，同一个 turn 的下一圈就能用。** 用户不用再说一句"好了"。
- **掉线那台的名字还在。** `available()` 把它挡在声明表外，模型看不到它；万一
  真被调到，报的是它自己那句错误（"连不上"），而不是"未知工具"——后者会让模型
  以为自己记错了工具名，然后开始瞎猜。

撞名警告只在 turn 开头那次 `rebuildTools()` 打。每圈打一次会刷屏，而那句话
每 turn 说一次是刻意的（一台 server 反复挂同名刀，用户该一直看得到）。

## 连带改掉的那句话

`mcpNewToolsNotice` 从

> 它们从**用户的下一条消息**开始才会出现在你的工具列表里——本轮请先把结果告诉
> 用户，不要在这一轮直接调用它们。

改成

> 它们**这一轮就能用**，不用等用户再说话——直接接着把用户原来要的事做完。
> 如果它们没出现在你的工具列表里，先用 tool_search 搜出来再调。

后半句不是废话：工具总数过阈值（`DEFAULT_DEFER_THRESHOLD = 12`）时新刀会被判成
`deferred`，那时它确实不在声明表里，得先 `tool_search`。与其让模型撞一次再自己
想明白，不如两条路都说清楚。

`tests/tools/mcpConfigure.test.ts` 和 `mcpAuthorize.test.ts` 里各有一条断言钉着
老文案，跟着产品代码一起改了（AGENTS.md 的 L2 例行开发：测试与它跟随的产品代码
同一个 PR）。

## 代价

每圈多跑一次 `buildTools()`。那是几十个对象字面量 + `createMcpTools`（从 hub 的
内存快照现读），跟一次模型调用比可以忽略。

## 被否掉的路

- **让 `mcp_configure` 自己去戳 engine 刷新表**：工具反向依赖 engine，破坏
  「工具只依赖 ExecutionWorld」那条硬规则。
- **只在检测到"上一圈调过 mcp_configure"时刷新**：省不了多少（刷新本来就便宜），
  却要引入一个"谁有资格让表变脏"的名单——下一个能改工具表的东西出现时，
  这个名单就是下一个 bug 的藏身处。
- **turn 内彻底不冻结（整张表换掉）**：破坏那条不变量，见上。
