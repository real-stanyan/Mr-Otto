# 0007 — skill 库：提示词注入，快照落 skill_invoked 事件

日期：2026-08-17　状态：已采纳

## 背景

用户要求：一个页面查看本机已安装的 skill，以及聊天里的 `$` 指令手动选一个 skill
随任务注入。AGENTS.md 的 MVP 边界写着"明确不做：插件系统"，需要先厘清 skill
算不算插件。

## 决定

1. **skill = 纯提示词包，不算插件系统。** 格式与 Claude Code 兼容
   （`<根目录>/<名字>/SKILL.md` + YAML frontmatter），注入 = 把 markdown 说明书
   拼进模型上下文。没有代码执行、没有扩展 API、没有生命周期钩子——"不做插件
   系统"的边界指的是可执行扩展面，原样成立。AGENTS.md 边界句加括号注明本 ADR。
2. **根目录两个，按序覆盖**：`~/.otter/skills`（原生，优先）、`~/.claude/skills`
   （兼容——用户已装的 skill 零迁移可用）。每次现扫磁盘，无缓存：skill 是用户
   随时增删的外部文件。
3. **注入落 `skill_invoked` 事件，content 存发送时刻的全文快照。** 位置在
   `user_message` 之前（模型先看说明书再看任务）；投影成 user 消息——中途插
   system 各家方言兼容性参差，与 compact 摘要同一决定（见 deriveMessages）。

## 备选与否决

- **不落盘，发请求时临时拼 prompt**：违背硬规则"model-visible means logged"，
  模型看到过的东西日志推不出来，回放缺一块。直接排除。
- **事件只存 路径 + 内容 hash**：事件瘦，但日志不再自包含——skill 文件后来被
  改/被删，重放就还原不出当时模型看到了什么。hash 只能证明"变了"，救不回原文。
- **workspace 级 OTTO.md 自动注入**：更轻的方案，另一条产品路线，不冲突，
  将来可加（届时同样走事件快照）。

## 代价（接受）

- 常用 skill 的全文在每个用到它的会话日志里各存一份，数据库随使用变肥。
- 投影层压缩只截老区的工具输出/参数，skill 注入永不折叠——大 skill 常驻
  上下文直到 /compact。
