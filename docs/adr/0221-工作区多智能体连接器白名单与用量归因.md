## 背景

1a/1b（ADR-0219/0220）之后，一个工作区里站着若干只 @ 得着的 agent，各有名字、提示词和
型号白名单。**它们此刻共用工作区里贡献的全部连接器，花的钱也全部记在 owner 头上而分不出
是谁烧的**——两个缺口，一个是授权面，一个是账面：

| 缺口 | 症状 | 为什么现在补 |
|---|---|---|
| 每只 agent 拿得到哪几台连接器 | `workspace_agents` 只有型号白名单，没有连接器白名单，一只只管写周报的 agent 也拿得到 Shopify 的下单工具 | 切片 5（agent 互相 @）之前必须有 |
| 每一笔花费是哪只 agent 烧的 | `usage_event` 只记 `user_id` + `workspace_id`，一条失控的接力链只看得到 owner 的周额度掉了一大块 | spec §10 原话：**先有那张用量表，再打开 agent 互相 @** |

顺带修掉 #945：云会话头部「模型」那一格拿 `model === null` 推断「@Agent 起不了 turn」，
而订阅用户走托管路照跑——那句话是假的，**且撒谎的方向是吓人的**：owner 会去配一把自己的
key，从此烧自己的 key 而不是订阅额度。它与切片 2/3 无关，只是同一分支同一 PR 一起做了
（维护者原话「#945,2,3 一起做了」）。

## 决策

### 1. 白名单两层都是「空 = 全给」，匹配只看 `serverId`

`src/shared/agentToolAllow.ts`（三端共用，只有类型 + 纯函数）：

```
顶层 []                      = 整池放行（拿得到工作区里贡献的全部连接器）
条目 { serverId, tools: [] }  = 这台服务的全部工具
条目 { serverId, tools: [..] } = 只给点名的这几个
```

口径与 `workspace_connectors` / `proxyShare.ts` 逐字一致（ADR-0151 的 `tools: []` = 整服务
放行）。**同一个字面量在相邻两张表里意思相反是最贵的那种不一致**——贡献连接器时勾的那张表
和分配给 agent 时勾的这张表并排住在同一个设置页里。

匹配**只看 `serverId` 不看 `hostUid`**：两个成员各自贡献了同一个 `serverId` 时两台都放行。
否决的是 `hostUid + serverId` 双键——界面上根本做不到分开授权（勾选行按 serverId 合并，
按 host 拆两行会让人以为能分开授权、实际做不到），而且贡献者换台机器 `hostUid` 就变了，
一份存量白名单会因为对方重装了一次 app 而静默失效。

白名单是「配错了」的护栏**不是越权闸**（spec §11）：真正的三道闸在 edge 的 pxGate
（身份 → 关系 → 白名单，ADR-0164），这一层只决定这只 agent 的工具表里挂哪几台。过滤落在
`services/runtime/src/sessionService.ts` 的 `cachedPxTools`（`filterGrantedByAllow(granted,
spec.tools)`）——`fetchGrantedTools` 的产物过一道，过滤后一个工具都不剩的服务不进结果
（engine 挂一台空服务没意义，还会在工具表里占一行）。

### 2. 「一台都不给」表达不了，所以表单层不许存出那种状态

`[]` 在线上是「整池放行」，于是「只用勾选的」却一台都没勾**不能存**——存出去就是把用户的
「都不要」翻译成「都要」。判据落在 `src/renderer/src/lib/agentToolsForm.ts` 的
`toolsDraftError`：`mode === "some" && buildAllow(sel).length === 0` → 「至少勾一台连接器，
或改回「全部连接器」」。

否决的是给编码引入 `null` / 哨兵条目来表达「一台都不给」。理由是决策 1 的同一条：那会让
`tools` 这一列在两张并排的表里各有一套语义，而**这个状态本身没有真实需求**——不想让一只
agent 碰任何连接器，删了它比给它一份空授权更诚实。代价只是用户得改回「全部」再存，多一次
点击。

### 3. 工具名只在**每个**贡献者都点了名时才列得出来；已撤回的残留勾选要画出来

`connectorChoices(ws)` 按 `serverId` 合并候选行，`toolNames: null` 表示「至少一个贡献者
整台放行」。那台此刻有哪些工具**本机快照里没有**（在 edge 的托管箱里，ADR-0197），所以那
一行只能整台勾。这是本切片最大的一处天花板，明写在代价段。

**已撤回连接器的残留勾选要画出来标「已撤回」，不静默丢**（`staleSelections`）。这只 agent
存量的白名单里点着一台已经从工作区撤回的 `serverId`：回填时它原样进了 `sel`，而
`connectorChoices(ws)` 里没有它、界面一行都不画——用户会看见「一个都没勾」却存不掉，或者
存下去后那条隐藏条目原样带走。静默丢更糟：那等于**替用户把一份他没碰过的授权收窄了**。
列出来渲染成一行、可取消勾，是 #722「撒谎的勾」那条教训的同一个形状——界面上看得见的
状态必须是真实状态。

### 4. `usage_event.agent_id`：带 id 不带名，空串 = 未归因

migration `supabase/migrations/0022_usage_event_agent_id.sql`（幂等，同 0018 的约定手动执行
一次）加一列 `agent_id text not null default ''` + 一条 `(user_id, workspace_id, created_at
desc)` 的索引（周用量表的查询形状）。runtime 调网关时随 `x-otto-on-behalf-of` 一起带
`x-otto-agent`（`services/runtime/src/hostedRoute.ts`，`AGENT_HEADER` 在 `src/shared/
billing.ts` 三端共用一份）。

**带 `agent_id` 不带名字**：名字随时会改，0021 把 `agent_id` 与 `name` 拆开正是为了这本账
不断。展示层现查名单换名（`workspaceUsageView.ts` 的 `agentNameOf`），查不到就回 id——同
`agentNameOf` 一贯的纪律，被删的 agent 在账上仍然是一行，不是消失。

**空串 = 未归因**，不是 `null`：桌面直连的请求、0022 之前的旧行都是空串，聚合时单列成
「未归因」一行。用 `not null default ''` 让「这一列一定有值」由数据库保证，省掉每个消费方
各判一次 null。

**tokens 列 = `prompt + completion`，不加 `cached`**：`cachedTokens` 是 `promptTokens` 的
**子集**（`llmGateway.ts` 计价时 fresh = `prompt - Math.min(cached, prompt)`），不是并列的
第三类——加进来就是把命中缓存的那部分 token 数了两遍。计划里那段代码块写错了，测试是对的。

编号取 **0022**（spec §7 预估的是 0023）：ADR-0074 那条「编号在合并前复核」对 migration
同样成立，切片 4 的记忆表顺延为 0023。

### 5. 周用量端点在 edge，在籍闸的编排是一个可单测的纯函数

端点 `GET /billing/v1/workspace-usage?workspace=<uuid>` 落在 edge Worker
（`services/edge/src/edge.ts`），**不做 Supabase RPC**：周窗起点要 owner 的订阅 +
`weekStartFor`，而那份逻辑只在 edge（`quota.ts`）。同一扇窗两个界面不能给出两个数——
ADR-0209 已经踩过一次。也**不碰 Quota DO**：DO 是限流用的投影，这里要的是归因，数据从
`usage_event` 现聚合（ADR-0203：钱的唯一事实是那张表）。

否决的是桌面直连 `usage_event`：RLS 只让本人读自己的行，成员读不到 owner 的账，而窗是
**owner 的**（工作区烧的是 owner 的额度，ADR-0217）——成员看到的「本周」就该是 owner 额度
页上的那个本周。

**四步编排（owner → 在籍 → 订阅周窗 → 拉行聚合）抽成 `usageAttribution.ts` 的
`fetchWorkspaceUsage(get, uid, workspaceId, now)`，`get` 是注进来的 PostgREST 读口。**
`worker.ts` 不进 vitest，编排留在那边等于**在籍这道闸零执行覆盖**，而它是这个端点唯一的
权限判断——安全闸不能只靠 tsc。worker 侧只剩一行
（`workspaceUsage: (uid, workspaceId) => fetchWorkspaceUsage(db.get, uid, workspaceId, Date.now())`）。

两条顺序上的判断：

- **先查 owner 再查在籍**，`not_found`（404）排在 `not_member`（403）前面。合成一个 404 的
  话，被踢出去的人看到的是「这个工作区没了」——那是另一件事，该做的动作也不一样。存在性
  oracle 是已接受的代价（知道一个 uuid 就能问出「这个工作区在不在」）。
- **只收真人 JWT**：`caller.source === "runtime"` 一律 403。平台身份代表谁都没意义——它不会
  来看设置页，同 checkout/portal 那两条的理由。

没订阅的工作区退回**滚动 7 天**（`usageWindowFor`）：那种工作区走自带 key，`usage_event`
里本来就没有它的行，窗口只是给界面一个日期范围。

### 6. #945：路由判定由 runtime 下发，协议进位 4 → 5

`welcome` 与 `config_result` 各多一格 `modelRoute: CsModelRoute | null`
（`{kind:"hosted", model}` / `{kind:"workspace"}` / `{kind:"blocked"}`），runtime 用
**与 turn 真正走的那条路同一份** `decideRuntimeRoute` 算好下发，渲染层不重算
（`src/renderer/src/lib/cloudModelStatus.ts`）。hosted 那一档带**实际型号**——退到网关第一款
时界面上该显示退到的那个。

否决的是让桌面自己拿 `billing.me` 判：那是**我的**订阅，而工作区走 owner 的（ADR-0217）。
一个没订阅的成员站在一个 owner 有订阅的工作区里，这条判据会把「跑得动」说成「起不了」。

`CS_PROTOCOL_VERSION` **4 → 5**。加字段照样进位是这份协议文件头注的既有约定：握手是精确
相等，桌面拿着 v4 连上 v5 的 runtime 会在 hello 那一步被明确拒绝，而不是收到一条它读不懂
的 welcome 之后静默少一格状态。代价是**两端一起发版**。

两处措辞上的裁定，都是「别把没发生的事说成发生了」：

- **`null` = runtime 探测这一步自己抛错**（`ownerOf` / 配置读取失败之类），**不是 edge 抖了**：
  `createHostedProbe` 把失败**缓存成「没有订阅」**而不抛，所以一次 edge 故障在这一格上表现为
  `blocked`（或有自带 key 时的 `workspace`），与同一分钟真跑一个 turn 得到的结论一致。初稿
  注释写的是「edge 抖了 → null」，那是过度声明；文案因此不往「探不到 / 连不上」那个方向写。
- **`modelRoute(workspaceId, ownerUid)` 由调用方递 owner**，实现里不再自己查一次：frameHandler
  这一层每条 welcome/config 都已经 `await` 过 `sessions.ownerOf`（一次未缓存的 Supabase 往返），
  实现里再查一遍就是同一帧上打两到三次——#915 那条 hot path 的同款教训。config 的失败路径
  **现探不预探**（`fail` 改 async）：预探等于每条 config 帧都为一条罕见路径付一次探测，而
  失败 = 一个字都没存、此刻的路由就是回执该说的那份。于是每条 config 帧恰好探一次。

### 7. 部署顺序：migration → edge → runtime

三步都做完之前，中间态必须无害，顺序是被这条约束定死的：

- **migration 先**：edge 先升级而列还没加，`settle` 落库会失败——而那条路径只记一行日志
  （钱的事实写不进去，DO 那份投影却已经动了）。
- **runtime 最后**：runtime 先带头（发 `x-otto-agent`）而 edge 没升级是**无害的**，多余的
  头被忽略，那几笔按未归因入账。
- **协议进位（决策 6）要求桌面与 runtime 一起发版**，与上面两步正交：桌面版本落后时是
  `version_mismatch` 明确拒绝，不是静默少一格。

## 否决的备选

| 备选 | 为什么否 |
|---|---|
| 白名单按 `hostUid + serverId` 双键 | 界面上做不到分开授权（勾选行按 serverId 合并），而且贡献者换机器 `hostUid` 就变，一份存量授权会因为对方重装 app 而静默失效。见决策 1 |
| 给 `tools` 引入 `null` / 哨兵条目表达「一台都不给」 | 同一个字面量在相邻两张表里意思相反；而且这个状态没有真实需求——删了那只 agent 更诚实。见决策 2 |
| 已撤回的连接器在勾选表里静默丢掉 | 等于替用户把一份他没碰过的授权收窄了；不画则是 #722「撒谎的勾」的一般形式。见决策 3 |
| 用量记 agent **名字**而不是 `agent_id` | 改名就断账。0021 把两者拆开正是为了这个 |
| tokens 列写成 `prompt + cached + completion` | `cached` 是 `prompt` 的子集（`llmGateway.ts` 的 `Math.min(cached, prompt)`），加上就是重复计数。见决策 4 |
| 周用量做成 Supabase RPC / 桌面直连 `usage_event` | 周窗起点要 owner 的订阅 + `weekStartFor`，那份逻辑只在 edge；而且 RLS 只让本人读自己的行，成员读不到 owner 的账。见决策 5 |
| 四步编排留在 `worker.ts` 里 | `worker.ts` 不进 vitest ⇒ 在籍这道闸零执行覆盖，而它是这个端点唯一的权限判断。见决策 5 |
| `not_found` 与 `not_member` 合成一个 404 | 被踢出去的人看到的是「这个工作区没了」，与真实情况指向相反的动作。见决策 5 |
| 桌面自己拿 `billing.me` 判「起不起得了 turn」 | 那是**我的**订阅，工作区走 owner 的（ADR-0217）。见决策 6 |
| `modelRoute` 加字段不进位版本 | 老桌面会收到一条它读不懂的 welcome 后静默少一格状态，而不是被明确拒绝。协议文件头注的既有约定 |

## 代价与天花板

| 面 | 结果 |
|---|---|
| 整台放行的连接器挑不了工具 | 至少一个贡献者 `tools: []` 时，那台此刻有哪些工具本机快照里没有（在 edge 的托管箱里），界面上只能整台勾。见决策 3 |
| 同名 server 无法只授其一 | 两个 host 各贡献了同一个 `serverId`，白名单只看 serverId ⇒ 要么两台都放行要么都不放。决策 1 的直接代价 |
| 用量表按 agent 不按会话 | 「哪只 agent 烧的」答得出，「哪条会话烧的」答不出——`usage_event` 有 `session_id` 但这张表不按它分组 |
| `model_usage` 本地事件仍无 `agentId` | 归因只落在 edge 那本账上；本机日志里那条用量事件没跟着加字段，桌面直连的花费仍然只能整体看 |
| 协议进位 | 桌面与 runtime 必须一起发版；老桌面连新 runtime 是 `version_mismatch`（明确拒绝，不是静默降级） |
| `parseAttributionRows` 静默丢坏行 | 一行坏数据不该让整张表 502——这是**展示面**，与 `pageAll` 那种「拿不全就报错」的取数面判据相反。理由写在函数头注里 |
| `hostedQuota` 缺 `get()` helper | `post()` 有、`get()` 没有，`workspaceUsage` 那条自己拼了一次 fetch；重复的那几行等下一个 GET 端点出现时再收 |
| `route.kind` 无穷举检查 | `cloudModelStatus` 里 `workspace` 与 `null` 两态共用 fallthrough，新加一档 kind 不会红。当前只有三档，加档时得记得回来看 |
| 存在性 oracle | 403/404 分开 ⇒ 知道一个 uuid 就能问出「这个工作区在不在」。已接受，见决策 5 |
| 手工冒烟 | **一次都没跑**。前置条件是登录账号 + 有订阅的工作区 + VPS 上活着的 runtime daemon + 手动执行过 0022。纯逻辑有单测覆盖；勾选表的渲染、用量 tab 的拉取时机、头部那一格的实际文案全部 UNVERIFIED |

## 推翻它的前提

- **若用户成规模地要在整台放行的连接器上挑工具**（决策 3 的天花板），修法是桌面多一条 IPC
  去 edge 拉 `toolDefs`——`pxCloudClient.fetchGrants` 已经有一半。届时 `ConnectorChoice.toolNames`
  的 `null` 一档消失，但决策 1 的「只看 serverId」不受影响。
- **若「一台都不给」被证明是真实需求**（比如一只只写文档的 agent 也想留着而不是删掉），决策 2
  连同决策 1 的编码一起要改：那时 `tools` 这一列需要一个显式的三态，而不是靠「空」的两层
  重载——代价是 `workspace_connectors` 那张表要跟着换口径，否则又回到「相邻两张表意思相反」。
- **若「哪条会话烧的」变成常问的问题**，用量表的分组键要从 `agent_id` 扩成
  `(agent_id, session_id)`——列已经在表里，改的是 `aggregateByAgent` 与那张表的形状，不是
  migration。
- **若切片 5（agent 互相 @）在真机上表明按周窗聚合看不出失控**（一条接力链能在一个 5h 窗里
  烧完周额度），决策 5 的窗口要从「owner 的周窗」再切一层 5h 窗——`weekStartFor` 旁边就是
  那份逻辑，但「同一扇窗两个界面不能给出两个数」这条约束原样成立。
- **若手机端也要看这张用量表**，`fetchWorkspaceUsage` 那份纯函数原样可用（端点已经只收真人
  JWT + 在籍），要加的是手机侧的一张表——决策 5 不受影响。
