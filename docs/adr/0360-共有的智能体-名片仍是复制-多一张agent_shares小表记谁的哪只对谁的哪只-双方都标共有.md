# ADR-0360：共有的智能体——名片仍是复制，多一张 agent_shares 小表记「谁的哪只 ↔ 谁的哪只」，双方名册上都标「共有」

原为 ADR-0360（另一条 PR 先占了 0359；按项目 ADR-0074 改成 max + 1）。

日期：2026-10-04 · issue #1545 · 维护者原话：「如果两个人同时拥有一个智能体那么显示共有」。**修订 ADR-0354 第 3 条**的后半句（「不记来源」）。

## 背景

ADR-0354 把智能体名片做成**复制定义**：接受方主场里是一只新 id 的、自己的电脑跑、自己的额度；不记来源、不同步。真机上维护者要的是：
两个人手里的那两只要看得出是「同一只」。记忆 / 聊天记录仍各管各（那一半不变），缺的只是**可见性**：分享方读不了接受方的 `workspace_agents`，反过来也一样，
所以「谁和谁共有哪只」得有一个两边都读得到的地方。

## 决定

1. **一张小表 `agent_shares`**（0058）：分享方 uid + 原 id + 接受方 uid + 复制出来的新 id + 名字快照，主键三元组。**接受方在接受那一刻写一行**
   （RLS：只有接受方能写、只能以自己为 `with_uid`、且两人是已接受的好友——名片只在好友私聊里发得出来），两边都读得到自己参与的行，接受方删掉那只时能删这一行。
   否决了在 `workspace_agents` 上加 `shared_from` 列：那只能让接受方知道来源，分享方那边仍然一无所知，还得再开一个 RPC。
2. **分享方那边不加 RPC**：接受方接受时顺手往这条私聊里发一句「我接受了你分享的智能体「X」，现在我们俩都有这只」（现成的 messages，两人都看得到），
   分享方资料页上的「共有 · X 也有一只」读的仍是 `agent_shares`（分享方对那几行有读权限）。
3. **怎么标**：接受方那只「共有 · 来自 X」，分享方那只「共有 · X、Y 也有一只」（超过三位写「等 N 人」）；资料页写在 tag 里、通讯录写在那一行小字前面。
   判据是纯函数 `agentShareBadge`。
4. **容错**：0059 没跑 = 读回空（当没有共有）、写不进去只记日志；两件都排在「已保存到我的智能体」之后，接受本身不受它们影响。

## 否决的

- 把两只做成**同一只**（接受方直接用分享方那只）：那是 #1523 / #1533 的共享车道已经在做的事（朋友在私聊里 @ 我公开的那只）；名片的语义是「给你一只你自己的」。
- 同步定义 / 记忆：另一种产品（订阅别人的智能体），不在这次范围。

## 代价与已知未做

- 名字快照：两边之后各自改名不同步，「共有」那一行仍说得出当初是哪只，但名册上显示的是各自现在的名字。
- 分享方删掉原来那只：`agent_shares` 那一行还在（只有接受方能删），接受方那只仍标「共有 · 来自 X」——说的是来源，不是「X 现在还有」。
- 分享方那边「X 也有一只」只有在 0058 跑过、且接受方的接受发生在之后才会出现；之前接受的那些没有记录。
- 真机未验。
