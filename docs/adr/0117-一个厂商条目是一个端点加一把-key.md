# ADR-0117：一个厂商条目 = 一个端点 + 一把 key，不是一家公司

日期：2026-08-26
状态：已接受
相关：issue #476、ADR-0010（厂商目录/型号目录拆两张表）

## 背景

用户拿 Kimi Coding Plan 的订阅 token（`sk-kimi-…`，从 kimi.com/code 领）填进设置页的「月之暗面 Kimi」，
存得进去，发第一条消息 401。

Kimi 有两套互不通用的服务：

| | 开放平台（按量） | Kimi Code（订阅） |
|---|---|---|
| 端点 | `https://api.moonshot.cn/v1` | `https://api.kimi.com/coding/v1` |
| key | 平台 `sk-…` | `sk-kimi-…` |
| 计价 | 按 token | 按月订阅，限频不限量 |
| 型号 id | `kimi-k2-0905-preview` … | `kimi-for-coding` / `k3` / `k3-256k` … |

实测（2026-08-26，同一把订阅 token）：

```
api.moonshot.cn/v1/chat/completions      → 401 Invalid Authentication
api.kimi.com/coding/v1/chat/completions  → 200
```

目录里 `moonshot` 那条只写了前者，于是订阅用户在 UI 上**看得见 Kimi、填得进 key、就是用不了**。

## 决定

`ProviderId` 的粒度是**一个端点 + 一把 key 的组合**，不是一家公司。同一家公司卖两套不通用的
接入方式，就是两条目录条目。据此加 `kimicode`（`api.kimi.com/coding/v1` + `KIMI_CODE_API_KEY`），
挂它自己的四款型号；`moonshot` 那条改名「月之暗面 Kimi（按量）」，keyHint 写明"不是 sk-kimi-…"。

`tests/shared/providerCatalog.test.ts` 钉两条：端点/`baseUrlEnv`/`apiKeyEnv` 三样各家独占；
Kimi 两条的 keyHint 必须互相区分。

## 理由

三个候选，选第三个：

1. **不做**，让用户自己设 `MOONSHOT_BASE_URL=https://api.kimi.com/coding/v1`。
   路由确实认这个覆盖（`agent.ts` 读 `process.env[choice.baseUrlEnv]`），但 UI 上没有这一格，
   只能从终端起 app —— Finder 双击起的 GUI 吃不到这变量。等于要求用户知道一个我们没写在任何界面上的变量。
2. **在 `moonshot` 那条上按 key 前缀自动切端点**。省一条目录项，代价是目录从"接线事实"退化成
   "带条件分支的猜测"：`sk-kimi-` 这个前缀是上游的私事，它哪天改了，我们会安静地拨错地址。
   而且余额探测、型号清单也得跟着分叉。
3. **加一条目录条目**（本决定）。多一条 UI 上的重复品牌是代价，换来的是目录里一条都不用改的
   接线路径：adapter 是 OpenAI 方言，端点三件套照旧从厂商表查，路由/余额/型号清单全都不用知道
   "这两条其实是一家"。

## 代价与推翻条件

- 设置页上出现两个 Kimi。用两枚不同的品牌字形（Moonshot / Kimi）+ 名字里带（按量）/（订阅）区分，
  但这仍然是要用户读一眼才能分清的东西。
- 订阅制没有按 token 的价，`modelPricing` 里**故意不写这四款** —— 那张表的规矩是"查不到价就不显示"，
  而订阅制的"这一次花了多少钱"这个问题本身不成立，不是查不到。
- 余额面板同理没有它（`providerBalance` 的 ENDPOINTS 是 Partial）。上游哪天给出配额查询接口，
  这条可以再加。
- **推翻条件**：如果 Kimi 把两套账号体系打通（同一把 key 两个端点都认），这条 ADR 的前提就没了，
  该合回一条。

## 型号数据的来源

`contextWindow` / `supportsVision` 不是从文档抄的，是问它自己的 `/coding/v1/models` 拿的
（2026-08-26）：`context_length`、`supports_image_in` 都在那份响应里，图片输入另做过一次真图实测。
`thinking` 挡位也实测过：四款都吃 `thinking:{type:"enabled"|"disabled"}`（GLM 那套方言），
disabled 时 `reasoning_content` 消失。k3/k3-256k 另有 `think_efforts`（low/high/max，默认 high），
本仓没接 —— 接了要动 `shared/thinking.ts` 的方言表，不在这次范围里。
