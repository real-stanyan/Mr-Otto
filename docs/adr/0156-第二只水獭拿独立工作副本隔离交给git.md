# ADR-0156：第二只水獭拿一份独立工作副本，隔离交给 git

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #641；**推翻 ADR-0152 对候选 1 的否决**（互斥那部分仍然成立，见下）；ADR-0155（跨进程锁）、ADR-0116（记忆作用域把 worktree 折叠回主仓）
- 仓库侧的同构决定：ADR-0149 / 0150（那套是给开发 Mr Otto 的 agent 的，与本 ADR 不共用代码）

## 背景

ADR-0152 面对「两只水獭指同一个文件夹」时列了三条候选，选了候选 3（**只拒绝、排队**），把候选 1（自动开 worktree）否掉，理由是：

> 改掉围栏根会连锁影响检查点、`project_instructions`、记忆作用域……而且它替用户做了决定。

维护者复盘后要的是**真并行**——两只水獭在同一个项目上干不同的功能，互不干扰，这正是 Claude Code 的形状。那条否决作废。

复盘时发现一条支持证据：**ADR-0116 早就把「worktree 折叠回主仓」做进记忆作用域了**。代码库其实预期过这件事，当初的连锁影响估得偏重。

## 决策

**同一个项目上的第二只水獭，拿到这个仓库的一个一次性 worktree。**

### 隔离交给 git，不自己造

独立工作目录、独立 HEAD、独立分支。git 拒绝同一分支被两处 checkout，所以「互切对方分支」这个动作**根本不存在**——不需要任何协调机制、锁或约定。这与仓库侧 ADR-0149 的论证同源：规则管不住的东西，换个结构就没有了。

### 第一只不隔离

用户在 GUI 里点了个文件夹，他的编辑器开着那个文件夹。单只水獭时把它挪进副本，等于第一次用就要他理解「你的活在别的目录、回头要 merge」——那是把 git 的心智模型推给不一定想要它的人。

隔离只在真的出现第二只时发生，那时用户本来就在做一件更复杂的事。**这是本 ADR 与「照搬 Claude Code」唯一的差别**，理由是用户不同：Claude Code 的用户坐在终端里，worktree 和分支是他的日常。

### 副本不放在用户的仓库里

落在 userData 下（`<userData>/worktrees/<项目哈希>-<随机>`）。放 `<repo>/.mr-otto/worktrees/…` 会进他的 `git status`、可能被误提交。同 ADR-0155 锁文件的理由：**用户的目录是他的**。git 的 worktree 本来就可以在任何位置。

### 判据是「同一个仓库」，不是「同一个路径」

用 `--git-common-dir`：已经在副本里的会话与主目录的会话共享同一个 `.git`，分支空间共享，算同一个项目。于是第三只水獭正确地拿到第三个副本，而不是与第二只撞在一起。

家族（子会话 / SideChat）不算占用——它们共享工作区是故意的（与 ADR-0152 的互斥判据同一条豁免）。

### 水獭自己知道它在副本上

`session_created.isolated`（已知类型上的新增可选字段，旧日志照常重放）落盘项目本体与分支，投影据此多注入一段系统提示：你在副本上、别去动项目本体、活干完提交在自己分支上、**合并前先问一句合到哪**。

这样「能不能把活交回去」不依赖任何新 UI——水獭有 bash，用户说一声它就能合。UI 是后续的事（见下）。

### ADR-0152 的互斥仍然成立

隔离之后两只水獭的 workspace 不同，那层互斥自然不再触发。但它仍是**兜底**：工作区不是 git 仓、`worktree add` 失败、旧会话没有副本——这些情况下退回排队。fail-open 的方向是「没有副本」而不是「建错副本」：一个建到半途的 worktree 会让人以为活在里面，而实际什么都没有。

## 为什么不是别的做法

| 候选 | 否决理由 |
|---|---|
| 每个会话都开副本（完全照搬 Claude Code） | 单只水獭的用户凭空多出一次 merge。收益为零——没有第二只时无人可踩 |
| 副本放项目里 + 改用户的 `.gitignore` | 改用户的 `.gitignore` 比放个文件更冒犯，而且它是仓库内容、会冲突 |
| 等 v2 的 Docker per bot | 会顺带覆盖，但那是大改造；期间用户只能排队 |
| 复制整个目录而不是 git worktree | 没有共享的对象库 = 磁盘翻倍、分支合不回去。worktree 的全部价值就在这 |

## 后果

- 接受：**这个版本没有 UI**。用户看不到「这只水獭在副本上」的显式标记，也没有「合回主分支」的按钮——他能问水獭，水獭知道。UI 与合并入口另开 issue。
- 接受：副本会攒着。会话删掉时没有自动清理（另开 issue），`git worktree prune` 是当前的手动出口。
- 接受：检查点按 workspace 键——副本被删时那条会话的文件回退锚点跟着没。
- 接受：只在**同一台机器**上成立（与 ADR-0155 同）。
- 不变：ADR-0152 的互斥、ADR-0155 的跨进程锁都留着当兜底；本 ADR 只是让常见情况不再走到它们。
