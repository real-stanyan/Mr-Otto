# ADR-0172：岛按**项目**分组，副本身份下沉到行

- 状态：已接受
- 日期：2026-08-28
- 相关：issue #690；ADR-0157（每只水獭一份独立 worktree）、ADR-0158（分支会改名）、ADR-0116（记忆的项目作用域：worktree 折回主仓）、#206（岛按工程文件夹分组收放）、#199/#210（用量表）

## 背景

ADR-0157 之后，每只水獭都在一份独立 worktree 上干活，落点是
`<userData>/worktrees/<sha256(projectRoot)[0:12]>-<randomBytes(3)>`。

而灵动岛的分组键与组头显示名一直是 `session.workspace` 的路径末段
（`IslandAgent.workspaceLabel = lastPathComponent`）。两件事撞在一起，
组头变成了 `d3dbc74d37b3-a29018`。

三个后果，一个比一个重：

1. 组头无意义 —— 它本来要回答的问题是「这是哪个项目」。
2. **同一个项目裂成 N 组** —— 每开一只水獭多一个组头，而刘海面板一屏就那么高。
3. 真正能区分同项目几只水獭的**分支名**，岛上反而无处可见。

## 决定

**组头回答「这是哪个项目」，副本身份是行级的事实。**

- 分组键从 workspace 换成**项目根**（worktree 折回主仓）。
- 每行给隔离会话挂一枚分支 chip。

## 为什么不是「按副本分组、只把哈希换成好名字」

那条路改动最小：组头写 `Mr_Otto · friends-a29018` 就完了。否掉它的理由不是审美，
是高度——同一个项目仍然占 N 个组头，而组头是**纯开销**（它不携带任何一只水獭的
状态）。样板里能直接看到代价：三个项目、四只水獭，最后一组已经被挤出可视区。

反过来说，折回项目的代价是组内行数会涨。这条取舍的前提是「同项目同时开的水獭是
个位数」。**前提若翻**（用户普遍同项目开 4+ 只，组内行数本身成为主要噪声），
这个决定要重估——那时该做的多半是组内的二级折叠，而不是退回按副本分组。

## 怎么实现的：一层镜头，不是一次 IO 下放

`pushFleet` 跟着**每条**事件跑（工具密集的 turn 一秒好几次），而「哪个项目、
哪条分支」两件事都要读 `.git`。

- `islandProjection` 保持纯函数：`orderedVisibleSessions` / `flattenFleet` /
  `flattenAgent` 接一个可选的 `WorkspaceLens`，默认镜头是「就地当项目、不是副本」
  —— 于是不传镜头时行为与从前**逐字**一致。
- IO 与缓存收在 `src/main/workspaceLens.ts`：30s TTL 记忆化。
  刻意**不**做事件驱动的失效——那要求每个改名/建会话的路径都记得通知这一层，
  漏一处就是一个「为什么组头不更新」的幽灵 bug，而 TTL 自愈。

分支**现查**而不是读日志里 `session_created.isolated.branch`：那是「当初叫什么」的
历史记录，自动标题出来后分支会改名（ADR-0158）。显示一个陈旧的分支名比不显示更坏
——你会拿它去 `git checkout`。

查法是**纯读文件**，不起 `git` 子进程：worktree 的 `.git` 文件指向
`<主仓>/.git/worktrees/<名>`，那个目录里的 `HEAD` 就是 `ref: refs/heads/<分支>`。
`resolveProjectRoot` 本来就要解析同一个 `gitdir:` 指向，于是两件事合成一次爬升
（`resolveWorkspaceOrigin`），`resolveProjectRoot` 成为它的投影——两者必须同源，
否则「worktree 折回主仓」会在项目记忆和灵动岛上给出两个不同的答案。

## 出机器的那一份：两个新字段都不出

`trim.ts` 是「什么东西离开这台机器」的唯一收口（ADR-0094）。`projectRoot` 是又一条
本机绝对路径，`branch` 是本机 git 的状态，而手机端那一屏既不分组也不显示分支
（`mobile/` 里没有任何地方读它们）。没人读的东西不该持续过公网，哪怕中继解不开。

> 顺带记下一笔已存在的账：`workspace` 今天就在往手机上发，而手机端同样不读它。
> 那是一条既有字段的行为改动，不在本条范围内。

## 顺带做的排版重做（apple-design）

同一次改动里把两张表按 Apple 的排版与层级规则过了一遍。逐项值在 issue #690 的表里，
这里只记三条**判断**：

- **层级不是靠字号一个维度给的**。组头 13pt regular 和行标题 14pt regular 几乎同权重，
  两条信息在抢同一层；改成组头 11pt semibold（小字要**正** tracking 才不糊）+
  行标题 13pt medium。
- **列表是拿来扫的**。计时和本轮改动原来只在**选中**那行的详情区出现，于是
  「哪只跑了多久、动了多少」要逐行点开。它们回到行上。
- **状态不能只靠颜色编码**。三档原来都是 7pt 实心圆、只差颜色；改成形状也分档
  （idle 空心环 / active 实心 + 扩散环 / approval 实心 + 光晕）。

以及一条被推翻的中间稿：用量表的「14 天占比」一开始画成整行的底色块，
满格那行会被读成「这一行选中了」而不是一个量——改成行底 2pt 细柱。

## 后果

- 岛的组头回到「一个项目一组」，与侧栏、与项目记忆（ADR-0116）同一套口径。
- `IslandAgent` 多两个可选字段；旧 helper 解码时忽略，Swift 侧 `projectRoot` 缺席时
  回落 `workspace`（NDJSON 向后兼容，同 `workspace` / `turnDiff` 的规矩）。
- 侧栏的 `groupSessionsByWorkspace` 有**同一个病**（它也按 workspace 分组、也取
  `lastPathComponent`）。本条只修岛——侧栏留给它自己的 issue，因为那里还牵扯归档
  分组、⌘K 搜索范围、折叠状态的持久化键，不是同一次改动的尺寸。
