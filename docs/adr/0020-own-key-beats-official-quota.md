# ADR-0020：自带 key 优先于官方额度，路线每次请求现算

- 状态：已接受
- 日期：2026-08-18
- 相关：issue #47；ADR-0019（官方 key 走网关）

## 背景

网关上线后，客户端每次调模型都有两条路可走：直连上游（用户自己的 key）
或走 otto-gateway（官方 key + 官方额度）。得定一条能指着代码念的规矩。

## 决定一：自带 key 优先，且优先级高于登录态

`src/main/modelRoute.ts` 的 `routeModel` 是唯一的判断处：

1. 配了自己的 key → **直连**
2. 否则，型号不是 DeepSeek → **blocked**，直说要填哪个 env
3. 否则，登录了 → **走网关**
4. 否则 → **blocked**，把两条出路都说出来

第 1 条压在登录态之上，是因为反过来会造成一件用户无法理解的事：他填了自己的 key，
顺手登录了一下，然后发现官方额度在掉。想省自己的钱就清掉 key，想省额度就填 key——
两个动作各自独立，互不牵连。

第 2 条存在的理由：官方额度只买了 DeepSeek。把 GLM 的型号 id 发给 DeepSeek 只会
换回一个上游 400，用户对着看不懂的错误发呆。与其如此，不如在客户端就说清楚缺什么。

**什么情况下该推翻**：如果官方额度将来覆盖多家上游（网关按型号分流），第 2 条就该
改成"网关支持的型号集合"而不是硬编码 provider。

## 决定二：端点每次请求现算，不在 adapter 构造时定死

`OpenAICompatibleOptions` 新增可选的 `resolveEndpoint()`，每次 `chat()` 调一次。
不给它 = 老路径一字不变（静态 `baseUrl`/`apiKey`）。

两个理由，第一个是硬的：

1. 网关的凭据是 Supabase access token，**一小时就过期**。构造时捕获等于 turn 跑到
   一半突然 401，而且是那种"昨天还好好的"型故障。读 `getSession()`（而非自己缓存）
   把刷新交还给 supabase-js——它开着 `autoRefreshToken`，自己缓存等于跟它抢活。
2. 用户可能在会话中途填了自己的 key 或登出。路线该当场改，而不是等他重开会话。

**什么情况下该推翻**：如果哪天凭据变成长期不过期的（例如设备级 token），
这层间接就只剩第 2 条理由，可以退回成"账号/密钥变化时重建 adapter"。

## 决定三：网关的错误不再裹一层

`model API 402: {"error":{"message":"token 额度已用尽…"}}` 这种字符串里，
真正给人看的那句话被埋在技术噪音中间。adapter 认出 `type: "otto_gateway"` 的错误后
只抛 `message` 本身，上游（DeepSeek）自己的错误照旧带状态码报——那不是网关说的话，
不该冒充。

## 决定四：余额查询走主进程，token 不过桥

`walletBalance()` 由主进程调网关，渲染层只拿到三个数字。access token 不过 IPC，
与 `AccountInfo` 那条既有约束（"token/session 对象永不过 IPC"）同源。

UI 上把「没有额度」和「查不到额度」分开显示：前者是事实，后者是故障，
显示成同一个 $0 会让用户去做完全错误的处置。
