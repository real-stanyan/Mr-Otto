# ADR-0194：忘记密码走验证码，闸门等设完新密码再抬

- 状态：已接受
- 日期：2026-08-30
- 相关：issue #735 #737 #739 #740 #741 #742 #743 #744、ADR-0182 / 0183（进门闸与它的判据）、
  ADR-0098（注册流程的前提，被 #738 推翻一半）、ADR-0187（`AccountInfo.id`）
- 说明：这条 lane 的代码写完后断在「没开 PR」那一步，ADR 是收尾时补的。**它记的是这一批
  改动里做过的判断**，实现细节在各提交的正文里，不重抄（ADR-0045）。

## 背景

登录/注册在 ADR-0182 之后成了**进门那道闸**：没有登录记录的人只看得到一屏 `SignInScreen`。
闸门立起来之后，「忘记密码」这条路第一次变成必答题——在此之前它可以推给「进 app 再说」，
现在忘记密码的人**根本进不到 app 里**。

## 决策

### 一、忘记密码走验证码，不走链接

链接那条路要跳出 app：默认浏览器打开落地页 → 系统再问一句「要打开 Mr Otto 吗」→ 中间可能
还隔着一次冷启动。**每一跳都是一个人会走丢的地方**，而这一切只为了传回一串数字。验证码把
整段流程留在窗口里。

链接**没有拆掉**：同一封邮件里两样都有，谁先到算谁的。

`OTP_LENGTH = 8` 不是 6——真值在 Supabase 项目的 `mailer_otp_length`（本项目实测 8，
GoTrue 的默认才是 6）。抄错的后果很轻但很烦：输入框的 `maxLength` 把最后两位吃掉，
用户看着自己打完的码提交不了。

### 二、闸门等设完新密码再抬（推翻同一条 lane 上一版的取舍）

recovery OTP 换到的是**真 session**，验完那一刻 `needsSignIn` 立刻变 false，闸门自己抬起来。
上一版据此选了「让 `SetPasswordDialog` 在闸门里面接手」，理由是不想让一张弹窗跨过闸门活着。

**看到实物就知道那条理由不成立**：一个还没设完密码的人，背后已经铺开了整个 app，前面压着
一张「设一个新密码」；而那张弹窗的「以后再说」等于让他带着**旧密码原封不动**的状态进去——
他刚才证明的只是「能收这个邮箱的信」。

改法不是让弹窗跨过闸门，是反过来让闸门先别抬：

```
showsSignInScreen = needsSignIn(...) || holdGateForPasswordReset
```

配套两条：

- **`atGate` 由发起方给，不从 `resetPending` 反推。** 账号页也渲染同一张登录卡（有记录但没
  验上的人落在那儿，是 ADR-0183 故意放进来的），那些人本来就在 app 里，把他们的界面换成
  登录屏是另一种意外。
- **那笔记号落盘（localStorage）而不是留在内存。** 点邮件链接那条路要经过浏览器、可能隔着
  一次冷启动，内存标记跨不过那次往返——不落盘的话，这个 bug 在链接那条路上原样复现，
  而且更难查。

### 三、`signUp` 显式传 `emailRedirectTo`，不把落点交给远端的 `site_url`

OAuth 和重置密码都显式传 `redirectTo`，唯独 `signUp` 漏了——于是确认邮件里那条链接的落点由
Supabase 项目的 `site_url` 说了算，而它至今指着一台**已经退役**的 VPS。

这不是「忘了改配置」，是**分工错了**：这条链接最终要唤起的是我们自己的 app，属于一条自己
必须处理的深链。它的落点不该由一个改起来不用发版、也没人盯着的远端设置决定——那个字段任何
时候被改动，注册流程就断，**而代码里看不出任何痕迹**。

轮询探测仍然留着：链接指对了，不等于那一跳一定回得来。

### 四、查无此人也不报错

`resetPassword` 对不存在的邮箱同样回成功。报了就等于把「这个邮箱注册过没有」做成一个人人
可查的接口。Supabase 本身也这么设计，不去拆它。

### 五、主窗默认大小跟着屏幕算

写死 1100×760 的毛病不是「这组数不好看」，是**它假装屏幕只有一种**：同一扇窗在 13 寸上顶天
立地，在 27 寸外接屏上是正中间一小块。

`min(想要的 1440×980, 可用区 × 0.92)`，**两个维度各自 clamp**——保宽高比的话，一块又宽又矮
的屏会为了迁就高度把宽度也砍掉，凭空浪费一大片横向空间。取**鼠标所在**那块屏而不是主屏：
人在哪块屏上点的图标，窗口就该开在哪块屏的尺度上。

不做窗口尺寸记忆——那是另一件事（要落盘、要处理显示器拔掉之后坐标失效），这里只回答
「第一次多大」。

### 六、用户名在注册表单里填，不等进了 app 再问

走 `signUp` 的 `options.data` 进 `raw_user_meta_data`，profiles 的插入触发器取它填 name，
不需要等登录成功再补写一次。**必填**：留一个可以空着的格子，人会以为填不填都行，然后在好友
列表里看到自己叫 `1464729020`。上限 `NAME_MAX` 在 IPC 那侧也截一次（渲染层的 `maxLength`
是可以绕过的）。

## 后果

- **闸门多了一条按住它的理由**，判据从「有没有登录记录」变成「有没有登录记录 **或** 正卡在
  重置的第二步」。代价是 `showsSignInScreen` 比 `needsSignIn` 多一个参数，两者不能混用——
  谁判错谁把人锁在门外或者放进不该进的地方。
- **验证码和链接并存**，两条路都要维护。推翻它的前提：如果哪天邮件模板里的 `{{ .Token }}`
  被人删掉（模板是 Supabase 后台的，不在本仓），验证码这条路会静默失效，只剩链接。
- **#738 不在这条 lane 的射程内**：Supabase 内置邮件通道全项目每小时 2 封，注册流程实际
  不可用——那是控制台里配自定义 SMTP 的事，代码改不动，issue 留着。
