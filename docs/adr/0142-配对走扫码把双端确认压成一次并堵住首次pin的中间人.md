# ADR-0142：配对走扫码——把两端各确认一次压成一次，顺带堵住「首次 pin 的中间人」

- 状态：已采纳
- 日期：2026-08-27
- 关联：issue #583，推进 ADR-0095（后果表第三行）、ADR-0130（多设备）、ADR-0101（Expo Go 就能跑）

## 背景

配对原来要人**在两台设备上各按一次**「安全码一致，配对」：桌面
`RemoteDevicesSettings.tsx` 一颗按钮，手机 `App.tsx` 一颗。

两次点头不是啰嗦，是 6 位码那套机制的必然：两端各自用两把公钥算出同一个数
（`handshake.ts` 的 `fingerprint`），**由人眼把这个数从一块屏幕搬到另一块**。
搬运是对称的，所以两边都得有人点头。

而且这个缺口有另一面。ADR-0095 的后果表里写着一行 ❌：

> 服务器在手机首次 pin **之前**下发假公钥 → 中间人成立

同一件事：信任的源头是 Supabase 那张 `devices` 表，而**目录不是信任来源**。
第 74 行当时就写下了唯一的堵法：「要堵第三行只能补带外验证（扫码 / 强制核指纹）」。

「删掉桌面那颗按钮、只显示配没配上」看起来能省一次点击，但它恰好把这两件事
一起做坏：桌面不再有人工确认，就只能无条件信任目录里那一行，能写库的人插一行
`kind: "mobile"` + 自己的公钥就拿到时间线和危险操作的审批权。手机是审批端、
桌面是真跑 bash 的那台 —— 两个方向里，桌面那颗恰恰是更不能省的。

## 决定

**加一条带外通道：桌面显示一次性二维码，手机扫。** 一次动作办成两件事：

1. 手机**直接读到**桌面的身份公钥（不经目录，中间人换不掉）→ 手机 pin 桌面
2. 码里那把一次性 secret，手机在握手里签一条**持有证明** → 桌面据此 pin 手机

于是人只动一次，而两个方向都被认证了。

具体形状（`src/shared/remote/pairing.ts`）：

- 码 = `otto-pair:1:<deviceId>:<b64u 身份公钥>:<b64u 32 字节 secret>`，
  TTL 3 分钟，**一次性**（配上一台就作废，再配下一台要重开一张）
- 证明 = `Ed25519Sign(手机身份私钥, "otto-pair-proof-v1|角色|设备id|" ‖ secret ‖ ephPub ‖ nonceHalf)`
  - **secret 进签名**：没扫过码的人签不出来 —— 这是「这台手机是我的」的全部依据
  - **eph/nonceHalf 进签名**：证明绑在这一次连接上，截走换条连接用不了
  - **角色进签名**：同 ADR-0095 第 3 条，挡反射
  - secret 本身不出现在线上，中继看不到它
- 握手包多两个**可选**字段 `identityPub` / `pair`，**只在配对路径上被看**：
  对端已经 pin 住时身份从 pin 组里来，hello 自称什么都不作数
- 桌面的受理顺序：pin 组逐把试 → 全不过且手上有活着的码 → 验证明 → 认下并落 pin。
  已配好的手机不消耗码

### 目录仍然不是信任来源

这是本决定最容易被读反的一处。手机自称的公钥进的是**验签的输入**，不是
「查表查出来的可信值」：拿到库的人插一行假公钥，签不出对应的证明，照样连不上。
桌面这一侧验的始终是「谁能对这把 secret 签出名」。

### 6 位码留着当降级路径

手机没给摄像头权限时走它，两端各按一次的老流程一字不改。文案要说清它比扫码
多一步，而多出来的那一步正是扫码替你做掉的那半边认证 —— 否则用户会以为
两条路等价，而随手挑了更麻烦的那条。

## 后果

ADR-0095 后果表第三行从 ❌ 变成**有条件的 ✅**：走扫码配对时不成立（公钥不经
目录），走 6 位码降级路径时仍然靠人核对那六位数。第四行（元数据可见）不变。

新增的攻击面与封法：

| 试法 | 结果 |
|---|---|
| 拍到屏幕上那张码 | 3 分钟内有效、且配上一台即废；抢在用户之前扫才有意义 |
| 截走握手包重放证明 | 证明绑着那一轮的 eph/nonceHalf，换条连接验不过 |
| 目录里插一行假公钥 | 签不出证明，认不下 |
| 拿别人的证明配自己的公钥 | 验签用的就是 hello 里自称的那把，冒名者签不出 |

代价：

- 多一个依赖 `qrcode-generator`（零依赖纯 JS，渲染进程用得起）和 `expo-camera`
- 手机端多一道相机权限。**已在 Expo Go 里真机验过**：SDK 57 的 Expo Go 自带
  expo-camera，权限弹窗正常、取景框正常渲染 —— ADR-0101 的「Expo Go 就能跑、
  无 native module」没破
- 桌面那张码只活在内存里。进程重启 = 码没了，这是刻意的：落盘等于把一次性变成长期

## 被否掉的路

- **删掉桌面那颗按钮，只显示配没配上**：见背景。省一次点击的代价是桌面无条件
  信任目录，把 ADR-0095 的核心前提拆了
- **手机盲信桌面、只保留桌面那颗**：损失比上一条小（伪装成桌面的攻击者只能喂
  假时间线骗人按批准，偷不到真会话），但没有必要 —— 扫码两边都省了
- **把 secret 塞进现有的 `signedPayload`**：那段签名是每连接都要验的主路径，
  为一次性的配对改它，等于让配对的形状永久压在握手上。分开一个字段，
  平时那条路径一个字节都不多
