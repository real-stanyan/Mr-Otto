# ADR-0167：代理的第四道防线是限流；单帧超限记成「执行了，传不回来」

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #674；ADR-0151（§5 三道防线：审计 / 撤销 / 白名单）；
  ADR-0165（取消 ≠ 没发生——同一条「副作用已经发生就要记账」的推理）；
  ADR-0129/0130（relay 是盲管道，单帧上限 `MAX_FRAME_BYTES`）

## 背景

两处都来自「代理这条路没人管帧有多大、也没人管来得有多快」。

**其一，单帧上限没人管。** relay 对整条消息设了 256 KiB 的闸，超了它
`ws.close(1009)` —— **关掉发送方的连接**，不是丢这一帧。而 `proxyMcp` /
`proxyHost` / `proxyConnection` 里一处大小检查都没有，代理协议也没有分块。
密封 +24 字节再 base64（×4/3），所以明文过约 192 KB 就会被掐。

后果不是「这次调用失败」，是连接被关 → 退避重连 → 对端等满 60 秒超时 →
每次调那把工具重演一遍。而且方向是反的：**B 的请求打掉的是 A 的连接**。
192 KB 对 MCP 工具很容易够到（一页订单、一段日志、一次查询），返回图片的基本必炸。

**其二，A 侧执行器没有闸。** 收到 `proxy_req` 就 `void execute(frame)`：
不排队、不限并发、不限速率。而白名单内是**全自动**的——好友那边一个跑飞的循环
就能对 A 的账号连开几百笔。ADR-0151 的三道防线没有一条管速率：审计只能事后看见，
撤销要人去点，白名单管「能不能调」不管「调多少次」。

顺带一个同源问题：每条拒绝都写一笔审计，而审计有 `AUDIT_CAP`（500）上限——
刷一串必然被拒的请求，就能把真记录挤出去。

## 决策

### 1. 大小闸放在 `sendSealed`，量的是编码后的长度

它是唯一知道**最终线上长度**的地方。超限就回 `false`，一个字节都不交给传输——
交出去的下场是本端连接被关。量实际长度而不是估算：估错的代价是断线。

`sendSealed` 因此从 `void` 改成 `boolean`，两端的传输接口跟着改。
调用方各自把 `false` 翻成人话，而不是让它表现成超时。

### 2. 单帧超限记成「执行了，传不回来」

结果太大时，工具**已经执行完了**——副作用已经发生。所以这笔按
`executed` / `outcome: "error"` 记账，并回一条**小的**错误帧让好友当场知道原因。

这与 ADR-0165 的取消是同一条推理：账本记的是「用我的凭证做了什么」，
而不是「好友收到了什么」。当作没发生过，就是让审计账在最需要它的那次是空的。

### 3. 第四道防线：并发上限 + 令牌桶，**放在所有闸的最前面**

- 并发上限（默认 4）：同时在跑的调用塞满了，后来的当场拒。
- 令牌桶（默认 30/分钟、桶容量 30）：挡住跑飞的循环，而不碰正常节奏的使用。

放最前面，是因为它保护的不只是 A 的凭证，**还有审计账本身**：
不限流的话，刷一串必然被拒的请求就能把真记录挤出去。

### 4. 被限流的不逐条记账：一个「限流时段」记一笔

逐条记等于把「防止刷爆审计账」这件事自己变成刷爆审计账。
进入限流状态时记一笔（写明「后续同类请求不再逐条记账」），
恢复放行时清掉标记。A 仍然看得见「有人在刷」，账本不被淹。

## 后果

| | |
|---|---|
| ✅ | 大结果不再打掉连接：当次失败、说清原因、通道活着 |
| ✅ | 跑飞的循环打不穿 A 的账号，也刷不爆 A 的审计账 |
| ✅ | 授权清单本身撞上限时**说出来**，不再表现成「连上了但一个服务都没授权」 |
| ⚠️ | **大结果就是传不回来**，没有分块。真要传大结果得另做（`uploads.ts` 那套分块是手机附件路，没有复用）。当前是「明确失败」而不是「悄悄坏掉」，这是取舍不是终点 |
| ⚠️ | 限流是**每条通道**的，不是每个账号的。一个好友多条通道（目前不会发生：A 侧一好友一通道）时上限会翻倍 |
| ⚠️ | 正常使用撞上默认值时会被拒（比如一次性批量改 50 个商品会吃到桶容量 30）。参数可注入，真撞上了调它，而不是把闸拿掉 |

## 被否掉的路

- **分块传大结果**：正确但工程量不小（重组、超时、乱序、内存上限——`uploads.ts`
  那一套的全部问题都要再来一遍），而目前没有一个已知场景需要传 192 KB 以上的工具结果。
  先让它明确失败，等真需要再做。
- **把大小闸放在 `proxyHost` / `proxyMcp`**：那两层看不到密封与 base64 之后的长度，
  只能估算，而估错的代价是断线。
- **限流逐条记审计**：见决策 4。
- **限流放在白名单之后**：那样刷一串「白名单外」的请求照样能把审计账挤爆——
  闸必须在写账之前。
