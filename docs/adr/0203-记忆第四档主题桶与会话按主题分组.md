# 0203 记忆第四档 TOPIC（主题桶）+ 会话按主题分组

日期：2026-09-02 ｜ 状态：已定 ｜ 关联：#846、ADR-0116（三档记忆）、ADR-0135（Default 标记）
spec：docs/superpowers/specs/2026-09-02-topic-memory-design.md

## 背景
任务会话（内置 Default）不在 git 仓里，projectRoot 为 null，只有 USER + MEMORY 两档。
「用户在改一台 WRX」这类领域事实没有档位可住。用户要的是 Claude.ai 那种按主题分桶的记忆。

## 决定
1. 第四档 `topic`：`memories/topics/<slug>.md`，沿用 § 格式 / applyOps / per-file 锁；预算 700/桶、封顶 8 桶、不可配置。
   种子桶不可删，只能清空（`deleteTopicMemory` 对种子 slug 直接拒）；种子桶照样占 `MAX_TOPICS`
   的名额（`withSeedTopics` 无条件把四个种子塞进 `known`，创建闸按 `known.length >= MAX_TOPICS`
   判满）——这是有意的：8 是模型看到的总数，不是「模型能建的数量」，效果上模型自己能新建的
   自定义桶只有 4 个。种子桶哪怕从没写过一条内容，也仍然吃掉一个名额。
2. 种子四桶 + 模型可建，新建过「先看索引」的闸（不带 create_topic 拒、报错列出现有桶）。
   工具描述里只带判据正文（`topicRuleText()`，见 `src/tools/memory.ts` 的 `tierRule`），不带
   活的桶索引——这是对 spec §2「工具描述与 system 尾部都注入桶索引」的刻意偏离：工具定义
   在一次会话里只生成一次（装配根拼 system prompt 时），是静态的；桶索引会随会话内的
   `create_topic`/其他会话建桶而变，一份静态描述扛不住这份活状态，写了也只是开局那一刻的
   快照、之后就是撒谎。活索引唯一该住的两个地方：① system 尾部（`deriveMessages.ts` 每轮
   现从 `memory_loaded.topics` 投影，随 turn 刷新）② 创建闸拒绝时的报错文案（`memory.ts`
   现读 `world.config.list` 现算，见上）——两处都是「这一刻真实状态」，工具描述做不到。
3. 整份注入，不做相关性检索；`memory_loaded.topics` 可选字段，旧日志投影逐字节不变。
   `SessionSummary.topic` 投影（侧栏分组用）用 `json_type(payload,'$.topic') = 'null'` 判断
   后再回落成 `''` 哨兵值，不是直接读 `json_extract` 的结果——`json_extract` 对「压根没有
   `topic` 字段」（还没分类）和「字段存在、值是 JSON null」（`session_topic_set(null)`，用户
   手动挪回未分类）这两种不同的事实，都会返回 SQL NULL，两者在 SQL 层面分不出来；
   `json_type` 先问「这个字段是什么类型」，只有真的存了 JSON null 才回 `'null'` 字符串，
   借这一步把两种情形分开，再各自映成 TypeScript 能表达的形状（`''` 哨兵 vs 真正的 SQL NULL
   经 `??` 落到默认值）。
4. 会话主题搭 turnAnnotator 的合并调用（任务四），只从索引里选；`session_topic_assigned` 落盘、投影丢弃；手动 `session_topic_set` 压过它。只对 workspaceKind=default 主会话跑。
5. 侧栏任务栏按 topic 分组；单组未分类不画组头。
6. `ExecutionWorld` 新增 `ConfigCapability.list(relDir)`：桶索引的定义就是「配置目录下
   `memories/topics/` 有哪些文件」，这是一条只有文件系统才回答得了的事实，而工具实现按
   Hard rule 不能直接 import `fs`——`list` 补的正是这个缺口，同 `read`/`write` 走同一条
   `fence`（越界抛错），目录不存在时回 `[]`（同 `read` 的「还没配过是常态不是故障」口径，
   不是抛错）。`memory.ts` 的 `slugsFromFileNames(await world.config.list(TOPICS_DIR))` 就是
   桶索引的现算入口。

## 被否掉的路
- 注入索引 + 按需读（多一次往返，违背「只注入不读」）
- 把 MEMORY.md 拆成桶（环境事实与领域事实是两回事）
- 模型自由建桶不设闸（长出 work/工作/Work 三个桶）
- 写记忆时顺手给会话贴主题（不写记忆的会话永远没分组）
- 发第一条消息前让用户选主题（#559 零决策底线）

## 什么前提垮了要重看
- 8 桶 × 700 字长期不够用 → 该上检索层，不是调数字
- 出现「一个会话横跨多个主题」的真实用法 → 单值 topic 要改成多值
- Default 分格（spec 第 4 节）落地后 workspaceKind 判定变了，任务四的触发判据要跟着
