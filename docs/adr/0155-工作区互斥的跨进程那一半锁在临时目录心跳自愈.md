# ADR-0155：工作区互斥的跨进程那一半——锁放临时目录，心跳自愈

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #634；#620 / ADR-0152（进程内那一半，明写了这条不覆盖）、#633 / ADR-0153（水獭 vs 人）
- 相关 ADR：0092（ExecutionWorld 安全边界）

## 背景

ADR-0152 用 `runningSessions` 挡住了同一个进程里的两条 turn，并在后果里明写了第一条不覆盖：

> **跨进程**（两个 app 实例，比如 dev 版和正式版指着同一个文件夹）。`runningSessions` 是进程内状态。

本 ADR 补那个洞。范围只有一句话：**此刻还有别的进程在这个文件夹里跑 turn 吗？**

## 决策

一个进程外可见的锁文件，turn 起跑时拿、收口时放。

### 锁不放在工作区里

放 `<workspace>/.mr-otto/…` 会污染用户的仓库：进 `git status`、可能被误提交、在别人的 diff 里出现。用户的目录是**他的**，不是我们放运行时状态的地方。

### 也不放在 userData 里

那是每个安装各自的目录——dev 版和正式版的 userData 不同。锁写进去等于两个进程各锁各的，**正好把要解决的问题解决不掉**。

落点：机器级临时目录 + 路径哈希取名（`<tmp>/mr-otto-workspace-locks/ws-<hash>.json`）。两个实例看得见同一份，用户的目录一个字节不动，OS 最终会自己清理。

### 陈旧锁必须自愈，这比「能挡住」更重要

一次崩溃留下的锁如果永远算数，那个文件夹**就再也用不了了**——那是比原问题更糟的故障。两道判据，任一不成立就当陈旧可抢：

- **心跳过期**：turn 可以跑很久，持锁期间每 10 秒刷一次；超过 60 秒没刷 = 卡死 / 被 SIGKILL / 机器休眠过久。
- **进程已死**：`process.kill(pid, 0)` 探活。同机才问得出来——而同机正是这层锁的适用范围。`EPERM` 算活着（别的用户跑的进程）。

### 一切失败都 fail-open

建不了目录、写不进、锁文件坏了 → 当作没有锁。这一层是**额外**的一道，进程内那道照常成立；为了一个辅助锁把人挡在门外是更坏的结果。

## 为什么不选另外三种

| 候选 | 否决理由 |
|---|---|
| `flock` / `proper-lockfile` 之类的成熟库 | 需要的语义很窄（一个可读的 JSON + 两道自愈判据），而库要引依赖、要处理它自己的陈旧策略。这层锁的全部难点在**自愈**，不在互斥原语 |
| 锁文件放工作区，用 `.gitignore` 挡住 | 改用户的 `.gitignore` 比放个文件更冒犯。而且 `.gitignore` 是仓库内容，会进 diff、会冲突 |
| 用单实例锁（Electron `requestSingleInstanceLock`）禁止开第二个实例 | 那是另一件事——dev 版和正式版**应该**能同时开，问题只在于它们不该同时动同一个文件夹 |

## 后果

- 接受：`STALE_AFTER_MS` 有 60 秒的窗口——对方崩溃后最多等一分钟。提示语里明说了「等一分钟锁会自己过期」，免得用户以为被永久锁死。
- 接受：只在**同一台机器**上有效。两台机器挂同一个网络盘不在覆盖范围（pid 探活跨不了机器）——真出现再说，别现在猜。
- 接受：临时目录被系统清理时锁跟着没，等价于「没人占」。这是安全方向的偏差。
- 与 ADR-0152 的关系：两道判据是同一件事，接线也紧挨着——一道在内存、一道在盘上。ADR-0152 后果里的第一条不覆盖到此关闭；第二条（同仓不同 worktree）本来就是安全的，不动。
