# ADR-0123：被挡下的握手要有主动信号，两种拒绝不合并成一条文案

- 状态：已采纳
- 日期：2026-08-26
- 相关：issue #485；ADR-0094（手机端远程投影）、ADR-0095（TOFU 按人核对安全码）

## 背景

`remoteBridge.adopt()` 有两条拒绝路径，此前都只打一行 `console.warn`：

- `peerIdentity()` 为 null —— 这台桌面还没配对过任何手机
- `deriveSession()` 回 null —— 签名 / 角色 / **pin 住的公钥**对不上

设置页「手机」栏目里那台手机确实列着、带配对按钮，所以这不算静默失败。缺的是**主动信号**：
不打开那一页，就永远不知道要去打开那一页。手机端表现为「转圈，然后什么也没发生」。

## 决定

### 1. 桥如实报每一次，去重在上层

`createRemoteBridge` 加 `onRejected`，两条拒绝路径各发一次，**刻意不节流**。

传输层是退避重连的，每次重连都要重新握手，所以这个回调天然重复。把节流放进桥里，
等于让「协议层」去猜「呈现层」多久提醒一次人合适。去重放在 `main/remoteRejections.ts`：
按 `deviceId + reason` 冷却 10 分钟。

### 2. 提示的可见性从「配没配上」现推，不清标志位

`visibleRejection(latest, peers)`：被挡的那台设备如果现在是 `pinned`，就不显示。

不用「握手成功就清提示」的原因：一台桌面只 pin 得住一把公钥（`peerIdentity()` 是单值），
所以**第二台手机是永久被拒的**。清标志位会让第一台手机每次连上来都把第二台的提示抹掉 ——
而第二台那条恰恰是用户唯一需要看见的。

### 3. 两种 reason 两套文案，`identity-mismatch` 用告警语气

`deriveSession` **分不出**「手机重装换了身份」和「有人在中间换了公钥」——两者都只表现为
签名验不过。所以文案把两种可能都摆出来让人判断，不写成「重新配一次就好」。

合并成一条中性提示，等于把「有人在中间换掉了公钥」这句话从用户眼前拿掉，
而这正是 TOFU 存在的全部理由。

### 4. 提示里不放「一键信任」

只指向下面那张列表（列表里的按钮写着「安全码一致，配对」，隐含前置动作）。
提示条里放一个能绕过核对的按钮，等于把 ADR-0095 拆了。

## 代价

- 通知有 10 分钟冷却：人恰好在冷却期内回到桌面，就只能靠设置页的横幅（横幅没有冷却）
- 系统通知是静默的。四个提示音各自钉着一件会话里的事（完成 / 失败 / 审批 / 提问），
  给远程再借一个会把「听声辨事」搅浑。强度靠「通知 + 横幅」两处同时在
- `RemoteStatus` 的 `rejected` 是**这一轮启动以来**的最近一次，不落盘。重启即忘 ——
  它是「现在有事」的信号，不是审计日志

## 前提若变

若将来一台桌面能 pin 住多把公钥（多手机），决定 2 的推理就不成立了：那时「握手成功」
不再意味着「别人的问题被解决了」，可见性要按 deviceId 逐台算，而不是靠单条 `latest`。
