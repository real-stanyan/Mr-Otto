# ADR-0352：长按一条消息派智能体——开一条它的私聊，引用拼进开场白，不改事件形状

日期：2026-10-04 · issue #1505 · 维护者原话：任何对话窗中的任何对话，长按选中可以派出 agent 去根据该对话以及上下文线索和你给的提示词完成相应任务

## 决定

1. **入口是长按一句话**（我的 / 别人的 / 智能体的，三张聊天页都有：智能体私聊、群聊、朋友私聊），弹一张单子：挑我主场里的
   一只（单选）+ 一句提示（可空，空用默认那句）。不做多选、不做「派给群」——派活是一对一的差事，群里的接力另有一套（ADR-0223）。
2. **去处是那只的私聊**，不是原会话。`navigation.push("Chat", { kind:"agent", agentId, dispatch })`：私聊还没建就建（`startDm`），
   建了就 `sendText`——走的是聊天页自己的 `onSend`，一行发送逻辑都不另写。原会话不被打扰，结果在那条私聊里；人回来看原会话
   时什么都没变（原消息上不留标，先不做）。
3. **引用拼进开场白正文，不改事件形状**：`[派活] 提示` + `（引用自「来源」的对话，最后一条是要办的那条）` + 若干行 `> 谁：…`。
   被选那条之前最多 6 句、每句 300 字、整段 1500 字（`quoteWindow`）；时刻、旁白、名单、通话卡不进引用；图片 / 视频 / 语音
   只带占位文字（图要进上下文得走 #1491 那条路，这里不重做）。模型与人读的是同一段话——对模型是上下文，对人是看得见的出处。
   加一格 `quote` 到事件上是 schema 变更、要跨桌面同步；真有需要（比如点引用跳回原消息）再立。
4. **朋友私聊里按好友权限给**：让我的智能体读你们俩的话，与「带它进私聊」是同一件事，所以同一条闸——生效档 ≥「可带智能体」
   （ADR-0350）才有长按。云会话里不另设闸：群里的话本来就是群里智能体读得到的。
5. 名单取**我主场**的智能体（`home.home.agents`），团队群里长按也派我自己的——团队的智能体不归我一个人使唤（同 ADR-0346
   私密车道的口径）。

## 代价

- 引用是文本拼的：模型看不到图、听不到语音，只看到「[图片]」「[语音]」；带转写的语音也只带占位（转写在 media 那一格里，
  这一版没摘出来——下一版可以把 `transcript` 当正文）。
- 原消息上没有「已派给 X」的标，派了几次只能去那只的私聊里看。
- 每次长按派活都是那只私聊里的一条新开场白、起一轮；连着派三条就是三轮。
- 真机未验。
