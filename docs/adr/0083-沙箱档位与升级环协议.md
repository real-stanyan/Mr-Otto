# ADR-0083: 沙箱档位与升级环协议（v2 前置）

日期：2026-08-24
状态：已接受
关联：issue #346（codex orchestrator.rs 对照研究）；ADR-0001（Electron 主进程 = agent 核心）、AGENTS.md 硬规则（工具只依赖 ExecutionWorld）

## 背景

Mr Otto v2 计划 Docker per bot。codex 的执行环是现成的策略层参考：`审批 → 选沙箱 → 尝试 → 沙箱拒绝 → 带 retry_reason 二次审批 → 无沙箱重跑`。等 v2 动工时再定协议，SandboxWorld、审批 UI、事件 schema 三处要同时改；现在定下来，v2 只补一个按契约抛错的 World 实现。

## 决定

1. **档位三态**（`src/world/sandbox.ts`）：`none`（v1 现状，无沙箱无环）/ `external`（已在外部沙箱内：允许全盘访问，仍守网络设置；沙箱由外部实施，本进程无处可逃逸，环不存在）/ `container`（v2 Docker，唯一有升级环的档位）。ExternalSandbox 语义现在钉死，v2 上线不改协议。
2. **升级环是 world 装饰器**（`src/world/escalatingWorld.ts`，withAbortSignal 同款手法）：只包 `exec`；沙箱拒绝 → `requestEscalation({command, reason})` 二次审批 → 同意则无沙箱世界重跑。工具实现无感——硬规则"工具只依赖 ExecutionWorld"原样成立，不在每个工具里各写一遍编排。
3. **硬约束照抄 codex**：policy 含拒读路径（`denyReadPaths`）时升级分支**硬拒**——不弹窗、不重跑。拒读只有沙箱能实施，逃逸到无沙箱 = 对拒读清单的静默授权。
4. **只认确定性标记**：升级环只对 `SandboxDeniedError` 反应。**不抄** codex 的 stderr 关键词启发式（其源码自认不可靠）——判定责任下放给沙箱实现（v2 Docker 有确定 exit code / OCI 错误），判不出的失败照常上抛。

## 权衡

- **只包 exec，不包 fs**：codex 的升级场景就是命令执行；v2 里 fs 天然落在容器文件系统内，"逃逸到宿主盘重写"没有合法语义。真需要时另开决定，不顺手预埋。
- **二次审批的落盘在装配层**：`requestEscalation` 由装配接到审批 UI 并落事件（全链路可回放），装饰器只管问——事件 schema 的具体形状推迟到 v2 有真实调用方时再定，避免现在发明一个没人消费的事件类型。
- **v1 零接线**：LocalWorld 不建环，本 ADR 的交付物 = 协议 + 单测（协议即测试）。

推翻前提：若 v2 放弃 Docker per bot（比如改用进程级沙箱 sandbox-exec），`container` 档位语义要重审——但三态枚举与硬约束（拒读禁逃逸）预计仍然成立。
