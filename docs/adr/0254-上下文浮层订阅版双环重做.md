# ADR-0254：上下文浮层给订阅用户重做——钱整段删掉，两扇额度窗画成两只表

- 状态：已接受
- 日期：2026-09-08
- 关联：issue #1071；收窄 ADR-0209（那一段的位置与主次）；沿用 ADR-0239 的剩余口径与色档；复用 ADR-0240 的档位徽章；与 ADR-0248「订阅用户不许自带 API key」同一条产品线；ADR-0233 是它在云会话那侧的同款判断

## 背景

上下文浮层今天是四段：上下文构成 / 花费 / 套餐额度，加上顶上那个 hero 数字。给订阅用户看的那一段花费——hero 一个 `4 credit`、按型号拆开的价目表、一条占比条——回答的是**「这一次花了多少」**，而那是一个和他买的东西相矛盾的心智模型：他买的是「一段时间内随便用」。

**注意不是把 `$` 换成 `credit` 就完了**：`CostPanel.money()` 对 hosted 段本来就走 `fmtCredit`，所以订阅用户今天看到的已经是 credit——换了单位，心智模型没换。ADR-0248 之后订阅用户连自带 key 那条路都没有了，于是这一整段对他而言只剩「看着像账单的噪音」。

维护者在会话里过了四轮设计稿（本机 demo：四张卡对比 × 7 个场景 × 深浅两色 × 真机模拟台），定稿为「双环（额度）」。

## 决策

### 1. 钱整段删，判据挂在**日志**上，且不给替身

`showsCost(rows) = rows.some(r => r.route === "direct")`：有一笔走自己的 key 才画整段。

- **为什么不按 `isSubscribed(billing)` 判**：那是「此刻的订阅状态」，而这张卡报的是**这个会话已经发生的事**。一个昨天订着、今天退订的人，日志里那些 hosted 行的花销确实由额度承担过；反过来，订阅前跑过的 direct 行是真金白银，账要报得出来。日志是事实，billing 是状态。
- **不给替身**：草案里在末尾补过一行「本会话用掉 5 小时额度的 1.3%」（同一个事实换成会拦住他的单位）。维护者砍掉：换了单位仍然在回答「这一次花了多少」，等于把按次计费的心智从后门请回来。**那一格就是空的，这是对的。**
- 推翻这条的前提：如果哪天产品口径回到「订阅也按次显示消耗」，这条判据要连同 ADR-0248 一起重议。

### 2. 两扇窗画成并排两只表，**平级**

ADR-0209 当时是主/次两条条子：先拦住人的那扇会变色，另一扇永远中性灰。现在两只 62px 的环并排，**谁先拦住人由颜色说，不由大小说**——周窗吃紧时右边那只变色，布局一个像素都不动。

- 好处是「哪扇当主」这个判断从**布局**降级成**着色**：`bindingWindow` 在这一段不再需要（它仍服务设置页与别处）。
- 代价：两只环比两条条子高（约 +30px）。这张卡本来就删掉了一整段，净高度是降的。

### 3. 环填**剩余**，色档按**已用**判

与设置页、上下文环共用的那组阈值（>90 危 / >75 警）。填已用的话，闲着的账号是两只几乎空的环——在屏幕上和「组件坏了」一样（#1026 已经为条子付过这笔学费）。同一件事的两个说法，判据只能有一份。

环心两行是 `98.6%` + 「可用」：**只写一个百分数会读成「已用」**。

**充足时是中性灰不是品牌蓝**：颜色在这两处只用来说「出事了」。

### 4. 清零的窗不画倒计时

窗口过了 `resetAt` 之后不存在「几点恢复」（5h 窗要等下一次调用才重新开窗）。原来那版会同时说「100.0% 可用」和「已恢复」，两行自相矛盾，读者得停下来想一秒。`countdown()` 自己不动（别处还在用），判断落在调用点的 `w.rolled`。

### 5. hero 数字改用 K

`865,481` → `865.5K`。这张卡上别的数（图例 `52.7K`、窗口 `1M`、剩余 `134.5K`、脚注 `379K`）本来就是这把尺子，只有最大那个数用逗号分组，读者要在同一张 300px 的卡里换两次读法——而它还是被对比得最频繁的那个（`865.5K / 1M` 一眼是比例）。

为此 `NumberTicker` 加两个本仓改动：`format?`（数字怎么写可换，滚动照旧）与 `label?` 改成可选（说明挪到右边同一条基线上，原来在数字底下、把卡撑高一行）。`fmtCtx` 从 `App.tsx` 的模块私有函数搬进 `lib/fmtTokens.ts`——现在有三个消费方。

代价：精度从个位降到百位（`fmtCtx` 对 ≥100K 不带小数），滚动时最后一位每 100 token 才动一格。它仍然是活的，只是不再每个 token 都跳。

### 6. 顺序：额度在上、上下文在下

**已知张力**：触发器是**上下文**那枚环，悬停后主语却在卡片下半——「从哪来回哪去」（apple-design §7 的锚定原则）断了一截。维护者看过两种顺序的实物后选了这个：额度是会真正把人拦住的那一个，而上下文满了还能压缩。

分隔线挂在额度那一段**自己的下沿**：它 `return null` 那天线跟着消失，下面那半不用知道上面有没有画（调用方判分支迟早会漏一种）。

### 7. 图例两列、按大小降序、零值行保留

- 两列：额度那半上了两只表，四行一列会把卡拉太长。
- 降序：**行序本身就是「谁吃掉了它」的答案**。条形段仍按固定顺序（前三段是每轮重付的固定开销，排在一起才看得出底噪有多厚）。
- 零值行留着但压成弱色：删掉会让卡片在类别出现/消失时抖动，而「这个类别存在且是空的」本身是信息。
- 单位 `tokens` 从每行撤掉：两列排下来它要出现四次，而这张卡上的数现在是同一把尺子。
- 条尾那截空白第一次有了名字（右上角 `剩 943.9K`）——这张卡两半现在都在答同一个问题。

### 8. 型号脚注一行到底 + 厂商 logo

原来这一行会**折成两行**（型号名折一次、右边那串折一次），而一行脚注折成两行之后，它「扫一眼」的全部用处就没了。

- 整行 `whitespace-nowrap`；右边那串是定长事实（`shrink-0`）；**挤不下时让步的只有型号名**（`truncate`）——反过来截数字等于把这一行唯一的量化信息弄丢。
- **`tokens` 这个词省掉**：实测最长的型号名（`kimi-k2-turbo-preview`）配完整右串要 304px，卡内可用宽度只有 274px。省一个单位词比截型号名便宜，何况这张卡上别的数本来也是裸数。完整那份（带单位、带全名）进 `title`。
- logo 是**打进包的本地 SVG**（simple-icons，CC0），画法照抄 `McpEntryIcon` 的 mono 那一档（mask-image + currentColor）：品牌色摆进一行 11px 的弱色脚注里会比旁边的字还响。**永远不接远程地址**——让渲染进程去加载第三方地址，等于每画一次型号名就把用户 IP 报给那家厂商。
- `PROVIDER_MARK` 是穷举 `Record<ProviderId, string | null>`：目录里加一家新厂商不来写一笔，tsc 直接红。`null` 不是「以后再补」——simple-icons 里确实没有智谱 / xAI / Groq / 硅基流动的标，**自己描一个「差不多像」的比画首字母更糟**，logo 的全部用处是让人一眼认出来，认错了比认不出更坏。
- **认不出的型号一律不画标**，不走 `resolveModel` 的 DeepSeek 兜底——那条兜底存在的理由是「发得出请求」，画到界面上就成了给一个陌生型号挂上鲸鱼。

### 9. 档位徽章复用 `PlanBadge`

不新写色表：「Lite 是什么颜色」的答案只能有一份（ADR-0240）。传的是 `planBadge(me)` 的 id 不是 `me.plan`——`null`（还没查到）不许退成 Free。

## 代价与已知未做

- **真机没验**：这张卡要有活跃订阅 + 一个跑过几轮的会话才画得全，本机门禁（jsdom）验的是结构与判据不是像素。设计稿那份在浏览器里逐场景看过（含深浅两色、额度吃紧/用完、周窗先拦住、自带 key、billing 未查到）。
- **`--warn` 在这张卡上有两个含义**：Max 的徽章借的是它（ADR-0240 记过这笔账「借形不借义」），而同一张卡上「5 小时窗 12% 可用」的告警橙也是它。搬进这张卡等于把冲突拉近了。哪天要给 Max 拆出自己那格颜色，这里是第二个理由。
- **触发器上仍然只有上下文**：额度用完那一刻静息界面一个字都不说（ADR-0209 的注释早就承认「不悬停就看不见」）。设计稿里试过「额度进 warn/deny 时环外补一道细弧」，本次不做，另开 issue。
- 环的几何（62px / stroke 4.5）与两处 Tailwind 字面量之间的关系**没写成断言**：那是布局算术，jsdom 量不出来，扫源码的正则会在任何无害重构上翻红（同 ADR-0236 第 1 条 `pb-14` 那笔账）。保鲜期在紧挨代码的注释里。
- `MAX_MARKS = 3`：多款型号时最多画三枚标，再多就把右边那串挤没了。
