# ADR-0255：额度吃紧时，输入框那枚环右上角亮一枚点——不是环外补一道弧

- 状态：已接受
- 日期：2026-09-08
- 关联：issue #1073（ADR-0254「代价与已知未做」第三条开的那一条）；收窄 ADR-0209 的已知代价；沿用 ADR-0239 的色档与阈值；`null` 那一态的纪律同 ADR-0240

## 背景

额度那两扇窗只画在上下文浮层里。`PlanQuotaSection` 的文件头自己承认了这件事——「**不悬停就看不见**；真用完那一下靠时间线上那条 `route_changed` 说话」——ADR-0209 当时把它记成已知代价，#1071 重做那张卡时也没动。

而**额度是唯一会真正把人拦住的那一个**：上下文满了还能压缩，额度用完那一刻只能等。于是最该被看见的那件事，是这张卡上唯一要先悬停才看得见的。静息界面上一个字都不说。

## 决策

### 1. 一枚点，不是环外那道弧

#1073 的标题写的是「环上补一道额度弧」，它自己的「要想清楚的两件事」第一条也点了这个名：内外两道弧共用一个圆心，而**上下文 >75% 走的也是 warn**——最坏形态是「橙内环 + 橙外弧」，两道同色暖弧只差一两个像素，那时人分不出是哪一个在告警。

而这个记号存在的全部理由，就是让人一眼知道**是额度出事了**（否则他会去按压缩）。所以取 issue 里列的另一个候选：一枚独立的点。形状不同、位置不同，「橙环 + 橙点」仍然分得开。

（第三个候选「告警时把百分数换成一个词」在这里不存在：触发器上只有 `RingVisual`，没有 `RingPercentLabel`。）

**代价：点不报量级**。这是有意的——issue 自己写着「它是『快满了』的信号，不是读数」，而 18px 的环外一道 1.5px 的弧，弧长本来也读不出什么。量级由悬停之后那两只 62px 的表回答（ADR-0254 决定 2）。

### 2. `null` 与「没订阅」都不画，且理由不同

- `billing === null`（还没查到）：冷启动那一瞬间渲染层手上必然是 null。画成「没事」是撒谎，画成「告警」是吓人——同 ADR-0240 那枚档位徽章为什么不许把 `null` 退成 Free。
- `windows === null`（没有活跃订阅）：他**没有额度可言**，那不是「额度充足」。同 `PlanQuotaSection` 那条「报一份满额度的窗口是谎话」。

两者在这里给同一个答案（不画），但记在两条上：哪天要给免费用户画点别的，这两条会分家。

### 3. `exhausted` 排在百分比前面

`BillingSnapshotView.exhausted` 是网关**亲口说的**「此刻拦住你了」；百分比是从响应头换算出来的推论。两者多数时候一致（`hostedQuota` 在响应头报剩余为 0 时同时置两者），但**只走 429 那条路时 `windows` 不更新**——光看百分比会漏掉本条 issue 标题说的那一刻。

渲染层这份快照是 push 来的、**不会自己在 `resetAt` 那一刻过期**，所以这里跟 `hostedQuota.liveExhausted` 一样现算：过了 `resetAt` 的记号不算数。

### 4. 判据抽成纯函数，不留在 JSX 里

`quotaAlert(billing, now)` 落在 `lib/billingView.ts`，两个消费方：点的颜色、钮的 `aria-label`。抽出来的第二个理由是「**什么时候不许画**」这件事有三条判据、每条都对应一个失败模式，写进 JSX 的 `&&` 链里就没有保鲜期了。

色档走 `bindingWindow` + `quotaTone`——与浮层那两只表、与设置页**共用同一组阈值**。分家的那天，点亮着而卡里两只环全是灰的，人会先怀疑这个点坏了。

### 5. 话进 `aria-label`，点自己不带 `title`

这枚钮当初就是为了不跟富浮层抢同一次悬停才不给 `title` 的（App.tsx 原注释：「原生气泡会在它旁边再冒一个，成了重影」）。给点加一个 `title` 等于把那笔账重新欠上。

于是 `aria-label` 从常量变成 `上下文用量详情 · 额度：5 小时窗仅剩 18.0%`——它同时是读屏软件在这枚点上**唯一**的出口（点本身 `aria-hidden`）。

### 6. 光环取 `paper`，不取 `ring-background`

`ring-2 ring-background dark:ring-popover`：输入框那张纸是 `lib/surfaces.tsx` 的 `paper = bg-background … dark:bg-popover`，深色下它是 popover 不是 background。抄错一个 token 的后果不是报错，是常年挂着一圈看得见的浅边。

光环顺带干了正事：18px 的环塞在 24px 的钮里，对角上只剩三个多像素，不打光环两者会糊在一起。

### 7. 表 60 秒一跳，作用域圈在这一枚钮里

`exhausted` 的记号与 5h 窗都会自己到点失效，而这枚钮是**常驻的**——浮层关着时整棵子树不挂载，它没有这个便宜可占。不走表的话，一个睡了一觉回来的人会对着一个早就恢复了的红点，而**常年挂着的假警报比不报更坏**。

为此把「钮 + 环 + 点」整块搬进 `ContextRingTrigger`：每分钟重渲的只有这一枚钮，不摊到整条 composer 上（那一层每个 token 都在重渲，不该再多一颗表）。

### 8. 不做入场动效

它是一个会挂一整天的状态记号，而不是一次事件。想只在「刚跨过 75%」那一刻动一下，就得记住上一帧的值；`@starting-style` 与 keyframes 都做不到这件事——它们会在每次挂载时都放一遍，于是换个会话、开个 app 都要闪一下（同 emil-design-eng 那条「一天看几十次的东西不要动效」）。

## 代价与已知未做

- **`ctxWindow === null` 时整枚钮不画**（型号的上下文窗未知就不画环，issue #193），那时额度告警也无处可挂。订阅用户跑的都是网关供着的型号，走不到；留在这里当账记着。
- **真机没验**：要有活跃订阅 + 一扇烧过 75% 的窗才画得出来，本机门禁（jsdom）验的是判据与类名，不是像素。承接 ADR-0254 同一笔债。
- 点与环的几何（6px / 光环 2px / `right-[1px] top-[1px]`）**没写成断言**：那是布局算术，jsdom 量不出来，扫源码的正则会在任何无害重构上翻红（同 ADR-0236 第 1 条 `pb-14` 那笔账）。保鲜期在紧挨代码的注释里。
- **`remainingPercent` 有一个浮点毛刺**：`80/100` 已用时真值 `19.999999999999996`，向下取整写出来是 `19.9%` 而不是 `20.0%`。它不是本条引入的（设置页与浮层那两只表读的是同一个函数），另开 issue，本 PR 不顺手改——那是一处会同时改变三个界面读数的共享函数。
