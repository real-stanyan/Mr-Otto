# ADR-0157：每只水獭都拿独立工作副本——取消「第一只不隔离」的例外

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #644；**推翻 ADR-0156 的「第一只不隔离」那一条**（其余部分全部沿用）；#643（UI 与回收，优先级因此上升）

## 背景

ADR-0156 让第二只水獭拿独立工作副本，但给第一只留了例外——直接在用户点的文件夹里干活。理由是不想让第一次用的人就面对「你的活在别的目录、回头要 merge」。

维护者要的是与 Claude Code 完全一致的行为。那条例外取消。

## 决策

**工作区在 git 仓里，就开副本。** 判据从三条收窄成一条。

### 为什么一条规则好过一条规则加一个例外

例外的代价不只是多一个分支判断：

- 用户要理解「什么时候会隔离、什么时候不会」——而这个条件（有没有别的会话活着）他看不见；
- 两只水獭形态不一致：第一只在原目录、第二只在副本，同一个项目里两种语义；
- 第一只关掉之后第二只还在副本里，此时再开新会话又变回原目录——状态依赖于历史，解释不清。

一条规则没有这些问题。

### 代价是真的，缓解写进提示词

**用户打开自己的项目目录会看不到任何改动**，直到合并。这是这套隔离的全部风险，ADR-0156 当初正是为它留的例外。

缓解不是把例外加回来，而是让水獭**主动说**：系统提示里明写「用户很可能不知道有这份副本，**第一次动文件之前**先用一句话告诉他：你在一份独立副本上干活、他的项目目录暂时不会变、要合回去随时说」。

这句话有测试钉着（`tests/shared/sessionWorktree.test.ts`）——掉了它就是静默的困惑：用户以为水獭什么都没干。

### 没变的

- 非 git 目录 / `worktree add` 失败 → 退回原目录，ADR-0152 的互斥在那儿兜底
- 旧会话（日志里没有 `isolated`）resume 后仍在原目录——向后兼容硬规则
- 子会话 / SideChat 不走这条路，直接继承父会话的 workspace
- 副本落点、判据用 `--git-common-dir`、`session_created.isolated` 落盘 —— 全部沿用 ADR-0156

## 后果

- 接受：每个 git 项目的每个会话都会产生一个 worktree 和一条 `otto/*` 分支。**回收（#643）从「早晚要做」变成「必须做」**——不做的话副本会一直攒。
- 接受：用户第一次用就会遇到副本这件事。缓解只是一句提示词，**不是 UI**；真正的解法是 #643 那张牌。
- 接受：`shouldIsolate` 现在不看 live 会话，`startSession` 里那段家族/仓库快照随之删掉——少一次查库、少一段代码。
