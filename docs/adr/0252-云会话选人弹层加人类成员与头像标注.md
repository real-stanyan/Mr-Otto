# ADR-0252：云会话 @ 选人弹层——名单里加**人类成员**，一行 = 头像 + 名字 + 「成员 / 智能体」

- 原为 ADR-0249（合并前 re-fetch 撞号：0249 被「选单三处收窄」那篇先占，ADR-0074）
- 状态：已接受
- 日期：2026-09-07
- 关联：issue #1059（本条）/ #1064（真通知，本条**不做**）；ADR-0220（@ chip 输入与 `openTurns`）/ ADR-0228（`resolveSendMentions` 把两件事分开说）/ ADR-0226（`profiles.name` 是从没过写入校验的自由文本）/ ADR-0219（`agentView`：群里两族都在同一份日志上）/ #831（本地 @好友 弹层，同一版式的先例）
- 来源：维护者给了参考组件 <https://www.assistant-ui.com/elements/composer-mentions> 与截图，原话「用这个 UI 组件来做工作区里 @人类组员或智能体的 UI：左边那个圆圈展示智能体或人类用户组员的头像，右边标注是人类还是智能体」

## 背景

云会话是**群聊**：一个工作区里既有 agent 也有人类成员，成员发的话、头像、署名在时间线上一直画着（#971 的 `SpeakerRow` / `PersonAvatar`）。唯独打 @ 的那一刻他们不存在——`candidates` 只取 `ws.agents`。

后果不只是"少几行"：`resolveSendMentions`（ADR-0228）把「正文写了 @token，一个候选都解析不出来」判成**用户打错了名字**并整句拦下。于是在群里 @ 一个真实存在的同事，得到的是一句红字「没有叫「张三」的智能体，检查一下名字」——这句话的每一个字都是错的。

本地会话那条 @好友 弹层（#831）早就是维护者要的版式（头像 + 名字 + 靠右那格），但它挂在 assistant-ui 的运行时上（`ComposerPrimitive.Unstable_TriggerPopover`），而云会话的输入框是手写 `Textarea` + Radix `Popover`，两条路共用不了组件。所以这次是把**版式**搬过来，不是把组件搬过来。

## 决策

### 1. 名单两族并排，agent 在前

`src/renderer/src/lib/workspaceMentionItems.ts` 的 `mentionRows(ws)`：agent 保持快照顺序在前（服务端按 `created_at` 升序，第一只是管理员），人类成员在后。

不按字母混排的理由：这枚 @ 在这个输入框里的主要用途是**把活派给一只 agent**——只有那一族会接话。排前面意味着默认高亮（下标 0）落在一只 agent 上，「打完 @ 直接回车」做的是有用的那件事。

截图里没有分组头，这里也不加：右边那格标注逐行说清了族属，再压一层组头是同一件事说两遍。

**自己也在名单里**。@ 自己在群聊里确实没用，但摘掉就要维护两份名单——列表一份、"这个 @ 认不认得"（`resolveSendMentions`）另一份——而后者**必须**含自己，否则用户 @ 了自己的名字会被拦下来说「没有叫 X 的成员或智能体」，而那个 X 就是他本人。一份名单，一条判据。

### 2. @ 一个人类成员今天只发生一件事：名字进正文

维护者选的是「要真通知（先只开 issue 不做）」，所以本条**只做 UI**，通知另开 #1064。

今天的语义因此是：那个名字进正文，房里所有人（含各只 agent 的上下文）看得见，**不起 turn、没有任何提醒**。

落地是**服务端零改动**：`resolveTargets`（`sessionService.ts`）按 agent id 的集合过滤 `mentions`，人类 uid 放进去只会被静默丢掉——所以客户端只把 agent 那几个 id 填进 `mentions`，只 @ 人时就是 `[]`，服务端照 `targets.length === 0` 那条分支只落一条 `chat_message`。

这推翻了 `resolveSendMentions` 文档里那句「这个函数**永远不会**在正文写了 @token 时返回 `[]`」（ADR-0228 立的）。新规则：有且只有一种情形返回 `[]`——那几个 @ 全都点在人类成员上。那时「没点任何 agent」是**事实**，不是"算不出来"，与它要防的那个失败模式（把算不出来伪装成权威的空数组）方向相反。

### 3. 「这个 @ 认不认得」复用 `parseMentions`，且排在 `fresh` 之后

判据不是拿 `mentionTokens` 的结果去比字符串——token 是**贪婪吃到空白为止**的（`@Mingxuan Zhang 看下` 切出来只有 `Mingxuan`），而 `parseMentions` 走 `startsWith` 最长匹配。两套切词判据分家，就会出现「弹层里点了这个人、发送时说不认识他」这种撕裂。所以人类成员按 `{agentId: uid, name: label}` 递进同一个函数，只用来判认不认得，**uid 永远不进 `mentions`**。

**顺序**：这道判断排在 `parseMentions(text, freshCandidates)` 之后。成员的显示名来自 `profiles.name`——那是一格自由文本，从来没过 `validateAgentName` / `agentNameConflict` 那套前缀检查（ADR-0226 点过同一件事）。于是「成员与 agent 撞名」是可能的，而本地名单健康时 `parsed` 会先命中、这句话归 agent 接。排在后面，「名单读得出来」与「读不出来」两条路对同一句话给出同一个接话人；反过来排就分家了。

`memberCandidates` 是**可选参数**：缺席 = 行为与改动前逐字相同。

### 4. 撞名要在列表上说出口

`memberShadowedBy(memberName, agentNames)`：成员名字**以某个 agent 名字开头**（含完全相同）时，正文里那句 `@名字` 一律被 `parseMentions` 解析成那只 agent——

> agent「运营」+ 成员「运营助理」→ `@运营助理` 里最长匹配吃掉「运营」就收工（「运营助理」不在它的名单里），于是 agent 运营接了这一棒。

反方向不成立：成员「运」+ agent「运营」时 `@运` 不满足 `startsWith("运营")`，那句话谁都没点到——正常状态，不报警。

不标出来的话，用户点了写着「成员」的那一行，回来接话的却是一只 agent，而界面上没有任何一个字解释过——#722「撒谎的勾」的一般形式。所以中间那格灰字优先画 `@ 会点到智能体「运营」`。

同名成员（两个人的 `profiles.name` 一样）补一段 uid 前缀。功能上确实没差别（都不起 turn），但列表上两行一模一样会让人以为看花了眼。

优先级 **会被抢走 > 重名 > 职责 > 空**：那一格会截断，两样都塞等于两样都读不到，而前两条说的是「这一行和你以为的不是一回事」，比「它是干什么的」更该占这格。

### 5. 显示什么就搜得出什么，标注也算一格

`filterMentionRows` 匹配名字 / 中间那格灰字 / **右边那格标注**。前两条是 `filterAgentCandidates` 原有的口径；把标注也算进来是照 `friendMentionItems.ts` 立的那条纪律（「列表上写着的字，必须搜得出来」——界面摆出一个字段又不认它，和界面骗人是同一类毛病），顺带 `@成员` 能把人类那一族筛出来，在一个几十行的工作区里这是最省事的一次筛选。

`filterAgentCandidates` 因此没有了消费方，连同它那三条断言一起删——动机是同一个 PR 里的产品改动（名单从"只有 agent"扩到两族），不是"删测试换绿灯"。

### 6. 版式与动效

一行：**20px 头像 · 名字 · 灰字 · 靠右的标注**。

- 头像 20px 不是气泡旁那两处的 24px（`Avatar size="sm"`）：这一行字号 12.5px，脸跟气泡一样大会把行撑到 34px，一屏少两行。所以 `MentionAvatar` 是单独一个组件，尺寸是它与 `PersonAvatar`/`AgentAvatar` 唯一的差别，但它决定整张列表一眼能扫几行。两族画法不同（agent 内置像素头像 / 成员 `profiles.avatar_url`）——头像是「这一行是谁」的第一眼，标注是给撞脸、没头像的情形兜底的第二道。
- 名字**可截断**（原来 `shrink-0`）：标注是常驻的，再加一个不肯让位的名字，长名字会顶破这张 320px 的卡。截了还能悬停看全（`title`）。
- 高亮**不给 transition**。上游那份带 `transition-colors`，因为它主要靠鼠标悬停；这一行是方向键连着按出来的，一次挑人可能扫过五六行，补间会让高亮拖在手指后面——键盘发起的动作不做动效。
- 标注文案取「成员 / 智能体」不照抄截图的 `human / agent`：设置页里人类那张表就叫「成员」，agent 一律叫「智能体」，同一个东西在两块屏幕上不能有两个名字。

配套改的文案三处：空态与拦截语从「没有叫「X」的**智能体**」改成「**成员或智能体**」，@ 按钮的 `title`、输入框 placeholder 跟着改。

## 代价 / 已知天花板

- ~~**@ 一个人不会惊动他**。这是维护者明确选的这一版形状，通知在 #1064。~~ **已还（#1064 / ADR-0256）**：被 @ 的成员会收到一条系统通知 + 侧栏角标。列表上仍然没有任何一个字说这件事——当初不写是因为它会过期，现在不写是因为它已经不成立了。
- 只 @ 了人 + **服务端名单降级**（`workspace_agents` 查询失败）时整句被拒：`say()` 的 `mentionedSomeone` 判据含 `mentionTokens(text).length > 0`，一句只 @ 人的话在它眼里也算"点了名"。降级路径的既有行为，本条没有让它更糟，也没有修。
- 一句话里既有认得出的名字、又有拼错的名字时，拼错的那个静默不管——那是既有规则（`@管理员 @不存在` 今天也这样），不是本条新开的洞。
- 弹层的真机验收没跑（要先部署 runtime + 起一条云会话，见 `cloud-ui-smoke-needs-runtime-deploy`）。纯逻辑两族、撞名、过滤、六条发送规则都有断言；版式那一层靠的是 `composer-trigger-popover.tsx` 这份已经在跑的先例。
