# 0056 子智能体只扫自己的目录,不再读 .claude/agents

## 状态

已接受(2026-08-22)。部分撤销 ADR-0048:去掉扫描表里的第 2、4 条根。

## 背景

ADR-0048 把 `<工作区>/.claude/agents/` 和 `~/.claude/agents/` 当只读根一起扫进来,
本意是复用用户在 Claude Code 里写好的子智能体。实际用下来:

- 那些定义的 `tools:` 用的是 Claude Code 的工具名(Grep/Glob/…),本仓一个都不认,
  列表里每条都挂着「N 个工具名无法识别」,真跑起来只剩没被点名的几把;
- 它们是只读的,改不了、又占着名字,用户得先「复制」一份才能动——多一步,而且
  复制出来的那份还是带着对方的工具名;
- `task` 工具的描述把全部清单喂给模型,模型会按描述把活派给这些半残的定义。

## 决策

扫描根只剩两条:`<工作区>/.mr-otto/agents/`(workspace)、`~/.mr-otto/agents/`(user),
都可写。`readOnly` 字段保留(内置定义仍靠它标「改不了」),但磁盘扫描不再产生
只读条目。skill 的 `~/.claude/skills` 兜底(ADR-0007)**不动**——skill 是纯提示词,
没有工具名对不上的问题。

## 后果

- 之前靠 `.claude/agents` 自动出现的子智能体从清单消失;要用就在设置页新建一份。
- `subagentRoots()` 的 `readOnly: true` 分支没有磁盘来源了;`writeSubagent` 的
  只读保护照旧(内置定义 materialize 那条路还用)。

## 后续（2026-08-24，issue #268）

上面「`readOnly: true` 分支没有磁盘来源了」这句当时只是记了一笔，代价直到 e2e
把清单跑一遍才浮出来（PR #266）：渲染层那一整条**只读定义 → 复制到本层**的路
从此没有入口——行上的「只读」徽章、编辑页的「复制到 X 这一层」按钮、以及给副本
取名的 `freeCopyName`（`-copy` / `-copy-2`，连同它的三条单测）全都点不到了。

删掉了，理由是 ADR-0056 当初是**主动收窄**边界（「Mr Otto 里只该看见 Mr Otto
自己配的」），不是「还没来得及做」；留着等于押注一个没人提过的需求，而真接了
第二层只读来源（团队共享目录之类）那天，要一并处理的是同步和冲突，那 30 行 UI
大概率也是重写。维护者 2026-08-24 会话内拍板。

**留下的**：`SubagentDef.readOnly` / `SubagentRoot.readOnly` 字段（数据模型，内置
那三份仍靠它标「改不了」）、以及 `writeSubagent` 的只读保护（写入边界上的防线，
不因为此刻没人踩得到就撤）。

**推翻它的前提**：真出现第二层只读来源。那时重写 UI，取名逻辑按当时的同步语义
重新设计，而不是把这段找回来。
