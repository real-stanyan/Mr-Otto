# ADR-0306：云会话断了时语音怎么收口——`gone` 不是通话结束

> 原为 ADR-0305（项目 ADR-0074：编号在合并时认领）。合并前 re-fetch 撞上 PR #1317

- 状态：已接受
- 日期：2026-09-21
- 关联：#1289（承接 #1281 / PR #1288 的终审）、ADR-0271（团队语音通话）、ADR-0273（本机 STT）、ADR-0299 第 7 条 seam

## 背景

`src/renderer/src/store.ts` 的 `onCloudSessionStatus` 收到 `gone` / `denied` 时只改
`cloudSession.state`，**不碰 `voice`，也不碰 `hold`**。

#1281 把「离开语音」的收口收成了一个出口（`flushHeld(get)` → `stopMic()`），六条真正
「离开语音」的路径一条都绕不开它，并且用一条断言钉住了「每一次裸 `stopMic()` 都必须紧跟
在 `flushHeld(get);` 之后」。`onCloudSessionStatus` 是第七条——它不是「离开语音」，它是
**会话在底下没了**，绕开那条断言的方式是压根不停麦，断言够不着。

issue 给了两个候选，并要求先回答一个问题：**「人确实说了」这条理由在会话已经没了的时候
还成立吗**。

## 开工后查出来的两条事实，两个候选都要据此修正

### ① `gone` 不是终态，它会自愈

`src/main/cloudSessionClient.ts` 的 `:peer` 分支（约 1049 行）：runtime 回来时
`gone → connecting → ready`，而 `CloudSessionPage.tsx` 的 `statusBanner` 在 `gone` 这一档
画的正是「云端连接已断开，**正在自动重连…**」。

所以候选 1 那句 `stopVoice(get)` 若跟着 `set({ voice: null })`，就是「daemon 重启一下，
这场通话被永久杀掉」——而通话名单是日志事实（`voice_call_changed`，ADR-0271），重连之后
它还在，只有本机这一格回不来了，页面却还在承诺重连。

`denied` 才是终态：`markDenied` 里明写「denied 没有重试的意义……主动断开，别留一条注定
失败的连接空转」。issue 把两者并称「终态分支」，它们不是同一件事。

### ② `flushHeld` 不接 ack，「发出去」在这条路上就是静默丢失

```ts
for (const fx of flushed.effects) if (fx.type === "send") void get().cloudSay(fx.text, [], [], true);
```

没有 `.then`。而 `speechOnEvent` 里的 `sendSpoken` 接了，失败写进 `voice.mic.error`。

于是候选 1 按字面实现是**倒退**：issue 自己描述今天的后果时写着「用户看到的是麦克风那一行
的错误，**不是静默丢失**」——那条路走的是封顶 → `tick` → `sendSpoken`（接 ack）。改成
`stopVoice` → `flushHeld` 之后，同一句话改走一条不接 ack 的路，失败从此无声。

## 决策

### 1. 那个问题的答案：不成立，但「不成立」不等于静默丢

`reset` 分支那句「人确实说了」的完整形式是「人确实说了，**而且此刻还有地方可送**」——
`flushHeld` 自己的注释就写着「这句话才赶得上此刻还开着的房间」。会话没了，后半句结构性地
不成立：`requireReady()` 对 `status !== "ready"` 必拒。

所以新增 `abandon` 事件：扣着的、等着的都清掉，**不发**，回一条 `drop` effect 带上丢掉的
原文；调用方把原文写进 `voice.mic.error`（「云端连接断了，这句话没送出去：「…」」）。

清掉不等于静默——这是本条与「只清不发」那个候选的全部分别，也是为什么不能用
「发一次必然被拒的 `cloudSay`」去间接产生那句提示：那条路今天不接 ack，而接上 ack 之后
文案是主进程的「云会话未就绪」，说的是**连接**，不是**你刚说的那句话**。

### 2. `gone` 与 `denied` 分开，判据是「会不会自愈」

- **`gone`**：`abandonHeld` → 停麦 → `mic` 归 `off`（**留着刚写上的 `error`**：那是这一刻
  唯一说得出「你刚说的那句没了」的地方）。**通话保留**，播放器也不停——TTS 走 edge 网关，
  不经这条断掉的连接，队列里那几句是真的。
- **`denied`**：`abandonHeld` → `stopVoice(get)` → `voice: null`，整段收掉。
  `abandonHeld` 排在 `stopVoice` 前面，于是后者内部那次 `flushHeld` 落在一个已经空了的
  `hold` 上——「发」这条路在这里是**关着的**，不是碰巧没走到。

### 3. `gone` 停的麦，`ready` 回来自己开回去

模块级 `micWantedAfterReconnect`：只在 `gone` 时置位（取 `micStarted` 的当下值），
`ready` 用掉即清。**人自己碰过麦克风开关、或整段离开语音，一律清掉**——他表达过意志，
压过这条自动恢复（`setVoiceMic` 两个分支都清，`stopVoice` 也清）。

不做自动恢复的那个选项是诚实的（麦哑了，用户看得见麦克风钮是 off，自己点一下），但闪断
是常见的（daemon 重启），每次都要手点一次，而页面同时在说「正在自动重连」——两处说的话
会不一致。

### 4. 接线排在 `set` 之外、之前

副作用不写进 `setState` 的 updater（StrictMode 跑两遍，同 ADR-0264 那笔账），而且它读的
`prev` 正是这次 `set` 即将覆盖掉的那个 `cs.state`。

判据（`cs.sessionId !== sessionId` 早退）与 `set` updater 第一行逐字相同：那个回调在渲染层
是全局的，会话换了它照样收推送，分家的话别条会话的 `gone` 会把这条会话的麦停掉。

### 5. 收口从此有两种，断言跟着放宽的是「认几种形状」不是「可以不收口」

`utteranceHoldWiring.test.ts` 那条「每一次 `stopMic()` 都紧跟在 `flushHeld(get)` 之后」
改成「紧跟在**某一种**收口之后（`flushHeld(get)` 或 `abandonHeld(set)`）」。守的仍是同一句
因果：停麦之前必须先给扣着的那句一个去向。新写一条自己平铺 `stopMic()`、两种收口都不提的
路径，照样让两个数不相等。

另加两条：`abandon` 的实现只有一份（与 `reset` 那条对称）；`voiceOnCloudState` 真的接在
`onCloudSessionStatus` 上、且在 `set` 之前（这一格 `voiceStore.test.ts` 的真跑够不着——
它直接调 action）。

## 否决的候选

- **候选 1 字面实现**（`gone` 分支里调 `stopVoice(get)`）：上面两条事实各否决它一次——
  杀掉一场会自愈的通话；把会说话的失败改成静默。
- **给 `flushHeld` 接上 ack，照 reset 发**：零新机制，但文案是主进程的「云会话未就绪」，
  说的是连接不是那句话；而且它仍然是一次注定失败的发送——用失败去产生提示，绕。
- **只清不发、什么都不说**：最小改动，但把一个会说话的失败变成静默，本仓纪律反对。
- **`gone` 时也整段收掉**：见事实 ①。
- **`gone` 时不停麦**（只清 hold）：人对着一个断了的房间说话，每一句 `final` 都会被拒、
  helper 还在录还在耗电，而那一行错误会被下一句覆盖。

## 已知代价

1. **`denied` 时那句话仍然是静默丢的**：`voice` 归 null，通话栏没了，`abandonHeld` 刚写进
   `mic.error` 的那句立刻跟着消失。承担它的是页面那条红色横幅（`cloudDeniedMessage`）——
   用户明确知道这条会话进不去。要让它也说出口，得给 `denied` 留一个通话栏，而那是撒谎。
2. **`micWantedAfterReconnect` 是模块级的一格状态**，不是从任何事实推导出来的。它错的方式
   有界（多开一次麦 / 少开一次麦），但它确实是本条引入的第二个真值来源。
3. **`gone` 期间人继续说话会怎样，没有改**：麦已经停了，所以 helper 不再产出——但如果
   `stopMic` 那条 IPC 在路上、helper 又吐了一条 `final`，它仍会走 `sendSpoken` 被拒，
   错误行照旧。这是个窄窗口，没有为它加闸。
4. **真机一次没跑过**：`gone` 要真把 VPS 上的 daemon 停掉才复现得了。
5. `drop` 这条 effect 在 `runHold` 那条路上产生不了（只有 `abandon` 会），那里写的是
   `else if (fx.type === "drop") continue;` —— 一条今天跑不到的分支。留着是因为去掉它就要
   把 `else` 兜底请回来，而兜底正是 tsc 这次替我们抓到的那个洞（`drop` 没有 `at`，会被当成
   一个 NaN 的定时器静默排进去）。
