# ADR-0088：已归档会话是侧栏的独立视图，不是列表底部的折叠区

- 日期：2026-08-25
- 状态：已接受（修订 ADR-0087 的 UI 落点那一段，归档的语义/日志部分不变）

## 背景

ADR-0087 给归档定了两件事：① 归档是**状态事件**，日志一字不删、随时可恢复；
② UI 上归档的会话不进工程组，收在侧栏**底部**一截默认收起的「已归档」折叠区。

第 ② 条在会话攒多之后不成立：侧栏主体是按工程分组的长列表，底部折叠区实际上
藏在滚动条尽头。归档的本意是「眼不见」，但代价不该是「找不回来」——ADR-0087
自己写的「必须有回来的路」，那条路在长列表里等于没有。

## 决定

已归档从「列表末尾的一截」升级为侧栏的一个**视图**，和设置模式同一套互斥逻辑：

- 入口是「＋ 新会话」正下方一颗**次级**按钮（不描边、字色压一档、带条数角标）：
  上面那颗是「开始干活」，这颗是「去翻旧账」，不是并列的两件事。
- 点击 = 整个侧栏切成归档列表，顶上一条「返回会话列表」；再点入口原路返回。
- 入口**常驻**（不随条数显隐），所以归档视图自己交代空态，而不是让入口凭空消失。
- 行为不变：行点击只是看历史，不自动恢复；恢复/删除仍在行尾 ⋮ 菜单里。

## 理由 / 取舍

- **为什么不只是把折叠区挪到顶部**：折叠区展开时会把会话列表顶下去，归档越多顶得越狠；
  互斥视图不占用主列表的地皮。
- **为什么入口常驻而不是「有归档才出现」**：一个会凭空出现/消失的导航项，用户第二次
  找它的时候不知道该不该找；代价是要写空态文案，这个代价更小。
- **推翻这条的前提**：如果归档最终变成「几乎不用」的功能（比如删除有了别的后悔药），
  那它连常驻入口都不配，该退回菜单项。

## 影响

- `src/renderer/src/App.tsx`：`archivedOpen` 折叠态 → `archivedView` 视图态；
  进设置自动退出该视图；「＋ 新会话」也退出该视图。
- `tests/e2e/archive.e2e.ts`：走新的入口和返回路径，断言从「归档区消失」改成「空态可见」。
- ADR-0087 的日志/恢复语义、`sessionGroups.ts` 的过滤规则一律不动。
