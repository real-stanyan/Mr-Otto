# ADR-0243：订阅供的那几款要进选单；Auto 是这一格的一个取值，不是第二个控件

- 状态：已采纳
- 日期：2026-09-07
- 关联：#1042；ADR-0176 决定二（托管优先于自带 key）、ADR-0237（云会话的 Auto）、ADR-0232（型号优先级链）、ADR-0233（云会话不许自带 key）、ADR-0217（`unknown` 一态）、#1040（同一族的盲区）

## 背景

维护者一句话：「用户消息输入框右下角那个模型选择，应该和工作区智能体的模型选择一样，
显示 Auto 或其他订阅可用模型。」

先验前提（AGENTS.md 那条五分钟）。查下来两件事都成立，而且第一件是个**功能事故**，
不是「少一项」：

1. `ModelPicker` 的分组过滤是 `ready(g.provider)`，判据是 `keyStatus[apiKeyEnv] !== ""`
   ——**配没配自己的 key**。而 `routeModel`（`src/main/modelRoute.ts`）里托管
   **优先于**自带 key（ADR-0176 决定二）：有活跃订阅 + 网关供这款，就走订阅额度。
   两者合起来：一个付费订阅、一把 key 都没配的用户打开这枚选择器，**一组都看不到**
   ——只剩「添加更多模型…」那一行。他此刻真正能跑的那几款，界面上一个都不列。
2. 真库 `model_route` 此刻供六款（`deepseek-v4-flash` / `glm-5.3-flash` /
   `qwen3.8-flash` / `deepseek-v4-pro` / `glm-5.3` / `qwen3.8-max`），跨 deepseek /
   智谱 / qwen 三家。本机配着 GLM、DeepSeek、KimiCode 三把 key——所以 qwen 那两款
   在本机也一直是隐形的，而全空 key 的机器上六款全隐形。

**为什么没人报**：与 #1040 逐字同一族的盲区——本机 key 齐全，这个失败模式被完全掩盖。

## 决策

### 一、选单分两组，分工是一句话：上面那组不额外花钱，下面那些烧自己的 key

新增「订阅」组，列网关此刻供着的每一款，**顺序原样照抄网关那一份**（edge 的
`routesQuery` 按 `price_out_micro_per_m.asc` 排过，所以是从便宜到贵，ADR-0237）。
判据是 `billingView.hostedModels`，与真正花钱那层（`hostedQuota.routeInput` 的
`subscribed`）**逐字同一条**：`status === "active"` 且有档。`past_due` 不算——
扣款失败时路由那层也不认它，列出来就是给一颗点了跑不动的钮（同 ADR-0217 的取舍）。

这几款**从厂商组里摘掉**，不并排出现两次：同一个型号在两处点下去跑的是同一条路
（托管优先），列两遍只会让人以为有得选。

`billing` 还没查到（`null`）与「没订阅」在这里给**同一个答案：空**，整块退回改动前的
样子。这是与 ADR-0217 相反的方向，理由也相反：那里 `unknown` 必须单列一态，因为把它
并进「没订阅」会劝一个已经付过钱的人再付一次；这里两个失败方向不对称——拿不到时按
「都能用」画，会给一个没订阅的人列出一排点了必然 blocked 的型号。冷启动那一瞬间的空窗
由侧栏那发 `loadBilling` 种子补上（ADR-0240）。

判据从组件的 `useMemo` 里搬进 `src/renderer/src/lib/modelMenu.ts`：这个菜单答错过一次，
而答错的样子是**安静的**——渲染不出错，只是少几行。留在 useMemo 里就没有保鲜期。

### 二、Auto 是这一格的一个取值，不是并排的第二个控件

选单里多一项 Auto，值是 `AUTO_MODEL`（`"__auto__"`，与工作区那一格**共用同一个常量**
——三处各写一个字面量的话，改一处忘一处不报错，只会让「选了 Auto」在其中一条路上变成
「选了一款叫 `__auto__` 的型号」）。

**它是真的在跑，不是一枚标签。** 只画一项而不接线 = #722「撒谎的勾」的一般形式，所以
这条 ADR 连带把 ADR-0237 的 Auto 移植到了本机：`src/shared/autoModel.ts` 收下分类提示词、
「拿不准算 hard」、「认不出来一律 null」这三条判据，两条路共用；**两边唯一的差别是怎么
向网关证明身份**（runtime 带 `x-runtime-secret` + on-behalf，桌面带用户自己的 JWT），
所以那一层收的是一份算好的 headers，不是各自的凭据。

**Auto 至少要有两款可挑才画出来**：不到两款时 `pickAutoModel` 一律回 null，画出来就是
一颗点了什么都不发生的钮。

**只有主会话那两个入口给 `allowAuto`**（会话中的输入框、新会话卡）。代读员 / 小模型 /
子智能体那几处换的不是「这一 turn 用哪款」，「先判难度」对它们没有意义。

### 三、「Auto 开着没有」是 `model_changed` 的投影，不是第二种持久化

`ModelChangedEvent` 加一个可选的 `auto?: true`，**两种事件都带它**：用户把选择器切成
Auto 的那一下（型号不变、只是从此由 Auto 说了算），以及之后每一轮 Auto 真挑出一款时落的
那一条。于是「Auto 开着没有」与「当前型号」「当前 lane」读同一条事件、同一个取法，
resume 时自动回来，不需要第二个存储位。可选字段 = 旧日志照常重放（schema 向后兼容硬规则）。

三个推论，每一条都是踩得到的坑：

- **`nextAuto` 必须进 `switchModel` 的相等性比较**。漏掉它，用户点 Auto 那一下型号没变、
  函数早退，**静默地什么都不发生**，而界面上已经显示 Auto 了。
- **Auto 自己挑出来的那条事件照旧带 `auto: true`** ——挑了一款不等于关掉 Auto。
- **手动挑一款的那条不带它**：那一条本身就是关掉 Auto 的动作，不需要第二个开关。

渲染层不新增 IPC：`autoModel` 跟着 `model_changed` 事件流回来（同 `model` 那一条，
UI 不抢跑）。新会话卡上 Auto 是本地草稿，**不塞进 `model`**——`useModelChoice(model)`
要拿它问上下文窗口和挡位表，`__auto__` 在那两处都答不出来，而 Auto 开着时这条会话
仍然有一个确定的起手型号。

### 四、判一手排在代读员那道判断**之前**

接线点在 `sendMessage` 里，`composeUserText` 之后、`skill_invoked` / `image_described`
两条 append 之前。两个理由，各自都能单独把顺序钉死：

- 代读员那道判断问的是 `agent.model` 的 `supportsVision`，而 Auto 这一下就可能把型号从
  看不见图的换成看得见图的（或反过来）——排在后面就是拿上一轮的型号决定这一轮要不要代读。
- `barrenTurns` 按 `events[i-1]` 认领 `image_described`，中间夹一条 `model_changed`
  就断了那条邻接。

## 代价（明写）

- **每条消息多一次网关往返**（约 200 输入 / 5 输出，最便宜那款上约 $0.00005，延迟
  0.3~0.8 秒）——只在 Auto 开着时。这一次调用走同一条网关、照常落 `usage_event`，
  不做暗扣（同 ADR-0237）。
- **分类器读的是这一条消息，不是完整上下文**（同 ADR-0237 的已知代价）。
- **Auto 够得到最贵那款，今天没有上限**（同 ADR-0237）。
- 目录里没有的型号（网关上了新款而本仓 `modelCatalog` 还没跟上）在选单里**原样显示 id**
  ——藏起来就是「看不见却仍然供着」；但给了 `filter`（比如只列看得见图的）时只能丢：
  那道筛子问的是一个我们此刻答不出的问题，答不出而放行就是撒谎的勾。
- 「当前选中的那一款照旧找得到自己」这条例外**收窄到那一款**，不再放行它那一家：
  按家放行会顺带把同厂另外几款没 key 也没托管的型号一起摆出来，那正是「没配 key 的
  厂商不进菜单」要避免的死路。

## 什么前提失效会推翻它

- **托管不再优先于自带 key**（推翻 ADR-0176 决定二）：那时「订阅」组与厂商组就不再是
  互斥的两条路，同一款要允许选走哪边，`lane` 那套两条目的形状会回来。
- **网关开始按档位供不同的型号**：今天 `me.models` 是全局路由表去重的结果，对每个用户
  都一样；哪天它变成「你这一档供哪几款」，这一组的语义从「网关供着」变成「你买到了」，
  文案与 `hostedModels` 的判据都要跟着改。
- **价目不再是能力的代理**（ADR-0237 那条）：Auto 的两档就要另找依据。
