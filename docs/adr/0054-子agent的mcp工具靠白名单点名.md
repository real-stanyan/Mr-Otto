# ADR-0054: 子 agent 的 MCP 工具靠白名单点名，不自动继承

日期：2026-08-21　状态：已接受

## 背景

MCP 接进来（ADR-0049/0050）时，`subagentRunner` 和 `createChildAgent` 都刻意不传
`mcp`，于是子 agent 一把 MCP 工具都没有。当时的注释理由是：

> 它的装备由那份 subagent 定义的工具白名单说了算，而白名单里写不出一台此刻才连上的
> server 的工具名

这句话的前半截是对的，后半截不成立——设置页的工具勾选框读的是
`BootInfo.toolDefs`，也就是主会话**此刻挂载的**工具表，`mcp__github__create_pr`
这类名字一直就在那张表里，用户早就勾得到。真正挡住它的是另一件事：
`TOOL_NAMES`（校验 subagent 定义里工具名的那份已知名单）来自一个刻意不给 `mcp`
的探针装配，所以任何 `mcp__` 名字都会被判成"认不出"，进 `unknownTools`，
子 agent 那边也从来不挂。

于是今天的状态是：勾得到、存得下、看着像生效了，实际一把都没有。issue #154。

还有一处不一致：活的子 agent 复用父的 world 实例（父身上带着 `withMcp` 那层），
而 `resumeChild.ts` 重建时新造一个没有 `mcp` 的 LocalWorld。今天两边行为相同
（都没工具），但接缝不统一——哪天有一侧改了，另一侧不会跟着改。

## 决定

**挂载 + 白名单过滤**，不自动继承：

1. `createAgent` 里"这次装配有没有 MCP 能力"改成问 `opts.mcp ?? world.mcp`——
   子 agent 跑在父的 world 实例里，父身上那份 `mcp` 就是它的。于是 MCP 工具对
   子 agent 是**挂载的**。
2. 挂载之后照旧过 `allowTools` 白名单。子 agent 的白名单是那份 `.md` 定义里
   `tools:` 那一行，逐个名字点名——**没点名就是没有**。今天没有任何一份定义
   写着 `mcp__…`，所以默认行为一字不变：子 agent 依旧一把 MCP 工具都没有。
3. `TOOL_NAMES` 之外再并上"此刻活着的那些 server 的工具名"，`mcp__…` 因此
   不再落进 `unknownTools`——用户勾了它，它就真的生效。
4. `createChildAgent` 加一个 `mcp` 参数，`index.ts` 两条分支都传 `mcpHub`。
   两条子 agent 路径的 world 形状就此统一。

## 理由

「该不该自动继承父 agent 的全部 MCP 工具」是这个 issue 的真问题。不继承，
理由和 ADR-0047 给子 agent 收权是同一条：**派出去的 agent 没人盯着**。
MCP server 是第三方代码，一台 server 可能提供发邮件、开 PR、动数据库的工具；
让子 agent 默认拿到父的全套，等于每接一台新 server 就悄悄扩大所有子 agent 的
权限面，而用户在建那些子 agent 的时候根本不知道这台 server 存在。

白名单点名把这件事变成一次显式动作：用户在设置页勾了 `mcp__github__create_pr`，
这个子 agent 才有它。名单是逐个工具而不是逐台 server——同一台 server 上
"读 issue"和"合 PR"不该共享一次授权。

审批门不受影响：MCP 工具一律 `requiresApproval: true`，`approval: "deny"` 的子
agent 换掉整条审批链，等于给了也用不了；`approval: "ask"` 的照旧把卡冒泡到父会话。

## 代价

- **名单随连接状态浮动**。某台 server 此刻没连上时，它的工具名不在已知名单里，
  用户定义里那几个名字会被判成"认不出"、进 `unknownTools`（文件里原样保留，
  设置页标注"N 个工具名无法识别"）。极端情况——一份定义里所有工具名都来自
  一台掉线的 server——会退回缺省工具集。这不是新行为（任何认不出的名字今天
  就是这个下场），但 MCP 让它从"用户写错字"变成"server 没连上"，频率高得多。
  接受它的理由：连不上的时候那把工具**本来就用不了**，名单诚实地反映了这一点；
  另一个方向（把没连上的 server 的工具名也算已知）要求我们记住上一次连上时
  它提供过什么，那份记忆没有任何东西保证它还成立。
- 子 agent 的工具表现在会随连上的 server 变——同一份定义在两台机器上挂载出来
  的工具数可能不同。这是 MCP 本身的性质，不是这次引入的。

## 什么前提倒了会推翻它

用户开始成规模地把同一批 MCP 工具复制进十几份 subagent 定义——那说明"逐个工具
点名"的粒度太细了，该谈的是"按 server 授权"或者一个可复用的工具组概念，
而不是继续往每份定义里抄名字。
