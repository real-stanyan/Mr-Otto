# ADR-0249：选单三处收窄 —— 去掉「订阅」组头、Auto 不带说明行、不画「视觉」记号

- 状态：已采纳
- 日期：2026-09-07
- 关联：#1058；ADR-0244（选单分两组 + Auto 那一行两层，**本 ADR 撤掉后半句**）、ADR-0248（订阅那一侧只剩一组）、ADR-0236（同一形状：维护者对着真机一口气点的几处）
- 来源：维护者对着选单截图点的三条 ——「1. 最上面不用写"订阅" 2. Auto 下面不要有那行文字解释，只要有个抬头和其他模型对齐 3. 有视觉的模型，不需要把"视觉"标出来」

## 背景

三条都是**收窄已经记过的决定**，且都要等真机画出来才看得见 —— 纸上读 ADR-0244 的那两条
论证（组头分组、Auto 需要一句说明）都站得住，画出来之后不站了。这本身是这条 ADR 存在的
理由：把「为什么当初那么写、现在为什么不」留下来，免得下一个人照着 ADR-0244 又加回去。

## 决策

### 一、订阅那一组不画组头

`ModelMenuGroup.heading` 从 `string` 放宽成 `string | null`，`null` = 不画。

判据是**这一组是不是唯一一组**：#1051（ADR-0248）之后订阅用户只有这一组，给唯一一组挂个
标题就是噪音 —— 组头的作用是把两组分开，没有第二组时它什么也没分开。

**厂商那几组照旧写**：没订阅的人那边是真的有 DeepSeek / 智谱 GLM / Ollama 好几组。
所以这不是「删掉组头」，是「这一组不需要」。

### 二、Auto 与其余各款同一个排版

撤掉 ADR-0244 里那条「Auto 这一行两层」。当时的论证是「只写一个词的话，点它的人只能靠
猜」—— 论证没错，错的是代价估小了：**一行两层会把这一列的基线打断**，而这枚选单本来就
靠「每行长得一样」扫得快。一个人一辈子只需要读懂 Auto 一次，而这一列他每天要扫很多遍。

那句话降级成 `title`。**这不是 ADR-0243 点名的那种「悄悄降级」** —— 那一条说的是危险状态
的常驻警示（开着免审时输入框上方那行），退成 hover 就把一个必须被看见的事实藏了；这里是
一句解释性提示，看不看得见不改变任何后果。

### 三、不画「视觉」记号

那枚记号在 `GLM-5.3 Flash（视觉）` 这一行是**同一件事说两遍**（标签里已经带着），在
`Qwen3.8 Max` 那一行则是唯一信号 —— 于是它既冗余又不完整，两头不靠。撤掉之后这一列
只剩「字形 + 名字」，齐得多。

代价明写：**选单里从此看不出哪款看得见图**。真正会撞上这件事的路径已经有话说 ——
带图消息由代读员接住（`createVisionBridge`），代读不了时 `routeModel` 会把「缺什么」
说成人话。

`ModelMenuItem.vision` 因此没了消费方，**一并删掉**：留着一段跑不到的数据，下一个人会
以为它还在被谁读（同 ADR-0248 删掉那道去重的理由）。要恢复的话它是 `choice.supportsVision`
的一次投影，一行就能算回来。

## 什么前提失效会推翻它

- **订阅那一侧重新出现第二组**（比如哪天允许订阅 + 自带 key 混用，推翻 ADR-0248）：
  组头要跟着回来，判据仍然是「有没有第二组」而不是「这组叫什么」。
- **Auto 长出更多档**（不止「便宜 / 贵」两档）：一行一个词可能不够，那时要重新掂量。
