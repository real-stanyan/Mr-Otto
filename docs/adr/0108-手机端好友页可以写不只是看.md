# ADR-0108：手机端的好友页可以写，不只是看

日期：2026-08-26
状态：已采纳
相关：#455、ADR-0094（手机端范围）、ADR-0027（实时链路降级轮询）、0001_friends.sql、0013_realtime_publication.sql

## 背景

ADR-0094 给手机端划的范围是「看 + 审批」：不建会话、不改设置、不切模型、不管 MCP。好友页按这条线做成了**只读**——列表能看，加好友、通过请求、私信一律「在电脑上做」。`mobile/src/friendsApi.ts` 开头原本就写着这个理由：把桌面那份（私信、实时订阅、乐观发送、降级轮询）整套搬过来，等于把手机做成第二个完整客户端。

用起来发现这条线划错了地方。它把两件不相干的事绑在了一起：

- **会话投影**确实是「这台电脑上的事」。手机看到的时间线、按下的审批，都只在那台电脑上有意义，所以要走中继、要配对、要密封流（ADR-0095/0096/0097）。
- **好友**不是。它活在 Supabase 里，由 RLS 看门，两个人之间的关系跟谁的哪台电脑开着没有半点关系。

按只读那条线，收到一条好友请求得等人回到电脑前才能通过；而如果电脑没开机，手机连「加个好友」都做不到——一个跟电脑毫无关系的动作，被电脑的在线状态卡住了。

## 决策

**好友的写操作在手机端直连 Supabase 做，不经中继。** 补齐三件：加好友（搜人 + 发请求）、收发好友请求（通过 / 拒绝 / 撤回）、私信。

范围仍然收着，收的地方换了一处：

- **不做** presence / 工作区在场 / 好友分支徽章那一层。那是桌面 Git Graph 的功能（ADR-0055），手机既不 track 也不读。
- **不做**历史消息往上翻：一条会话只拉最近 50 条。往前翻要一个 `before` 游标和一套「翻到顶」的界面，等真有人翻到顶再说。
- 未读数**不落盘**：冷启动时收件箱游标对到「此刻」，只数这一趟新到的。持久化未读要一套 per-friend 的已读位点，而它的收益是「关掉 app 再打开，红点还在」——现在还不值这一套。

「手机不是第二个完整客户端」这句话保留，它约束的是**投影那条链路**（会话、工具、审批），不是账号体系里人对人的东西。

### 实时性

订两条 Realtime 通道（`friendships` 的两个方向 + 发给我的 `messages` insert），和桌面订的是同一批，少一条 presence。任一条没通 → 健康度降 `degraded` → 每 8 秒轮询一次兜底。这是 ADR-0027 在手机上的同一条：实时链路断了也不能让好友/私信整条失效。另外 `AppState` 回到 `active` 时立刻对一次表——挂起期间 WebSocket 多半已经被系统收走了。

去重靠一个**单调游标**（收到过的最大消息 id）：Realtime 和轮询会送来同一条，游标保证「未读 +1」只发生一次；内容那边 `mergeMessages` 按 id 去重，后到的覆盖先到的（轮询那份是从库里重读的，更权威）。

### 服务端一行没动

`friendships` / `messages` 的表结构、RLS、列级 grant 在 `0001_friends.sql` 里就是按「客户端直连」写的，publication 在 `0013` 里补齐了。手机用的是同一个 anon key + 同一套用户 session，RLS 看到的 `auth.uid()` 是同一个人。**没有新的信任面**——桌面能做的写操作手机才能做，一条不多。

## 代价 / 余量

- **两个客户端会同时写同一批行。** 无序对唯一索引（`friendships_pair_unique`）挡住了双向重复请求；`23505` 在手机端被翻译成「你们已经是好友，或者请求已经在路上了」。删好友 / 通过请求是幂等的（删不存在的行、把已 accepted 的再 accept 一次都不报错）。
- **未读数不跨冷启动**，见上。
- **一条会话只有最近 50 条**，见上。
- 桌面那份 `FriendsManager`（乐观发送、收件箱补齐、健康度收敛）没有被复用——手机那份是重写的、薄得多的一份。这是有意的：桌面那份的复杂度大半来自 presence 和工作区在场，而手机不要那一层。**代价是两处都要改的 bug 会有两处**；缓解是把两边真正共用的纯逻辑（PostgREST 过滤串的拼法、健康度合并、消息合并、排序、时间戳）提到 `src/shared/friendsQuery.ts`，两边 import 同一份——其中 `profileSearchOr` / `dmOr` 是**注入面**，复制一份等于复制一份漏洞的修法。

## 顺带做的一件加固

`dmOr(uid, friendId)` 会当场把两个 id 校验成 uuid 才拼进 PostgREST 的 `.or()` 串。它们**当下**都来自库里的行，拼进去是安全的——但「当下安全」是调用方的性质，不是这个函数的性质，而调用链是会长的（手机端就是新长出来的一环）。桌面的 `listMessages` 一并改成走它。

## 什么前提不成立会推翻这条

如果好友系统将来长出「只有这台电脑知道的东西」（比如私信里带本地文件、或者好友之间直接看对方的会话），那条「好友与电脑无关」的前提就塌了，那部分得回到中继上走密封流，而不是直连 Supabase。
