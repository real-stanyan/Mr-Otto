# ADR-0093：分支切换是一条日志事实，不是渲染层的一次心情

- 状态：已接受
- 日期：2026-08-25
- 关联：issue #411、ADR-0014（checkout 是 git 服务唯一的写操作）、ADR-0090（checkpoint_created 同款 ignorable 审计事件）

## 背景

顶栏的分支下拉是切分支的唯一入口。切完之后，对话流里什么痕迹都没有。

这在往回翻的时候会出问题：一段对话里 agent 读了三个文件、改了两处，读的到底是哪个分支上的那三个文件？会话日志答不上来，因为它压根不知道分支变过。屏幕上也答不上来——顶栏只显示"此刻在哪"，不显示"那时候在哪"。

## 决策

新增一个 `branch_checked_out` 事件类型：

```ts
export interface BranchCheckedOutEvent extends SessionEventBase {
  type: "branch_checked_out";
  repoDir: string;
  branch: string;
  from?: string;
}
```

- **落盘**（`shouldPersist` 判 durable）。时间线上「切到分支 xxx」那一行是日志投影，硬规则要求任何投影可从日志推导。渲染层自己记一份的话，刷新即失忆，且日志和屏幕会有两份说法。
- **`ignorable: true`**，且投影时不喂给模型。分支名不是对话内容：工作区里此刻是哪份代码，模型读文件时当场就知道；把分支名喂回去只是多一句它无法核对的断言。旧版本读到这条事件跳过即可，不影响模型视野的重建。
- **在主进程写，不在渲染进程写**。`CHANNELS.gitCheckout` 多收一个可选 `sessionId`；checkout 成功且带了 sessionId 才追加。渲染层只是发起者，事实由执行方记录。
- **切之前问一次 `git branch`** 拿 `from`。切完再问只能得到切之后的答案。问不出来（detached HEAD）就不写 `from`——不编一个名字上去。
- **原地切不落**（`from === branch`）。顶栏点中当前分支也会走到这个 handler，日志只记发生过的事。

时间线上用 `components/ui/marker.tsx` 的 `separator` 变体渲染：它是一条横穿时间线的界线，而切分支正是一条界线——线之上和线之下，脚下的代码不是同一份。模型切换用的是缩进小字（`AUDIT`）：那是"谁在说话"变了，这个是"说的是哪份代码"变了，管得更宽，值一条真的分隔线。

## 取舍

**为什么不复用 `session_created.workspace` 那条路（每次切分支开新会话）**：切分支是个轻动作，常常只是去看一眼隔壁分支的实现。为它开一条新会话等于把对话切碎，代价远大于收益。

**为什么 `repoDir` 也要存**：会话的工程文件夹将来可能变（多工作区），事件得自己说清是哪个仓库切的，不能靠读会话的当前状态倒推——那又是一次"投影推不出事实"。

**这条事件不参与模型视野推导，为什么还要严肃对待 schema**：`assertReplayable` 的默认是拒读，标了 `ignorable` 才放行。标错（该让模型看的标成 ignorable）的代价是静默复活一个残缺会话。这里明确表态：模型不消费。

## 推翻它的前提

如果将来模型需要知道自己在哪个分支上工作（比如自动提 PR、自动选目标分支），那就不再是"模型不可见"的审计事实了——那时应该把它投影进 system 消息，`ignorable` 也要跟着摘掉。

## 顺带修的

`tests/session/persistencePolicy.test.ts` 里那两道"漏写的成员"类型检查是空转的：数组写了 `: SessionEvent["type"][]` 标注之后，`(typeof DURABLE)[number]` 就是整个 union 而不是实际写下的字面量，`Exclude` 恒为 `never`。它当时已经漏了七个事件类型没人发现。去掉标注让它推断字面量联合，检查才真的在挡人。
