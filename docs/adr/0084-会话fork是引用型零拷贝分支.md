# ADR-0084: 会话 fork 是引用型零拷贝分支

日期：2026-08-25
状态：已接受
关联：issue #352（codex HistoryPosition + ForkPersistence::Referenced 对照）；ADR-0002（物理删除语义）、ADR-0033（会话 id 带随机性）、issue #351（有界重建）

## 背景

「从这条消息重来」的正确形态是 fork 而不是破坏性回退（append-only 日志根本回退不了）。codex 的 fork 不复制历史：新会话只存 `(源会话, 位置)` 引用，读取时先读父前缀再读自己的追加段，父子共享不可变前缀。`session_created.forkedFrom` 字段在 events.ts 里早就预留了（`{sessionId, seq}`），一直没有实现。

## 决定

1. **零拷贝**：`EventStore.fork(source, endSeq, newId, ts)` 只写一条 `session_created`（带 `forkedFrom`，schema 零改动）；`load()` 沿链递归取父前缀（seq ≤ endSeq）+ 自己的追加段，前缀的 `sessionId` 改写成分支自己（投影呈现，日志不动），环保护深度 16。
2. **seq 播种**：分支首事件的 seq = endSeq + 1（不是 0），此后 append 的 MAX(seq)+1 自然续上。链式视图因此**全局严格递增**——micro 的 coversUpTo、engine 增量快照的 afterSeq、steer 的 turnId 全是 seq 语义，一个都不用翻译。代价：四处 `seq = 0` 的 SQL 假设改成按 `type='session_created'` 查。
3. **边界语义**：endSeq 必须指向一条 `turn_ended`。「不继承半截 turn」由此是结构保证——源会话正在跑时半截 turn 没有 turn_ended 可指，不需要写中断标记（issue 里设想的标记方案被这个更强的约束取代）。
4. **删除保护（对照 ADR-0002）**：父会话有分支引用时 purge 拒绝（报错列出分支），先删分支再删父。**刻意不做级联**：分支是用户看得见的独立会话，静默连坐与「删除 = 用户明确要抹掉的那一段」的心智模型相悖；子会话级联（ADR-0047）不同——子会话只能从父时间线进入，父没了它就是孤儿。
5. **围栏只认第一条**：链视图里有两条 session_created（父的围栏 + 分支的 fork 标记），deriveMessages 只让第一条造 system 消息。普通日志只有一条，行为逐字节不变。
6. **有界重建（#351）对分支退回全量**：typed 原子步是单会话查询，看不到父前缀里的 checkpoint——保守正确，分支的有界重建等真实需求。

## 权衡

- **父子共享 = 父删除受限**。接受：报错信息把分支列出来，用户知道去删什么。
- **sessions() 的统计只算自己的行**（events 计数、startedTs）——分支在列表里显得"新且短"。可接受：它本来就是从分叉点开始的新会话。
- **UI 二期**：会话树可视化、「从这条消息重来」入口（Esc-Esc 回溯）不在本次——store 层协议先立住。

推翻前提：若将来 seq 改成全局自增（今天是按会话 MAX+1），播种一招作废，但链视图递增反而免费成立，只需删掉播种逻辑。
