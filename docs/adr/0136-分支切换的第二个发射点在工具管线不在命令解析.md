# 0136：分支切换的第二个发射点在工具管线，不在命令解析

日期：2026-08-26
状态：已接受
关联：issue #568；ADR-0093（分支切换是一条日志事实）；tests/main/branchWatch.test.ts

## 背景

ADR-0093 把「切分支」定为会话日志事实（`branch_checked_out`），但发射点只有一个：
顶栏 checkout 的 IPC handler。上线后实测：用户真实使用里分支切换全部由 agent 在
bash 工具里执行（`git checkout -b …`），两个实例的 sessions.db 中该事件历史总数为
**0**——时间线 Marker 一次都没出现过。事实的判定不该取决于是谁按的按钮。

## 决定

在工具中间件管线（DSH 原则 #2 的 seam）加一层 `createBranchWatchMiddleware`
（`src/main/branchWatch.ts`）：bash 调用前后各读一次 workspace 所在仓库的
`.git/HEAD`，分支名不同即追加一条 `branch_checked_out`（`from` = 调用前的分支），
事件形状与 ADR-0093 完全一致，渲染端零改动。

三个关键取舍：

1. **比对 HEAD，不解析命令。** 判据是「HEAD 真的变了」而非「命令里出现了
   checkout」——`git switch`、alias、脚本里的切换全覆盖，误报为零；且与命令
   退出码无关（checkout 成功、后续命令失败，切换仍是事实）。
2. **读 fs，不起 git 子进程；注入 reader，不走 world.fs。** 与 projectRoot.ts
   同一取舍：HEAD 是纯文本，起子进程只为读一行不值得。不用 world.fs 是因为它
   圈在 workspace 内（软沙箱），而 worktree 的 gitdir 指向主仓 `.git/worktrees/<名>`，
   在圈外。本模块是主进程装配件（组装根特权可碰 fs），reader 注入、测试喂假实现。
3. **worktree 不折叠回主仓。** 与 projectRoot 的结论相反且刻意：那边答「这份记忆
   属于哪个项目」，这边答「脚下这份 checkout 在哪个分支」——后者就是 worktree
   自己的 HEAD。

detached HEAD 沿用 0093 的规矩：发不出名字就不发（切完是 detached 不出事件；
切之前是 detached 则 `from` 缺席，不编名字上去）。

## 刻意不覆盖（代价写明）

- 外部终端切分支：app 进程外没有钩子。要覆盖得上 fs.watch(.git/HEAD)，那是
  常驻 watcher 的生命周期管理换一个边缘场景，此刻不值。真需要时它是本中间件
  的替换实现，事件形状不用动。
- bash 里 cd 到别的仓库切分支：会话时间线管的是 workspace 所在仓库的脚下事实。
- `run_in_background` 的命令：结果回来时 turn 早收口，比对窗口已关。

## 被否掉的路

- **解析 bash 命令文本**：alias/脚本/`git switch` 全是漏网，误报漏报双输。
- **fs.watch 常驻监听**：覆盖面最大（含外部终端），但 watcher 生命周期跟着
  会话走、macOS 上 rename 语义又出名地碎，为把「顶栏之外」补上不需要付这个价。
- **在 bash 工具实现里发事件**：工具只依赖 ExecutionWorld（Hard rule），
  且「切分支值得记一笔」是 harness 的判断，不是工具的。

## 事件排序说明

中间件 post 在 engine 落 `tool_result` 之前跑，所以 `branch_checked_out` 的
seq 排在触发它的那条 `tool_result` 前面。语义成立：切换发生在命令执行**中**，
先于结果返回；投影按类型各走各的，排序只影响时间线上两行的相邻顺序。
