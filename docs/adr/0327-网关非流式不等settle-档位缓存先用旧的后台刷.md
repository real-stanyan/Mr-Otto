# ADR-0327：网关非流式不等 settle；DO 档位缓存先用旧的、后台刷

- 日期：2026-09-28
- 状态：已采纳
- 关联：#1398（续 #1304）。维护者 2026-09-28 原话：「先把 #1304 的延迟修掉」
- 关系：落下 #1304 第四条评论里的候选 ②（`planCache` 落 DO storage）。同一条评论里候选 ④ 说「合不成一趟：settle 要等上游回来才知道花了多少」——这句只对了一半：settle 确实要等上游，但它不必**挡在响应前面**。ADR-0303 让 hold 与 settle 都顺带回额度快照，settle 那一份从此没人读（DO 照旧回）

## 背景

2026-09-28 用同一个 dev 账号（DO 落在悉尼附近）从两边各打一轮：非流式 ×3 + 流式 ×1，每轮之前先闲 70 秒。

| | VPS（今天从 AMS 进 Cloudflare） | Mac（SYD） |
|---|---|---|
| hold 一趟往返 | 327–377ms | ~20ms |
| settle 一趟往返，**挡在非流式响应前面** | 325–351ms | ~20ms |
| 闲 70 秒后第一发：DO 同步查档位 | 642 / 136 / 675ms | 136 / 330ms |
| 上游（`glm-5.3-flash`，只回一个字） | 2–2.7s | 1.3–3s |

闲置之后的第一发，五次里五次都是冷的（`cold=1`）：`planCache` 是实例内存、60 秒过期，而 DO 闲 70–140 秒就会被驱逐，内存那份随之没了。云会话里「隔一会儿有人说话」正好是这个形状。上游那两三秒两边一样，**不是 colo 的问题**，是那款模型自己慢。

## 决定

1. **非流式三条路（chat 非流式 / 决策 / 语音）的 settle 发出去、交给 `waitUntil`，不等它回来再回响应**（`llmGateway.ts` 的 `settleInBackground`）。响应里的每一个字节在它之前就定了：额度头取 hold 的快照（流式那条一直这么取，chat 非流式其实也早就取的是 hold 那份，决策与语音这次对齐），花费头本地算。结算本身一个字没变——同一个 requestId、同一份 usage、同一个 costMicro。
2. **后台 settle 失败时照旧 release 那笔 hold。** 改动前这条路是「settle 抛 → 外层 catch → release + 502」，内容已经交出去之后只剩 release 这一半，钱的结局不变。不照抄流式那条（只记日志、等 `HOLD_TTL_MS`）：`MAX_INFLIGHT` 是 4，挂着的 hold 会把这个账号堵十分钟。
3. **DO 档位缓存改成「先用旧的、后台刷」并落 DO storage**（`planCache.ts`，storage 键 `plan`）：60 秒内照旧直接用；60 秒到 24 小时之间拿手上那份答这一发，同时后台刷一趟（单飞）；没有、或超过 24 小时，同步查（改动前的行为）。DO 被驱逐之后从 storage 那份接着用，本地读、毫秒级。
4. **`planChanged` 强制重读，不搭后台那一趟的车；刷新按发起的先后落，先发起、后回来的旧结果不许盖掉新的。** webhook 刚改完库，它那一趟必须读到改完之后的库。
5. **为什么「先用旧的」在钱上站得住。** 档位上影响放行的只有 `status` 与 `weekLimitMicro`（`quota.ts` 的 hold 只看这两格，不看 `periodEnd`），而它们的每一次变动都由 Stripe webhook 触发 `planChanged`，走第 4 条。旧的那份只在「webhook 丢了」或「维护者手改了 plan 表」时才是错的；而每用一次旧的就立刻刷一次，错也只错一发（外加刷新在途那几百毫秒里的并发）。
6. **纯逻辑住 `planCache.ts` 不住 `worker.ts`**：后者进不了 vitest，而「强制那一趟与后台那一趟谁盖谁」正是会安静出错的那种。接线靠一条读源码的断言（`tests/edge/planCache.test.ts`）。

## 没做的

- **hold 那一趟本身**（远 colo 上约 340ms，每一次调用都付，流式也付）。它是结构性的：runtime 在欧洲，DO 跟着所有者落在他第一次用的地方。能动它的两条路都要维护者拍板：把 VPS 搬到离用户近的地方；或者 hold 与上游请求并行发，被拒的那一发白花 prompt 的钱（这改的是「先预扣再花钱」这条计费规矩）。
- **派活分类器用的最便宜那款（`glm-5.3-flash`）自己就要 1.3–3 秒**，两边一样。与网关无关，另开。

## 后果

- 远 colo 上非流式调用少一趟 DO 往返（约 330ms）；闲置之后的第一发少 136–675ms。流式 chat 只吃到后一项。
- 计时头（`x-otto-quota-timing`）里非流式不再有 settle 那一段，与流式一样。
- 非流式的额度头报的是 hold 之后的数：预扣已经扣了、差额还没退。比真值略少，是保守的方向，下一发就对上。
- settle 失败对客户端不可见了（原来是 502），只在 Worker 日志里留一句。
- 手改 plan 表之后，改动晚一发生效（改动前是最多晚 60 秒）；DO 闲了几个小时之后的第一发，用的可能是几个小时前的那份。
- DO storage 多一个键 `plan`，里面有这个用户的订阅行。
- 要部署 edge 才生效（`npm run edge:deploy`）。
