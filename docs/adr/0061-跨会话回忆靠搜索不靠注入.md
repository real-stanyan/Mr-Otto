# ADR-0061：跨会话回忆靠搜索不靠注入

- 状态：已接受
- 日期：2026-08-22
- 相关：issue #177；spec `docs/superpowers/specs/2026-08-22-memory-design.md` §二；ADR-0060；参考 hermes-agent `tools/session_search_tool.py`

## 背景

长期记忆刻意不存任务进度（ADR-0060），过去做过什么需要另一条路。
hermes 的做法是给模型一把检索工具而不是把历史注入上下文。
两种策略的对比：注入历史 = 每轮为用不上的东西付 token 且污染上下文；
搜索工具 = 模型主动决定什么时候需要往回翻、往哪翻。

## 决定

1. `events_fts`（FTS5 trigram）是派生索引，随时可 DROP 重建，不是事实。
   只索引 user_message / assistant_message / tool_result 正文。
   insert 触发器同步，老库首开回填，purge 连带删。

2. 查询经 `ExecutionWorld.history` 可选能力（`src/main/historyCapability.ts` 焊 EventStore），
   工具 `session_search` 只认 world.history——硬规则「工具只依赖 ExecutionWorld」原样成立；
   v2 SandboxWorld 可换成 RPC。

3. 不自动注入历史。只有模型主动调 `session_search`（四形态：query / session_id / session_id+around_seq / 无参）
   才进上下文，且每次调用都落 tool_call + tool_result 事件。

4. 永远排除：归档会话、`spawnedBy` 子会话、当前会话。

5. trigram 要求 ≥3 字符；更短的查询走 LIKE 子串兜底（中文双字词常见）。

## 理由

- 注入历史 = 每轮为用不上的东西付 token 且污染上下文；搜索工具把决定权给模型，
  效率和清晰度都更高。
- 索引不当事实是因为它可从日志一键重建，而事实只能是日志。
- 排除子会话是因为它们是父任务的内部不是「过去的对话」（ADR-0047 的职能划分）。

## 推翻条件

若出现跨设备同步的会话库，索引仍成立但「当前会话排除」需改为「当前设备活跃会话」。
若需要语义检索（embedding），FTS 退为候选召回的第一层，接口不变。
