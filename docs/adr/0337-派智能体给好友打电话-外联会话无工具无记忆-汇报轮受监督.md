# ADR-0337：派智能体给好友打电话——外联会话无工具无记忆、汇报那一轮受监督、语音票只认好友的语音路径

- 状态：已采纳（2026-10-03）
- Issue：#1441；spec：`docs/superpowers/specs/2026-10-03-agent-calls-friend-design.md`；计划：`docs/superpowers/plans/2026-10-03-agent-calls-friend.md`

## 背景

维护者原话：「智能体可以被派遣去和自己的好友沟通，语音」。回电（ADR-0331 / 0332 / 0335）是智能体打给**叫起这一轮的那个人**，
模型传不了别的 uid；这一条是反过来：主人开口派它，它去给**主人的好友**打电话，聊完回主人那条聊天里汇报。

分两期。**一期（本条）= 实时电话 + 文字汇报**；二期 = 没接时在好友私聊里留一条语音消息，**没做**，一期落地后另开 spec。

## 维护者拍板的七条（2026-10-03）

1. 两种形态都要（打电话；没接留语音），拆两期。
2. 通话里只说话、不动手：那条会话里智能体一把工具都没有。
3. 是好友就能打：好友关系本身就是同意，好友可以不接。
4. 你开口派才算数：不弹确认卡；只有主人本人点起的那一轮能打。
5. 语音合成的钱记派的人：好友没订阅也听得到。
6. 聊完在派它的那条聊天里回一段文字。
7. 每对（智能体，好友）一条永久会话，这条会话不注入主人的记忆。

## 决定

1. **外联会话**：主人个人主场里的一条云会话，`chat_kind='outreach'`，名单恒为「一只智能体 + 一位好友」，每对一条、永久复用，
   由 runtime 自己建（`services/runtime/src/outreachSession.ts` 的 `ensureOutreachSession`：先查、接住 23505；不走 `chatCreate.ts`）。好友那边它是收件箱里的一行「<主人> 的 <智能体>」，靠
   ADR-0325 的客人通道进房。名单改不了、不归档、不自动起名。**没有工具**（`engineFor` 在这种会话里一把都不挂，含 wiki、
   `call_user`、`invite_to_call`、连接器、git，断言钉 `request_envelope.tools` 长度为 0）、**不注入记忆**（不落 `workspace_wiki_loaded`）、
   **有自己的提示词**（`systemPromptText` 与 `cloudSessionText` 各分一支：原提示词开头就在宣称工具存在，不止云那一段要改）。
2. **说话闸**：好友只在「有一通外联在进行」（`ringing` 到 `ended` 之间）能 `say`，其余时候拒收；主人在这条会话里也不能说。
   没有 brief 的闲聊花的是主人的额度。名单只有一只，好友每句话都由它接，不问分类器（盖过 ADR-0328「有别人时照问」——这里的「别人」就是通话对象）。
3. **`call_friend` 只有主人亲口派的那一轮才能打**：判据从这一轮**覆盖的每一条开场白**折出来（`openingTraits`）——全部是主人本人的普通消息
   （不是接力、不是招呼 / 汇报开场白、不是客人的话）才亮这把刀；这条是 spec 里没写透、评审逼出来的（见下）。
4. **汇报那一轮每一把工具都要主人批**：转写是外人的话，不能让它在全免审批的主场（ADR-0298）里直接动手。复用客人那一轮掀审批的路径（ADR-0325），
   `supervisedTurn() = approveAll && (guestTurn || reportTurn || foldedNonOwner)`，`call_friend` 在受监督的轮里不亮。
5. **语音合成记派的人，靠一张签名票**：runtime 在外联进行期间给**好友那条连接**的 welcome 与 `call` 回执带 `speechTicket`
   （`base64url(payload).HMAC-SHA256(RUNTIME_SECRET, payload)`，payload = 主人 / 好友 / 工作区 / 会话 / 过期时间，起算 +15 分钟）；
   手机合成时带 `x-otto-speech-ticket`，edge 的 `/llm/v1/speech` 验签、没过期、**调用者 JWT 的 uid 等于票上的好友**才改记主人；
   任一条不过都按没带票处理（记调用者自己）。票**只在 speech 路径认**，别的网关端点一概不认；签发与验票是同一个纯模块
   `src/shared/speechTicket.ts`（`signSpeechTicket` / `verifySpeechTicket`，edge 在 `services/edge/src/edge.ts` 里调后者）。
6. **汇报**：原聊天落新事件 `outreach`（`started` / `ended`，`ignorable`，模型不可见，`fromAgentId` 不叫 `agentId`——理由同 `call_ring`），
   `ended` 带结局（`completed` / `missed` / `capped` / `failed`）、时长与**转写全文**（总长封顶 20000 字、超了留尾）；转写抄进原聊天日志，
   原聊天因此自足，画卡与汇报都不用跨会话读。外联会话自己也落一份 `outreach`（不带转写），「此刻有没有一通在进行」从它折。
   随后给这只落一条 `user_message{greeting:"outreach_report"}`，让它用两三句话告诉主人结果。
7. **生命周期四个出口收到同一个 `finishOutreach`**：好友挂断（`completed`）、45 秒没接（`missed`，含拒接——服务端分不出）、接通满 10 分钟
   （`capped`，runtime 清空通话名单）、推送一台都没送到 / 归档（`failed`）；接通后好友掉线 90 秒没回来按 `completed`。常量：单对冷却 10 分钟、
   每只 24 小时外呼 10 通、brief ≤500 字、opening ≤200 字、锁屏一行 ≤60 字。
8. **否决的两条路**：① 把好友拉进主人派它的那条聊天——私聊不收客人，且主人的聊天记录整份暴露给对方；② 走好友私聊的 `public.messages` 表——
   没有 runtime、没有实时语音，等于重造一套（二期的留言才落那里）。

## 评审逼出来的安全修正

- **闸不能只卡 `say`**：外联会话里还有别的路能追加 `user_message` 并起 turn——`setVoiceCall`（只认进行中那通外联的好友）、`greetNewAgent`
  （外联里直接 no-op）、`relayAfterTurn`（外联里不接力）。逐个 appender 审过一遍，其余路径因为没有工具而够不到。
- **监督要从「这个 job 覆盖的每一条开场白」推**，不是只看起这个 job 的那条：汇报或客人的话会折叠进主人的 job（coalesce），只看主开场白会让
  工具无监督地带着好友的转写跑。起跑最后一刻（`turnBoundary` 之前）按日志重算一次，且**只收紧不放松**（`applyTraits`）；turn 进行中 `notify`
  看到汇报开场白或非主人的发言再收紧（增量快照每圈都可能把它们带进上下文）；工具的 `requiresApproval` 是**活取值**，不是建工具表时定死。
- **`call_friend` 的资格同理**：只有覆盖的开场白全是主人的普通消息才亮；起点是别人说的话、外部内容里的指令都触发不了。
- **票的三重绑定**：只在 speech 路径认、只认语音那条调用链的好友本人（uid 对上）、过期即失效。写这一条是因为一张能在网关别处生效的票就是一把代付的钥匙。
- 外联会话的建立：insert → append → open 不是原子的，崩在中间会留下没有 `session_created` 的行。现在已有行也「缺种子就补种」、23505 的输家先补种再开房、
  同一对的并发建线在进程内串行、客人名单每次开房都对齐一次、原聊天已归档就把房间收掉。

## 部署顺序

**0048 migration → edge → runtime → 手机包**，协议 21 → 22（welcome 的 `chat.kind` 多 `outreach`、多 `speechTicket`；`RingPush.chat` 多 `outreach`）。
0048 先于 runtime：CHECK 与唯一索引不在，runtime 建不出外联会话；edge 先于 runtime：不然 runtime 发出的票没人认，好友合成会记在好友自己头上（或被挡）。
旧手机连新 runtime 协议号不等，提示升级。**这些一件都还没部署**，等维护者明说（#791 的纪律）。

## 已知代价

- **brief 在线上帧里**：模型看得见的必须落盘，brief 随接通那条 `user_message{greeting:"outreach"}` 进外联会话日志，好友的客户端收得到这一帧，
  界面不画。懂技术的好友抓包看得到主人交代了什么。
- **转写留在原聊天的日志里，之后主人亲口点起的轮上下文里都有它，且那些轮照旧免审**（同一只、或主场群里别的智能体——`agentView` 里用户消息是共享的）。
  只有汇报那一轮和覆盖了非主人开场白的轮受监督。这与 ADR-0325 对客人历史的立场一致；若把汇报改成「只摘要进上下文」或给所有含外人话的轮上监督，
  要么重做汇报、要么把整个主场群永远置于监督——**2026-10-03 维护者被摆出了两种做法（只摘要进上下文 / 作为已知代价接受），只回了「做完」；把这当作接受是执行中的 agent 的裁定，不是维护者明确选的——他仍可推翻**。出了事故再加的是按转写的隔离，不是回头改全免审批。
- **智能体自己的 instructions（人设）原文到得了好友的客户端**：不是「可能套得出来」——人设进外联会话的 `agent_briefed.instructions`
  与每一轮的 `request_envelope.system`，而会话房的直播（daemon 的 `broadcast`）与 `backlog` 都是整条日志原样下发、不按类型筛，
  好友那条连接收得到这两条事件，界面不画（与 brief 同一类）。主人在人设里写的私事，抓包就看得到；记忆不进，人设挡不住。`agent_briefed` 那一块仍写「这个团队」。
- **拒接与没接分不出**（同回电），汇报只能说「没接通」。
- **好友不能回拨、不能在那条聊天里打字**；一期只有 runtime 派出去的电话。二期重判。
- **进行中的那通在 daemon 重启时按没打通（`failed`）收**：brief 与定时器只在内存里续不上，照样在原聊天汇报一句。
  好友在那通里说了、还没答的话**不补跑**：外联会话里此刻没有外联在进行时，重启补跑把这些开场白一律落 `turn_ended{error}` 收口（终审 M1），
  不然就是一条记在主人账上、对着挂掉的电话说的回复。
- **重启补跑重放主人那条开场白时 `call_friend` 打不出去**（终审 M7）：上一个进程里那通可能已经打出去了；刀回一句「可能已经打过了，先问主人」。
  代价是主人得再说一次「打」。
- **受监督的轮不把主人的名字盖到接力上**（终审 I1）：只有 job 的发起人是主人、而这一轮因汇报或折进了非主人说的话而受监督时，回话里 @ 了别的
  智能体这一棒才不接，群里说一句让主人 @——这时接力开场白的 `fromUid` 会是主人，接下去那一轮会被当成主人亲口、照全免直接动手，监督在这一跳断掉。
  客人点起的轮照常接力（开场白记在客人名下），下一棒照样受监督。
- **好友关系只在派的那一刻查**：通话窗口（最长约 11 分钟）内好友删了主人不复查。
- **票 15 分钟内能合成任意文字**，记主人的账，起算时刻之后**不续**（长通话靠 `call` 回执换票；过期后网关退回记好友自己）；没做按票的字数预算，封顶靠过期时间与网关并发上限。
- **起跑时已被启动循环开成非外联的未种子行**，要等重启才补种（`session_created` 不在最前，房间保持非外联）。
- **好友收件箱第二行不显示响铃 / 未接状态**：沿用「最后一句」（要显示得改 `lastWriter`，demo 里的那一格维护者没要）。
- **一只同一时刻只打一通**（跨它的所有外联会话判，`outreachHub` 的 `activeFor`，终审 M2——此前只挡同一个好友那条线），
  同时派去打三个人要排队说三次。判的是日志，两次派活几乎同一刻到达时仍可能都放行：窗口从 `activeFor` 那次检查起，经 `countSince`、
  设备与额度查询、`ensureSession`（查库 / insert / 开房），一直到外联会话里同步落 `started` 为止——好几次往返，不是一次。
  转写在两条日志里各存一份。
- **没响过铃的那几通不算进「每只 24 小时 10 通」**（终审 M6）：冷却 / 推送没送到 / 没设备时外联会话里仍是 `started` → `ended{failed}`，
  `ended` 上多一格 `unrung`。`started` 没有挪到响铃之后：响铃那段 await 里，同一条线一次一通、说话闸、语音票都靠折叠里有这一通，
  挪后就有两次 start 同时响铃、推送先到人先接被闸拒掉的窗口。旧日志里没有这一格的照旧算（宁可多算）。
- **桌面一个字不画**（`hiddenFromCloudTimeline` 藏 `outreach`），等 #1403；好友必须装了 Otto 手机端、开了来电权限，通话目前只在开发版里有（ADR-0320）。
- 受监督的轮里 `call_friend` 若在 turn 中途才收紧，仍留在模型的工具表里，调用时被 `mayCall` 拒；中途收紧会对「客人发给别的智能体的话」也过度收紧（失败方向是更严）。
- **真机一次没跑过**；手机四处（好友收件箱外联行、外联聊天页的来电记录 / 输入栏说明条 / 转写抽屉、主人原聊天的外联气泡与群灰条）**视觉未验**，
  只过了 demo 与单测；没有任何一项部署到线上。
