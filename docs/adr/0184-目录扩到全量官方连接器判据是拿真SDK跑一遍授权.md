# ADR-0184：目录扩到「所有有官方公开连接器的平台」，进不进的判据是拿真 SDK 跑一遍授权

> 原为 ADR-0182 —— 合并前 re-fetch 时发现 main 上已经有 0182/0183 了（项目 ADR-0074：号在合并时 claim）。
> 提交信息改不了，本条 PR 的提交里写的仍是 0182，这一行是它的转发地址。

- 状态：已接受
- 日期：2026-08-29
- 相关：issue #725 / #733、ADR-0171（两层目录）、ADR-0180（图标两档画法）、ADR-0181（卡片按真实状态画）

## 背景

目录原来 20 条，全是国外的。需求是「把市面上所有提供官方公开连接器的平台都整合进来，
国内、国外都要」。

「所有」这个词落到实处，第一个要回答的问题不是"抄哪份清单"，而是**凭什么说一条能用**。

## 决策一：判据是拿仓里那份 SDK 跑一遍授权的前半段，不是抄清单

社区那几份 remote MCP 清单（awesome-remote-mcp-servers 等）都带一列"认证方式"，
其中区分了"支持动态客户端注册"和"不支持"。抄它是最省事的做法，也是错的：

- 那份表把 **GitHub 标成支持动态注册**。实测不支持——`https://github.com/login/oauth`
  的授权服务器元数据里根本没有 `registration_endpoint`。
- 反过来，Intercom 的 `/.well-known/oauth-protected-resource` 直接 404，按"读元数据"
  的土办法判会判成不可用，而 SDK 有一串回退路径，实际连得上。

所以判据只能是**把我们自己那条路走一遍**：用 `@modelcontextprotocol/sdk` 的 `auth()`，
配一个和 `createOAuthProvider` 同形状的 provider，跑到 `redirectToAuthorization`
——走到"浏览器该开了"这一步，才算"用户点授权真的会有反应"。

约 150 个候选端点是这么过的一遍。探针脚本没有进仓：它打的是外网，进门禁等于让
CI 依赖二十来家第三方的可用性（而门禁红了要能立刻知道是自己坏了）。方法写在这里，
下次扩表照着重做一遍即可。

## 决策二：连不上的三条不删，改说人话

实测结果里有三条**目录里早就有、但从来连不上**的：

| 条目 | 症状 | 原因 |
|---|---|---|
| GitHub | 点授权报"不兼容" | 授权服务器不支持动态注册，要预注册 client_id |
| Asana | 同上 | 同上 |
| Figma | 动态注册被服务端 403 | 支持注册接口，但拒绝我们的注册请求（换 UA 无效） |

盘上的凭据存档印证了这件事：`~/.mr-otto/mcp-auth.json` 里 github 只有 `redirectUri`，
一次都没注册成功过。

删掉它们是最干净的，但 GitHub 是这份目录里最常被找的一台——目录里没有它，用户的结论
是"这软件接不了 GitHub"，而不是"这台暂时连不上"。所以留着，把 `authNote` 从
"配好后点一次授权"改成说清楚为什么现在不行、缺的是什么（#697 的手填 client_id）。
根治在 #697，跟踪在 #733。

## 决策三：八十多条要分组，分组顺序不能是书写顺序

20 条平铺没问题，82 条平铺是一堵墙。给 `CatalogEntry` 加 `category`，精选层按分类
分段渲染。

两个细节：

- **段落顺序取自 `CATALOG_CATEGORIES` 这个有序数组，不是条目在目录里出现的顺序。**
  目录数组是按分类写的，但那是书写顺序——挪一条目录的位置不该顺带改掉界面上的段落次序。
  代价是联合类型和这个数组是两份东西，可能分叉（给联合加一个分类、忘了加进数组，
  tsc 全绿而那一整段在界面上消失），所以有一条断言钉住它。
- **`category` 在 `CatalogEntry` 上是可选的，在 `CuratedEntry` 上必填。** 长尾条目来自
  公开注册表，那边没有分类字段也没人给它归类；长尾本来就平铺。精选层漏填要在 tsc 里红，
  不能静默掉出所有分段——`MCP_CATALOG: readonly CuratedEntry[]` 就是干这个的。

「精选」这个标题改成只在搜索时出现。它存在的意义是跟下面那块「来自公开注册表，未经核验」
对照，而不搜时下面那块根本不在，一个没有对照物的来路标记只是又一行字；来路由每张卡自己
带的「已核验」角标承担，那个在两种排法里都在。

## 决策四：精选层的图标认 png

ADR-0171 第四节定的是"精选层用打进包的本地 SVG，长尾层才一律首字母色块"，有断言钉住。
扩表时它挡住了一批条目：有相当一部分牌子**根本不发 SVG 标**——国内几家（高德、腾讯位置、
腾讯云）官网只挂 ico/png，Klaviyo、Vanta、Fireflies、DeepWiki、Context7 也一样。

三条路，选第三条：

1. 我们自己画一个——那是伪造商标，否决。
2. 让它们退化成首字母色块——等于让"精选层每条都有图标"这条规则名存实亡，而这条规则
   是 #715 的产物，不该为了凑数松掉。
3. **认 png**：`import.meta.glob` 收 `*.{svg,png}`，`iconUrl` svg 优先、png 兜底。

代价说清楚：png 不能走 ADR-0180 那条 mask 的路（不透明底会被 mask 成一格实心方块），
所以 `MONO_ICONS` 里不许出现 png 键——这条由 `tests/renderer/mcpIcons.test.ts` 钉住。

图标来源：simple-icons（CC0，38 个）、svgl（AWS / Microsoft / WorkOS / Firecrawl）、
iconify 的 logos 集（monday / Amplitude）、其余从各家官网自己的 favicon / apple-touch-icon 抓。
mono 还是原色按 ADR-0180 那条判据算：品牌色的相对亮度低于 0.06（深色卡上没影）或
高于 0.6（浅色卡上没影）走 mask，中间那段保原色。Supabase 的绿是 0.55，仍在带里。

**没抓到图标的两条直接不进目录**（Attio、智谱）：规则不为个别条目让路。

## 决策五：多一条"svg 里得真有形状"的断言

批量生成时踩了一个坑，值得写下来：simple-icons 那份 `simple-icons.json` 里**没有
`path` 字段**（只有 title/slug/hex/source，路径在 `package/icons/*.svg` 里），脚本照着
`icon.path` 取，38 个文件全成了 `d="undefined"`。

症状是：卡片上什么都没有。不报错、不告警、连首字母色块都不会退回去——因为文件确实存在，
`iconUrl` 找得到，`<img>` 老老实实画了一张空图。已有的三条图标断言一条都拦不住它
（它们查的是颜色和底板，不查"有没有东西可画"）。所以补第四条。

## 后果

- 目录 20 → 82 条，其中国内平台 10 条（高德 / 百度地图 / 腾讯位置服务 / EdgeOne Pages /
  支付宝 / 飞书 / CloudBase / 阿里云运维 / 阿里云云效 / MiniMax）。
- 顺带解掉 #697 的一个前提错误：**Vercel 是能连的**（`https://mcp.vercel.com/` 支持动态
  注册），它被列进 #697 的受阻名单是误判。Slack / HubSpot 的 OAuth 那条路确实还堵着，
  但 HubSpot 有私有应用令牌，这次按 token 那一档进来了。
- 目录长了四倍，`searchCatalog` 仍是线性扫，82 条无所谓；真到几百条再说。

## 被否掉的路

- **抄社区清单直接进表**：GitHub 那行就是反例，见决策一。
- **按注册表长尾解决国内平台**：公开注册表里国内那批基本没有条目，长尾搜不到；
  而且长尾是"未经核验"，把高德放进未经核验层等于没做。
- **给缺图标的牌子画一个替代标**：伪造商标。
- **为了凑齐图标松掉"精选层必须有图标"**：那条规则是 #715 的产物，松掉就等于回到
  "一半卡片没有 logo"的状态。
