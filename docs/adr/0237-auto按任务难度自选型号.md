# ADR-0237：Auto —— 便宜模型先判一手，再决定这一 turn 用哪款

- 状态：已接受
- 日期：2026-09-07
- 关联：#1009；ADR-0232（型号优先级链）、ADR-0233（统一走订阅额度）、ADR-0236（型号下拉）

## 背景

ADR-0232 把 agent 的型号白名单做成一条优先级链，界面上是一个空白文本框；ADR-0236（#1005）把它换成下拉并加了 Auto 一项，但那时的 Auto 只是「不指定型号」——落到路由里就是取网关首选款，和「按任务难度自选」没有关系。

维护者要的是后者，并在会话里从三条候选里选定了机制：**便宜模型先判一手**。

## 决策

### 1. 判据由一次真实的分类调用给出，不是启发式

turn 起跑前，用网关**最便宜那款**读一遍这一轮的开场白，只要它回一个词：`simple` 或 `hard`。

否掉的两条与理由：

- **纯启发式**（正文长度 / 有没有连接器 / 上下文多长）：零成本零延迟，但「长 ≠ 难」——一句「把这段翻译成英文」可以很长而很简单，一句「修一下这个 bug」可以很短而很难。这个代理变量和要判的东西没有稳定关系，做出来是一个说不出理由的数。
- **先便宜后升级**（先用 flash 跑，失败了换 max 重跑）：只在真需要时花钱，但「这一轮算失败」没有现成判据（`turn_ended{completed}` 里没有「答得不好」这一档），且难任务的延迟直接翻倍。

代价明写：每个 Auto turn 多约 200 输入 / 8 输出 token（最便宜那款上约 $0.00005）与 0.3–0.8 秒延迟。

### 2.「哪款更强」拿价当代理，不给 `model_route` 加 tier 列

这个信息今天在系统里**不存在**：`BillingMe.models` 只是一串 id，`model_route` 有价没有能力字段。

选价当代理。理由是**它自己会保鲜**：价目是我们照厂商价目维护的（#1001 / #1003 刚各改过一次），而厂商本来就按能力定价；加一列 tier 则是第二份要人手同步的事实，而两份事实迟早分家（同 `wire.ts` / `billing.ts` 那条「共用一份」的纪律）。

落地方式是 edge 的 `routesQuery` 补两个排序键：`order=priority.asc,price_out_micro_per_m.asc,id.asc`。于是 `me.models` **从便宜到贵有序**，`autoModel.ts` 的 `modelForDifficulty` 拿 `[0]` 与 `at(-1)` 当两档。

这顺带还清了一笔旧账：六行 `model_route` 的 `priority` 全是 10，只按 priority 排的话同分行之间是**未定义顺序**——「没指定型号时用哪款」因此是碰运气，而最贵与最便宜之间输出价差 21 倍。补上次级键之后，**默认款 = 最便宜那款，是个承诺**。第三个键 `id.asc` 兜住「两款价一样」那种情况。

### 3. 判不出来一律回落到「今天的行为」

网络挂了、网关非 2xx、答案认不出、清单不足两款、所有者没订阅——**全部回 null**，调用方不加 override，路由照旧走网关首选款。

**不猜，也不「拿不准就往贵的偏」。** Auto 失灵时该有的表现是「跟以前一样」，不是「悄悄开始烧钱」——这与 ADR-0233 拆掉「额度用完改烧自带 key」是同一条纪律：安静地换一条更贵的路，是这套东西最不该有的失败模式。

注意这与**分类器自己**的偏向是两回事：提示词里明写「拿不准回 hard」。那是分类器**给出了答案**的情形，两类错误里它的代价更小（判错往便宜了走会让一整轮白跑还要重来；判错往贵了走只是这一轮多花点钱）。而「没有答案」不是一种答案。

### 4. 覆盖的方式是换一份 spec，不是给路由层加参数

`preferredModels: () => agent.models` 已经是每轮现读的那一格（#932 坑 ①）。所以 `runJob` 里判出型号后，交给 `engineFor` 的是 `{ ...spec, models: [picked] }`——路由那一层什么都不用知道，`decideRuntimeRoute` 一个字不改。`agentId` 不变，`engines` / `currentAdapters` / `specNames` 的缓存键一个都不受影响。

`SessionServiceDeps.pickAutoModel` 是**可选**的：缺席 = 今天的行为一字不变（测试假件与旧装配不必关心这一格，同 `contextWindowOf` / `loopGuardMaxNudges` 的先例）。装配在 daemon——凭据与订阅探针都在那一层。

### 5. 这一次调用照样记账

分类调用走同一条网关、带同样的 `workspace/session/agent` 头，所以它照常落 `usage_event`、照常扣所有者的窗口。**不做暗扣**：一次用户看不见的模型调用如果不进账，那本账就不再是「钱的唯一事实」。

## 后果

- edge 与 runtime **都要重新部署**，且 edge 先（排序键是 runtime 那两档的前提）。
- Auto 是 agent 的默认状态（`models: []`），所以存量三只 agent 一上线就都走这条路——每 turn 多一次分类调用。要退回旧行为，在型号下拉里挑一款具体的即可。
- 已知代价：接力链上每一棒各判一次（最坏 `depth` 次）；分类器读的是**开场白**不是完整上下文，长会话里「这一轮其实很难」判不出来；提示词注入面积由 `CLASSIFY_MAX_CHARS` 截断封住，但截断本身也意味着超长请求只按开头判。
- 没做：按工作区配「Auto 最多用到哪一档」（今天 Auto 够得到最贵那款，没有上限）；把判定结果画进时间线（型号已经落在 `assistant_message.model` 上，再加一条事件要过新事件类型那十处检查清单）。
