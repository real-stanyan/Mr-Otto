# 0062 自动压缩推翻只手动触发

日期：2026-08-22 · Issue #178 · 相关：ADR-0003（被部分推翻）、ADR-0060（记忆快照）

参考：hermes-agent `agent/context_compressor.py` / `conversation_compression.py`

## 背景

ADR-0003 定的是「/compact 贵，只手动触发」。实际没人记得按 /compact，上下文撑爆比一次摘要成本更高。
hermes 的做法：按窗口比例自动触发，摘要前把记忆快照提供给摘要人避免重复描述。

## 决定

1. `LoopEngine.loop` 每次模型调用前用 `contextUsed` 判定，超阈值先 `compact({trigger:"auto"})`
2. 阈值：窗口 ≥512K 用 0.50，否则 0.75；用户可覆盖 0.3–0.9；未知窗口不触发
3. 同一 turn 只压一次；摘要失败 warn 不毁 turn；Stop 能打断摘要请求（signal 透传）
4. 摘要 prompt 在历史之后、指令之前插入 `MEMORY CONTEXT` 段 = 最新 `memory_loaded` 快照脱敏（`src/shared/redact.ts`）+ 头 4000/尾 1500 截断，指令加「已在记忆里的不要重复」；投影出的 system 消息同样脱敏后再给摘要人
5. `context_compacted.trigger?: "auto"|"manual"`，旧事件缺省 = manual
6. 设置落 `userData/auto-compact.json`，ShellBridge 读写，设置页「上下文」卡

## 理由

触发点放 loop 而不是 turn 开头——工具密集的 turn 中途也会胀；一 turn 一次——摘要本身若仍超阈值，再压只是烧钱；脱敏——记忆是自由文本难免混 key，摘要是第二次外发。

## 推翻条件

模型/服务端原生支持上下文压缩或缓存式长上下文时，本地摘要退为兜底。
