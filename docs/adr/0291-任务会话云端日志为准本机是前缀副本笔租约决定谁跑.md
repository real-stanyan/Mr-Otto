# ADR-0291：任务会话云端日志为准，本机是前缀副本，「笔」租约决定谁跑

- 日期：2026-09-10
- 状态：已接受
- Task issue：#1223；spec：`docs/superpowers/specs/2026-09-10-task-session-cloud-sync-design.md`

## 背景

维护者要的两个场景：电脑睡了手机接着聊、手机开的会话回家电脑接着聊。今天手机只是电脑的加密投影
（中继一帧不存，ADR-0094/0095），云会话从帧到容器全按 workspaceId 键（ADR-0199），没有任何
「个人会话」的云端表；本机日志的 `seq` 是 `MAX+1` 本地分配、事件不带来源——两台设备同时写必撞。

## 决定

1. **云端日志为准、本机 sqlite 是前缀副本。** 两张表（`task_sessions` / `task_session_events`）、
   own-row RLS、写只走 `security definer` RPC 的 `seq` CAS。桌面加复制器 `taskSessionSync`
   （`EventStore.onAppend` 观察者按持久化游标推；realtime `task_sessions` UPDATE + 60 s sweep 拉尾巴
   muted append，断言本地分到同一个 seq）。否决了 B「runtime 为准、桌面变显示器」（桌面离线就没有
   任务会话；本机工具调用绕 VPS + 256 KiB 帧上限）与 C「手机自己跑 LoopEngine」（iOS 后台 30 秒杀 JS）。
2. **「笔」租约决定同一时刻谁写 turn。** 只在跑 turn 时握（拿 → 10 s 续 → 收口帮手跑完才放，ttl 30 s）；
   executor 类事件必须握笔才能追加，人的动作免笔（`PEN_VERDICTS` 穷举 Record）。手机从不握笔，天然只
   发得出人话；runtime 同一条规矩不因 service key 绕过。建行那一批由 RPC 顺手把笔发给创建者。
   否决了「电脑常握笔」：手机永远要等到过期才轮到云端，且醒着没在跑也不该独占。
3. **换执行器是日志事实。** 新事件 `executor_changed`（ignorable），拿到笔的一方在起 turn 前落，
   投影成 system 尾块（云端：碰不到电脑文件；回到电脑：全部工具可用；换了一台 Mac：文件不在这台）。
4. **冲突：云端赢，本机不丢。** 重叠段逐条相等只是游标陈旧；本地多出的尾巴全是人为动作 → 重放到
   云端日志之后；含 turn 痕迹 → 整份复制成兄弟会话「（本机未同步的分支）」再把原 id 换成云端那份。
   不做三路合并。本地永远不因云端行消失而删数据（`detached`）。**有子智能体会话的不走复制这条
   路**：`store.purge` 会级联删掉那些从没同步过的子会话，改成冻结（`frozen`）、本地全留、其他设备
   照旧在云端那份上继续，等人来处理。`frozen` 落 `task-sync.json`，四种终态原因：`forbidden`（RPC
   判定这批不可重试）/ `has_children_conflict`（有子智能体会话）/ `needs_upgrade`（云端那份含这个
   版本不认识的事件类型）/ `purge_rejected`（有引用式分支，`store.purge` 拒绝）；除 `needs_upgrade`
   会在每次 backfill 时解冻重试，其余要人介入。
5. **Default 路径每台机器自己算。** default 种的会话 resume 时日志那个目录不在就按 sessionId 派生
   `<内置 Default>/<sessionId>`（文件夹名就是 sessionId，ADR-0206）；云端建的会话日志里没有路径。
6. **睡眠打断用 `interrupted` 收口。** `engine.abortTurn("interrupted")`；`lastUnanswered` 把它算
   「没答」、`aborted`（人按停止）算「答过」，接手的一方据此接着答。
7. **先验再换（`needs_upgrade`）。** 用云端日志替换本地（分叉路径）或拉尾巴之前，先用
   `shouldPersist` 逐条验证；验不过——包括拉取时撞到本版本不认识的事件类型（`store.append` 的
   `assertNever` 会抛）——就停在那一条、保住已有前缀、冻结为 `needs_upgrade`：旧桌面对着新版本写的
   会话，看到的是「请升级」而不是半截日志，不做「跳过不认识的事件继续拼」。
8. **准入用 `admitting` 挡竞态，笔按三种情形放，held 时挡掉需要笔的消息。** `handleSendMessage` /
   `answerLogged` / `compact` 三处起 turn 前先进程内 `admitting` 集合，把「判断还在不在跑」到「加进
   `runningSessions`」之间那次 `await acquirePen` 的窗口盖住，防止这 ~100 ms 内连按回车分岔成两条
   turn。笔的放法：起 turn 前抛错先放；`executor_changed` 的落盘在 try 块里（放笔前一定已经声明过
   执行器）；收口帮手排空后**只在没有下一轮在跑或正在准入时**才放，避免后台任务回注紧接着起下一轮
   时笔被提前收走。对方握着笔（`held`）时，带 skill 调用或图片的消息直接拒收并说明原因——它们是
   executor 类事件，没有笔落不了盘；纯文本人话照常落盘，不受影响。

## 后果 / 已知代价

日志两份、Supabase 存储随工具输出长、开机回填一次性上传存量、对面没有 token 流式、离线分歧分叉
永不合并、`memory_loaded` 仍是起点快照、机器专属事件（检查点 / 残留）复制到对它们没意义的机器、
任务文件夹的**文件**不同步、一台删除其他设备留 detached 副本、桌面在线判据借好友 30 s 心跳、
子智能体会话不上云且**冲突分叉时随父会话冻结（不 purge），停止同步直到人来处理**、附件是
「拉到即取」（puller 追加事件后立刻下载引用的图片，失败进 `missingAttachments` 下次 sweep 重试，
期间那张图在本机画占位）而非读时回取。`service_role` 有 BYPASSRLS：append-only 与笔约束对
runtime 是「只走 `_as` 包装」的约定，不是 DB 强制；held 时 skill / 图片消息要等对面答完再发一次；
`state()` 是瞬态、`frozen` 是持久，渲染层那一行看不到「为什么停了」的持久原因（下一次成功 sweep
才把非 frozen 状态刷回 idle）；`acquirePen` 没有超时，悬住的 socket 会让准入卡住到 undici 自己
放弃；compact 期间放笔检查会跳过、等下一 turn 收口，F3 放笔的正确性依赖收口帮手链是真异步；
`answerLogged` 的 held 分支不排空 `pendingBg`（只是延迟，不丢）；0036 未在真库执行前，桌面状态行
写「云端还没有任务会话表」（有意的失败方向）。完整清单见 spec §7 与「实施偏差」。

## 推翻条件

多 runtime 水平扩展、或 Supabase 单表写入成为瓶颈时，「云端那份是事实」要换载体；手机端能常驻后台
执行时，C 路线值得重估。
