# ADR-0159：副本合回项目与回收——合到你此刻所在的分支，冲突就回滚

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #643；ADR-0156 / 0157（独立副本）、0158（分支名与锁）、0150（`lane:prune` 的回收判据）、0153（脏工作区上的破坏性 git）

## 背景

ADR-0157 之后每只水獭都在副本里干活，于是两件事从「早晚要做」变成必须做：

1. **合回去**：副本里的活怎么交回项目。之前只能让水獭用 bash 合。
2. **回收**：会话删了副本还在，一直攒。

issue #643 里列了四个不是纯工程的问题，逐条答。

## 决策

### ① 合并的目的地：项目目录**此刻所在的那条分支**

不猜，不写死 `main`。用户自己 `checkout` 在哪，那就是他唯一说过的话；把它当成目的地，行为可预测且不需要再问一次。

系统提示里那句「先问一句合到哪个分支」仍然对水獭有效——**那是给对话路径的**，用户可能想合到别处；UI 这条路径走的是「就合到你现在待的地方」。两条路径答案不同不是矛盾：一个是商量，一个是默认。

### ② 项目目录脏 → 拒绝

往有未提交改动的工作区上合并，正是 ADR-0153 拦的那类事故：用户自己没提交的活可能被卷进冲突里。拒绝，并把目录路径写进错误信息。

**副本里有未提交改动也拒绝**，理由不同：合并只带走已提交的部分，不说清楚的话用户会以为全带走了。错误信息里点明「先让水獭提交」。

### ③ 冲突 → `git merge --abort` 回滚

绝不把用户的 checkout 留在冲突态。GUI 用户卡在 conflicted 里比合并失败糟得多——他没有终端上下文，界面上也没有解冲突的地方。

回滚后把 git 的原话截断带回，并给一条出路：让水獭先把目标分支合进副本、在副本里解完冲突再来。**解冲突发生在副本里**，那儿本来就是水獭的地盘。

### ④ 回收只收「干净且已合并」的

判据照 ADR-0150 的 `lane:prune`：脏的留着（那些东西只在这儿，删了就没了）、没合的留着（活还在分支上，用户找得回来）。锁是 ADR-0158 上的，删之前先 `git worktree unlock`；分支用 `-d` 安全删，删不掉就留着。

回收发生在**会话删除**时，且必须在 `purge` 之前把 `isolated` 从日志里取出来——日志没了就不知道它在哪条分支上。

留下来的情况打一条 `console.warn`：留是有意的，但得让人知道去哪儿找。这条路径没有 UI 出口，控制台是唯一的。

### ⑤ UI：状态是常驻标记，操作在已有的「更多」菜单里

头部加一枚「独立副本」chip——**只是状态，不是控件**：常驻、不动画、不抢注意力；用户真正需要知道的那句（你的项目目录不会变）挂在 `title` 上。

合并进已有的溢出菜单，不新增头部按钮：头部一行已经装着会话名 · 工程 · 分支选择器。不在副本上的会话**整条菜单项不出现**，而不是灰着——菜单里没有意义的行不该占位置。

结果显示在菜单里那一行下面，不弹窗：合并是用户主动发起的，他此刻正看着这儿。四档失败各有一句人话，UI 原样显示，不翻译成「失败了」。

## 后果

- 接受：合并目的地不可选。想合到别处 → 让水獭做（它有 bash，系统提示也让它先问）。
- 接受：冲突不在 UI 里解。副本是水獭的地盘，那儿有工具。
- 接受：没合的副本会攒着。这是有意的——删掉才是不可逆的错误。
- 接受：检查点按 workspace 键，副本被回收时那条会话的文件回退锚点跟着没（ADR-0156 后果第三条，未变）。
- 归档（不是删除）不回收：归档是「收起来」，还能恢复，副本得留着。
