# ADR-0190：已知接不上的连接器不发那颗按钮 —— 结论要上屏

- 状态：已接受
- 日期：2026-08-29
- 关联：issue #760、#733（判据与复现法）、#697（根治）、#722（撒谎的勾）、ADR-0184、ADR-0189

## 背景

用户在目录里点了 GitHub 的「添加」，卡片落进「待接通」并给出一颗「授权」。点它：

```
「github」授权没跑通：Incompatible auth server: does not support dynamic client registration
```

再点还是这句。这台永远出不了「待接通」。

而 `src/shared/mcpCatalog.ts` 里早就写着（ADR-0184 那次实测的产物）：

```ts
authNote: "暂时连不上：GitHub 要求预先注册的 client_id，Mr Otto 还没有手填它的地方（#697）",
```

**我们知道，写下来了，然后没说出口。** 两个原因叠在一起：

1. `installSlot` 只看安装状态，从不看这条已知结论 —— `null` 照发「添加」，`needs-auth` 照发「授权」。
2. `authNote` 唯一的渲染点是 `InstallConfirmDialog`，而那个对话框**只对未核验的注册表条目弹**。GitHub 是核验过的，所以这句话一个用户都没看见过。

这是 #722 那个撒谎的勾的同一个形状：**界面提供了一个我们已经知道会失败的动作。**
上一次是一格勾在说"完事了"，这一次是一颗按钮在说"点我就能连上"。

## 决策

### 一、把结论从 `authNote` 里拆出来，成为一个界面读得懂的字段

`CatalogEntry.blocked?: string` —— 实测过、此刻接不上，值是给用户看的那句原因。

为什么不能继续放 `authNote`：那个字段回答的是"要授权的话该干什么"，是**流程说明**；
"现在干不成，因为对方不支持动态注册"是**状态判断**。两件事混在一个字符串里，
就没有任何一段代码能对后者做出反应 —— 事实上也确实没有，这就是这个 bug。

拆开之后加了一条门禁断言：**`authNote` 里不许出现「连不上」「接不上」**
（`tests/shared/mcpCatalog.test.ts`）。下一次有人把真相写回错误的字段，会在门禁上红，
而不是在界面上安静地不出现。

### 二、`installSlot` 在两档上让位，`connected` 不让位

`add`（还没装）和 `needs-auth`（装了没授权）换成一句安静的「暂时连不上」+ 原因 —— 这两颗
按钮点下去必失败。`failed` / `connecting` / `disabled` 本来就是说明，不受影响。

**`connected` 例外**：真连上了说明我们的结论过期了（对方补上了动态注册，或者用户手改
`mcp.json` 塞了个能用的凭据）。这时候还画「暂时连不上」，说的是我们的记忆而不是事实。
判据的优先级是：**现实 > 我们上次实测的结论 > 什么都不知道**。

### 三、原因要画出来，不能只挂在 tooltip 上

详情页在头部下面画一条 `warn` 色的说明。理由：用户是带着"为什么点了没反应"这个问题
点进来的，答案该在他视线落点上；tooltip 要悬停才有，而"我该悬停哪里"本身就是个问题。

### 四、`humanizeMcpError` 认得这一类，agent 那边也要知道

目录里的三条走 `blocked`（那句更具体，还带 issue 号）。但**目录外**的 server —— 手填的、
注册表来的 —— 会撞同一堵墙，那条路上只有 SDK 的原话。所以 `humanizeMcpError` 补两条：
`does not support dynamic client registration` 和 `Incompatible auth server` 的其余变体。
同时把授权失败那条路径（`McpDirectory.tsx` 的 `install` / `authorize`）接进 humanize ——
它原来直接贴 `bridgeErrorMessage`，ADR-0189 那次只改了卡片上的错误行，漏了这一条。

`src/tools/mcpCatalog.ts` 的 `render()` 也要把 `blocked` 说一遍。这一句原来混在 `authNote`
里，水獭是读得到的；拆成新字段而不补这一行，就等于**只有界面知道、agent 不知道** ——
水獭照样 `mcp_configure` 落盘再 `mcp_authorize`，撞同一堵墙，还白留一台永远连不上的
server 在用户的 `mcp.json` 里。

## 否决的路

**删掉这三条目录**。理由同 #733：GitHub 是这份目录里最常被找的一台，删了用户的结论
不是"这台暂时接不上"，而是"这软件接不了 GitHub"。把问题藏起来比说清楚糟糕得多。

**做成一个「接不上」的第三组**。三条条目不值一个新分组；而且 `blocked` 是**临时**状态
（#697 落地就没了），为一个会消失的状态在信息架构上开一格，成本留在结构里而收益会走。

**把按钮禁用（`disabled`）而不是换成说明**。一颗灰按钮回答不了"为什么"，用户只会多点
两次再来问。说明文字本身就是答案。

## 代价

`blocked` 是人手维护的实测快照，会过时 —— 对方补上动态注册之后，我们仍然画着「暂时
连不上」，而且**这一次错在保守的方向**（把能用的说成不能用）。缓解有两层：`connected`
不受 `blocked` 影响（用户真连上了界面立刻改口），以及门禁里那条 "#733 那三条挂着 blocked"
的断言 —— 它在删字段的时候会红，逼着改的人同时更新测试，那一刻正好回头看一眼 #733。

## 后果

- 已经装了 GitHub 的用户（就是报这个 bug 的人）：卡片仍在「待接通」，但不再有那颗骗人的
  按钮，点进详情页能看见原因，也能在「设置」里把它删掉。
- 门禁 `npm test`。
