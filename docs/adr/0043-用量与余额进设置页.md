# ADR-0043：设置页的用量图与厂商余额

- 日期：2026-08-20
- 状态：已接受

## 背景

「模型配置」页原来只回答一个问题：这家配没配 key。用户真正想知道的另外两件事没地方看 ——
**这家我用得多不多**（钱花在哪家了）、**账户还剩多少**。

用量本来就在日志里：`assistant_message` / `context_compacted` / `section_classified` /
`suggestions_generated` 四类事件带 `usage`（见 `session/deriveUsage.ts`）。
但既有的投影（`usageByModel`）是**单会话**的，浮层里的花费面板用它；
设置页要的是**跨会话、按厂商、按天**。

余额不在日志里，只能问厂商。

## 决定

### ① 跨会话用量：主进程 SQL 筛行 + 共享纯函数投影

`EventStore.billedUsage(since)` 在 SQL 层用 `json_extract` 把计费行投影成四个数
（ts / model / 入 / 出），`shared/usageStats.ts` 的 `usageByProviderDaily` 把它们
归并成「每家每天多少 token」。一次 IPC 过桥的是聚合结果，不是几万行原始用量。

- 「哪些事件算账」这条规则**只写一份**：`BILLED_EVENT_TYPES` 从 `deriveUsage.ts` 导出，
  SQL 用它拼 `IN (...)`。两处各抄一份四个字符串，迟早有一处漏掉新增的计费事件类型。
- 分桶按**本地日历天**（`Date.UTC(年,月,日)`），不按 86400s 整除：跨夏令时那天不是
  24 小时，按毫秒切会把一整天错位一格。
- **归档的会话照样算**：archive 是"从会话列表里消失"，不是"这笔钱没花过"。
  （purge 例外——那是日志被完整遗忘，账跟着没了，与 append-only 不矛盾，见 store.ts。）
- 认不出厂商的型号**整行丢掉**，不塞进任何一家：多半是目录里删掉的旧 id，
  硬归到某家会让那家的数字凭空变大。少算一点好过算到别人头上。

### ② 余额：只有四家有 API，其余厂商**什么都不显示**

有公开余额端点的只有 DeepSeek / 月之暗面 / 硅基流动 / OpenRouter。
OpenAI、Anthropic、Google、GLM、Qwen、xAI、Mistral、Groq、MiniMax 都没有
（OpenAI 的 `/dashboard/billing` 要控制台 session，不是 API key）。

查不到的厂商在 UI 上不长出这一格 —— **不是显示 $0**。同 `modelPricing.ts` 的老规矩：
「不知道」和「免费/没钱了」是三件不同的事，把前者显示成后者会让人去做完全错误的处置
（比如去充一笔并不需要的钱，或者以为还有余额而没充）。

**币种照厂商自己报的**，不写死在表里：同一家 DeepSeek，境内账户结算 CNY、境外账户结算 USD，
它在响应里说了。写死一个符号就会把 $7.08 显示成 ¥7.08 —— 一个看着完全正常、
数量级也对、却错了七倍的数。认不出的币种原样带上代号，不猜符号。

三条边界：

- 请求发在**主进程**：key 只活在主进程 env，永不过桥。去向只有签出这把 key 的那家自己。
- **设了 `*_BASE_URL`（自建代理）就不查**：代理后面挂的是谁的账户无从得知，
  拿官方端点的数字冒充它是在报一个不相干的数。
- 缓存 60 秒：设置页开开关关是常事，余额是分钟级才变的东西。

### ③ 图表用 `elements/chart.tsx` 的 `bars`，**每家一张**、**按型号分层**

这个元件画的是**时间序列**：一根柱 = 一天。所以是"每家一张自己的近 14 天"，
而不是"一张图里每家一根柱" —— 后者会让"最右边 = 最新"这个语义变成假的。

一根柱按**型号分层**（本仓给元件加了 `stacks` / `layerClass` / `renderTip` 三个可选口）：
同一家里正文走贵的、压缩/分区/建议走便宜的，只报每天总量会把这件事抹平，
而"钱花在哪一款上"恰好是看这张图的人想知道的。因此投影的形状是
`days[i][m]`（第 i 天、第 m 款），不是 `days[i]`。

三条附带的取舍：

- **分层时不再高亮最后一根**。原件用"末柱变蓝"表达"这是今天"，但分层之后颜色
  已经被型号占用了 —— 一根柱同时用颜色说两件事，读者只能猜哪一件算数。
- **悬停命中区是整列，不是柱子本身**：一根 2px 高的柱要求用户把鼠标停在底边那一线上。
- **靠边的浮窗改成侧贴**：浮窗比一根柱宽得多，居中会有一半探到卡片外，
  而外面那层卡是 `overflow-hidden`，探出去的部分会被直接切掉。
- 快照带上投影时的 `now` / `days`（`UsageSnapshot`）：UI 要把第 i 格换算成日期，
  得用投影那一刻的"今天"，用渲染时的会在跨过午夜时整体错一格。

元件自带的 `delta`（涨绿跌红）不用：那是给营收看的配色，
而这里涨的是**花销**，绿色等于把"这周多烧了四成"表扬一遍。涨跌另起一行，中性色。

## 后果

- 设置页开页时多两趟请求：一趟本地 SQLite（毫秒级），一趟出网查余额（各家 60s 缓存）。
  两者**分开 set**，不绑成一个 `Promise.all` —— 否则毫秒级就能画出来的图要陪网络请求一起等。
- 不做轮询：这一页是改配置的地方，不是仪表盘。**但存完 key 立刻重查一次**（主进程同时清掉
  60 秒缓存）—— 否则用户刚贴完 key，盯着一个"已配置"却没有余额的行，会以为功能坏了。
- 新增了本仓第一处「带用户 key 访问厂商非推理端点」的调用。将来若有厂商加了余额 API，
  加一条 `ENDPOINTS` 记录即可，UI 不用动。
- 前一个窗口一个 token 都没有时不报百分比（没有分母），报"前 14 天没用过"。

## 被否掉的选项

- **一张总图 + 每家一张**：同一个数在一页上出现两次，读者会以为是两件事。
- **在 UI 层把查不到价的型号按 $0 计入合计**：报出来的是一个偏小的"这家花了多少"，
  比不报更坏。整家退回 token 总量。
- **把整库事件 `load()` 出来再过 `usageByModel`**：一台用了几个月的机器，
  日志里绝大多数字节是工具输出，为几个 token 数把它们全读进内存不划算。
