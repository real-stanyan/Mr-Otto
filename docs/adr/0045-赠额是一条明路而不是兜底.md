# ADR-0045：官方赠额是一条可以点的路，不只是"没 key 时的兜底"

- 日期：2026-08-20
- 状态：已接受
- 关系：**修订 ADR-0020**（自带 key 优先于官方额度）。0020 没有被推翻，它降级为 `lane=auto` 的规则。

## 背景

ADR-0020 定的是：自带 key 优先于官方额度 —— "他自己付的钱，不该因为顺手登录了
就被改成花官方的"。这条在**没有第二个入口**的年代是对的：用户表达"我想用赠额"
的唯一方式是把 key 清掉，那确实该被当成一次明确表态。

代价是：配了 key 的人在型号选单里**看不到赠额这回事**。他的 20M flash 额度躺在
账上，界面上一个字都没有 —— 想用只能先删掉自己的 key，用完再贴回来。
"表达意图"和"改配置"被绑成了同一个动作。

## 决定

引入 **lane**（`shared/modelLane.ts`）：一次模型选择除了"哪一款"，还带"走哪条路"。

- `auto`（缺省）：ADR-0020 的老规矩 —— 自带 key 优先，没 key 才用赠额。
- `grant`：明确要花官方赠额，**哪怕自己配了 key**。

三条随之而来的取舍：

**① lane 落进日志，不当运行时偏好。** `ModelChangedEvent.lane?`（可选 = 旧日志无此
字段照样重放）。thinking / 审批模式是运行时偏好、不落盘，lane 不一样：它决定
这个 turn 的钱**从谁账上出**，那是"发生过什么"的一部分。`auto` 不写进事件 ——
它是缺省，写了等于给每条事件补一个没有信息量的字段。

**② `lane=grant` 排在路由的最前面**（`main/modelRoute.ts`）。它是用户刚刚亲手做的
选择，不该被"你配过 key"这个更早、更含糊的事实推翻。点了赠额却没登录 → blocked
并说清楚，**不悄悄回落到自己的 key**：悄悄回落等于替用户花了他没打算花的钱。

**③ 选单里同一款可能出现两次，靠 id 前缀区分**（`grant:deepseek-v4-flash`）。
但只在两条路**真的不同**时才出现两份：没配 key 又登录着的时候，`auto` 本来就会
走网关，两组一模一样 —— 那种情况下只留赠额一组，否则读者得回答"点哪个才是免费的"，
而那个选择根本不存在。

## 后果

- 用户不必再为了用赠额去删自己的 key。"表达意图"和"改配置"解绑了。
- 反过来也成立：赠额用完时，切回 `auto` 那一份就是自己的 key，不用登出。
- 路由的判断顺序从"三个 if"变成"四个 if"，但它仍然是一句能指着代码念的话
  （modelRoute.ts 开头那句注释的要求）。
- 旧会话重放不受影响：没有 lane 字段 = auto = 老行为。

## 被否掉的选项

- **赠额优先于自带 key**（把 0020 整个翻过来）：那会让"配了 key"这件事变得不可预测 ——
  用户配 key 的动机通常是"我要用我自己的账号/额度/速率"，默认花别人的不符合这个动机。
- **只显示不可选**：能看见余额但点不动，等于把"你有 20M 额度，但拿不到"写在脸上。
- **靠清 key 表达意图**（现状）：见背景。
