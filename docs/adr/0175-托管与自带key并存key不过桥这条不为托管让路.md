# ADR-0175：托管与自带 key 两条路径并存，「key 不过桥」这条不为托管让路

- 状态：已接受（stanyan 会话指示，issue #696）
- 日期：2026-08-29
- 推翻：ADR-0020 决定一的**优先级顺序**（付费订阅下反过来），决定二（端点现算）原样保留
- 相关：ADR-0173（订阅计量）、ADR-0174（比价路由）、ADR-0085（被 0173 推翻的那条）

## 背景

上了订阅制之后，一次模型调用有两条路：走官方网关（Otto 的 key + 用户的订阅额度），
或直连上游（用户自己的 key）。免费档保留自带 key 且**能力全开**。

得定两件事：谁优先，以及自带 key 那条路走不走网关。

## 决定一：自带 key **不走网关**，保持本地直连

```
托管模式：客户端 ──JWT──> otto gateway ──官方 key──> 一方站
BYOK  ：客户端 ────────────用户自己的 key─────────> 一方站   （现状，不变）
```

让 BYOK 也走网关能省下「统计要合并两个来源」的麻烦，但代价是**用户的 key 要上传到
我们的服务器**。AGENTS.md 的硬规则和 `src/main/providerCatalog.ts` 的约束写的是
「key 只活在主进程 env，永不过桥」；`src/main/providerBalance.ts` 的头注也照这条写了
「请求的去向只有一个 —— 发给签出这把 key 的那家自己，不经第三方」。

**这条约束不为托管让路。** 「你的 key 不上传」是这个产品最强的信任卖点之一，
尤其对那些因为合规原因不能用托管档的用户（见决定四）。为了少写一个聚合函数
把它拆掉，是拿资产换便利。

代价明说：**用量统计有两个来源**（服务端 `usage_event` + 本机事件日志），
`usageStats.ts` 那条投影要能把两边并起来显示，且必须让用户看得出哪一段是花的谁的钱。

## 决定二：付费订阅下，**托管优先于自带 key** —— 与 ADR-0020 相反

ADR-0020 定的是「自带 key 优先，且优先级高于登录态」，理由是：

> 他填了自己的 key，顺手登录了一下，然后发现官方额度在掉。

那条理由在**赠额**形态下成立 —— 白送的东西被悄悄花掉是意外。在**付费订阅**下它反过来：
用户每月付了 \$19，结果系统绕过他买的东西去烧他自己的 key，这才是意外。

新顺序（`routeModel` 仍是唯一判断处）：

1. 有活跃订阅 且 额度未耗尽 → **走网关**
2. 额度耗尽 且 配了自己的 key → **直连**（这是耗尽处置的第二条出路，见决定三）
3. 无订阅 且 配了自己的 key → **直连**
4. 无订阅 且 无 key → **blocked**，把两条出路都说出来（订阅 / 填 key）

ADR-0020 决定一的第 2 条（「型号不是 DeepSeek 就 blocked」）随 ADR-0174 自然失效 ——
它自己写明「如果官方额度将来覆盖多家上游，这条就该改成『网关支持的型号集合』」，
比价路由正是这件事。

ADR-0020 **决定二（端点每次请求现算）原样保留**，两条理由都还成立：Supabase
access token 仍然一小时过期，用户仍然可能在会话中途填 key 或登出。

## 决定三：额度耗尽 = 自动落到自己的 key，不降级、不硬等

耗尽处置只有两条出路：**加购**，或**切自己的 key**。

不做「自动降级到最便宜的模型」—— 那是偷偷换差模型，用户会以为产品变笨了而不是
额度用完了。不做「硬等到窗口重置」作为唯一出路 —— 配了 key 的用户没有理由被挡。

所以第 2 条是默认行为：配了 key 就无缝继续，UI 上明确提示「本次起用的是你自己的
key」。硬停只发生在没配 key 且不加购的情况下，配倒计时（固定窗口的好处，见
ADR-0173 决定三）。

## 决定四：免费档能力全开，转化支点不是「帮你付 token 钱」

免费档 = 完整产品 + 自带 key。这意味着转化故事**不能是**「我帮你付钱」——
国内一方站的入门 Coding Plan 是 ¥8–49/月（\$1–7），用户自己去充值比订阅便宜。

真实的转化支点按强度排：

1. **多模态**（Pro 给图、Max 给视频）—— 配齐火山 / 快手 / 阿里的图视频 API，门槛
   远高于配一个 LLM key。这是最强的一条，也是能力门禁全部集中在图 / 视频的理由
2. **一个订阅打通多家** —— 六个一方站，不用开六个账号充六次值
3. **免配置** —— 目标用户是不想搞这些的人

代价明说：**技术用户恰恰不怕配 key**，早期转化会偏低。这是接受的。

## 决定五：UI 上两种单位不能混

同一个位置，托管模式显示「消耗 X credit」，BYOK 模式显示「\$X」
（`src/shared/modelPricing.ts` 那套现算的钱数）。混在一起会让用户以为在双重扣费。

## 一个已知且接受的取舍：欧盟 / 英国卖不了托管档

全走境内一方站意味着数据落在中国大陆。中国无 GDPR 充分性认定，多国已对
中国模型 API 有政府部门禁令。因此：

- 托管档的可服务市场 = 美国（最大且私营部门无禁令）、加拿大、澳洲、新西兰、
  东南亚、中东、拉美、日本
- **欧盟 / 英国不卖托管档**
- 合规敏感的客户（政府承包商、金融、医疗）走免费 BYOK 档 —— 产品照卖，只是不
  买托管。这正是决定一「key 不过桥」在商业上的回报：这类客户能用，是因为他们的
  key 和数据从没到过我们这儿
- ToS 与隐私页必须明写数据流向。这是硬要求，不是可选项

## 会被推翻的前提

- 若将来做**通道 C**（西方平台托管中国开源权重，如 Fireworks / Together），
  欧盟那条限制就解开了，代价是成本涨 2–3.4 倍。届时「通道按档位分层」
  （个人档走境内、企业档走西方托管）会是一个独立决定。
- 决定二的顺序压在「订阅是付费的」这个前提上。若将来又出现免费赠额形态，
  ADR-0020 的原顺序对那一档重新成立。
