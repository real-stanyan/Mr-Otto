# ADR-0141：一次写盘的行数账落进日志，而不是渲染层现算

- 状态：已采纳
- 日期：2026-08-26
- 相关：issue #584；ADR-0140（动过的文件画成一棵树）、issue #345 / `src/main/turnDiff.ts`（turn 级聚合 diff）
- 推翻：ADR-0140 的「树上不画 +N/−M」

## 背景

ADR-0140 把文件卡换成文件树时，明确留白了增删行数，理由是「`write_file` 是整份覆盖，渲染层手里只有新内容没有旧内容，算不出增删」——并把两条可能的出路都否了：渲染层读磁盘算 diff（投影里做 IO，越界）、往日志里落行数（"为一行数字不值"）。

那个"不值"的判断错在没看清楚**账在哪儿已经算过了**：`turnDiff` 中间件为了 turn 级聚合，本来就在每次写盘前从 `world.fs` 读了一遍旧内容。算这一笔的行数是顺手的事，不需要多一次 IO，也不需要渲染层越界。

而 turn 级那份聚合撑不起时间线：它是运行时投影（**刻意不落盘**，见 `turnDiff.ts` 开头），turnId 换代整份作废，app 一重启就没了。时间线上每一个历史工具组都要报数字，数字只能从日志里来。

## 决策

**每一次写盘的行数账，在写盘那一刻算好，落进 `tool_result`。**

- `ToolResultEvent` 新增可选字段 `diffStat?: { additions, deletions }`。可选 = 旧日志无此字段照样重放（schema 向后兼容硬规则）。
- 产出方是 `turnDiff` 中间件：它已经在写前读了旧内容，`writeStat(oldText, newText)` 用同一个 `diffView` 算一遍，挂在 `ToolOutcome.diffStat` 上。
- `LoopEngine` 落盘时**有才写**（`...(outcome.diffStat ? {…} : {})`）：新日志里没有账的那些和旧日志长得一样，读者侧只有一条判据。
- 被拒 / 出错不带账：盘上没变过，报个数字就是撒谎。

**这一笔的基线是「这一次写之前」，不是「本 turn 第一次碰它之前」。** 同一个文件在一个 turn 里写两次，turn 级聚合报一次总账（面板要的），日志里是两笔各自的账（时间线一步一行要的）。两份数字都对，各答各的问题——所以是两套，不是一套的两个副本。

渲染层因此只做加法：同一组里同一个文件写了两次，`mergeChangedFiles` 把两笔相加。**"没账"和"0"分开**：旧日志那样的行不报数字（连键都不带），不填零——`+0 −0` 是在说"这次没改"，而事实是"不知道"。

## 后果

- 时间线上任意历史工具组都能报数字，重启、换机器、重放旧会话都一样——因为它就在日志里。
- 树上的红绿与「本轮改动」面板同源同色（`--ok` / `--err`），但**不是同一个数**：那边是 turn 聚合，这边是这一组。同一个文件两处数字不一致时，不一致本身是对的（一个是总账、一个是分账）。
- 事件日志每条 `write_file` 的 `tool_result` 多两个整数。schema 向后兼容，重放路径不变。
- 算不动的情况（单边超 200KB / `diffView` 超预算）退化成行数计数，与 `fileDiff` 同一套规则：宁可给个粗的数，也不留空让读者以为"没改"。

## 被否掉的路

- **继续留白**（ADR-0140 的原判）。留白的成本是读者每次都得点开文件才知道改了多少；而补上它的成本已经被证明只有"顺手算一遍"。
- **让渲染层去读磁盘算 diff。** 投影里做 IO，而且读到的可能是之后又被改过的版本——数字会随着时间漂移。
- **复用 turn 级聚合的数字。** 不落盘，重启即无；而且它答的是另一个问题（本 turn 总账）。
- **让 `write_file` 工具自己返回行数。** 工具只拿到新内容，读旧内容要多一次 IO——而中间件那一次已经读过了。
