# ADR-0363：好友私聊里的「代办」——入口只有对方的管理员：客人点名与通话一律改到管理员、公开车道必带管理员、由它下发给主人选的那只

日期：2026-10-04 深夜 · issue #1563（父）/ #1564（本条，P1）· 维护者原话：「给对话者的 AGENT 打电话的目的是在对方不在线或繁忙
情况下，可以先由 AGENT 代办。而现在如果 AGENT 是公开的，那么对话者的所有和 AGENT 的对话都会出现在聊天页面，并且如果该页面有
多个 AGENT 他们会互相抢活。所有代办的 AGENT 必须是管理员，由它下发任务给对应的 AGENT。」四问拍板见 #1563 的评论。

## 背景

ADR-0353 让主人把自己的智能体带进与朋友的私聊并公开给朋友；ADR-0356 让主人选一只「公开智能体」，朋友能 @ 它、打给它。
真机上两条叠起来的样子（#1563 截图）：朋友在私聊里 @Otto开发、@峰哥 轮流说话，谁都能接、谁都在抢；打给「公开的那只」
时车道里别的智能体也一起接。根因是**朋友那一侧有多个入口**——每多公开一只就多一个。

## 决定

1. **朋友那一侧只有一个入口：主人的管理员。** 客人在公开车道里点的名（`say` 的 targets）与客人开的通话（`setVoiceCall` 的
   participants）**在 runtime 一律改成管理员**（`guestTargetsInLane`）；手机那侧 @ 名单里对方的智能体只列管理员，电话钮那一项
   改成「给 TA 的管理员打电话」。否决了只在手机上收口：老客户端 / 别人写的客户端照样能点别的名字，入口必须在 runtime 收。
2. **公开出去的车道必带管理员**（`delegationRoster`，管理员排第一）：朋友替主人开的车道 = [管理员, 公开智能体]；主人自己
   建着就公开的、或事后切成公开的车道，建 / 切那一刻把管理员补进名单；收回私密时不动名单。
3. **「公开智能体」保留，语义改成「管理员的下发目标」**（维护者选的是「可自选但先过管理员」）：它仍是「开了代办」的开关
   （没设 = 朋友开不了车道、打不了电话，同 ADR-0356），管理员的提示词里点名「主人指定的代办智能体：X」，要动手的事
   管理员在回复里 @ X 交给它。下发走的就是现成的接力（ADR-0223）：客人点起的轮的接力开场白记在客人名下，下一棒照旧
   受监督（每一刀等主人批，ADR-0325 第 7 条）——**这里不新开免审口子**：下发是「说话」，动手仍要主人点头。
4. **车道里的别的智能体**（主人带进来的、或被下发的那只）的提示词加一句：朋友的请求一律先到管理员，管理员 @ 你下发的
   事才轮到你做。它们在名单里、朋友看得到，但不再是入口。
5. **老车道**（名单里还没有管理员的）客人点名原样——不能让朋友一句话都发不出去；下一次切朝向 / 重建时补上。

## 没做 / 之后

- 主页只留任务卡、过程进抽屉（P2，#1565）：那是投影层的事，这一条先把事实层（谁是入口、谁在名单里）收口。
- 不限制主人自己在车道里 @ 谁：主人点谁还是谁。
- 不把公开智能体固定成管理员（维护者没选那一项）。
