# ADR-0153：破坏性 git + 工作区脏 = 必须问人，越过 bypass 模式

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #633；#620 / ADR-0152（水獭之间的互斥）、#543（本仓自己踩的那三次）
- 相关 ADR：0041（长期授权）、0092（ExecutionWorld 安全边界）、#347（execpolicy 静态判定）、0093/0136（branch_checked_out）

## 背景

ADR-0152 让「同一个文件夹同一时刻只跑一条 turn」。那管的是**水獭之间**。

但踩掉未提交改动这件事，**一只水獭就够**：它在用户的仓里跑一条破坏性 git，用户自己在编辑器里没提交的活就没了。互斥完全拦不住——只有一条 turn 在跑，规则一个字都没违反。频次也更高：不需要两只水獭同时在场，只需要一只 + 一个正在写代码的人。

## 一处必须先纠正的事实

「`git checkout` 会静默吃掉未提交改动」是个流传很广的误解，本轮排查里我自己也先信了。**普通的 `git checkout <分支>` 不会**：

```
error: Your local changes to the following files would be overwritten by checkout
```

git 自己会拒绝；冲突不到的改动它会带着一起过去。

这个纠正直接决定了名单的形状：**裸 checkout 不进名单**。进了就是天天误报，而误报会训练用户闭眼点「批准」——那比不拦更糟，等于把审批卡变成噪音。

真正会丢东西的是那些**语义就是「丢弃」**的命令，git 不拦是因为你已经说了要丢：`reset --hard`、`clean -f`、`checkout -- <路径>` / `checkout .`、`checkout -f` / `switch --discard-changes`、`restore <路径>`、`stash drop|clear`。

## 决策

**破坏性 git + 工作区脏 → 越过一切短路，问人一次。**

### 挂在审批链的哪一节

```
policyAware( dirtyTree( modeAware( grantAware( ui ) ) ) )
```

- 用户亲手写的 execpolicy `forbidden` 仍然最先赢（那是「永不放行」，不该被任何东西降级）；
- 但**「完全访问」模式和任何长期授权都压不过这一条**——命中时直接找 UI，绕开 `modeAware` / `grantAware` 的短路。

越过用户选的 bypass 模式是**故意的**，理由与既有的 `forbiddenGuard` 同款：bypass 说的是「这台机器上的操作我都认」，而这里要丢的东西**可能根本不是水獭做的**。用户授权的是 agent 的行为，不是「把我自己没提交的活删掉」。这一下值得打断。

### 摩擦只在真会丢东西时出现

工作区干净 → 一路放行，链路与从前逐字节一致。不是破坏性命令 → **连 `git status` 都不去跑**（不给正常操作加开销）。

### 读不到工作区状态 = fail-open

不是 git 仓 / git 不在 / 目录没了 → 不加摩擦，回到原有链路。这一层是**额外的一道**，不是唯一那道：该弹卡的照常弹。在这里 fail-closed 会把「在非 git 目录里跑命令」也卡住，那是纯粹的误伤。

### 判定的松紧：不照搬 execpolicy 的严格度

`canonicalizeCommand` 的元字符表为**授权 key 的等值比较**服务，把 `~ ^ *` 也算复杂脚本。照搬会放过 `git reset --hard HEAD~1`——最典型的那一条（本模块第一版就栽在这，测试当场红）。

所以退化成 raw 时再看一眼：只有真正改语义的元字符（管道/逻辑/子 shell/命令替换/重定向/转义）才放弃判定，其余按空白切一刀。**兜底只用于判定意图，不产出任何授权 key**——宽一点的代价是多问一次，不是多放一条。

## 为什么不是别的做法

| 候选 | 否决理由 |
|---|---|
| 写成 execpolicy 规则（`git reset --hard` → prompt） | 静态前缀规则看不见工作区状态。而这条命令在干净的仓里完全正常——静态规则只能在「永远问」和「永远不问」之间选，两个都不对 |
| 做成 `ToolGuard`（像 `execpolicy-forbidden` 那样直接拒） | guard 是 deny-only。直接拒等于水獭永远做不了这件事，用户想让它做也不行；而且错误信息里教模型「加 `--force` 再试」是最坏的结果 |
| 靠每 turn 的影子 git 检查点（#395）事后恢复 | 那是**恢复**不是**保护**，而且它存的是 turn 起跑那一刻——同一 turn 内跑的破坏性命令，丢的是这条 turn 里人刚写的东西。恢复手段留着，但不能替代拦一下 |
| 拦 `git checkout <分支>` | 见上：git 自己会拒绝，拦它就是训练用户闭眼点批准 |

## 后果

- 接受：用户在 bypass 模式下也会被打断一次——仅当工作区脏且命令真会丢东西。
- 接受：判定用了比 execpolicy 宽的 token 化，可能在极少数畸形命令上多问一次。宽的方向是安全的：多问 ≠ 多放。
- 不覆盖：`git push --force`（丢的是远端历史，不是工作区未提交改动，风险模型不同）、`git branch -D`（丢的是提交，不是未提交改动）。两条都值得单独想，不在本 ADR 范围。
- 不覆盖：绕过 bash 的路径——比如模型用 `write_file` 覆盖文件。那是另一条链上的事。
- 子会话/裸装配没有注入 `dirtyFiles`，这一层不存在，链路一字不变（子会话本来就是 `denyingApprover`，没人盯屏幕时危险操作一律拒）。
