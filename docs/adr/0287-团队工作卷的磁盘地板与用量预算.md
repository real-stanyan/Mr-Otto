# ADR-0287：团队工作卷的磁盘地板与用量预算——真配额在这台机器上做不到，验过的

- 状态：已接受
- 日期：2026-09-10
- 相关：#836；ADR-0199（每团队一容器一卷）、ADR-0201 第六节（`--depth 1`）、#838（clone 前的可用空间闸）、ADR-0232（同团队多会话共用一容器一卷）、ADR-0243（「读不到」不许说成「没有」）、ADR-0134（做不了先验前提）

## 背景

`sandbox.ts` 建容器时 `Memory` / `NanoCpus` / `PidsLimit` 都设了，**磁盘一个上限
都没有**。一个大仓库、或者水獭在 `bash` 里一条 `dd`，就能把 VPS 磁盘写满，
连累这台机器上**所有**团队。

#836 前两批已经做掉了两件事：`git clone --depth 1`（ADR-0201 第六节，历史往往比
工作树大一个量级）与 clone 之前查一次 `df /work`（#838）。剩下的那一半——**真配额**
——上一条评论里记了两条路，前提是「这台 runtime VPS 还没开出来、没法验」。

## 决策

### 1. 那两条路都走不通，而且这不是「还没做」是实测的结论

2026-09-10 按 ADR-0134 的规矩上机验了一遍（探针与原文贴在 #836 的评论里）。
**这台 runtime VPS 是一个 Incus/LXC guest**（`systemd-detect-virt` → `lxc`，
`/` = `/dev/md2[/var/lib/incus/storage-pools/default/containers/stan/rootfs]`）：

| 候选 | 结论 |
|---|---|
| 每卷一个 loop 挂载的 ext4 镜像（`--opt o=loop`） | **死**。`loop` 是 `mount(8)` 的用户态特性不是内核挂载选项，docker 的 local driver 走 `mount(2)`：`data: loop: invalid argument`。注意 `volume create` 本身**会成功**，失败推迟到第一次挂载 |
| 自己 `losetup` 出 `/dev/loopN` 再喂 `device=` | **死**。LXC guest 里没有 loop 设备也加载不了模块：`Module loop not found in directory /lib/modules/6.8.0-110-generic` |
| 把 `/var/lib/docker` 迁到带 prjquota 的 xfs 上 | **死**。`/proc/filesystems` 里只有 ext4 没有 xfs；`/` 的挂载选项由 Incus 宿主决定，guest 改不了；也没有第二个块设备可格式化（没有 loop） |
| `--storage-opt size=` | **比死更坏**：Docker 29.4.1 + overlayfs **收下这个参数、不报错、也不生效**（实测 `size=64M` 的容器里 `dd` 200 MiB 照写、`df /` 报 436G）。谁哪天顺手加上这行，会以为配额已经有了 |

真配额只剩**动 Incus 宿主**那一条（给这个 guest 挂一块带 size 限制的独立 disk
device，或换一台真 VM）。guest 里够不着那台宿主，**这是维护者动作、不是本仓能
合并的代码**——另开 issue 记着，不留在 #836 里假装还没想清楚。

写进 `MIN_FREE_KIB` 的头注不写进别处：那段注释此前写着「VPS 还没开出来、没法验」，
而它就是下一个人做这个判断时会读到的那段字。

### 2. 两层，判决**故意不同**

| 层 | 判据 | 判决 |
|---|---|---|
| 地板 | 这台机器的可用空间 < `MIN_FREE_KIB`（2 GiB） | **硬拒**：`ensure()` 抛错，一个容器都不建、不起 |
| 每团队预算 | 这个团队的卷用量 > `DISK_LIMIT_KIB`（10 GiB） | **只说不拒**：群里落一条 `chat_message{fromUid:"system"}` |

**地板为什么硬拒**：机器要死了，而这时候拒绝写是唯一救得回来的动作——#838 已经为
clone 定过同一条，这里只是推广到所有写路径。措辞里必须说清**是整台机器不是这个
团队**：不说的话，一个自己只占了几十 MB 的团队会以为是自己超了，跑去删自己的文件。

**超预算为什么不拒**：`ensure()` 是拿容器句柄的唯一入口，超了就拒等于**连 `bash`
一起挡住**，而清理文件的唯一出路正是 `bash`——那个团队会被自己的工作卷锁死，
没有出口。（`readWork` / `searchWork` 不走 `ensure()`（ADR-0251），所以「团队设置 →
文件」那一页照样翻得动——超了之后人要看的正是"哪个目录这么大"。）

这条也是维护者拍的板：候选里那条「硬拒 + 另开一条只能删文件的逃生路径」被否了，
工作量翻倍换来的是同一件事。

### 3. 量用量：`ensure()` 里 fire-and-forget，报的永远是上一次的读数

`du -sxk /work | awk '{print $1}'`（`-x` 不跨文件系统：/work 就是卷的挂载点，
里面再挂别的不该算进来；真镜像上验过输出形状）。三条判据：

- **不等它**：`du` 是 O(整棵树)，等它就是把「拿容器句柄」的延迟押在工作树的大小上。
  于是 `diskUsage()` 报的永远是上一次的读数，**超出最晚在下一次碰容器时被说出口**
  ——一个 turn 的写入量是这条设计明写的窗口。
- **60 秒 TTL**：`ensure()` 挂在**每一条**容器操作上（read/write/bash/git 全过它），
  不设这道就是每条命令前白扫一遍工作树。
- **量失败/读不出数字都保留上一次的值**：「拿不到」不是「变成 0」（同 ADR-0197
  grants 缓存、ADR-0243 三态那条纪律）。`du` 的超时给 60 秒不吃默认那 30——
  **最该被量到的正是那棵最大的树**，被默认超时切掉的话它永远量不出读数。

### 4. 说那句话的地方是 `gateContainer()`，一轮一次

不是 turn 起跑处：**只聊天的 turn 一次都不碰容器**，对它说「你的工作文件夹太大了」
是答非所问（同 ADR-0232 容器锁「第一次碰容器才拿」的判据）。

一轮一次（`diskBudgetAnnounced`，同 `relayWaitAnnounced` / `sandboxProbeFailAnnounced`）：
这条 `chat_message` 在 `agentView` 里是 keep，一轮里每碰一次容器说一句，等于把
每只 agent 的上下文喂成噪音。去重的作用域是一个 **job**，不是一条会话。

### 5. 接线：两半各有各的保鲜期

- `CloudSessionOpts.diskUsage` **必需**（同 `sandboxApproval` / `workspaceLock` 的
  纪律）：忘接线该编译不过——这条能力唯一的出口就是群里那一句话，不出声与「没超」
  在界面上长得一模一样。代价是 98 处内联测试装配各多一行 `diskUsage: () => null`。
- `createSandbox` 的 `freeKib` **可选**（缺省 = 这道闸不存在，既有装配与测试行为
  一字不变），所以忘接线不会编译不过——**而那正是 #836 报的那个洞本身**。判据因此
  落在源码上：`tests/runtime/sandbox.test.ts` 读 `daemon.ts` 断言那次
  `createSandbox` 带了 `freeKib` 且量的是 `dataDir`（同 `tests/main/accountScope.test.ts`
  的做法——daemon.ts 一 import 就要连 docker/Supabase，进不了 vitest）。

`freeKib` 量的是 **`config.dataDir` 那个文件系统**，前提是它与 docker 的数据根在
同一个文件系统上（真机 2026-09-10：两者都在 `/`）。为什么不直接量
`/var/lib/docker`：runtime 是宿主上的 systemd 进程（`User=otto`），那个目录是
root 0710，statfs 走不通。clone 那道闸（#838）量的是容器里的 `df /work`，那一份
才是卷所在文件系统的真读数——**两道各量各的、判据同一个 `MIN_FREE_KIB`**。

### 6. `DISK_LIMIT_KIB` 写成常量，不做成 env 开关

一个能调松的数，在「忘了配」那天就是没有；而这个数的意义本来就是一条要写进 ADR 的
策略，不是部署参数。要改就改这一行、走一次 PR。

## 代价与已知未做

1. **挡不住存心的人**：一个 owner 可以在一条 `bash` 里 `dd` 到磁盘满——地板在
   下一次 `ensure()` 才拦，而那一次已经写完了。真配额要动 Incus 宿主（决策 1）。
2. **超预算只说不拒**，所以「说了但没人理」是正常状态。这是决策 2 的直接代价。
3. **一个 turn 的窗口**：读数是上一次的（决策 3），这一轮写进去多少要下一次碰
   容器才知道。
4. **`du` 跑不完的树量不到**：大到 60 秒还没跑完的工作卷永远没有读数、也就永远
   不出声。
5. `du` 走的是**容器锁之外**的一次 `docker exec`（它只读，不改卷），代价是多一份
   I/O 负载，好处是不占那把锁。
6. **地板量的是 dataDir 不是卷所在的那个文件系统**（决策 5 的前提），两者分家的
   那天这个数说的是另一块盘。
7. **真机一次没跑过**：改的是 `services/runtime/`，云会话要**重新部署 runtime**
   才生效（#791）。
