# ADR-0102：回注消息的身份记在事件上，不靠正文前缀猜

- 状态：已接受
- 日期：2026-08-25
- 相关：issue #389（后台任务回注）、issue #428（本次）、ADR-0073（不 mid-splice）

## 背景

后台任务（`bash` 的 `run_in_background`）在 turn 之外完成，结果以新 turn 注回会话，
载体是一条 `user_message`（ADR-0073：不往正在跑的 turn 中间插；model-visible means
logged）。载体选择没有问题，问题是**它和人亲手打的字在 UI 上完全同形** —— 同样的
蓝气泡，翻历史时分不出哪句是自己说的。

正文里确实有 `[后台任务 bg-N 完成]` 前缀，但那是给模型读的文案，不是身份。让 UI 去
匹配这个前缀等于把渲染挂在一句随时会改的中文上，而且人自己打出同样的字就会被认错。

## 决定

`UserMessageEvent` 加可选字段 `origin?: "background"`：

1. **身份是事件上的字段，不是正文的形状**。缺席 = 人发的（旧日志照常重放，
   schema 向后兼容硬规则）；`runTurn` 只在传了 origin 时才落这个字段，不传时事件
   形状与从前逐字节一致。
2. **只有主进程写得了它**。`handleSendMessage` 的 origin 参数不经 IPC 透传
   （`CHANNELS.sendMessage` 的 handler 显式只转发前五个参数），渲染层伪造不出
   "这条是后台发的"。同 `OutgoingAttachment` 的立场：渲染层送来的都是不可信输入，
   而 append-only 日志收不回。
3. **模型投影读都不读它**。`deriveMessages` 不碰 origin —— 对模型来说这就是一条
   用户消息，和从前逐字节一致。这个字段是纯 UI 事实，不是模型事实。

## 代价与边界

多一个只服务于 UI 的字段。接受的理由：身份本来就是事件的一部分（"这句话是谁说的"
和"这句话说了什么"同等重要），把它挤进正文才是把两件事混在一起。

将来若出现别的非人类来源（定时任务、远程手机端代发、hook 注入），扩成
`origin?: "background" | "..."` 即可 —— 这也是当初不用布尔 `isBackground` 的原因。
