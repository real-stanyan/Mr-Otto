# ADR-0277：群语音有回声消除就不半双工——能量断句、按句出声、人可以插嘴

> 原为 ADR-0276（撞号：#1187 / PR #1189 先落了 0276，按 ADR-0074 在合并前改号）

- 状态：已采纳（2026-09-09）
- Issue：#1184（承 #1176 / ADR-0273、#1163 / ADR-0271）
- 维护者拍板：按此做；打断先不告诉模型（否掉「say 帧带打断位置」）
- 对照：real-stanyan/dryrun 的 AI 面试语音间（`bargeInGate` / `echoFilter` / `endpointing` / `sentenceChunker`）

## 背景

ADR-0273 上线后真机第三次用：识别是通的，但「我说完到它开口」慢得像对讲机——
说完 → 识别器再滞后 0.5～1 秒 → 断句等转写 1.5 秒没变 → 发出 → 派活分类调用 0.5～2 秒 →
模型 2～4 秒 → 整段写完才合成、合成 1～3 秒。6～9 秒才出声。且 agent 说话时人插不进嘴
（半双工闭麦）。维护者：「把整个语音聊天质感做得真实一点」，并点名 dryrun 里「人类说话可以
打断 AI」。

派活那一段已由 ADR-0275 砍掉（通话里只有一只时不问分类器）。本条砍剩下的三段、加上插嘴。

## 决策

### 1. 系统回声消除开着就不半双工

helper 的 `inputNode` 开 voice processing（`setVoiceProcessingEnabled(true)`，VPIO）。**真机探针
（2026-09-09）**：AEC 关，`say` 从扬声器放的一句被原样转写出来；AEC 开，一个字都没有，而人说的
话照常识别出来。也就是 macOS 的 VPIO 在系统级减掉了**这台机器扬声器里的任何声音**——包括
Electron 那边放的 agent 语音，helper 不需要拿到它的参考信号。

于是麦可以真的常开：`status.aec === true` 时渲染层不再 `speechPause`（`micShouldPause` 多一个判据），
半双工只留给开不了 AEC 的机器 / 旧 helper（`aec` 为 `false` / `null` 照旧）。两条真机踩出来的细节：
开着 VPIO 时输入格式变成多声道（这台 9 声道），识别器吃不下，只取第 0 声道折成 mono；VPIO 默认会把
别的 app 的声音压低（ducking），而 agent 的语音正是「别的 app」放的，`voiceProcessingOtherAudioDuckingConfiguration`
压到最低（macOS 14+）。`MROTTO_SPEECH_NO_AEC=1` 是排障开关（怀疑 AEC 吃掉了人声时关掉对比）。

### 2. 插嘴：够长 + 不像回声 → 停播放，这一轮剩下的不读

麦开着、agent 在说（或队列里排着）时来了一片 `partial`：≥ 3 个 token（汉字逐字算；「嗯」「好的」
是应声不是插话）且与正在读的那句 token 重叠 < 70%（`isSelfEcho`，AEC 偶尔漏一点、漏出来的正是
它自己的话——dryrun 的 echoFilter 同款）→ `voicePlayer.stop()`，并把在说的 + 排着的每只记成
`interrupted`：这一轮之后的快照与终态**记成已读但不出声**，`turn_ended` 清。不清「已读」的话，
终态落下来会把没读的补回去——人已经打断它了。**不告诉模型**（维护者拍板）：本机停播放即可，
不加帧不加事件；模型下一轮从文字看得到自己整段话，代价是它不知道人听到哪儿。

### 3. 能量断句：人停嘴就收口，不等转写「自己稳住 1.5 秒」

helper 每块音频算 RMS，过一道底噪自适应的能量门（`LevelGate`：比底噪高 9 dB 且高于 -55 dBFS 算说话；
安静样本抬底噪快、说话样本抬得很慢，持续十几秒的噪音会被吸收成底噪）。`Endpointer` 多一条时钟：
人停嘴之后安静够久（像说完了 700 ms、没说完 1500 ms）且转写稳住 250 ms → 收口。「像说完了」=
句末标点（识别器 `addsPunctuation` 给的）或很短；逗号 / 没标点的长句按没说完——判错的代价不对称
（切成两半 vs 多等 0.8 秒），同 dryrun 的 endpointing。**文本 1.5 秒没变仍是天花板**：背景一直响时
不能永远不收口；没收到过能量样本（旧路）只剩这条。tick 从 250 ms 改成 100 ms。
顺带每 100 ms 一条 `level` 事件（0..1 + 有没有人在说话）给界面画声浪。

### 4. 按句出声不按段

delta 快照按空行切段之后，段内再按句末标点切一刀（`splitSpoken`：。！？直接切，.?! 后面要跟空白——
「2.0」「Dr.」不切；代码围栏整块一个单位）。一段里第一句写完就合成，首句出声从「整段写完 + 合成」
缩到「第一句写完 + 合成」。已读判据不变（原文相等），单位从段变成句；快照末尾那句只在以中文句末
标点或西文 !? 收尾时算完（西文句号可能是「2.」半截）。

## 否掉的候选

- **软件回声过滤代替 AEC**（只靠 token 重叠）：扬声器外放时人的话与 TTS 混在同一条转写里，
  人那几个字占比小就整句被当回声丢掉；中文同音字还会把 TTS 的话转成「新词」触发假插话。
  探针证明系统 AEC 可用之后没有理由自己做。
- **告诉模型被打断在哪一句**：多一次协议进位 + runtime 部署，且「人听到哪儿」本身是本机事实
  （别的成员那台可能没在听）。留到真机证明模型因此答非所问再做。
- **流式 TTS**（MiniMax 分块回音频）：首句更早出声的下一刀，但边合成边播要改播放器整条链。
  按句切之后首句已经短，先看真机够不够。

## 代价与已知未做

- 插嘴只停本机播放；别的成员那台照旧读完。
- 被打断的那几只这一轮剩下的话永远不读（文字仍在时间线里）。
- 能量门的几个数（9 dB / -55 dBFS / 700 / 1500 / 250 ms）是拍脑袋 + 探针，要靠真机校；
  `start` 命令可递 `completeMs` / `midMs` 调。
- AEC 探针只验了「扬声器外放的 `say`」；耳机、外接麦、蓝牙耳机没验（VPIO 对它们的行为可能不同）。
- helper 二进制一变 TCC 就要重新授权（同 ADR-0273），dev 下每次重编都会再弹一次。
- 真机上时序一次没量过（探针等授权没等到）；合并后按 #1184 在 dev 里量：说完到出声。

## 推翻前提

- 真机上 AEC 漏得多（插嘴误触发、或它自己的话被当人话发出去）：把 `bargeInOn` 的门槛抬到 4 个
  token、`isSelfEcho` 阈值降到 0.5；再不行 `MROTTO_SPEECH_NO_AEC=1` 退回半双工，渲染层一字不改。
- 能量门在某台机器上永远「活着」或永远「安静」：天花板保证前者仍在 1.5 秒收口；后者退化成旧行为。

> 2026-09-09 后记（#1196）：真机第一次跑，边想边说的长句被切成三条（「我们近期 / 在web上做了浮窗式的栅栏 / 近期做了外部版的」），agent 逐条回。决策 3 的数改成：短答只认 ≤3 字（「我们近期」四个字已经可以是长句开头）、没说完的等 2.5 s、无标点长句的文本静默兜底 3 s；有句末标点的仍 700 ms / 1.5 s。没收到过能量样本的旧路不变。
