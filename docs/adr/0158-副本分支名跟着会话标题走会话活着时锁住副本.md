# ADR-0158：副本分支名跟着会话标题走，会话活着时锁住副本

- 状态：已接受
- 日期：2026-08-28
- 关联：issue #647；ADR-0156 / 0157（独立工作副本）、#643（回收，②是它的前置）
- 参照：Claude Code 的 `locked claude session <名> (pid …)`

## 背景

ADR-0156/0157 之后，副本本身能用了，但两件外围的事没做，对照 Claude Code 缺得明显：

1. **分支名是废的**：接线处写死 slug，所有副本都叫 `otto/session-<hex>`。一个项目开三只水獭就是三条认不出来的分支。
2. **没有占用标记**：副本上没有任何「有人正在用」的痕迹。将来的回收程序（#643）分不出「活着」和「早该清了」。

## 决策

### ① 分支名跟着自动标题走

建会话那一刻还没有主题（用户先配文件夹/模型，再说第一句话），所以创建时只能给占位名。**自动标题落盘之后把分支改名**：`otto/<标题 slug>-<原随机后缀>`。

后缀保持不变——目录名带着它，改名只换可读的那一半，两边仍然对得上。

**关键取舍：系统提示不再写死分支名。** 日志是 append-only，`session_created.isolated.branch` 改不了，所以它是「当初叫什么」的历史记录，不是「此刻叫什么」。要是提示里写死它，改名之后模型看到的就是个陈旧名字。改成让水獭自己 `git branch --show-current`——投影仍然完全可从日志推导（硬规则成立），只是它推导出的是一条指令而不是一个值。

改不动就不改：目标名已存在（用 `-m` 不用 `-M`，绝不覆盖别人的分支）、标题里没有可用字符、分支不是我们建的那种形状。**名字是便利，不是正确性。**

### ② 会话活着时锁住副本

`git worktree lock --reason "mr-otto session <id> (pid N)"`，照 Claude Code 那行的形状。

锁**只挡「别人来删这份副本」**，不挡任何读写。原因串是给清理程序看的：里面的 pid 让它能按探活判断这把锁是不是陈旧的——与 ADR-0155 的自愈判据同一套。没有这条，#643 的回收要么不敢删（副本永远攒着），要么乱删（删掉正在用的）。

## 为什么不是别的做法

| 候选 | 否决理由 |
|---|---|
| 建会话时就要主题（让用户先写一句话再建会话） | 改的是产品流程，代价远大于一个分支名 |
| 推迟到第一条消息再建副本 | 围栏来自 `session_created.workspace`（硬规则）。会话建立后再换围栏根，等于中途改围栏 |
| 提示里写死名字，改名时补一条事件把新名字落盘 | 为一个显示用的字符串新增事件类型。而「现查」这条指令本身就是可从日志推导的投影，不需要新事件 |
| 用文件锁而不是 `git worktree lock` | git 自己的锁 `git worktree remove` 会认，多一层自己的锁等于两套真相 |

## 后果

- 接受：会话没有标题（用户从不说话 / 自动标题失败）时分支就一直叫 `otto/session-<hex>`。
- 接受：改名之后日志里的 `isolated.branch` 与实际不一致——这是**有意**的，字段语义已改成「当初叫什么」，注释里写明了。
- 接受：锁要有人解。#643 的回收必须先 `git worktree unlock` 再删，并且要按 pid 探活跳过活着的会话。
- 这两条都是 #643 的前置：没有可读的名字，用户在合并 UI 上分不清要合哪条；没有锁，回收不敢动手。
