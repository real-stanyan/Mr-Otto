# 0134 接班读到「做不了」，先验前提再决定跳过

Issue: #560

## 背景

handoff issue 和维护者留言里「只能维护者做 / 源码不在本仓 / 服务器侧 agent 做不了 /
agent 跑不了 GUI」这类判断，本仓连续错了四次，每次都被下一班照抄、没人去试：

1. 「migration 只能维护者在 Supabase Studio 手动跑」→ 服务器 SSH 免密可达（#234 等多个 handoff 照抄）
2. 「#76/#77/#78 是服务器侧，agent 做不了」→ nginx / docker / systemd 全在同一台可达机器上，三条一次做完
3. 「otto-gateway 源码不在本仓」（#122 维护者留言）→ 就在 `services/gateway/`
4. 「实施 agent 跑不了 Electron GUI」→ 四张真机验收清单（#123/#142/#147/#169）挂了三个多月，
   `tests/e2e/` 的 Playwright-electron 一直就能起真 app（ADR-0076）

共同机制：这类判断写进 handoff 之后就变成下一班的**既定前提**。它读起来像调查结论，
其实往往只是上一班没试。代价不对称——issue 一挂几周到几个月，验一次前提只要几分钟。

这条教训此前只存在于单一工具的私有记忆层（Claude Code 的 `~/.claude` memory），
别的 agent 永远看不到。本仓协议是 AGENTS.md 单一事实源、多工具共读——对每一班都
有用的先验必须落在这里，私有记忆只配当 staging area。

## 决定

Working agreement「While working」新增一条：接班读到「做不了 / 不在本仓 / 只能人来做」
这类判断时，先花五分钟验前提本身（`ssh` 能不能连、`ls` 有没有那个目录、`grep` 有没有
那个符号），再决定要不要跳过；验完确实做不了，把**验的方法和结果**写进 issue，让下一班
不用再验。

分层：Working agreement 非 Gate 部分，L2 自治（ADR-0006）；条文不引用任何协议机制
关键词，不触发 ADR-0012 的机制引用升级。

## 接受的代价

- 每次接班多花几分钟验证成本，换 issue 不再按周挂起。验证结果写回 issue 后，
  同一判断第二班起零成本。
- 「验的方法和结果写进 issue」依赖执行纪律，没有门禁可断言——和 blocking edges
  （ADR-0044）同级：hygiene convention，坏了顶多多花一次判断。

## 推翻它的前提

如果哪天「做不了」判断的正确率显著高于错误率（比如权限收紧后大多数真做不了），
这条先验的期望收益转负，可以退回默认相信 + 抽查。
