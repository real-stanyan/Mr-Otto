# ADR-0086: 归档复活——用户归档只收起列表，仍可被跨会话召回

日期：2026-08-25
状态：已接受
关联：ADR-0002（物理删除语义，本决定与之并存不冲突）、ADR-0065（跨会话回忆靠搜索，本决定修订其第 4 条）、ADR-0047（子会话过滤）

## 背景

会话此前只有一种收纳手段：物理删除（ADR-0002）。删除把 `events` 和 `events_fts` 的行一并抹掉——`session_search`（跨会话召回）的数据源随之永久丢失。用户想要一个中间态：**把会话从列表收起，但记忆不丢**——过去聊过的内容仍能被后续会话搜到。

ADR-0002 当年否决过「归档 + 删除两个按钮」，理由是 MVP 认知成本，并明确留了后路：「将来真需要『可恢复的归档』再加回来，事件类型都还留着」。现在就是那个将来。遗留资产：`session_archived` 事件类型、`sessions()` 的过滤、`searchText()` 的排除、Timeline 渲染都在——但旧语义是归档 = 列表和召回**都**排除（唯一使用方是 sys-memory-edits 系统保留会话，本意就是彻底藏起）。

## 决定

1. **两种归档，一个字段辨**：`session_archived` 加可选 `reason?: "user" | "system"`（加字段 = schema 向后兼容硬规则）。
   - `"user"`：用户手动归档——从主列表收进「已归档」区，**仍可被 `session_search` 召回**，可恢复。
   - `"system"`：系统保留会话（sys-memory-edits）——列表和召回都排除，旧行为原样。
   - **缺席 = `"system"`**：ADR-0086 之前的旧事件全部来自早期"删除"或系统保留会话，两者本意都是彻底藏起——安全默认，隐私语义不回退。
2. **新增 `session_unarchived`**：恢复归档。归档状态 = 最后一条 archived/unarchived 事件说了算（append-only，历史全留）。
3. **修订 ADR-0065 第 4 条**：「永远排除归档会话」改为「永远排除**系统**归档会话」。用户归档的排除本来就不是隐私承诺，只是当年归档 = 删除的遗留。
4. **归档 ≠ 删除，两按钮并存**（回应 ADR-0002 的否决理由）：删除仍是物理抹除、不可逆、弹 confirm；归档可逆、不设闸。UI 用 ⋮ 菜单把两个动作并排呈现，语义可辨。
5. **归档注销活资源**：pty/浏览器/agent/岛投影照删除的清单注销；恢复后走 resumeSession 正常懒加载重建。turn 进行中拒绝归档（同删除）。
6. **账单不变**：`billedUsage()` 照旧统计归档会话——归档是从列表消失，不是这笔钱没花过。

## 权衡

- **「已归档」区点击行 = 只读查看历史，不自动恢复**。恢复是显式动作（菜单「恢复归档」）——点一下就把会话拽回主列表太容易误触。
- **归档会话可以被继续对话**（查看后发消息不被拦）。接受：拦截需要贯穿 send 链路的状态检查，收益只是防一个罕见的困惑场景；日志层面这也不是错误。
- **系统归档的判定靠 reason 字段而不是会话 id 前缀**：id 前缀是命名约定，字段是协议。

推翻前提：若将来引入 embedding 语义检索（ADR-0065 预留的演进），排除逻辑跟着候选召回层走，本决定的「用户归档可搜」语义不变。
