# 灵动岛手动冒烟清单

原生 notch UI 用不了 Playwright（不是 Electron 渲染进程，见 ADR-0061），跟 `tests/e2e/` 一样这份清单不进 `npm test` gate，靠人手动跑。GUI 改动的 PR 贴这份清单的结果（哪些跑了、哪些没跑、结果如何）。

## 前置

- 一台带物理刘海的 Apple Silicon Mac（M1 Pro 及以上机型的 14"/16" MacBook Pro），已解锁、非远程会话（远程桌面/截屏软件下 `NSScreen` 刘海几何和焦点抢还行为可能不准）。
- `npm run dist:mac` 出过包，或 dev 模式下 `scripts/build-island.mjs --debug` 跑过一次（确认二进制存在）。
- 至少一个已登录、可发消息的会话。

## 一般冒烟项（对齐设计文档「测试策略」）

- [ ] **四态切换**：idle 折叠 → active（turn 跑起来）→ approval（工具需要审批时）→ 输入态，四个状态之间的转场都触发、视觉正确。
- [ ] **hover 展开**：鼠标悬停折叠态岛，展开出详情视图；移开鼠标收回。
- [ ] **岛内发消息落到主窗会话**：在岛的输入态打字发消息，消息出现在主窗对应会话的对话流里，跟直接在主窗发消息效果一致。
- [ ] **审批双向**：审批卡片出现时，
  - 在岛上点「同意/拒绝」，主窗的审批卡片同步消失/更新；
  - 在主窗点「同意/拒绝」，岛上的审批卡片同步消失/收起。
- [ ] **多屏 / 拔插**：外接显示器、切换主屏、插拔外接屏，岛始终显示在当前主屏（带刘海的那块）合理位置，不留在已拔掉的屏上、不重叠出现两份。
- [ ] **非 notch Mac floating 兜底**：在没有物理刘海的机型（或用非 notch 显示器作为主屏）上，DynamicNotchKit 走 `.floating` 呈现，功能等价、不报错。

## 多会话（ADR-0063：单会话 → 会话集合）

对齐 `docs/superpowers/specs/2026-08-22-notch-island-multiagent-design.md`「测试策略」的手动冒烟项，验的是主进程 `Map<sessionId, IslandState>` + `IslandFleet` 整包推送 + Swift `List(agents)` 这条端到端链路。

- [ ] **多会话各自显状态**：主窗开 2 个以上会话，让至少一个在跑（active）、至少一个挂着 pending approval（如果只开两个就正好各占一个）。展开岛，列表里每个会话一行，各自的状态点/当前工具/审批徽标跟主窗侧栏对应会话的实际状态一致——尤其验证**非聚焦**（主窗当前没选中）的那些会话也正确显示 active/approval，不会因为不是 `focusedSessionId` 就卡在 idle（这是 review 抓到过的 Map-miss 回归点，见 ADR-0063「后果」）。
- [ ] **审批行置顶**：多个会话里有一个或多个处于 approval 阶段时，这些行排在列表最上面、带高亮，不必滚动就能看到。
- [ ] **点不同行切换详情**：点列表里的每一行，下方详情区跟着切换成对应会话的详情（active 详情 / 审批三按钮 / 输入框），点哪行详情就是哪行的，不会显示成别的会话的内容。
- [ ] **就地审批落到对的会话**：选中一个非聚焦的（不是主窗当前活跃会话的）approval 行，点"允许"或"拒绝"，验证主窗里**那个被选中的会话**（不是主窗当前聚焦的会话）的审批卡片消失/更新——命令带的 `sessionId` 是选中行的，不是 `focusedSessionId`。
- [ ] **删会话掉行**：在主窗删除/关闭列表里的一个会话，岛的列表应该跟着掉这一行（不再显示已删除的会话），且不影响其它行的状态和选中态（除非被删的正好是当前选中行，此时应回落到 `focusedSessionId` 或列表首行，参考下一项）。
- [ ] **`focusedSessionId` 默认高亮**：主窗切换当前活跃会话（点侧栏另一个会话），岛还没有手动选过行时，展开态默认高亮/选中的应该是主窗当前这个新聚焦的会话；已经手动点过某一行的情况下，主窗切会话不应该打断当前的手动选中（除非该行本身消失，见上一项的回落规则）。
- [ ] **展开面板是贴合刘海的紧凑卡片**：展开态整体宽度应该是一张约 380pt 的紧凑卡片（能看到桌面/菜单栏在卡片两侧），不是横贯全屏的通栏黑条——这是真机验收中发现并修复过的一个回归点（`.frame(width: 380)`），改动 `IslandExpandedView` 之后重点回归这一项。

## 需要真机解锁验证 — 尚未验证（NOT yet verified）

以下七项是焦点/输入链路的交互验收，实现期间开发机处于锁屏状态，**没能在真实解锁环境下跑过**，是这次交付里唯一未经人工验证的部分：

1. [ ] **TextField 实际收到键盘输入**：进入输入态后，敲键盘，字符真的出现在岛的文本框里（焦点抢还链路端到端打通，不是"看起来有焦点但打字进了别的窗口"）。
2. [ ] **Enter 提交产出正确命令**：输入文字后按 Enter，helper stdout 上出现一行 `{"type":"send","sessionId":...,"text":...}`（可用 `swift run` 直接跑 helper、手动往 stdin 喂状态、观察 stdout 验证，或在主进程日志里确认收到了 `sendMessage` 调用）。
3. [ ] **点击纸飞机 Send 按钮**（跟 Enter 是两条独立代码路径）：鼠标点发送按钮也能正确提交，草稿文字不会在点击瞬间丢失/清空错。
4. [ ] **Esc 清空并收起**：输入态下按 Esc，文本框内容清空，岛从输入态收起（回到 idle 或 active，视当时状态而定）。
5. [ ] **焦点还给前台 app**：无论是提交（Enter/点击）还是 Esc 还是失焦退出输入态，键盘焦点都要还回退出输入态之前最前面那个 app——用户不用额外点一下就能在原来的 app 里继续打字。
6. [ ] **失焦到别的 app 触发 exitCompose**：不是按 Esc，而是直接点到别的 app（切前台），岛能通过焦点变化的回调感知到，自动退出输入态（对齐设计文档 §焦点/输入 "退出输入态（Enter 提交 / Esc / 失焦）后放回 `.accessory`"）。
7. [ ] **入口点击靶区可靠**：折叠态的小图标（键盘图标 idle / 脉动小圆点 active）作为点击进入输入态的入口，命中区域大小合理、点击稳定命中，不会因为图标太小或动画中点偏了而点不中。

> 这七项没跑通不算这次改动失败——它们是交付时的已知缺口，不是回归。下一次有解锁真机可用时优先补跑，跑完把对应勾选打上、把这个块整体挪到上面「一般冒烟项」或视情况关掉本节。
